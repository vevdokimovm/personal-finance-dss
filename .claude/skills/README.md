# Скиллы FINPILOT

Шесть скиллов, покрывающих слои, где ошибка стоит дороже всего: деньги, схема БД,
персональные данные, канон матмодели, контракт API, фронтенд.

| Скилл | Когда срабатывает |
|---|---|
| `finpilot-money-format` | Денежная сумма в коде: вывод, парсинг, хранение, округление |
| `finpilot-react-component` | Любой `.tsx`, вёрстка экрана, форма, график |
| `finpilot-fastapi-endpoint` | Роут, схема запроса или ответа, код статуса |
| `finpilot-alembic-migration` | Таблица, колонка, индекс, ограничение, рассинхрон ревизий |
| `finpilot-152fz-guard` | Поле с данными пользователя, логи, экспорт, публикация в зеркало |
| `finpilot-math-model-guard` | Ликвидность, ресурс, ПДН, SAW, лавина, прогноз |

## Евалы

У каждого скилла `evals/evals.json`: позитивные кейсы, негативные и граничные.
Прогон: «Evaluate the skill at `.claude/skills/<name>` using its evals», три прогона
на кейс для устойчивого trigger-rate. Считать precision и recall, писать в
`docs/claude_token_lab/results.md`.

**Негативы обязательны.** Скилл, срабатывающий на всё подряд, ест контекст и мешает.
Замер из захода 7: baseline активации скилла — 55%, с форсирующим хуком — 100%.
Разрыв обычно не в поведении модели, а в **описании**: оно объясняет WHAT вместо WHEN.
Если скилл не триггерится — переписывать `description`, а не тело.

## Правка

Описание — про момент срабатывания, а не про содержание. Тело — короткое: под Claude 5
длинные инструкции с верификацией и эмфазой вредят (заход 7, направление 6).
Скиллы **не наследуются** субагентами — объявлять в `skills:` явно.
