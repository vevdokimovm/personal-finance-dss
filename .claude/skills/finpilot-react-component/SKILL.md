# React-компонент FINPILOT

Стек: React 19 + TypeScript + Vite, TanStack Router и Query, Zustand для клиентского
состояния, Radix UI и shadcn/ui как база, Recharts и visx для графиков, KaTeX для формул.
Тесты — Vitest, E2E — Playwright.

## Обязательное

**Только токены дизайн-системы.** Ни одного хардкоденного цвета и ни одного `px` вне
токенов — на это стоит `PostToolUse`-хук, он подсветит. Значения берутся из слоя токенов,
не из макета глазами.

**Типы на границах.** Пропсы компонента и ответы API типизированы явно. `any` не проходит
ревью. Типы ответов API не дублируются руками — генерируются из OpenAPI-схемы бэкенда.

**Доступность не опциональна.** Каждый интерактивный элемент достижим с клавиатуры,
у каждого поля есть связанный label, фокус видим. Radix даёт это из коробки — не ломать
его кастомными обёртками. Проверяется субагентом `a11y-auditor`.

**Серверное состояние — только через TanStack Query.** Не `useEffect` с ручным `fetch`,
не дублирование серверных данных в Zustand. Zustand — для того, что живёт только на клиенте.

## Денежные значения

Форматирование — через общий модуль, не локально в компоненте. Правила — скилл
`finpilot-money-format`.

## Состояния, которые надо предусмотреть сразу

Загрузка, пусто, ошибка, частичные данные. Финансовый интерфейс без состояния ошибки
выглядит так, будто у пользователя нет долгов, — это худший вид молчаливого сбоя.

## Структура

Компонент, его тест и его стили лежат рядом. Один экспорт по умолчанию на файл.
Логика, которую тянет больше одного компонента, переезжает в хук, а не копируется.
