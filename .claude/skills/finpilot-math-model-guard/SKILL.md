# Канон матмодели — только `docs/math_model.md`

Авторитет — `docs/math_model.md` и код. Не память, не инструкции, не прошлые чаты.
**Имя файла стабильно и не меняется при рекалибровках** (с v8.9.4) — номер версии смотри
внутри файла (заголовок/«Статус»), не угадывай по памяти: канон уже шесть раз рекалибровался
(v3.0.0 → v3.1.0 → v3.2.0 → v3.3.0 → v3.4.0 → v3.5.0 → v3.6.0), и до этого исправления версия в имени
файла была источником систематической путаницы (репозиторий полгода ссылался на устаревший
`math_model_v3_0_0.md` как на канон — разобрано в v8.9.2–v8.9.3). Исторические версии —
`docs/model/history/`, каждая со своим номером в имени и баннером `SUPERSEDED`. Разночтения
между кодом и текстом ВКР, полная хронология калибровок — `docs/model/model_history.md`.

## Опорные факты

**Ликвидность `Lt`** — stock-based, месяцы автономии: `Lt = B_liq / Σe`.
Ортогональна ресурсу. Это не поток.

**Ресурс `Rt`** — поток: `Rt = CF − ΣP`. Баланс `Bt` в ресурс **не входит**.

**Альтернативы:** `|A| = 66`, шаг дискретизации 10%.

**`r_bench`** — динамический: ключевая ставка ЦБ × (1 − НДФЛ). Фолбэк 0.14 при
недоступности источника. В проде — зеркало `cbr-xml-daily.ru`: `cbr.ru` отдаёт 403
датацентровым адресам, это защита от нагрузки, а не баг.

**Доверительный интервал прогноза — 80%** (p10–p90).

**Жёсткие инварианты:** `Rt >= 0` и `ПДН <= 0.40`. Только эти два.
Отсев по ликвидности мягкий: `L_min = 0`, по умолчанию выключен.

## Калибровки G1–G8 + инфляция (v3.1.0 → v3.6.0), поверх базы выше

Базовые формулы Lt/Rt/66-альтернатив/r_bench/80%-CI/жёсткие инварианты не менялись ни в одном
из пяти раундов сертификации — только это добавилось поверх:

- **G1 — насыщение резерва** (`app/core/...`): полезность ликвидности насыщающая,
  `min(Lt', Lt*)` с целевой подушкой по профилю (6/5/4.5/3.5/3 мес.), не бесконечный рост.
- **G2 — кризисный режим** (`app/core/crisis.py`, §12 канона): при `Rt < 0` обязателен план
  действий (балансовый ход из ликвидности → срез трат → заморозка целей → реструктуризация),
  не просто диагностика без действия.
- **G3 — гейт ПДН:** план не должен УВЕЛИЧИВАТЬ ПДН (`Dt' <= max(0.40, Dt)`), а не тупо
  отсекать уже перегруженных.
- **G4 — слой излишка:** разовые ходы из накопленного сверх целевой подушки остатка.
- **G5 — инвест-транш:** терминальный сток сверх подушки, инструмент по горизонту цели.
- **G6/G8 — floor резерва:** базовый `RESERVE_FLOOR_MONTHS = 2.0` (было 1.0 в v3.0.0–v3.3.0);
  токсичный долг (ставка `>= max(30%, r_bench + 15 п.п.)`) опускает floor 2.0 → 1.0 (G8,
  v3.5.0) — не жёстко «всегда 2.0».
- **G7 — честный ПДН при нулевом доходе** + **G7-остаток** (§10.4, ADR-009): непотраченный
  остаток целевого бакета каскадом уходит в резерв, не испаряется.
- **Инфляция целей (v3.6.0, ADR-013, §11.3):** цели с горизонтом > 36 мес индексируются по
  цели Банка России по инфляции (4%/год) — `T^fut_s = T^tgt_s·(1.04)^(τ_s/12)` вместо
  номинала в $S_n(a)$. Не спорная позиция (не требует экспертного консенсуса) — систематическая
  ошибка, подтверждена стендом (локализация 0 портретов без длинной цели, footprint 0.23%).

## Запрещённая legacy v2.x

Если в коде или обсуждении всплыло что-то из этого списка — это ошибка, а не альтернативный
подход:

| Устаревшее v2.x — не использовать | Действующий канон (`docs/math_model.md`) |
|---|---|
| v2.x: `Lt = Rt / (Σe + ΣP)`, flow-based — устарело | `Lt = B_liq / Σe`, stock-based |
| v2.x: `\|A\| = 21`, шаг 20% — устарело | `\|A\| = 66`, шаг 10% |
| v2.x: CI 95% интервал — устарело | CI 80% (p10–p90) |
| v2.x: `L_min = 0.30` жёстко — устарело | `L_min = 0`, мягко, выключен |
| v2.x: `r_bench = 0.14` статично — устарело | Динамический от ключевой ставки |

`v2.0.2` — исторический документ ВКР, не источник для кода. Файлы в `docs/model/history/`
(`math_model_v3_0_0.md` … `v3_4_0.md`) — тоже исторические (каждый с баннером `SUPERSEDED`),
не редактировать задним числом, не использовать как источник текущих порогов.

## Веса целей

Немонотонны нестрого: между профилями 2 и 3 плато на 0.20. В тестах сравнивать
нестрого — строгое сравнение даст ложное падение.
