# Стандарт выходных файлов прогона матмодели через датасет

> Зафиксировано по требованию владельца (2026-07-18). Каждый прогон модели через
> датасет портретов выдаёт **ровно этот комплект**, и имена файлов **всегда**
> кодируют версию матмодели и итерацию датасета. Действует для всех будущих
> прогонов.

## 1. Комплект выходных файлов (всегда два)

При каждом прогоне модели по датасету выдаются:

1. **Читаемая сводка** — `.md`, человеческим языком: статусы, разбивка по слоям,
   вердикт по битым записям (слой D), метаморфическая дисциплина, доминанты,
   разовые ходы, вывод «сломалась / не сломалась и где». Отдаётся владельцу
   локально через `present_files`.
2. **Построчные результаты** — `.csv.gz`: ответ модели по каждому портрету
   (`id, kind, risk, status, rt, lt, dt, xo, xr, xg, invest, dom, dt_alert,
   crisis_severity, crisis_actions, invalid_reason, model_lump`). Кладётся в
   `knowledge/model_validation/` и остаётся в репозитории (входит в архив кода).

Сводка — для человека, csv — для стенда сравнения с экспертами. Оба нужны всегда.

## 2. Правило нейминга (обязательно)

Имя обоих файлов кодирует **версию матмодели** и **итерацию/версию датасета**:

```
model_outcomes_<версия_модели>_on_<версия_датасета>.csv.gz
model_results_<версия_модели>_on_<версия_датасета>.md
```

Версия модели пишется с подчёркиваниями (`v3_4_0`), версия датасета — коротко
(`v4`). Примеры фактических прогонов:

| Файл | Модель | Датасет |
|---|---|---|
| `model_outcomes_v3_1_0_on_v2.csv.gz` | v3.1.0 | v2 |
| `model_outcomes_v3_3_0_on_v2.csv.gz` | v3.3.0 | v2 |
| `model_outcomes_v3_4_0_on_v2.csv.gz` | v3.4.0 | v2 |
| `model_outcomes_v3_4_0_on_v3.csv.gz` | v3.4.0 | v3 |
| `model_outcomes_v3_4_0_on_v4.csv.gz` | v3.4.0 | v4 |

**Зачем строго так:** матмодель и датасеты развиваются независимо и
пересекаются многократно (одна модель гоняется по нескольким датасетам, один
датасет — по нескольким версиям модели). Без версий в имени снимки путаются, а
сравнения «что изменилось» становятся невозможны. Имя файла — самодостаточная
метка: видно, что с чем прогонялось, без открытия файла.

## 3. Как получить комплект одной командой

```bash
python -m tools.model_validation.dataset_export run \
  --dataset-version 4 --seed 20260718 \
  --model-version v3_4_0 \
  --out-dir knowledge/model_validation
```

Команда `run` сама собирает оба файла с корректными именами: прогоняет outcomes
(слой D → `status=invalid` без запуска модели) и печатает сводку в stdout для
переноса в `.md`. Версия модели берётся из аргумента `--model-version` (сверяется
с `APP_VERSION`), версия датасета — из `--dataset-version`. Ручной набор имени не
требуется — нейминг гарантирован кодом.
