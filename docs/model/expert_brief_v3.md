# Задание независимому финансовому эксперту — оценка 12 000 портретов (раунд 3)

> Вы — независимый эксперт по личным финансам, практикующий в России в 2026 году.
> Вы НЕ знаете, каким алгоритмом или продуктом будут сравниваться ваши ответы, и
> не должны пытаться это угадать. Отвечайте так, как советовали бы живому клиенту:
> предметно, с числами, по собственному профессиональному суждению.

## Что дано

Файлы `expert_portraits_v3_part1..4.jsonl.gz` — 12 000 финансовых портретов,
по одному JSON-объекту на строку. **Первая строка каждой части — служебный
meta-объект** (`"__meta__": true`): версия датасета, номер части, дата среза —
пропустите его при обработке. Поля портрета:

| Поле | Смысл |
|---|---|
| `id` | Идентификатор портрета (SP3-00000 … SP3-11999) — вернуть в ответе как есть |
| `income_total` | Суммарный доход, ₽/мес |
| `expense_total` | Суммарные расходы на жизнь (БЕЗ платежей по кредитам), ₽/мес |
| `obligations[]` | Кредиты: `name`, `amount` (остаток тела, ₽), `interest_rate` (годовая ставка, доля), `monthly_payment` (₽/мес) |
| `goals[]` | Финансовые цели: `name`, `target_amount` (₽), `current_amount` (уже накоплено, ₽), `deadline` (ISO-дата или null = бессрочная) |
| `bliq` | Ликвидные накопления (подушка): счета/депозиты/кэш, ₽ |
| `r_bench` | Безрисковая альтернативная ставка (годовая, доля) — ориентир «сколько приносят деньги без риска» |
| `risk_tolerance` | Риск-профиль клиента 1–5: 1 консервативный, 2 умеренно-консервативный, 3 сбалансированный, 4 умеренно-агрессивный, 5 агрессивный |

Свободный месячный поток клиента = `income_total − expense_total − Σ monthly_payment`.
**Дата среза (все дедлайны оценивать относительно неё): 2026-07-16.**

## ВАЖНО: данные — «как из реальной выгрузки»

В файлах намеренно присутствует небольшая доля дефектных записей — как в сырой
выгрузке из реальной CRM: отрицательные или строковые суммы, `null` вместо числа,
непарсящиеся даты, отсутствующие поля, **дубли `id`**. Это осознанный дизайн:

- Дефектную запись НЕ чинить и НЕ додумывать: статус `invalid`, `dom` = `none`,
  все суммы = 0.
- Запись считается дефектной, если её нельзя однозначно прочитать как валидные
  финансовые данные (тип/знак/формат поля нарушен или обязательное поле
  отсутствует). Пограничные, но читаемые значения (очень большие суммы, ставка
  59% годовых, дедлайн в прошлом) — НЕ дефект: оценивайте по существу.
- **На каждую ВХОДНУЮ СТРОКУ — ровно одна строка ответа, в порядке входа.**
  При дубле `id` отвечайте на обе строки (в CSV будет два ответа с одним `id` —
  это корректно).

## Что нужно сделать

Для КАЖДОЙ валидной записи решить, как распорядиться деньгами клиента:

1. **Месячный свободный поток** (если он ≥ 0) — распределить по направлениям:
   досрочное погашение долгов / резерв (подушка) / цели / инвестиции.
2. **Разовые ходы из накоплений** (`bliq`) — если считаете правильным
   (например, погасить кредит из подушки, разово закрыть цель, разместить
   излишек), укажите суммарную разовую сумму.
3. Если бюджет в дефиците — статус `deficit` и ваши разовые ходы (если есть).

## Формат ответа — СТРОГО CSV

Одна строка на входную строку, разделитель — запятая, без пробелов, шапка обязательна:

```
id,status,dom,res,debt,goal,inv,lump
SP3-00000,deficit,none,0,0,0,0,150000
SP3-00001,ok,goals+,2000,0,25000,10000,0
SP3-00002,invalid,none,0,0,0,0,0
```

| Колонка | Значение |
|---|---|
| `status` | `ok` (поток ≥ 0), `deficit` (поток < 0) или `invalid` (дефектная запись) |
| `res` | ₽/мес в резерв (подушку) |
| `debt` | ₽/мес на досрочное погашение долгов (сверх обязательных платежей) |
| `goal` | ₽/мес в цели |
| `inv` | ₽/мес в инвестиции |
| `dom` | крупнейший из бакетов: `debt` / `reserve` / `goals+` (цели + инвестиции вместе) / `none` (если поток нулевой, дефицит или invalid) |
| `lump` | суммарные РАЗОВЫЕ ходы из накоплений, ₽ (0 — если не предлагаете) |

Требования: `res + debt + goal + inv` не превышает свободный поток; суммы в
рублях без разделителей тысяч; ровно 12 000 строк данных + шапка; никакого
текста вне CSV (пояснения не нужны — только таблица).

## Что сдать помимо CSV

1. **Методология** (`expert_methodology_v3.md`) — ваши правила и константы,
   зафиксированные ДО обработки данных (целевая подушка по риску, пороги
   «дорогого»/«токсичного» долга, правила разовых ходов, критерий `invalid`).
2. **Ревью датасета** (`dataset_review.md`) — статистический аудит по разделам
   (а) дескриптивные статистики, (б) распределения/маргиналы, (в) корреляции,
   (г) реалистичность кредитов и целей, (д) граничные кейсы, (е) целостность,
   (ж) что хорошо, (з) рекомендации следующей итерации генератора.
3. **Метаданные прогона** (`run_metadata.md`) — НОВОЕ обязательное: какая
   модель/инструменты использованы, дата и длительность обработки, полнота
   (все 12 000 или подвыборка — тогда какая), способ обработки (скрипт/вручную).

## Правила чистоты

- Свежий диалог, без каких-либо инструкций проекта, памяти и описаний алгоритмов.
- Не спрашивать уточнений — данных достаточно; недостающее трактовать
  консервативно, как сделал бы советник по телефону (кроме дефектных записей —
  см. правило `invalid`).
- Обрабатывать файлы по частям — как удобно; главное, чтобы в итоге была ровно
  одна строка ответа на каждую входную строку.
