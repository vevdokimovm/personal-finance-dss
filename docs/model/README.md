# Математическая модель FINPILOT — хаб

> **Что это.** Единая точка входа по математике продукта: какие версии модели
> были, что и почему менялось, как модель соотносится с независимыми экспертами,
> где лежат каноны, данные и инструменты. Сами канонические спецификации живут
> в `docs/` (имена файлов несут версию), датасеты — в `knowledge/model_validation/`,
> исполняемые инструменты — в `tools/`.

---

## 1. Действующий канон

**v3.1.0** — `docs/math_model_v3_1_0.md`. При расхождении документа с кодом
прав код (`app/core/`). Исполняемая спецификация — инварианты I1–I13
(`tools/portrait_testing/invariants.py`), гоняются свипом на каждом наборе
портретов.

## 2. История версий модели

| Версия | Период | Суть | Статус |
|---|---|---|---|
| **v1.x** | ВКР, ранний прототип | Математический MVP: SAW-свёртка, первая решётка альтернатив | История (в материалах ВКР) |
| **v2.0.2** | ВКР (защищена 23.05.2026) | Flow-based ликвидность Lt = Rt/(Σe+ΣP), 21 альтернатива (шаг 20%), CI 95%, L_min = 0.30, статичный r_bench = 0.14 | Исторический документ ВКР (защищена 23.05.2026); полный текст — в материалах ВКР |
| **v3.0.0 (refined)** | v3.8.0 → v5.25.0 кода | Stock-based ликвидность (месяцы автономии, ортогональна ресурсу), 66 альтернатив (шаг 10%), динамический r_bench = ключевая × (1 − НДФЛ), CI 80%, мягкий отсев по ликвидности | Заменена; `docs/math_model_v3_0_0.md` с superseded-баннером |
| **v3.1.0 (calibrated)** | с v6.0.0 кода | Калибровка советника по независимой экспертизе: насыщение резерва на Lt*(risk), кризисный режим при Rt < 0, гейт «план не увеличивает ПДН», инвестиционный транш, floor резерва 1 мес | **Действующий канон** |

Ключевой принцип всех версий: математическое ядро (`app/core/`) отделено от веба
и БД; смена версии модели — осознанное решение с валидацией, а не побочный
эффект рефакторинга.

## 3. Как модель соотносится с независимыми экспертами

Полная статистика и методология — **`docs/model/expert_alignment.md`**.
Коротко: на 12 000 синтетических портретов против консенсуса четырёх независимых
экспертных движков модель v3.0.0 согласовывалась в 51.9% (аутлайер), v3.1.0 —
в **87.4%** при коридоре согласия самих экспертов между собой 85.6–95.6%.

## 4. Оценки экспертов

* **Заключение независимой экспертизы (июль 2026)** —
  `docs/reports/testing/independent_expert_review_2026_07.md`: скоркарта
  (математика 9/10, валидность советов 5/10, практичность 3/10, безопасность
  7/10 — для v3.0.0), дефекты G1–G7, рекомендации. Экспертиза дала прогноз
  «одна правка насыщения → ~85%+» — подтверждён эмпирически (87.4%).
* **Метрики до/после калибровки** —
  `docs/reports/testing/expert_agreement_v3_1_0.md` (генерируется стендом).
* **Оценка датасета v1 экспертами (выжимка).** Дефект подтверждён пятью
  независимыми расчётами: тело кредита не связано с доходом (corr ≈ 0.02 —
  «кредиты раздавались без андеррайтинга»), сроки аномально коротки
  (платёж 2–6% тела в месяц ≈ 17–50 мес при любой ставке), из-за чего 80.8%
  сета в дефиците и содержательная оценка советника строилась на 17.5%
  портретов. Вердикт: «дефект генератора, не модели». Ответ — генератор v2
  (§6 ниже) и второй датасет.

## 6. Генератор портретов и его версии

`tools/portrait_testing/generator.py`:

* **v1** — заморожен бит-в-бит ради регенерации эталона `joined.csv.gz`.
  Не использовать для новых прогонов и не «чинить».
* **v2 (актуальный)** — калибровка по фидбеку экспертизы: долги через целевой
  ПДН ~ Beta(2.2, 4.4) (медиана ~0.31, p90 ~0.55 — картина ЦБ/НБКИ после МПЛ),
  тело кредита из аннуитета со сроком 12–84 мес (corr доход–платежи > 0.3),
  расходы от бюджета «после платежей» (дефицит сета ≤ ~30%), подушка с
  экспоненциальным профилем, adversarial-слой (ПДН у гейта 0.40, ставка ровно
  на r_bench, дедлайн «сегодня», копеечные и гигантские масштабы).

## 8. Протокол второй сертификации (план вехи 6)

1. Портреты v2 и ответ модели уже материализованы (§5).
2. Карточки/JSONL портретов v2 передаются ≥ 3 независимым экспертным движкам
   **строго вне проекта** (без памяти и инструкций — против bias; правило §6.1
   ROADMAP).
3. Ответы экспертов сводятся в joined-файл по образцу эталона.
4. Стенд считает согласие; критерий готовности — модель в коридоре согласия
   экспертов между собой.
