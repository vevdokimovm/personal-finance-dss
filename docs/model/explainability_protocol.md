# Протокол проверки объяснимости

**Тип:** лёгкая экспертная итерация, не раунд сертификации · **Введён:** после Волны 0 (v8.13.0)
**Предложил:** владелец, `docs/reports/testing/round5_owner_memo.md` п.6.3
**Материал для раздачи:** `docs/reports/testing/explainability_review_material_blind.md`
(40 портретов, без служебной разметки веток) · **Материал для приёмки отбора (не раздавать):**
`docs/reports/testing/explainability_review_material.md` (та же выборка с явной разметкой
«ветка «X»» по каждому портрету — только чтобы проверить, что квота 7 веток набрана честно)

## Чем это отличается от раунда сертификации

Пять раундов сертификации (`docs/model/expert_certification/`) проверяли **решения** модели
против консенсуса профессионального суждения: 4 независимых эксперта, 12 000 портретов,
статистика согласия, коридор. Этот протокол впервые проверяет **текст объяснения** —
понятно ли человеку, почему модель решила именно так. Другая ось карты качества
(`docs/model/model_quality_scorecard.md`, ось 9), другой метод:

| | Раунд сертификации | Этот протокол |
|---|---|---|
| Проверяет | решение (совпадает ли с суждением) | текст (ясно ли, почему) |
| Экспертов | 4, коридор согласия между ними | 1 — не с кем сверять консенсус |
| Портретов | 12 000 | 40 |
| Статистика | Spearman, split-half, коридор | нет — качественная разметка |
| Результат | % согласия | список: понятно/отчасти/непонятно + что именно неясно |

## Дисциплина слепой сессии сохраняется

Правило проекта (ROADMAP, сквозное правило §4): тестирование матмодели — строго вне сессии
с памятью/инструкциями проекта. Материал (`explainability_review_material.md`) уже подготовлен
кодом в сессии с полной памятью — это не нарушение (отбор портретов и рендер текста
детерминированы, не требуют суждения), но **саму оценку** обязан проводить отдельный чистый
аккаунт/сессия без доступа к этому чату, коду модели, WATCHLOG. Полная процедура изоляции —
`docs/model/expert_certification/blindness_protocol.md` §2.1, применяется без сокращений: если
техническая изоляция невозможна, оценка всё равно проводится, но помечается **ослабленной**.

## Как раздать

Сопроводительное сообщение (аналог `covering_message_v5.md` для раундов, но короче —
формат ответа «одна строка на карточку», без требования комплекта артефактов) —
`docs/model/explainability_review_covering_message.md`. Копируется целиком одним
сообщением вместе с приложенным `explainability_review_material_blind.md` в чистую
сессию/аккаунт.

## Что видит эксперт

Ровно то, что видел бы пользователь на экране: краткая сводка портрета (доход/расходы/долги/
цели/подушка/риск-профиль — контекст, не формулы) + текст `gains`/`costs`/`insight` (и
контрфакт, где применимо) `explain_alternative()`, либо `summary` кризисного режима. **Не**
видит: код, канон, формулы, названия критериев SAW, ветку классификации портрета — файл
`explainability_review_material_blind.md` уже не содержит заголовков «ветка «X»»
(`explainability_protocol_selection.py::render(..., blind=True)`), раздавать нужно именно его,
не аннотированную версию.

## Вопрос и шкала

По каждому из 40 портретов один вопрос:

> Понятно ли из этого текста, почему система решила именно так?

Ответ: **да** / **отчасти** / **нет**. Если не «да» — одна фраза: что именно осталось
неясным (не «плохо написано», а «непонятно, почему в подушку, а не на долг» — конкретная точка
непонимания, не общая оценка стиля).

## Приёмка результата

1. Доля «да» по каждой из 7 веток (`plain`/`crisis`/`toxic_debt`/`thin_cushion`/`no_goals`/
   `saturated_cushion`/`long_goal_inflated`) — не общий процент. Слабая ветка важнее среднего.
2. Все «нет»/«отчасти» с конкретной точкой непонимания сводятся в список — это прямой вход в
   следующую правку `explain_alternative()`/`build_recommendation_text()`, не только оценка.
3. Результат — короткий отчёт в `docs/reports/testing/` (имя файла — по факту создания,
   например `explainability_review_result.md`): таблица по веткам + список конкретных
   находок. Без консенсусной статистики (нет с чем сверять) — просто зафиксированные точки
   непонимания.
4. Ось «объяснимость» карты качества (`model_quality_scorecard.md`) обновляется по этому
   результату — доля «да» + честная оговорка, что это одна оценка, не консенсус.

## Что этот протокол НЕ проверяет

Правильность решения — это раунды сертификации. Согласие с законом/нормативом — это
адекватность (ось 5). Полноту охвата предметной области — ось 10. Протокол проверяет ровно
одну вещь: понятность уже принятого решения тому, кто его читает.
