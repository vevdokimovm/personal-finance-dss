## План итераций

Пять итераций по 12 000 портретов. На каждой: генерируем датасет → отдаём всем
эксперт-аккаунтам один и тот же промпт → собираем CSV-разметку + `dataset_review.md` →
чиним генератор и модель по фидбеку → следующая итерация. Только входные портреты меняются
между прогонами; промпт постоянен.

| Итерация | Датасет | Фокус фидбека |
|---|---|---|
| 1 | baseline | первичная калибровка, крупные дефекты распределений |
| 2 (текущая) | v2 (реалистичный ПДН, аннуитет) | согласие вердиктов, граничные кейсы |
| 3 | + слои C/D/E расширены по P-замечаниям итерации 2 | монотонность (метаморфические пары) |
| 4 | добор углов (DOE/Sobol), устранение обрезанных хвостов | стабильность констант между экспертами |
| 5 (текущая) | v5 по ТЗ `iterations/4/expert_feedback_aggregate.md` §5 | проверка H5-1/H5-2/H5-3, полоса L_t∈[1;2) и уверенные позиции |

Фактическая история фокусов (что реально проверялось), полезнее плановой:
итерация 3 — метаморфика (0 рекалибровок); итерация 4 — метрика action-vector
(+7.8 п.п.) + G8 токсичного долга (предзарегистрирован, подтверждён); итерация 5 —
кромка floor L_t∈[1;2) как источник 52.6% расхождений.

## Архитектура тест-сета: 5 слоёв

Один случайный сэмпл неэффективен: переплачивает за центр распределения и не гарантирует
углы. Тест-сет — из слоёв с разными задачами.

- **Слой A — реалистичная популяция (~40%).** Совместное распределение через гауссову
  копулу: сэмплировать MVN с целевой корреляционной матрицей, преобразовать Φ → ppf целевых
  маргиналов. Маргиналы/корреляции калибровать по внешним источникам (доход — лог-нормаль;
  долговая нагрузка — публикации ЦБ/НБКИ). Долги задавать через ПДН × доход, аннуитет
  согласован (срок n ∈ [6, 360], платёж из формулы). Цели масштабировать доходом
  (target ~ k × годовой доход, k ∈ [0.2 … 5]); дедлайны — смесь (доля null + горизонты).
  Бенчмарк доходности непрерывный. Хвосты не обрезать клампами.
- **Слой B — равномерное покрытие входов, DOE (~30%).** Работать с нормализованными осями
  решений (доход, exp/inc, ПДН, месяцы ликвидности, число кредитов, spread = ставка −
  бенчмарк, число целей, ближайший дедлайн, готовность целей, риск-профиль). LHS или Sobol
  по гиперкубу → обратное преобразование в рубли. Pairwise-покрытие предикатов ветвления
  (t-wise, t=2; `allpairspy`).
- **Слой C — детерминированные граничные кейсы (~20%).** Каталог: нулевой доход; нулевые
  расходы; дефицит потока; перегруженность долгами; только дешёвые долги; interest-only
  кредит; ставка == бенчмарку; дедлайн сегодня; просроченный дедлайн при недоборе; target ==
  current в копейку; перефинансированная цель; цель на минимум; суммы ~10⁹; максимум целей с
  одним дедлайном; отсутствие целей; отсутствие кредитов; аномально большая подушка.
  **Правило пополнения:** каждый найденный баг модели и каждое расхождение экспертов из
  прошлой итерации → новый кейс здесь.
- **Слой D — validity/adversarial (~5%).** Битые даты, отрицательные суммы, дубли ID, NaN,
  пустые массивы, лишние поля. Критерий: модель отклоняет/флажит запись, не падает и не
  выдаёт совет по мусору.
- **Слой E — метаморфические пары (~5%).** (портрет, портрет+δ) для проверки монотонности
  без эталона: M1 доход +1% ⇒ статус не хуже, бакет инвестиций не меньше; M2 ставка +1 п.п.
  ⇒ приоритет гашения не ниже; M3 дедлайн дальше ⇒ требуемый взнос не больше; M4 подушка
  +1% ⇒ развёртываемый излишек не меньше; M5 все денежные ×k ⇒ все рекомендации ×k.
  Нарушение любой M-связи — баг модели, находимый без разметки.

## Размер выборки (power analysis)

Доля с точностью ±e при 95%: n = 1.96²·p(1−p)/e². Худший случай p=0.5: **±2% → 2 401
портрет; ±5% → 385 на страту**. Слоистая структура информативнее i.i.d. того же объёма.
12 000 портретов дают запас на стратификацию и метаморфические пары.

## Приёмочные тесты генератора (гонять в CI перед раздачей эксперту)

1. KS-тест маргиналов против целевых распределений (p > 0.05).
2. Корреляционная матрица в допуске ±0.05 от целевой.
3. Доли диагностических состояний (знак FCF, бакеты ПДН, бакеты ликвидности) в допуске.
4. Аннуитетная согласованность 100% (кроме слоёв C/D по дизайну).
5. Продуктовая согласованность: (ставка, срок, остаток) в спеке, имя = продукт,
   ставки ≤ потолка ПСК вне D, легальные лимиты остатка (р.4→5).
6. Имя ↔ сумма цели; фактический k в заявленной спеке (р.4→5).
7. Отчёт покрытия: все pairwise-комбинации уровней закрыты.
8. Отсутствие обрезанных хвостов сверху И снизу вне C/D; киты отделены от стресса.
9. Слепой экспорт без меток дизайна и без чужих префиксов id, но с дублями и дефектами.
10. Точность границ: «ровно нулевой поток» даёт ровно 0.0 в float.

**Реализация — dataset_stats_v{N}.py (в tools/portrait_testing/), прогон НА 12 000 перед
раздачей** (порог, пройденный на выборке 3 000, на боевом объёме может не пройти — р.5).
Полный разбор процедуры — `ITERATION_RUNBOOK.md` фаза B.

## Версионирование датасета

`dataset_version`, seed, конфиг слоёв и корреляционная матрица — первой строкой JSONL.
Ревью экспертов линкуются на версию, иначе итерации несравнимы.

## Сравнение аккаунтов между собой

Чтобы комментарии разных экспертов были мёржабельны: (1) все работают на одной
`dataset_version`; (2) сравнивать по трём срезам — распределение статусов; попарное согласие
вердиктов на общем подмножестве ~400 стратифицированных портретов (даёт ±5%); расхождения
констант методологий (это и есть «независимость»: константы у экспертов ДОЛЖНЫ отличаться,
а направление решений — совпадать); (3) расхождения направлений решений на одинаковых входах
— кандидаты в новые граничные кейсы слоя C следующей итерации. Дополнительно свести
метаданные прогонов (модель, усилие рассуждения, время, сэмплинг) — они объясняют часть
расхождений помимо констант.

## Раскладка артефактов в репозитории

```
docs/model/expert_certification/
  expert_prompt_unified.md          # промпт итерации 1 (исторический)
  iteration_protocol.md             # этот файл
  testset_methodology.md            # методичка тест-сетов (слои, power analysis, чек-лист)
  artifact_catalog.md               # что сдаёт каждый эксперт и почему (провенанс находок)
  prompts/README.md                 # эволюция промпта по итерациям
  iterations/
    <N>/                            # номер итерации (1..5)
      dataset_meta.json             # dataset_version, seed, конфиг слоёв, контракт сопоставления
      <account>/                    # V / S / J / M
        recommendations.csv         # пер-портретная разметка (id,status,dom,res,debt,goal,inv,lump)
        dataset_review.md           # статистический анализ датасета
        expert_methodology_v<N>.md  # методология: константы, зафиксированные ДО обработки
        engine.py                   # код движка эксперта
        run_metadata.md             # модель, усилие, время, полнота, способ обработки
        <авторские файлы>           # аудиты, планы сравнения, доп. скрипты — как сдал эксперт
      comparison.md                 # сравнение аккаунтов между собой за итерацию
      expert_feedback_aggregate.md  # агрегат: слепые зоны модели + дефекты датасета + ТЗ генератора
```

Правила архива:

- **Улики не переименовываем и не реформатим.** Авторские имена и стиль кода
  экспертов — часть доказательной базы (`.flake8` исключает `iterations/`).
- **Тяжёлое сжимаем побайтово** (`*.jsonl`, крупные `*.csv` → `.gz`), вложенных
  архивов в репо не держим — распаковываем в подпапку.
- **Исторические исключения фиксируем в README итерации**, а не приводим к
  единому виду задним числом: итерация 1 жила до CSV-брифа (ответы — jsonl с
  полем `kind`, слепоты ещё не было), у V и S сохранились два слоя сдачи —
  финальный и полный рабочий (`full/`).
