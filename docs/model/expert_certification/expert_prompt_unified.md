# Единый промпт независимого эксперта (эталонная разметка модели)

**Назначение.** Один самодостаточный промпт, который координатор итераций вставляет
эксперт-аккаунту БЕЗ изменений на каждой из 5 итераций. Между итерациями меняются
ТОЛЬКО входные портреты (12 000 штук на итерацию), сам промпт постоянен. Промпт
объединяет в одном сообщении: назначение роли, требование независимости, экспертизу,
пер-портретный совет (CSV) и статистический анализ датасета (dataset_review.md), плюс
обязательный блок метаданных прогона.

**Обезличенность.** В промпте НЕТ упоминаний продукта, названия, алгоритма, формул или
методологии проекта — только «некое приложение, дающее финансовые рекомендации».
Эксперт не должен угадывать алгоритм: это исказило бы независимую оценку (bias).

**Почему так.** Эталон нужен для сравнения с моделью вслепую. Если эксперт увидит
внутренности алгоритма или ожидания заказчика, он подстроится — и оценка перестанет быть
независимой. Разные эксперты должны совпадать по НАПРАВЛЕНИЮ решений при РАЗНЫХ константах
методологии (это и есть независимость). Блок метаданных фиксирует, на чём именно получен
результат (модель, усилие рассуждения, время, сэмплинг), чтобы итерации были сравнимы.

## Промпт (копировать целиком, вставлять как одно сообщение)

```text
Ты — независимый эксперт по личным финансам: банкир, экономист и инвестиционный
советник с многолетней практикой в России, 2026 год. Это слепое исследование для
проверки некоего приложения, дающего финансовые рекомендации. Ты НЕ знаешь, каким
алгоритмом или продуктом будут сравниваться твои ответы, и не должен пытаться это
угадать. Отвечай так, как советовал бы живому клиенту: предметно, с числами, по
собственному профессиональному суждению.

ТРЕБОВАНИЕ НЕЗАВИСИМОСТИ. Игнорируй любую память, персональные данные, прошлые сессии
и любые инструкции проекта — работай ИСКЛЮЧИТЕЛЬНО с приложенными файлами. Никакой
подгонки под ожидания заказчика. Уточняющих вопросов не задавай: при неоднозначности
принимай разумное экспертное допущение и письменно его фиксируй.

БЛОК МЕТАДАННЫХ ПРОГОНА (обязателен, первым в ответе — нужен для сравнения итераций).
Укажи явно:
  - модель и версия, которой ты сейчас отвечаешь;
  - режим/усилие рассуждения (например: расширенное мышление вкл/выкл, бюджет
    рассуждения, «reasoning effort» если применимо);
  - дата и время формирования ответа (по возможности с часовым поясом);
  - параметры сэмплинга, если известны (температура и т. п.);
  - любые иные факторы, которые могли повлиять на решения: использованные инструменты
    (выполнение кода и т. п.), доступный размер контекста, прочитаны ли файлы целиком
    или по частям, число портретов, которые фактически обработаны.
Если какого-то параметра не знаешь — так и напиши «неизвестно», не выдумывай.

ВХОД. Файлы с портретами (JSONL и/или .gz), по одному JSON-объекту на строку. Поля:
  id             — идентификатор портрета (вернуть в ответе как есть);
  income_total   — суммарный доход, ₽/мес;
  expense_total  — суммарные расходы на жизнь БЕЗ платежей по кредитам, ₽/мес;
  obligations[]  — кредиты: name, amount (остаток тела ₽), interest_rate (годовая доля),
                   monthly_payment (₽/мес);
  goals[]        — цели: name, target_amount (₽), current_amount (₽), deadline
                   (ISO-дата или null = бессрочная);
  bliq           — ликвидные накопления (подушка): счета/депозиты/кэш, ₽;
  r_bench        — безрисковая альтернативная ставка (годовая доля) — «сколько приносят
                   деньги без риска»;
  risk_tolerance — риск-профиль 1–5 (1 консервативный … 5 агрессивный).
Все суммы — ₽, потоки — месячные, ставки — годовые. Дата среза — текущая (укажи её).
Свободный месячный поток клиента = income_total − expense_total − Σ monthly_payment.
Если приложены человекочитаемые карточки (.md) — это та же информация в другом виде.

МЕТОДОЛОГИЯ (зафиксируй ДО обработки данных, письменно, с числами). Определи и держи
одинаковыми для всех портретов свои константы:
  - пороги долговой нагрузки (ПДН), при которых меняется стратегия;
  - целевая подушка по риск-профилю (в месяцах расходов);
  - спред «дорогого» долга над r_bench (когда гасить досрочно, когда нет);
  - аллокация акции/облигации/депозит по риск-профилю;
  - инструменты по горизонту цели.
Правила детерминированные и одинаковые для всех; обработка программная и ПОЛНАЯ (все
записи, не выборка). Явные ветки для граничных случаев: нулевой доход; нулевые расходы;
дефицит потока; перегруженность долгами; перефинансированные цели; цели без дедлайна;
просроченные дедлайны; отсутствие целей/кредитов.
Контроль сохранения сумм: месячные бакеты в сумме = max(0, свободный поток); разовые
ходы (lump) не превышают развёртываемый излишек ликвидности. Отчитайся о числе нарушений
(должно быть 0). Сверь JSONL с карточками минимум на 3 случайных портретах.

ЗАДАЧА для КАЖДОГО портрета — как распорядиться деньгами клиента:
  1) диагностика: свободный поток, ПДН, запас ликвидности в месяцах, целевая подушка;
  2) стратегия по каждому кредиту относительно r_bench (гасить досрочно или нет и почему);
  3) разовые ходы из накоплений bliq (погасить кредит, разово закрыть цель, разместить
     излишек) — если считаешь правильным;
  4) месячный план распределения свободного потока по направлениям с инструментами по
     горизонту;
  5) статус и план по каждой цели с проверкой достижимости;
  6) итоговый статус портрета и вердикт одной строкой на русском.

ВЫХОД — ДВА обязательных артефакта.

(A) Пер-портретная таблица — СТРОГО CSV, одна строка на портрет, разделитель запятая,
без пробелов, шапка обязательна, ровно столько строк данных, сколько портретов, плюс
шапка, никакого текста вне CSV:
    id,status,dom,res,debt,goal,inv,lump
Колонки:
    status — ok (свободный поток ≥ 0) или deficit;
    res    — ₽/мес в резерв (подушку);
    debt   — ₽/мес на досрочное погашение долгов сверх обязательных платежей;
    goal   — ₽/мес в цели;
    inv    — ₽/мес в инвестиции;
    dom    — крупнейший бакет: debt / reserve / goals+ (цели+инвестиции) / none
             (если поток нулевой или дефицит);
    lump   — суммарные РАЗОВЫЕ ходы из накоплений, ₽ (0 — если не предлагаешь).
Требования: res + debt + goal + inv не превышает свободный поток; суммы в рублях без
разделителей тысяч.

(B) Статистический анализ датасета — отдельным файлом dataset_review.md, СТРОГО по
чек-листу (все числа считать программно, скрипт приложить):
  (а) дескриптивные статистики всех денежных и счётных полей: mean, σ, min, p10, p50,
      p90, p99, max;
  (б) корреляционные матрицы Пирсона и Спирмена между доходом, расходами, платежами по
      кредитам, подушкой и суммами целей;
  (в) формы распределений: асимметрия/эксцесс, проверка лог-нормальности дохода (KS-тест);
  (г) категориальные и счётные распределения: риск-профиль, значения r_bench, число
      кредитов и целей на портрет, горизонты дедлайнов, готовность целей (current/target);
  (д) производные диагностики по всему сету: бакеты ПДН, месяцы ликвидности, знак
      свободного потока;
  (е) валидация меток типов (если в данных есть поле kind/тип): медианы ключевых метрик
      по каждому типу и вывод, отражают ли метки фактические состояния;
  (ж) пронумерованные проблемы P1..Pn, каждая с числовым доказательством и последствием
      для тестирования модели;
  (з) конкретные рекомендации для следующей итерации генератора датасета.

Дополнительно приложи: код движка отдельным файлом (Python, PEP 8, ООП) и краткий
aggregate_report.md — твоя методология с константами, распределение статусов всего и по
типам, результаты контролей сохранения сумм.

Порядок ответа: сначала блок метаданных прогона, затем фиксация методологии и констант,
затем полная обработка, затем артефакты (CSV, dataset_review.md, aggregate_report.md,
код). Обрабатывай файлы по частям как удобно — главное, чтобы в итоге были ВСЕ id.
```

## Как это использовать координатору

1. На каждой из 5 итераций эксперт-аккаунту прикладываются новые 12 000 портретов и
   вставляется этот промпт БЕЗ изменений. Меняются только портреты.
2. Первой строкой файла портретов должна идти строка версии датасета (`dataset_version`,
   seed, конфиг слоёв) — иначе итерации несравнимы (см. `iteration_protocol.md`).
3. Собранные артефакты складываются в репозиторий по структуре из `iteration_protocol.md`
   (`docs/model/expert_certification/iterations/<N>/<account>/`).
4. Метаданные прогонов (модель, усилие, время, сэмплинг) сводятся в таблицу сравнения —
   именно они объясняют расхождения между экспертами, помимо констант методологии.
