# Стандарт сдачи: один архив на эксперта, фиксированный нейминг

**Тип:** нормативный процедурный документ · **Введён:** v6.26.0 по итогам
раунда 5 · **Обязателен** во всех последующих итерациях и мини-раундах.

> **Почему появился.** В раунде 5 четыре пакета пришли по-разному: три плоским
> архивом с файлами в корне, один — вложенным (`expert_package_v5.zip` внутри
> внешнего архива), и координатору пришлось разбирать это вручную перед сборкой.
> Само по себе мелочь; проблема в том, что ручная распаковка — это место, где
> незаметно теряется файл. Пакет, собранный по-своему, стоит координатору
> времени на каждом раунде и однажды будет стоить потерянного артефакта.

---

## 1. Правило одной строкой

**Один эксперт — один архив. Имя различается ровно одной буквой.**

```
expert_package_v{N}_{X}.zip
```

- `{N}` — номер итерации датасета: `5`, `6`, …
- `{X}` — буква эксперта заглавной латиницей: `V`, `M`, `J`, `S`

Раунд 5 в правильном виде:

```
expert_package_v5_V.zip
expert_package_v5_M.zip
expert_package_v5_J.zip
expert_package_v5_S.zip
```

Ничего, кроме буквы, различаться не должно: ни регистр, ни разделители, ни
порядок частей. Это позволяет координатору собирать раунд одной командой, а не
глазами.

---

## 2. Структура внутри архива

**Плоско. Все файлы в корне архива.**

```
expert_package_v5_M.zip
├── expert_allocations_v5.csv
├── recommendations_v5.jsonl.gz
├── summary_v5.csv
├── expert_methodology_v5.md
├── … остальные артефакты комплекта
```

**Запрещено:**

- вложенный архив внутри архива (двухступенчатая распаковка);
- обёртка-папка (`expert_package_v5/` внутри `expert_package_v5_M.zip`);
- служебный мусор упаковщика (`__MACOSX/`, `.DS_Store`);
- разбиение комплекта на несколько архивов.

**Кодировка и переводы строк:** UTF-8 без BOM. Перевод строки — любой, сборщик
нормализует; но внутри одного файла он должен быть одинаковым.

---

## 3. Обязательное содержимое

Комплект — по `artifact_catalog.md` (в раунде 5 это шестнадцать позиций).
Ядро, без которого пакет не принимается вообще:

| Файл | Зачем |
|---|---|
| `expert_allocations_v{N}.csv` | основной ответ, 12 000 строк + шапка |
| `recommendations_v{N}.jsonl.gz` | `lump_sum_plan`; без него не считается action-vector |
| `summary_v{N}.csv` | диагностика на портрет |
| `expert_methodology_v{N}.md` | по нему проверяется, что движок делает заявленное |
| `run_metadata_v{N}.md` | в том числе обязательный раздел о постороннем контексте |

Отсутствие любого из пяти — **возврат пакета эксперту**, а не починка
координатором: починка чужого ответа делает его неотличимым от своего.

---

## 4. Что делает координатор при приёме

1. Проверяет имена: ровно четыре архива, различие в одной букве.
2. Распаковывает одной командой, без ручного разбора вложенности.
3. Гоняет `build_joined_v{N}` — он же и есть приёмка: позиционный контракт,
   бюджет, форма `invalid`, `lump` против `lump_sum_plan`, `confidence`.
4. Складывает сырьё в `docs/model/expert_certification/iterations/{N}/{X}/`.
5. Ничего в чужих файлах не правит. Нарушение контракта → возврат.

---

## 5. Мелочь, которая экономит раунд

Архивы приходят одним сообщением, а не по одному по мере готовности.
Причина та же, что и с неймингом: раунд разбирается целиком, и частично
собранный комплект провоцирует начать анализ раньше, чем собраны все четверо —
а это прямой путь увидеть в первых двух пакетах то, что потом будешь искать в
остальных.
