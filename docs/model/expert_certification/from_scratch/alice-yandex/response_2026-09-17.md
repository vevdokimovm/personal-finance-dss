## 1. Постановка задачи формально

### Состояние

Состояние системы в месяце \(t\) описывается кортежем:

\[\mathcal{S}_t = (S_t,\ \mathcal{D}_t,\ \mathcal{G}_t,\ I_t,\ E_t,\ \pi)\]

где:

- \(S_t\) — ликвидные накопления (рубли), доступны в любой момент без штрафа;
- \(\mathcal{D}_t = \{(B_i, r_i, m_i)\}_{i=1}^{N_d}\) — множество долгов: остаток \(B_i\), годовая ставка \(r_i\) (%), обязательный платёж \(m_i\) (руб/мес);
- \(\mathcal{G}_t = \{(T_j, \tau_j, A_j, w_j, \text{type}_j)\}_{j=1}^{N_g}\) — цели: целевая сумма \(T_j\), дедлайн \(\tau_j\) (может быть \(\text{None}\)), накоплено \(A_j\), вес \(w_j\), тип (обязательная / важная / желательная);
- \(I_t\) — доход месяца \(t\) (может колебаться);
- \(E_t\) — обязательные расходы месяца \(t\);
- \(\pi = (\text{возраст},\ \text{толерантность\_к\_риску},\ \text{стабильность\_дохода})\) — профиль пользователя.

### Свободный денежный поток

\[F_t = I_t - E_t - \sum_i m_i\]

### Решение

Вектор распределения:

\[\mathbf{a}_t = (a_{\text{debt},1}, \ldots, a_{\text{debt},N_d},\ a_{\text{reserve}},\ a_{\text{goal},1}, \ldots, a_{\text{goal},N_g},\ a_{\text{invest}},\ a_{\text{spend}})\]

Ограничения:
- \(\sum_k a_k = \max(F_t,\, 0)\) (все свободные деньги распределены);
- \(a_k \geq 0\) для всех \(k\);
- \(a_{\text{debt},i} \leq B_i\) (нельзя погасить больше, чем долг).

### Горизонт

- **Горизонт планирования** — до погашения всех долгов и достижения всех целей с дедлайнами (могут быть годы);
- **Горизонт решения** — один месяц, пересчёт каждый месяц при обновлении состояния (rolling horizon);
- **Дорожка** — алгоритм строит прогнозную траекторию на весь горизонт для отображения пользователю, но решение принимается помесячно.

### Что максимизируем

Задача **многокритериальная**. Три цели:

1. **Минимизация общей стоимости долга** (сумма процентов, уплаченных за всё время);
2. **Максимизация вероятности достижения целей в срок**;
3. **Максимизация долгосрочного богатства** (инвестиции).

Сведение к одной целевой функции — через **предельные нормы доходности** (marginal rates). Каждому варианту распределения присваивается «эффективная ставка доходности» — гарантированный или ожидаемый возврат на рубль, направленный в этот канал. Дальше решение сводится к жадному заполнению от самой высокой ставки к самой низкой (см. раздел 3).

**Почему именно так:** в личных финансах альтернативные издержки (opportunity cost) — это не абстракция, а конкретные проценты. Погасить кредит под 50% — то же самое, что получить 50% годовых гарантированно. Положить на вклад под 14% — получить 14%. Копить на обязательный платёж, опоздать с которым грозит штрафом 20%, — «доходность» этого действия не ниже 20%. Сведение к ставкам делает сравнение честным и единообразным.

## 2. Выбор класса метода

### Подход A: Жадные правила и эвристики (waterfall)

**Суть:** приоритетный каскад — сначала резерв, потом дорогой долг (avalanche), потом цели, потом инвестиции.

**Даёт:** простоту, скорость O(n log n), тривиальную объяснимость, детерминированность. Воспроизводимость 100%.

**Стоит:** не обрабатывает конфликты между конкурирующими целями с разными дедлайнами и долгами с разной ставкой — разве что через жёсткие правила, которые в краевых случаях дают субоптимальное распределение.

**Где ломается:** когда одновременно есть цель с горящим дедлайном и дорогой долг. Жёсткий waterfall «сначала весь долг» — потеря цели. «Сначала вся цель» — переплата процентов. Нужен разрез, а не переключатель.

### Подход B: Линейное (или выпуклое) программирование

**Суть:** формализовать как задачу LP/MILP с переменными распределения, ограничением бюджета и линейной целевой функцией.

**Даёт:** математический оптимум для заданной целевой функции, скорость (LP решается за полиномиальное время), детерминированность.

**Стоит:** целевая функция должна быть линейной. Полезность достижения цели нелинейна (выпукла вверх при приближении к дедлайну). Чтобы использовать LP, придётся линеаризовать — вводить кусочно-линейные сегменты. Многопериодная задача с неопределённостью превращается в стохастическое программирование — это уже не «быстро и объяснимо».

**Где ломается:** при попытке выйти за один период. Многопериодное LP с неопределённостью дохода требует сценариев, число которых растёт экспоненциально. Объяснимость резко падает: «LP-солвер решил, что 23 481 ₽ идёт на кредитку, а 21 519 ₽ — на цель» — почему именно так, из решения не очевидно.

### Подход C: Динамическое программирование / стохастическое управление

**Суть:** состояние — (накопления, долги, цели), действие — вектор распределения, переход — стохастический (доход и расходы случайны).

**Даёт:** теоретически оптимальное решение для многопериодной задачи с неопределённостью.

**Стоит:** **проклятие размерности**. Даже с 3 долгами и 2 целями, дискретизируя каждый параметр на 20 значений, получаем \(\sim 20^7\) состояний. На каждый месяц. Это не продукт, это исследовательский проект.

**Где ломается:** размерность. Даже аппроксимации (аппроксимация значений функции, ADP) теряют объяснимость и воспроизводимость.

### Подход D: Обучение с подкреплением (RL)

**Суть:** агент учится политике распределения через взаимодействие с симулированной средой.

**Даёт:** потенциально хорошую политику для сложных нелинейных задач.

**Стоит:** не объяснимо («нейросеть так решила»), не воспроизводимо (зависит от инициализации, seed, версии модели), требует огромного объёма данных для обучения (синтетических или реальных), может сойти в локальный оптимум, нестабильно на краевых случаях.

**Где ломается:** везде, где требуется доверие. Финансовый совет, который нельзя объяснить, — это не совет, это гадание.

### Подход E: Многокритериальный выбор (TOPSIS, AHP)

**Суть:** сравнение вариантов по нескольким критериям с весами.

**Даёт:** хорош для качественных trade-off.

**Стоит:** не учитывает временную динамику. TOPSIS не ответит «что будет с долгом через 6 месяцев при таком распределении».

**Где ломается:** как только нужно учитывать время и изменение состояния.

---

### Мой выбор: **Модифицированный жадный каскад с предельными ставками (segment-based greedy fill)**

Я беру подход A (жадный waterfall), но заменяю жёсткие приоритеты на **сортировку по предельной норме доходности**. Это эквивалентно решению LP с кусочно-линейной целевой функцией, но без солвера — потому что LP с такой структурой решается простым сортированием сегментов.

**Почему выбран:** объединяет простоту и объяснимость waterfall с оптимальностью LP для одного периода. Каждый рубль идёт в канал с самой высокой «эффективной ставкой» — это и математически верно, и объясняется одним предложением.

**Почему отвергнуты остальные:**
- **B (LP)** — то же самое решение, но через более тяжёлый механизм. Мой метод и есть LP с кусочно-линейной аппроксимацией, решённый в замкнутой форме.
- **C (DP)** — непрактично по размерности.
- **D (RL)** — пожертвует объяснимостью и воспроизводимостью, которые прямо требуются.
- **E (MCDM)** — не учитывает временную динамику.

## 2а. Нужен ли здесь машинный интеллект

**Короткий ответ:** ядро — нет. По краям — да, но не обязательно.

### Ядро (распределение свободных денег) — формулы и правила, без обучаемых моделей

Распределение — это задача оптимального выбора из конечного набора вариантов с известными ставками. Она решается сортировкой. Обучаемой модели здесь нет места: если ставки известны, оптимум определён. Модель не найдёт ничего лучше сортировки по предельной доходности, потому что это и есть оптимум.

### Где обучение на данных даёт прирост, который нельзя получить формулой

| Задача | Что даёт ML | Можно ли без ML | Порядок потери |
|--------|-------------|----------------|----------------|
| **Прогноз дохода (нерегулярного)** | Улавливает сезонность, тренд, режимы (например, предприниматель: пик в декабре, провал в январе) | EWMA + скользящее среднее — 80% качества | 10–15% точности прогноза для нерегулярного дохода; для оклада — 0% |
| **Прогноз расходов** | Классификация категорий, предсказание выбросов (ЖКХ зимой, лечение) | Простое среднее + ручная разметка категорий | 5–10% точности; обязательные расходы и так стабильны |
| **Категоризация операций** (какие траты обязательные, какие нет) | NLP/классификатор по MCC-кодам и описанию | Правила по MCC + ручная разметка — ~70–80% покрытия | 20–30% операций некорректно категоризируются без ML |
| **Вероятность срыва платежа** | Классификатор на истории | Простое правило: ПДН > 50% → высокий риск | 15–20% точности для пользователей с нестабильным доходом |
| **Распознавание выписок / OCR** | Извлечение ставок, остатков, платежей из PDF/фото | Ручной ввод | Качество UX: ручной ввод отпугивает 30–40% пользователей |
| **Персональные пороги** (сколько тратить на себя) | Вывод из поведенческой истории | Анкета + стандартные пороги | 10–15% персонализации |

### Где обучение вредит

- **Объяснимость:** «модель решила направить 23 481 ₽ на кредитку» — почему? Модель не объясняет. Человек не финансист, ему нужно «потому что у кредитки ставка 50%, а вклад даёт 14%». Формула даёт это бесплатно.
- **Воспроизводимость:** одинаковый вход — разный выход (зависит от версии модели, seed, батча). Это прямо нарушает требование задачи.
- **Данные:** для прогноза нужен профиль транзакций. У нового пользователя его нет. Алгоритм без ML работает с первого дня.
- **Стоимость:** обучение, валидация, мониторинг дрейфа, переобучение. Для продукта с массовым потребителем это существенная стоимость.
- **Риск для пользователя:** модель может выдать nonsensical совет на краевом случае (например, «не гасите кредит, инвестируйте» — если модель обучилась на периоде бычьего рынка).

### Что не сможет продукт без ML

Без ML продукт НЕ сможет:
1. **Автоматически категоризировать транзакции** — пользователю придётся размечать вручную. Это снижает удержание на ~30–40% (оценка из опыта ф fintech-продуктов).
2. **Предсказывать нерегулярный доход точнее EWMA** — для предпринимателей и фрилансеров прогноз будет грубее на 10–15%.
3. **Распознавать выписки** — ручной ввод данных о кредитах.
4. **Оценивать вероятность срыва** — будет работать на пороговых правилах (ПДН > 50%), что грубее, но приемлемо.

### Граница смешанного подхода

```
┌─────────────────────────────────────────────────────────────┐
│                     ДЕТЕРМИНИРОВАННОЕ ЯДРО                     │

│  • Прогноз дохода/расходов (модель: EWMA → градиентный буст)  │
│  • Категоризация транзакций (классификатор по MCC + тексту)   │
```

### Порядок шагов

```
АЛГОРИТМ allocate_month

ВХОД: income, expenses, savings, debts, goals, profile
ВЫХОД: allocation vector + explanation

--- ШАГ 0: Расчёт производных ---
1. mandatory_payments = Σ min_payment_i для всех долгов
2. free_cash = income - expenses - mandatory_payments
3. pdn = mandatory_payments / max(income, 1) * 100
4. months_reserve = reserve_months(profile)  # см. раздел 4
5. reserve_target = months_reserve * expenses
6. min_reserve = 1 * expenses  (минимум: 1 месяц)

--- ШАГ 1: Проверка дефицита ---
if free_cash < 0:
    → ДЕФИЦИТНЫЙ ПРОТОКОЛ (см. раздел 6)
    return

--- ШАГ 2: Избыточный резерв ---
excess_reserve = max(0, savings - reserve_target)
if excess_reserve > 0 AND есть долги с rate > r_inv:
    free_cash += excess_reserve
    savings -= excess_reserve
    # Эффект: избыточный резерв направляется на дорогой долг
    # через механизм сегментов (долг получит ставку выше invest)
    add_explanation("У вас избыточный резерв {excess_reserve} ₽. 
                      Направляем на досрочное погашение дорогого долга.")

--- ШАГ 3: Построение сегментов ---

segments = []  # каждый элемент: (name, capacity, rate, category)

# 3a. Резерв: минимум (1 месяц)
if savings < min_reserve:
    cap = min_reserve - savings
    segments.append(("reserve_min", cap, R_EMERGENCY_MIN, "min_reserve"))

# 3b. Резерв: до полной цели
if savings < reserve_target:
    lower = max(savings, min_reserve)
    cap = reserve_target - lower
    if cap > 0:
        segments.append(("reserve_target", cap, R_EMERGENCY_FULL, "reserve"))

# 3c. Долги (avalanche: по убыванию ставки)
for d in debts:
    if d.balance > 0:
        segments.append(("debt:" + d.name, d.balance, d.rate, "debt"))

# 3d. Цели
for g in goals:
    remaining = g.target - g.accumulated
    if remaining <= 0: continue
    
    w = goal_weight(g.type)  # mandatory=1.0, important=0.5, discretionary=0.2
    
    if g.deadline_months is not None:
        if g.deadline_months <= 0:
            # Просрочена — максимальный приоритет
            segments.append(("goal:" + g.name + ":overdue",
                           remaining, 100.0, "goal"))
        else:
            uf = urgency_factor(g.deadline_months)
            required_monthly = remaining / g.deadline_months
            
            # Обязательная часть (чтобы успеть к дедлайну)
            rate_req = R_GOAL_BASE * uf * w
            segments.append(("goal:" + g.name + ":required",
                           required_monthly, rate_req, "goal"))
            
            # Опциональная часть (сверх графика)
            rate_opt = R_GOAL_BASE * 0.3 * w
            optional_cap = remaining - required_monthly
            if optional_cap > 0:
                segments.append(("goal:" + g.name + ":optional",
                               optional_cap, rate_opt, "goal"))
    else:
        # Без дедлайна — низкий приоритет
        rate = R_GOAL_NO_DEADLINE * w
        segments.append(("goal:" + g.name + ":nodeadline",
                       remaining, rate, "goal"))

# 3e. Инвестиции (бесконечная ёмкость)
r_inv = investment_return(risk_tolerance)  # см. раздел 4
segments.append(("invest", float('inf'), r_inv, "invest"))

# 3f. Discretionary траты
v_spend = spend_utility(risk_tolerance)  # см. раздел 4
segments.append(("spend", free_cash, v_spend, "spend"))

--- ШАГ 4: Сортировка и заполнение ---

# Сортировка: по ставке убывание, при равенстве — по приоритету категории
priority_order = {
    "min_reserve": 0, "reserve": 1, "debt": 2,
    "goal": 3, "invest": 4, "spend": 5
}
segments.sort(key=lambda s: (-s[2], priority_order[s[3]]))

# Жадное заполнение
remaining_cash = free_cash
for (name, capacity, rate, cat) in segments:
    if remaining_cash <= 0: break
    amount = min(remaining_cash, capacity)
    if amount <= 0: continue
    record_allocation(name, amount)
    remaining_cash -= amount
    add_explanation(explain(name, amount, rate, next_best_rate))

--- ШАГ 5: Прогноз ---
# Симуляция: применяем стратегию помесячно, пока все долги не погашены
# и все цели с дедлайнами не достигнуты
# Используем прогноз дохода (EWMA) и расходов (EWMA)
# Вычисляем: дата освобождения от долгов, дата достижения каждой цели,
#             дата достижения полного резерва
# Запускаем 1000 симуляций с возмущением дохода/расходов → вероятности

return allocation, explanation, forecast
```

### Псевдокод urgency_factor

```
function urgency_factor(months_left):
    if months_left <= 0:  return 100.0    # Просрочена
    if months_left <= 1:  return 10.0     # Критично
    if months_left <= 3:  return 5.0      # Срочно
    if months_left <= 6:  return 2.0      # Внимание
    if months_left <= 12: return 1.0      # Норма
    return 0.5                            # Далеко
```

### Псевдокод explain

```
function explain(name, amount, rate, next_rate):
    # name — куда направлено
    # rate — ставка этого сегмента
    # next_rate — ставка следующего сегмента (альтернатива)
    
    if category == "min_reserve":
        return f"{amount} ₽ — в подушку безопасности (минимум 1 месяц). 
                 Без неё любой непредвиденный расход загонит в долг под {R_EMERGENCY_MIN}%."
    
    if category == "reserve":
        return f"{amount} ₽ — продолжаем копить подушку до {months_reserve} месяцев. 
                 Пока здесь выгоднее, чем следующий вариант ({next_rate}%)."
    
    if category == "debt":
        return f"{amount} ₽ — досрочное погашение {debt_name} (ставка {rate}%). 
                 Это гарантированная экономия {rate}% годовых — больше, 
                 чем дал бы вклад ({r_inv}%)."
    
    if category == "goal":
        if "overdue" in name:
            return f"{amount} ₽ — на цель '{goal_name}'. Дедлайн прошёл, 
                     это приоритет номер один."
        if "required" in name:
            return f"{amount} ₽ — на цель '{goal_name}'. Нужно откладывать 
                     по {required_monthly} ₽/мес, чтобы успеть к {deadline}."
        return f"{amount} ₽ — на цель '{goal_name}'."
    
    if category == "invest":
        return f"{amount} ₽ — в инвестиции (ожидаемая доходность {rate}%). 
                 Все долги дешевле этого, гасить досрочно невыгодно."
    
    if category == "spend":
        return f"{amount} ₽ — можно потратить на себя. 
                 Все важное уже профинансировано."
```

### Почему это работает (математическое обоснование)

Каждый сегмент — это **кусочно-постоянная предельная полезность**. Сортировка сегментов по убыванию ставки и жадное заполнение — это **точно решение LP-релаксации** с кусочно-линейной вогнутой целевой функцией. Для вогнутой целевой функции жадное заполнение по предельной полезности даёт глобальный оптимум (это следствие теоремы Куна-Таккера: в оптимуме предельные полезности всех активных направлений равны и не меньше предельной полезности неактивных).

| Профиль | Месяцев расходов | Источник |
|---------|-----------------|----------|

| Есть лиждивенцы | +1–2 месяца | SwitchWize |

**Минимальный резерв (hard floor):** 1 месяц обязательных расходов. Пока не достигнут — все свободные деньги идут сюда. Обоснование: без месяца резерва любой непредвиденный расход (болезнь, поломка) загоняет в новый долг по ставке кредитки (~50%).

### Ставка «дорогого» долга

Порог: **20% годовых**.

Обоснование: это выше ключевой ставки (14%) + типичная маржа вклада (~2 п.п.) = 16%. Долг дороже 20% гарантированно обходится дороже, чем любой доступный вклад или ОФЗ. Ставка 20% также близка к нижней границе ставок потребкредитов в 2026 году (рекламные ставки от 20%). **Это моя экспертная оценка.**

### Предельные ставки доходности для сегментов

| Константа | Значение | Обоснование |
|-----------|----------|-------------|
| \(R_{\text{EMERGENCY\_MIN}}\) | 50% | Равна средней ПСК кредитки — стоимости денег, в которые упадёте без резерва. Моя экспертная оценка: если нет резерва, первый непредвиденный расход → кредитка под 50%. |
| \(R_{\text{EMERGENCY\_FULL}}\) | 16% | Ключевая ставка + 2 п.п. = альтернативная стоимость «замороженных» в резерве денег. Выше, чем доходность вклада (13,6%), потому что резерв — это страховка, а не инвестиция. Моя экспертная оценка. |
| \(R_{\text{GOAL\_BASE}}\) | 14% | Равна ключевой ставке. Выполнение обязательства в срок = безрисковая альтернатива. Моя экспертная оценка. |
| \(R_{\text{GOAL\_NO\_DEADLINE}}\) | 5% | Цель без срока — «хотелка». Приоритет ниже вклада. Моя экспертная оценка. |
| \(R_{\text{GOAL\_OVERDUE}}\) | 100% | Просроченный дедлайн = максимально возможный приоритет. Моя экспертная оценка. |

### Ожидаемая доходность инвестиций (\(r_{\text{inv}}\))

| Профиль риска | Ставка | Инструмент | Обоснование |
|---------------|--------|------------|-------------|
| Консервативный | 13,6% | Банковский вклад | Средняя ставка по 3-месячным вкладам в топ-20 банках |
| Умеренный | 15,0% | Вклад + ОФЗ (50/50) | Среднее между вкладом (13,6%) и ОФЗ (16,3%) |
| Агрессивный | 18,0% | Диверсифицированный портфель | ОФЗ + акции. Моя экспертная оценка: историческая премия акций над облигациями ~4–6 п.п. |

Налог (НДФЛ 13%) не учитывается в ставке для упрощения, так как необлагаемый порог (140 000 ₽) покрывает доход большинства пользователей. Для крупных портфелей — версия 2.

### Полезность discretionary трат (\(v_{\text{spend}}\))

| Профиль | Ставка | Обоснование |
|---------|--------|-------------|
| Консервативный | 1% | Минимальный — «чуть-чуть можно» |
| Умеренный | 3% | Низкий, но заметный |
| Агрессивный | 5% | Позволяет больше тратить на себя |

Моя экспертная оценка. Ставка намеренно ниже любого финансового инструмента — чтобы discretionary траты получали деньги только после того, как всё важное профинансировано.

### Веса целей

| Тип цели | Вес \(w_j\) | Примеры |
|----------|-------------|---------|
| Обязательная | 1,0 | Налоги, штрафы, медицинские счета, юридические обязательства |
| Важная | 0,5 | Образование, первоначальный взнос на жильё, ремонт необходимый |
| Желательная | 0,2 | Отпуск, гаджет, хобби, машина сверх необходимой |

Моя экспертная оценка. Обязательная цель с горящим дедлайном (urgency 5,0, weight 1,0) получает ставку \(14 \times 5 \times 1 = 70\%\) — выше кредитки (50%). Желательная цель с тем же дедлайном: \(14 \times 5 \times 0{,}2 = 14\%\) — ниже вклада. Это правильно: налоги важнее отпускного долга.

### Учёт инфляции и альтернативной доходности

Инфляция не вычитается из ставок в основной модели — все ставки номинальные. Причина: сравнение идёт между номинальными альтернативами (долг под 50% vs вклад под 14%), инфляция влияет на обе одинаково.

Для целей с горизонтом > 1 года — цель корректируется на инфляцию:

\[T_j^{\text{adj}} = T_j \times (1 + \pi)^{n}\]

где \(n\) — лет до дедлайна, \(\pi\) = 6,5% (прогноз ЦБ на 2026). Это моя экспертная оценка применения прогноза ЦБ.

### Влияние возраста и склонности к риску

| Фактор | Влияние на модель |
|--------|-------------------|
| Возраст < 30 | \(r_{\text{inv}}\) + 1 п.п. (дольше горизонт → больще риска) |
| Возраст 30–55 | Базовые значения |
| Возраст > 55 | \(r_{\text{inv}}\) − 1 п.п.; резерв + 1 месяц; вес discretionary − 0,5% |
| Возраст > 65 | Резерв + 2 месяца; \(r_{\text{inv}}\) − 2 п.п. (консервативный по умолчанию) |

Моя экспертная оценка. Логика: с возрастом горизонт инвестирования сокращается, а потребность в ликвидности растёт.

## 5. Неопределённость

### Прогноз дохода и расходов

**Метод:** экспоненциально взвешенное скользящее среднее (EWMA) с параметром \(\alpha = 0{,}3\):

\[\hat{I}_{t+1} = \alpha \cdot I_t + (1 - \alpha) \cdot \hat{I}_t\]

Для дохода используется **нижний квартиль** прогноза (P25), не медиана — планирование должно быть консервативным. Для расходов — **верхный квартиль** (P75).

При наличии ML (опционально): модель прогноза на градиентном бустинге с сезонностью. Но ядро работает с EWMA.

**Дисперсия:** \(\sigma^2_I\) оценивается по скользящему окну за 6–12 месяцев.

### Вероятность достижения цели

**Метод:** Монте-Карло, 1000 симуляций.

В каждой симуляции:
1. Доход каждого месяца \(I_t \sim \mathcal{N}(\hat{I}_t, \sigma_I)\), ограничение \(I_t \geq 0\);
2. Расходы \(E_t \sim \mathcal{N}(\hat{E}_t, \sigma_E)\), ограничение \(E_t \geq E_{\min}\);
3. Запустить алгоритм распределения;
4. Проверить: достигнута ли цель к дедлайну?

Доля успешных симуляций = **вероятность достижения цели**.

### Как показывать неуверённость пользователю

| Элемент | Формат | Пример |
|---------|--------|--------|
| Прогноз дохода | Диапазон (P10–P90) | «Доход в следующем месяце: ~85 000 ₽ (возможно 70 000–100 000)» |
| Дата освобождения от долгов | Месяц + диапазон | «Кредитка закрыта: февраль 2027 (январь–апрель)» |
| Вероятность цели | Процент + интерпретация | «Отпуск к июлю: 72% — хорошие шансы» |
| Дата достижения резерва | Месяц + диапазон | «Подушка 3 месяца: октябрь 2026 (сентябрь–декабрь)» |

**Принцип:** никогда не показывать точную дату без диапазона. Точность без доверия хуже, чем приблизительность с честностью.

**Цветовая шкала вероятности:**
- > 80%: «почти наверняка» (зелёный)
- 50–80%: «хорошие шансы» (жёлтый)
- 30–50%: «под вопросом» (оранжевый)
- < 30%: «маловероятно» (красный) — предложить изменить план

## 6. Крайние случаи

### 1. Нулевой или почти нулевой доход

```
free_cash = 0 - expenses - mandatory_payments → большой минус
→ ДЕФИЦИТНЫЙ ПРОТОКОЛ
```

**Алгоритм:**
1. Покрыть из резерва. Если резерв ≥ дефицита + 1 месяц расходов → покрыть полностью, предупредить об уменьшении резерва.
2. Если резерва не хватает → покрыть частично, остаток → раздел 2.
3. Одновременно: рекомендовать «связаться с банками о кредитных каникулах», проверить право на пособия.
4. Прогноз: «При текущем резерве вы протянете N месяцев без дохода».

**Выдача:** «У вас нет дохода в этом месяце. Покрываем расходы из подушки: −45 000 ₽. Резерва хватит на 2,3 месяца. Если доход не восстановится — свяжитесь с банками о реструктуризации.»

### 2. Свободных денег минус

Та же логика — дефицитный протокол. Дополнительно:

```
if pdn > 80:
    "Критическая долговая нагрузка (ПДН {pdn}%). 
     Рекомендация: рефинансирование, консультация с финансовым омбудсменом,
     при необходимости — процедура банкротства (Закон 127-ФЗ)."
elif pdn > 50:
    "Высокая долговая нагрузка (ПДН {pdn}%). 
     Приоритет: рефинансирование дорогих кредитов, снижение обязательных расходов."
elif pdn > 30:
    "Умеренная нагрузка. Покрываем дефицит из резерва.
     Рекомендуем найти источник дополнительного дохода."
```

### 3. Долгов больше, чем человек может обслуживать (ПДН > 80%)

Алгоритм распределения **не запускается** — проблема не в распределении свободных денег, а в структуре долга.

**Выдача:**
```
"Ваша долговая нагрузка — 85% дохода. Алгоритм распределения здесь бессилен:
проблема не в том, как распределить свободные деньги, а в том, что их нет.
Рекомендации:
1. Рефинансирование: объединить кредиты в один с меньшей ставкой.
2. Кредитные каникулы: запросить отсрочку у банков (ст. 6.1-1 ФЗ 353).
3. Продать активы (если есть).
4. При невозможности — обратиться к финансовому омбудсмену
   или рассмотреть внесудебное банкротство (ФЗ 127)."
```

### 4. Целей нет

Сегменты целей не добавляются. Свободные деньги идут в резерв → долг → инвестиции → траты. Объяснение: «Все долги закрыты, резерв сформирован. Свободные деньги — в инвестиции.»

### 5. Кредитов нет

Сегменты долгов не добавляются. Резерв → цели → инвестиции → траты.

### 6. Цель уже перефинансирована

Если цель была «погасить кредит X» и он рефинансирован в кредит Y — цель удаляется (target = accumulated), кредит Y добавляется в debts. Алгоритм работает с новым состоянием.

### 7. Срок цели прошёл

Сегмент получает ставку 100% (максимальный приоритет). Алгоритм направит все свободные деньги на эту цель, отодвинув даже кредитку под 50%.

Если цели невозможно достичь (осталось 200 000 ₽, а свободных 10 000 ₽/мес):
```
"Дедлайн цели 'Отпуск' прошёл. Накоплено 30 000 из 100 000 ₽.
 Направляем все свободные деньги на эту цель, но при текущем темпе
 потребуется ещё 7 месяцев. Предлагаем: перенести дедлайн или 
 уменьшить сумму цели."
```

### 8. Огромный резерв при дорогом долге

Шаг 2 алгоритма (избыточный резерв): если накопления > цели резерва и есть долг дороже 15% — избыток направляется на долг.

**Выдача:**
```
"Ваша подушка — 300 000 ₽, это 8,5 месяцев расходов. 
Цель — 3 месяца (105 000 ₽). Избыток: 195 000 ₽.
У вас кредитка под 50% с остатком 150 000 ₽.
Направляем избыточный резерв на досрочное погашение.
Оставшиеся 45 000 ₽ — в инвестиции."
```

### 9. Ставка по долгу ниже доходности вклада

Сегмент долга (8%) попадает ниже сегмента инвестиций (13,6%) в сортировке. Алгоритм направляет деньги в инвестиции, а не на досрочное погашение.

**Выдача:**
```
"Ипотека под 8% дешевле, чем вклад под 13,6%. 
Досрочное погашение невыгодно: вы потеряете 5,6 п.п. доходности.
Свободные деньги — на вклад."
```

### 10. Нет ни долгов, ни целей, резерв сформирован

Всё в инвестиции + небольшой discretionary.

**Выдача:**
```
"Все долги закрыты, подушка сформирована, целей нет.
42 000 ₽ — в инвестиции (ожидаемая доходность 15%).
Вы в отличной финансовой форме."
```

## 7. Объяснимость

### Принцип

Каждый рубль распределения объясняется одним предложением формата:

> **[Сумма] → [Куда] — [Почему], потому что [Ставка] > [Альтернатива].**

### Пример объяснения

**Вход:**
- Доход 120 000 ₽, расходы 50 000 ₽, мин. платежи 25 000 ₽
- Свободный остаток: 45 000 ₽
- Накопления: 30 000 ₽ (меньше 1 месяца)
- Кредитка: 80 000 ₽ под 50%
- Цель «Налоги»: 45 000 ₽, дедлайн через 2 месяца, накоплено 10 000 ₽

**Выдача алгоритма:**
```
В этом месяце у вас осталось 45 000 ₽ после обязательных расходов 
и платежей по кредитам.

1. 17 500 ₽ — на оплату налогов. Срок через 2 месяца, 
   нужно откладывать по 17 500 ₽/мес, чтобы успеть. 
   Это обязательный платёж, пропустить — штраф.

2. 20 000 ₽ — в подушку безопасности. У вас сейчас меньше 
   одного месяца расходов в резерве. Без подушки любой непредвиденный 
   расход — это новая кредитка под 50%.

3. 7 500 ₽ — на досрочное погашение кредитки (ставка 50%). 
   Это гарантированная экономия 50% годовых — больше, 
   чем даст любой вклад.

Отпуск и ноутбук подождут: кредитка под 50% и просроченные налоги 
важнее.
```

### Что НЕ использует объяснение

- Формул, переменных, LaTeX — нет;
- Терминов «сегмент», «предельная ставка», «EWMA» — нет;
- Ссылок на алгоритм — нет;
- Только бытовой язык и конкретные числа, которые человек может проверить.

### Генерация объяснения

Объяснение строится из двух частей:
1. **Что** — сумма и направление (из allocation vector);
2. **Почему** — сравнение ставки этого выбора со следующим лучшим (из segments sort order).

Дополнительно: один абзац «общая картина» в начале (ПДН, состояние резерва, сколько долгов) и один «что отложено» в конце (что не получило денег и почему).

## 8. Границы и риски

### Где модель заведомо даёт плохой совет

| Ситуация | Почему плохо | Что делать |
|----------|-------------|------------|
| **Пользователь не следует совету** | Модель оптимизирует распределение, а не поведение. Если человек тратит «discretionary» на новую кредитку — модель бессильна. | Не решаемо в рамках алгоритма. Версия 2: поведенческие нуджи. |
| **Скрытые обязательства** | Пользователь не сообщил о алиментах, судебных взысканиях, скрытых кредитах. Алгоритм работает с неполным состоянием. | Предупреждение: «Учтите ВСЕ обязательные платежи, иначе расчёт будет неверным.» |
| **Переменные ставки** | Кредитка с меняющейся ставкой (плавающей). Алгоритм фиксирует ставку на момент расчёта. | Пересчёт каждый месяц нивелирует. Но прогноз может быть неточным. |
| **Семейные финансы** | Модель работает с одним человеком. Супруг может иметь общий бюджет, общие долги. | Версия 2: совместные счета. |
| **Налоговые вычеты** | Не учитывает возврат НДФЛ (имущественный, социальный, ИИС). Может недооценить доступные средства. | Версия 2. |
| **Инфляционный пересмотр целей** | Цель «купить машину за 1 млн через 2 года» — через 2 года машина стоит 1,13 млн. Модель корректирует только при горизонте > 1 года. | Реализовано, но зависит от точности прогноза инфляции. |
| **Экстренный расход внутри месяца** | Модель считает помесячно. Если поломка машины на 15-й день — резерв может не успеть пополниться. | Не решаемо в рамках месячного цикла. |
| **Эмоциональные факторы** | Человек может хотеть погасить маленький долг «для психологического облегчения» (snowball), даже если математически выгоднее avalanche. | Модель использует avalanche. Версия 2: опция snowball с объяснением trade-off. |

### Что сознательно упрощено

1. **Помесячный цикл** — нет внутри месяца. Реальность: зарплата 5-го, ипотека 20-го, но алгоритм считает всё за месяц.
2. **Безналоговая модель** — НДФЛ на инвестиционный доход не вычитается из ставки. Допустимо для большинства (порог 140 000 ₽), неточно для крупных портфелей.
3. **Линейная полезность** — нет насыщения. Каждый рубль в discretionary имеет одинаковую полезность. В реальности 10-я тысяча на развлечения ценнее 100-й.
4. **Без нового долга** — модель не предусматривает, что человек возьмёт новый кредит. Не учитывает «искушение» нераспределённых discretionary средств.
5. **Без деления расходов** — все обязательные расходы равны. Нет различия «жильё» (нельзя не платить) и «подписки» (можно отменить).
6. **Стационарность** — ставки долгов и доходность инвестиций не меняются в прогнозе. В реальности ключевая ставка меняется.

## 9. Как проверить, что модель работает

### Данные

1. **Синтетические сценарии** (primary): сгенерировать 10 000 профилей с случайными, но правдоподобными параметрами (доход 40–200 тыс, 0–5 кредитов, 0–5 целей, разные профили риска). Для каждого — запустить алгоритм и проверить свойства решения.

2. **Ретроспективные данные** (secondary): если есть доступ к анонимизированным транзакциям реальных пользователей (через партнёрство с банком или open banking API) — за 12–24 месяца. Запускать алгоритм помесячно, сравнивать с фактическим поведением.

3. **Сравнение с экспертами** (validation): 20–50 кейсов отдать финансовым консультантам, сравнить их рекомендации с алгоритмом.

### Метрики

| Метрика | Как считать | Целевое значение |
|---------|-------------|------------------|
| **Сэкономлено на процентах** | \(\sum\) процентов, фактически уплаченных − \(\sum\) процентов по стратегии алгоритма | > 0 для каждого кейса с дорогими долгами |
| **Достигнутые цели (%)** | Доля целей, достигнутых к дедлайну | > 90% для целей с вероятностью > 70% |
| **Резерв адекватен** | Резерв ≥ 1 месяц расходов после 6 месяцев работы | 100% (hard constraint) |
| **Время до бездолжности** | Месяцев до погашения всех долгов | < базового сценария (только мин. платежи) |
| **Следование совету** | Доля месяцев, где пользователь следовал рекомендации | > 60% (иначе продукт не работает) |
| **Согласие с экспертами** | Доля кейсов, где алгоритм совпает с большинством экспертов | > 80% |

### Что считать провалом

1. **Алгоритм рекомендует действие, которое увеличивает общую стоимость** более чем на 5% по сравнению с базовым сценарием (только минимальные платежи). Это означает, что модель хуже «ничего не делать».
2. **Цель с вероятностью > 80% не достигнута** при стратегии алгоритма. Это означает, что алгоритм не учёл срочность.
3. **Резерв опускается ниже 0** при наличии возможностей его пополнить. Это означает, что приоритет резерва нарушен.
4. **Несогласие с экспертами > 50%** — модель систематически расходится с профессиональным консенсусом.
5. **Недетерминированность** — одинаковый вход даёт разный выход. Это не метрика, а инвариант: проверяется автоматически на каждом релизе.

### Сравнение с бейзлайнами

1. **Бейзлайн 1: только минимальные платежи** — если алгоритм не побеждает этот бейзлайн по метрике «сэкономлено на процентах», он бесполезен.
2. **Бейзлайн 2: avalanche (всё на дорогой долг)** — если алгоритм не побеждает по «достигнутые цели», он не лучше правила «гаси дорогой долг».
3. **Бейзлайн 3: пропорциональное распределение** (20% — каждому каналу) — если алгоритм не побеждает по сумме всех метрик, он не оправдывает сложность.

## 10. Если бы делал вторую версию

### Приоритет 1: Семейные финансы

**Что:** модель для пары/семьи с общим и раздельным бюджетом, общими и личными долгами, общими и личными целями.

**Почему:** подавляющее большинство пользователей живут не одни. Долг супруга влияет на семейный риск. Цель «первоначальный взнос» — общая. Без этого модель даёт совет, который может противоречить интересам семьи.

### Приоритет 2: Налоговая оптимизация

**Что:** учёт вычетов (имущественный, социальный, ИИС-3), расчёт «стоит ли досрочно гасить ипотеку, если вычет компенсирует часть процентов».

**Почему:** в России имущественный вычет по ипотеке возвращает 13% от суммы процентов. Для ипотеки под 8% эффективная ставка после вычета — ~7%. Это меняет вывод «гасить или инвестировать». Без учёта вычета модель может советовать «гасить досрочно» там, где выгоднее «инвестировать и получать вычет».

### Приоритет 3: Поведенческий слой

**Что:** не просто рекомендация, а нуджи — напоминания, визуализация прогресса, опция «snowball для психологического комфорта», «договор с собой» (commitment device).

**Почему:** лучший алгоритм бесполезен, если ему не следуют. Метрика «следование совету > 60%» — это барьер, который решается не математикой, а поведенческим дизайном.

### Приоритет 4: Динамические ставки

**Что:** прогноз траектории ключевой ставки (на основе форвардных кривых ОФЗ), пересчёт \(r_{\text{inv}}\) и порогов каждый квартал.

**Почему:** модель 2026 года со ставкой 14% будет давать заниженные пороги в 2027 году при ставке 10%. Константы должны обновляться автоматически.

### Приоритет 5: Open Banking API

**Что:** автоматический импорт транзакций, остатков, ставок из банков через API (Закон о финансовых платформах, ФЗ 211).

**Почему:** ручной ввод — главный барьер входа. Продукт без ML категоризации теряет 30–40% пользователей на онбординге. Автоматический импорт решает это без обучаемой модели в ядре.

---

**Резюме:** ядро алгоритма — детерминированный жадный каскад на предельных ставках, эквивалентный решению LP с кусочно-линейной целевой функцией. Каждый рубль идёт в канал с максимальной «эффективной доходностью», которая для долга равна ставке, для резерва — стоимости избегания будущего долга, для цели — функции срочности и важности. Это даёт математически оптимальное, объяснимое и воспроизводимое решение без обучаемых моделей. ML уместен по краям — прогноз, категоризация, OCR — но не в ядре распределения.
