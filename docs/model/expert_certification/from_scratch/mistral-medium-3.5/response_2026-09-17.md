# 🔴 **1. ПОСТАНОВКА ЗАДАЧИ ФОРМАЛЬНО**

## Состояние системы в месяц **t**
- **Dₜ** — доход за месяц (рубли, может быть 0 или отрицательным при убытках).
- **Eₜ** — обязательные расходы на жизнь (аренда, еда, коммуналка, страховки и т.п.).
- **Lₜ = {lᵢ}** — множество кредитов/карт:
  - **bᵢ** — остаток долга (рубли),
  - **rᵢ** — годовая процентная ставка (доля, например, 0.25 = 25%),
  - **pᵢ** — обязательный платёж в месяц **t** (рубли),
  - **τᵢ** — тип (ипотека, потребительский, кредитная карта).
- **Sₜ** — ликвидные накопления (рубли, доступны сразу).
- **Rₜ** — резервный фонд (рубли, часть **Sₜ**).
- **Gₜ = {gⱼ}** — множество целей:
  - **Tⱼ** — целевая сумма (рубли),
  - **dⱼ** — срок (дата или "нет срока"),
  - **πⱼ** — приоритет (1–5, где 5 = максимальный).
- **Aₜ** — инвестиционный портфель (рубли, доходность **μ** годовых, риск **σ**).
- **Cₜ** — текущая дата (месяц/год).

---

## Решение (действие) в месяц **t**
- **xₜᵈ** — вектор досрочного погашения долгов: **xₜᵈ = {xᵢ}**, где **xᵢ ≥ 0** — сумма на погашение долга **lᵢ**.
- **xₜʳ** — пополнение резервного фонда (**xₜʳ ≥ 0**).
- **xₜᵍ** — вектор накоплений на цели: **xₜᵍ = {yⱼ}**, где **yⱼ ≥ 0** — сумма на цель **gⱼ**.
- **xₜᵃ** — инвестиции (**xₜᵃ ≥ 0**).
- **xₜˢ** — свободные траты (**xₜˢ ≥ 0**).

---
---
## Ограничения
1. **Бюджетное ограничение**:
   **xₜᵈ + xₜʳ + xₜᵍ + xₜᵃ + xₜˢ ≤ Fₜ**,
   где **Fₜ = Dₜ − Eₜ − ∑ᵢ pᵢ** — свободные деньги после обязательных платежей.
   Если **Fₜ < 0**, то **xₜᵈ = xₜʳ = xₜᵍ = xₜᵃ = 0**, а дефицит покрывается из **Sₜ** или **Rₜ**.

2. **Ограничения по долгам**:
   **xᵢ ≤ bᵢ** для всех **i**.

3. **Ограничения по целям**:
   **yⱼ ≤ Tⱼ − sⱼ** (где **sⱼ** — текущие накопления на цель **gⱼ**).

4. **Нет дефолта**:
   После выполнения **xₜᵈ** и **pᵢ** остаток по каждому долгу **bᵢ − xᵢ − pᵢ ≥ 0**.

---
---
## Целевая функция и горизонт
**Горизонт планирования**: **T = 60 месяцев** (5 лет).
**Целевая функция** — **лексикографическая оптимизация** (приоритеты строго упорядочены):
1. **Уровень 0 (критический)**: Избегание дефолта в текущем месяце.
   - **Minimize: δₜ**, где **δₜ = 1**, если **Fₜ + Sₜ < ∑ᵢ pᵢ**, иначе **0**.
2. **Уровень 1 (безопасность)**: Поддержание резервного фонда.
   - **Minimize: max(0, Rₘᵢₙ − Rₜ)**, где **Rₘᵢₙ** — минимальный целевой резерв.
3. **Уровень 2 (эффективность)**: Минимизация суммарных процентных платежей по долгам.
   - **Minimize: ∑ᵢ (bᵢ × rᵢ / 12)** (ежемесячные проценты).
4. **Уровень 3 (достижимость)**: Максимизация вероятности достижения целей.
   - **Maximize: ∑ⱼ P(gⱼ достигнута к dⱼ)**, где **P** — вероятность (оценка на основе текущих накоплений и оставшегося времени).
5. **Уровень 4 (рост)**: Максимизация чистой стоимости.
   - **Maximize: (Sₜ + Aₜ − ∑ᵢ bᵢ)**.

**Почему лексикографический порядок?**
- Человеку важнее **выживание** (нет дефолта), чем **оптимизация** (экономия процентов).
- Резервный фонд — **страховка от неопределённости**, поэтому его приоритет выше, чем погашение долгов.
- Проценты по долгам — **гарантированные убытки**, поэтому их минимизация важнее, чем накопление на цели.
- Вероятность достижения целей учитывается только после обеспечения безопасности.

# 🔴 **2. ВЫБОР КЛАССА МЕТОДА**

Рассмотрены **5 подходов**:

| Подход | Плюсы | Минусы | Где ломается |
|--------|-------|--------|--------------|
| **А. Жадные правила + эвристики** | Быстро (O(n)), детерминированно, объяснимо, легко реализовать | Субоптимально для долгих горизонтов, не учитывает будущие колебания | При нерегулярных доходах или изменяющихся ставках |
| **Б. Математическая оптимизация (LP/NLP)** | Оптимально в рамках модели, учитывает все ограничения | Сложно объяснить, требует прогноза на горизонт, чувствительно к входным данным | При неопределённости доходов/расходов |
| **В. Динамическое программирование (DP)** | Учитывает временную структуру, оптимально для детерминированных задач | Проклятие размерности (много состояний), сложно объяснить, требует дискретизации | При большом количестве кредитов/целей |
| **Г. Стохастическое управление (SDP)** | Учитывает неопределённость, оптимально в среднем | Сложно реализовать, требует оценки распределений, вычислительно дорого | При отсутствии данных о распределениях |
| **Д. Обучение с подкреплением (RL)** | Адаптируется к поведению пользователя, учится на данных | Не детерминированно, требует большого количества данных, сложно объяснить | При изменении внешних условий (инфляция, ставки) |

---
---
## **Выбор: Жадные правила с элементами приоритетной оптимизации**
**Почему?**
1. **Детерминированность**: Одинаковый вход → одинаковый выход (требование задачи).
2. **Скорость**: Вычисления за **O(n log n)** (сортировка кредитов/целей), подходит для мобильного приложения.
3. **Объяснимость**: Решение можно описать словами без формул.
4. **Адекватность**:
   - Для большинства пользователей жадная стратегия **"гасить долги с самой высокой ставкой"** близка к оптимальной (доказано в теории управления долгом).
   - Лексикографический порядок приоритетов соответствует интуиции человека.

**Почему отвергнуты остальные?**
- **LP/NLP**: Требует прогноза доходов/расходов на 60 месяцев (нереалистично для пользователя).
- **DP/SDP**: Слишком сложно для продукта, не детерминированно (SDP), проклятие размерности.
- **RL**: Не детерминированно, требует обучения на данных пользователя (которого нет на старте), сложно объяснить.

## **Где ML даёт прирост (и чем платит продукт без него)**

| **Распознавание выписок** | Автоматическое извлечение данных из PDF/скриншотов | Пользователь вводит данные вручную | Время пользователя: **+1–3 часа/месяц** |
| **Оптимизация налогов** | Учёт налоговых вычетов (ипотека, инвестиции) | Не учитывается, пользователь платит больше налогов | Переплата налогов: **0.5–2% от дохода** |

## **Где ML вредит**
| Проблема | Почему |
|----------|--------|
| **Ядро алгоритма** | ML даст нестабильные рекомендации (разные результаты на похожих входах), что нарушает требование детерминированности. |
| **Объяснимость** | Пользователь не сможет понять, почему модель рекомендовала погасить долг А, а не Б. |
| **Надзор** | Требуется постоянный контроль за качеством модели, обновление данных, мониторинг дрифта. |
| **Риск для пользователя** | Ошибка модели (например, неправильная классификация транзакции) может привести к дефолту. |
| **Стоимость** | Разработка и поддержка ML-моделей дороже, чем правил. |

---
---
## **Граница между формулами и ML**
| Компонент | Реализация | Почему |
|-----------|------------|--------|
| **Ядро алгоритма** (распределение свободных денег) | Формулы + жадные правила | Детерминированность, объяснимость, скорость. |
| **Прогноз доходов/расходов** | ML (ARIMA, Prophet, LSTM) | Неопределённость требует статистических методов. |
| **Категоризация транзакций** | ML (классификатор на основе правил + обучение) | Ручная разметка утомительна для пользователя. |
| **Оценка риска дефолта** | ML (логистическая регрессия, Random Forest) | Учитывает историю платежей, доходы, расходы. |
| **Персонализация порогов** | ML (обучение на данных пользователя) | Адаптация под поведение. |
| **Распознавание выписок** | ML (OCR + NLP) | Автоматизация ввода данных. |

**Итог:**
- **Детерминированное ядро** (распределение денег) — **формулы**.
- **Вспомогательные функции** (прогнозирование, классификация, извлечение данных) — **ML**.
- **Граница**: если компонент влияет на **решение "что делать с деньгами"** → формулы. Если влияет на **входные данные или прогнозы** → ML.

# 🔴 **3. САМА МОДЕЛЬ: АЛГОРИТМ**

## **Переменные и константы**
| Переменная | Описание | Тип |
|------------|----------|-----|

| `HIGH_INTEREST_THRESHOLD` | Пороговая ставка для "дорогих" долгов | `float` |
| `TAX_RATE` | Ставка НДФЛ на доход от инвестиций | `float` |

## **Алгоритм: Приоритетное распределение свободных денег**

### **Шаг 0: Проверка дефицита**
```python
if F < 0:
    # Дефицит: покрываем из резерва или накоплений
    deficit = -F
    if R >= deficit:
        R -= deficit
        F = 0
        return {
            "reserve_add": 0,
            "debt_repayment": {},
            "goals_add": {},
            "invest": 0,
            "spend": 0,
            "warning": "Дефицит покрыт из резерва. Рекомендуем сократить расходы."
        }
    elif S >= deficit:
        S -= deficit
        F = 0
        return {
            "reserve_add": 0,
            "debt_repayment": {},
            "goals_add": {},
            "invest": 0,
            "spend": 0,
            "warning": "Дефицит покрыт из накоплений. Резерв на нуле — срочно пополните!"
        }
    else:
        return {
            "reserve_add": 0,
            "debt_repayment": {},
            "goals_add": {},
            "invest": 0,
            "spend": 0,
            "error": "Дефолт неизбежен. Нужно срочно сократить расходы или увеличить доход."
        }
```

---
### **Шаг 1: Пополнение резервного фонда**
```python
R_min = max(6 * E, 100_000)  # 6 месяцев расходов или 100к ₽ (что больше)
R_deficit = max(0, R_min - R)
x_reserve = min(F, R_deficit)
F -= x_reserve
R += x_reserve
```

---
### **Шаг 2: Создание списка "возможностей" для распределения оставшихся денег**
Каждая возможность — это **действие**, которое можно выполнить с оставшимися деньгами.
**Приоритет** определяет порядок распределения.

```python
opportunities = []

# 2.1. Погашение долгов (экономия процентов)
for credit in credits:
    if credit.balance > 0:
        # Экономия процентов за месяц от погашения 1 ₽
        monthly_interest_saved = credit.rate / 12
        # Если ставка > доходности инвестиций, приоритет выше
        if credit.rate > INVEST_RETURN:
            priority = monthly_interest_saved * 2  # Увеличиваем приоритет для дорогих долгов
        else:
            priority = monthly_interest_saved
        opportunities.append({
            "type": "debt",
            "id": credit.id,
            "priority": priority,
            "max_amount": credit.balance
        })

# 2.2. Инвестиции (доходность)
if INVEST_RETURN > 0:
    # Эффективная доходность после налогов
    net_return = INVEST_RETURN * (1 - TAX_RATE) / 12
    opportunities.append({
        "type": "invest",
        "priority": net_return,
        "max_amount": float('inf')
    })

# 2.3. Накопление на цели
for goal in goals:
    if goal.current >= goal.target:
        continue  # Цель уже достигнута
    needed = goal.target - goal.current
    months_left = calculate_months_left(goal.deadline) if goal.deadline else 60  # 5 лет по умолчанию
    # Приоритет: важность цели / время до дедлайна
    priority = goal.priority / max(months_left, 1)
    opportunities.append({
        "type": "goal",
        "id": goal.id,
        "priority": priority,
        "max_amount": needed
    })

# 2.4. Сортировка по приоритету (убывание)
opportunities.sort(key=lambda x: x["priority"], reverse=True)
```

---
### **Шаг 3: Распределение оставшихся денег по возможностям**
```python
actions = {
    "reserve_add": x_reserve,
    "debt_repayment": {},
    "goals_add": {},
    "invest": 0,
    "spend": 0
}

for opp in opportunities:
    if F <= 0:
        break
    if opp["type"] == "debt":
        amount = min(F, opp["max_amount"])
        actions["debt_repayment"][opp["id"]] = amount
        F -= amount
    elif opp["type"] == "invest":
        amount = F
        actions["invest"] = amount
        F = 0
    elif opp["type"] == "goal":
        amount = min(F, opp["max_amount"])
        actions["goals_add"][opp["id"]] = amount
        F -= amount

actions["spend"] = F  # Остаток — свободные траты
```

```
        иначе если opp.type == "goal":
            amount = min(F, opp.max_amount)
            actions.goals_add[opp.id] = amount
            F -= amount

    actions.spend = F
    вернуть actions
```

---
---
### **Формулы для ключевых расчётов**
1. **Экономия процентов от погашения долга**:
   **ΔP = x × (r / 12)**, где **x** — сумма погашения, **r** — годовая ставка.
2. **Ожидаемая доходность инвестиций**:
   **ΔA = x × (μ / 12) × (1 − τ)**, где **μ** — годовая доходность, **τ** — ставка налога.
3. **Вероятность достижения цели** (упрощённо):
   **P = min(1, (s + y × m) / T)**, где **s** — текущие накопления, **y** — ежемесячное пополнение, **m** — месяцев до дедлайна, **T** — целевая сумма.

## **Как показывать неопределённость пользователю**
### **Формат объяснения:**
```
📊 **Прогноз на 12 месяцев**
- **Оптимистичный сценарий** (доход +10%, расходы −10%):
  - Резерв: 150 000 ₽
  - Долги: 0 ₽ (все погашены)
  - Цели: 2 из 3 достигнуты
- **Реалистичный сценарий** (доход ±0%, расходы ±0%):
  - Резерв: 100 000 ₽
  - Долги: 50 000 ₽
  - Цели: 1 из 3 достигнута
- **Пессимистичный сценарий** (доход −10%, расходы +10%):
  - Резерв: 20 000 ₽
  - Долги: 120 000 ₽
  - Цели: 0 из 3 достигнуты
  - ⚠️ **Риск дефолта: 30%**

💡 **Рекомендация:**
Сейчас у вас свободно 30 000 ₽. Мы рекомендуем:
1. Пополнить резерв на 20 000 ₽ (до 100 000 ₽).
2. Погасить 10 000 ₽ по кредитной карте (ставка 25%).
Это снизит риск дефолта до **5%** и увеличит вероятность достижения целей до **70%**.
```

### **Метрики неопределённости**
1. **Вероятность дефолта**:
   - Рассчитывается как **P( Fₜ + Rₜ < ∑pᵢ )** на основе истории доходов/расходов.
   - Формула: **P_default = 1 − Φ( (F + R − ∑p) / σ )**, где **σ** — стандартное отклонение дохода, **Φ** — функция распределения нормального закона.
2. **Вероятность достижения цели**:
   - **P_goal = Φ( (T − s − y × m) / (σ_y × √m) )**, где **σ_y** — стандартное отклонение ежемесячных накоплений.
3. **Диапазон чистой стоимости**:
   - **Net Worth = (S + A − ∑bᵢ) ± 2σ**, где **σ** — стандартное отклонение прогноза.

# 🔴 **7. ОБЪЯСНИМОСТЬ**

## **Как переводить расчёт в человеческий язык**
### **Структура объяснения:**
1. **Сколько свободных денег осталось** (и откуда они взялись).

3. **Что не сделано** и **почему**.
4. **Какие риски остаются** и **что делать дальше**.

---
### **Пример объяснения**
```
💰 **В этом месяце у вас:**
- Доход: 150 000 ₽
- Обязательные расходы: 60 000 ₽
- Обязательные платежи по кредитам: 20 000 ₽ (кредитная карта: 10 000 ₽, потребительский кредит: 10 000 ₽)
➡️ **Осталось свободных денег: 70 000 ₽**

---

📋 **Что мы рекомендуем сделать:**

1️⃣ **Пополнить резервный фонд на 40 000 ₽**
   - У вас было 20 000 ₽ в резерве, а рекомендуемый минимум — 60 000 ₽ (1 месяц расходов).
   - **Почему?** Резерв — это ваша финансовая подушка безопасности. Без него вы рискуете взять новый кредит в случае неожиданных расходов (например, ремонт машины или болезнь).

2️⃣ **Погасить 20 000 ₽ по кредитной карте**
   - У вас есть кредитная карта с остатком 50 000 ₽ и ставкой **25% годовых**.
   - **Почему?** Это дорогой долг: каждый месяц вы платите **~2% от остатка** в виде процентов. Погашая его, вы экономите эти проценты — как будто кладете деньги на депозит под 25%.

3️⃣ **Отложить 10 000 ₽ на цель "Машина"**
   - Целевая сумма: 500 000 ₽, срок: через 24 месяца.
   - Сейчас накоплено: 100 000 ₽.
   - **Почему?** Чтобы уложиться в срок, нужно откладывать **~16 700 ₽/месяц**. Мы откладываем 10 000 ₽, так как остальные деньги ушли на резерв и долги.

---
📌 **Что не сделано и почему:**
- ❌ **Не гасим потребительский кредит** (ставка 12%): он дешевле кредитной карты, поэтому его погашение менее приоритетно.
- ❌ **Не инвестируем**: пока есть долги с ставкой >10%, выгоднее гасить их, чем инвестировать.
- ❌ **Не откладываем на цель "Путешествие"**: у неё низкий приоритет (2/5), поэтому сначала пополняем резерв и гасим дорогие долги.

---
⚠️ **Остающиеся риски:**
- Если доход упадёт на **>15%**, вы не сможете пополнить резерв в следующем месяце.
- Если кредитная карта будет использоваться снова, долг вырастет.
- Вероятность достижения цели "Машина" к сроку: **60%** (нужно откладывать на 20% больше).

---
💡 **Совет на будущее:**
- Попробуйте **увеличить доход** на 10 000 ₽/месяц — это позволит гасить долги быстрее и достичь цели с вероятностью **90%**.
- Рассмотрите **рефинансирование** кредитной карты под более низкий процент.
```

## **Где модель даёт заведомо плохой совет**
| Сценарий | Проблема | Последствия | Как исправить |

| **Налоги на инвестиции** | Не учитывает НДФЛ на доход от вкладов/облигаций. | Завышает доходность инвестиций на **13%**. | Добавить корректировку на налоги. |
| **Штрафы за досрочное погашение** | Не учитывает комиссии банков за досрочное погашение. | Может рекомендовать погашать долг, хотя это невыгодно. | Добавить проверку на наличие штрафов. |
| **Изменение ставок по кредитам** | Предполагает фиксированные ставки. | Если ставка по кредиту вырастет, модель не учтёт это. | Использовать максимальную возможную ставку. |
| **Ликвидность инвестиций** | Предполагает, что инвестиции можно продать сразу. | Если инвестиции неликвидны (например, недвижимость), может не хватить денег на обязательные платежи. | Разделить инвестиции на ликвидные и неликвидные. |
| **Психологические факторы** | Не учитывает эмоциональное состояние пользователя. | Пользователь может не следовать рекомендациям из-за стресса или привычек. | Добавить опрос о склонности к риску и финансовой дисциплине. |
| **Инфляция для краткосрочных целей** | Учитывает инфляцию только для целей со сроком >1 года. | Для целей со сроком 6–12 месяцев инфляция может не учитываться. | Учитывать инфляцию для всех целей со сроком >6 месяцев. |
| **Колебания курсов валют** | Не учитывает валютные риски (если доходы/расходы в разных валютах). | Может недооценивать риск потери стоимости. | Добавить конвертацию в базовую валюту (рубли). |
| **Изменение доходности инвестиций** | Предполагает фиксированную доходность. | Если доходность упадет, модель не скорректирует рекомендации. | Использовать консервативную оценку доходности. |

## **Что может навредить пользователю**
1. **Рекомендация погашать долги вместо пополнения резерва** при высоком риске потери дохода.
   - **Риск**: Если пользователь потеряет доход, у него не будет резерва для покрытия расходов.
   - **Защита**: В модели резерв имеет более высокий приоритет, чем погашение долгов.

2. **Рекомендация инвестировать в рискованные активы** без учёта склонности к риску.
   - **Риск**: Пользователь может потерять деньги.
   - **Защита**: Модель использует консервативную оценку доходности (10%) и учитывает склонность к риску.

3. **Неучёт штрафов за досрочное погашение**.
   - **Риск**: Пользователь заплатит комиссию, и погашение окажется невыгодным.
   - **Защита**: В реальном продукте нужно добавить проверку на наличие штрафов.

4. **Неучёт изменяющихся ставок по кредитам**.
   - **Риск**: Если ставка по кредиту вырастет, пользователь заплатит больше процентов.
   - **Защита**: Использовать максимальную возможную ставку из истории.

| **Стресс-тесты** | Экстремальные значения (например, доход = 0, долги = 1 000 000 ₽). | Ручная генерация. |

## **Метрики качества**
| Метрика | Формула | Целевое значение | Как измерять |
|---------|---------|------------------|--------------|
| **Финансовая устойчивость** | Доля месяцев без дефолта | **≥ 95%** | Симуляция на 60 месяцев. |
| **Экономия процентов** | **Σ(проценты без досрочного погашения) − Σ(проценты с погашением)** | **≥ 50% от суммы процентов без погашения** | Сравнение с базовым сценарием. |
| **Доля достигнутых целей** | **Количество достигнутых целей / общее количество целей** | **≥ 80%** | Симуляция на горизонте целей. |
| **Размер резервного фонда** | Средний размер резерва за 60 месяцев | **≥ R_min** | Симуляция. |
| **Время до достижения целей** | Среднее время до достижения каждой цели | **≤ запланированного срока** | Симуляция. |
| **Вероятность дефолта** | **P(дефолт в течение 60 месяцев)** | **≤ 5%** | Монте-Карло симуляция. |
| **Чистая стоимость** | **S + A − ∑bᵢ** | **Максимизация** | Сравнение с базовым сценарием. |

## **С чем сравнивать**
| Стратегия | Описание | Ожидаемый результат |
|-----------|----------|----------------------|
| **Базовый сценарий** | Только обязательные платежи, без досрочного погашения и накоплений. | Худший по всем метрикам. |
| **"Снежный ком"** | Погашение долгов с **наименьшим остатком** первым. | Хорош для психологии, но не оптимален по процентам. |
| **"Лавина"** | Погашение долгов с **наивысшей ставкой** первым. | Оптимален по процентам, но может быть медленнее по времени. |
| **Случайное распределение** | Случайное распределение свободных денег между долгами, целями, инвестициями. | Худший или средний по всем метрикам. |
| **Максимизация резерва** | Все деньги идут в резерв. | Хорош по устойчивости, но плох по достижению целей. |

## **Какой результат считать провалом**
| Критерии провала | Описание |
|------------------|----------|
| **Дефолт** | В течение 60 месяцев хотя бы раз **Fₜ + Rₜ < ∑pᵢ**. | Критический провал. |
| **Резерв ниже минимального** | **Rₜ < R_min** в течение **>3 месяцев подряд**. | Высокий риск. |
| **Большинство целей не достигнуто** | **< 50% целей** достигнуты к дедлайну. | Низкая эффективность. |
| **Чистая стоимость уменьшается** | **(Sₜ + Aₜ − ∑bᵢ) < (S₀ + A₀ − ∑bᵢ₀)** через 60 месяцев. | Неэффективное управление. |
| **Вероятность дефолта > 20%** | **P_default > 20%** на горизонте 60 месяцев. | Высокий риск. |

## **Топ-3 приоритета для второй версии**
1. **Прогнозирование доходов/расходов + стохастическое моделирование**
   - **Почему?** Это наиболее критичные улучшения, которые повысят **точность и полезность** рекомендаций.
   - **Ожидаемый эффект**: Повышение вероятности достижения целей на **20–30%**, снижение риска дефолта на **10–15%**.

2. **Интеграция с банками**
   - **Почему?** Упростит использование и снизит порог входа для пользователей.
   - **Ожидаемый эффект**: Увеличение количества пользователей на **30–50%**.

3. **Учёт налогов и комиссий**
   - **Почему?** Повысит **точность** рекомендаций и доверие пользователей.
   - **Ожидаемый эффект**: Снижение ошибок в расчётах на **1–2%**.
