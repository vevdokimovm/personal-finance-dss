# Независимый статистический аудит датасета FINPILOT v2

**Эксперт:** независимый специалист по личным финансам (РФ, 2026), слепое ревью.
**Вход:** `expert_portraits_v2_part1..4.jsonl.gz` — 12 000 портретов, 4 шарда.
**Дата среза:** 2026-07-11. **Скрипт:** `dataset_stats.py` (все числа воспроизводимы).
**Сверка JSONL ↔ .md-проекция:** совпадение на SP-00000, SP-05000, SP-11999 (доход,
расход, подушка, ставки, кредиты, цели — идентичны).

Главный вывод одной строкой: **реалистичное ядро датасета адекватно (медианы дохода
71.7k, расходов 41.3k, подушки 69.9k ₽ выглядят как живая популяция), но граничные и
экстремальные страты влиты в общий пул без единого разделяющего флага, а метка `kind`
из v2 удалена — из-за этого все популяционные агрегаты (среднее, σ, корреляции,
KS-калибровка) непригодны, а часть приёмочных тестов генератора из методички §3
проваливается.**

Spearman income~{expense, bliq, debtpmt, goalgap} = **0.68 / 0.38 / 0.26 / 0.042**.

**Диагноз:** income~expense = 0.70 — здоровая, реалистичная связь (богаче → тратит больше).

`target ~ k × годовой доход`. bliq~debt_pmt ≈ 0 — подушка и долговая нагрузка независимы
(допустимо).

## (е) Валидация меток типов

**Поле `kind` в v2 ОТСУТСТВУЕТ** (проверено программно: `kind` нет ни в одной записи).
Пункт чек-листа (е) в полном объёме **невыполним** — не по чему валидировать медианы по типам.
Это регресс относительно v1, где метки были. Дополнительно: методичка §4 требует первой строкой
JSONL `dataset_version`, seed и конфиг слоёв — **ничего этого в файлах нет**, версии не привязать.

## (ж) Пронумерованные проблемы (P1…P9) — каждая с числом и последствием

**P1 — Граничные/экстремальные страты влиты в общий пул без флага.**
242 портрета имеют поле ≥ 1e10 (доход до 13.2 млрд ₽/мес), 280 ≥ 1e9, 285 ≥ 1e8.
Число: mean income / median = 822×.
*Последствие:* любой популяционный агрегат (среднее, σ, корреляционная матрица, KS) на цельном
файле — мусор. Приёмочные тесты §3 (#1–#3, #6) невозможно посчитать без предварительной
фильтрации, а **фильтровать не по чему** (нет `kind`/флага). Это критический блокер для §3.

**P2 — Метки `kind` удалены; нет версионирования датасета.**
Число: 0 записей с `kind`; 0 строк с `dataset_version`.
*Последствие:* невыполним пункт (е); нельзя стратифицировать результаты модели по типам;
ревью разных экспертов невозможно привязать к версии (нарушение §4, §6 методички).

**P3 — `r_bench` дискретизирован до 5 значений и не зависит ни от чего.**
Число: distinct(r_bench) = 5; равномерен по всем risk_tolerance.
*Последствие:* ось `spread = ставка_кредита − r_bench` — первичная ветвящая переменная —
квантована в 5 грубых уровней; граничный предикат «ставка == бенчмарк точно» (слой C)
органически почти недостижим. Логика модели у границы решения недотестирована.

**P4 — Цели декоррелированы с доходом.**
Число: corr(goal_gap, income) = 0.042 (Pearson и Spearman).
*Последствие:* низкодоходные портреты с многомиллионными целями и наоборот; популяционная
метрика «% достижимых целей» не отражает реальную популяцию. Нарушение дизайна генератора
(методичка §1: `target ~ k × годовой доход`).

**P5 — Маргинал дохода не проходит тест логнормальности.**
Число: KS D = 0.2014, p ≈ 0 (ядро <1e8).
*Последствие:* приёмочный тест §3 #1 проваливается; форма дохода отклоняется от целевой
(Росстат-логнормаль). Калибровка маргиналов требует доработки.

**P6 — Слой validity/adversarial (D) отсутствует.**
Число: отрицательных значений 0, NaN 0, дублей id 0, непарсящихся дат 0.
*Последствие:* нельзя протестировать поведение модели на «мусоре» (отклоняет / флажит /
не падает) — целое измерение робастности из §1-D непокрыто.

**P7 — Экстремальные хвосты для теста масштабируемости, но без изоляции.**
Число: income max 1.32e10, goal_gap max 1.70e11, bliq max 4.19e10; goal_gap min = −95 381
(нетто-перефинансирование).
*Последствие:* эти портреты полезны для метаморфической M5 (×k → ×k) и проверки
переполнения, но, влитые без флага, разрушают статистику (см. P1). Нужна изоляция/тег.

**P8 — Доля дефицита завышена инъекциями.**
Число: FCF<0 = 18.8%; неоплатных портретов (платёж > доход) 152; нулевой доход 286;
interest-only/вечных кредитов 25.
*Последствие:* распределение статусов смещено к `deficit` относительно реальной популяции —
дефицит-страта раздута влитыми граничными кейсами (нулевой доход + неоплатные долги).

**P9 — Спайк числа целей на фиксированной 8.**
Число: n_goal ∈ {0,1,2,3,4} органически, затем 0 на 5/6/7 и ровно 286 на 8.
*Последствие:* ось «число целей» имеет провал и детектируемый искусственный спайк; реальная
популяция заполнила бы 5–7.

## (з) Рекомендации для следующей итерации генератора

1. **Вернуть traceability:** первой строкой JSONL — `dataset_version`, `seed`, конфиг слоёв,
   корреляционная матрица (методичка §4); добавить в каждую запись поле `kind`/`layer`
   (`population` / `boundary_C` / `adversarial_D` / `metamorphic_E`). Без этого §3 и §6 неисполнимы.
2. **Изолировать экстрим:** боундари и 10⁹–10¹⁰-кейсы вынести в помеченные страты, чтобы
   популяционные агрегаты считались только на слое `population`. Сейчас mean/σ/корр непригодны.
3. **`r_bench` непрерывным:** тянуть из узкой полосы вокруг ключевой ставки (напр. нормаль/
   логнормаль ~15% ± неск. п.п.) + добавить в слой C явные кейсы «ставка == бенчмарк точно».
4. **Связать цели с доходом:** `target ~ k × годовой доход`, k∈[0.2…5], через ту же копулу —
   вернуть corr(goal, income) на реалистичный положительный уровень.
5. **Перекалибровать маргинал дохода** под логнормаль (fit по Росстату), гейт KS p>0.05 в CI.
6. **Добавить слой D** (битые даты, отрицательные суммы, NaN, дубли id, пустые массивы, лишние
   поля) ~5% — иначе reject-garbage не тестируется.
7. **Заполнить n_goal 5–7 органически** вместо спайка на 8.
8. **Включить приёмочные гейты §3** (KS маргиналов, допуск корреляций ±0.05, 100% аннуитетной
   согласованности вне C/D, отчёт pairwise-покрытия) — часть сейчас красная.
