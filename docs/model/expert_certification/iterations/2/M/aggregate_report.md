# Методология независимого эксперта — раунд 2 (12 000 портретов)

**Дата среза:** 2026-07-11. Все константы зафиксированы ДО обработки данных.
Правила детерминированные, одинаковые для всех портретов, обработка программная и полная.

## 1. Диагностика

- **Свободный поток (FCF)** = `income_total − expense_total − Σ monthly_payment`.
  FCF ≥ 0 → `status=ok`; FCF < 0 → `status=deficit`.
- **Обязательный месячный расход (burn)** = `expense_total + Σ monthly_payment`.
- **ПДН** = `Σ monthly_payment / income_total` (при доходе 0 и платежах > 0 — ∞).
  Пороги: ≤ 0.30 комфортная; 0.30–0.50 повышенная; > 0.50 критическая.
- **Запас ликвидности** = `bliq / burn`, мес. При burn = 0 — не определён (∞).

## 2. Целевая подушка (резерв)

`target_reserve = k(risk) × burn`, k = **{1: 6, 2: 5, 3: 4, 4: 3, 5: 3}** месяцев.
Операционный минимум — 3 мес, критический уровень — 1 мес.
**Допущение** (граничный случай): при burn = 0 берём прокси
`burn* = 0.5 × income_total` (будущие нормальные траты ~50% дохода); при
доходе 0 и burn = 0 подушка не нормируется.

## 3. Классификация кредитов (относительно r_bench)

- **Дорогой:** `interest_rate ≥ r_bench + 0.02` (спред ≥ 2 п.п.) → досрочное
  гашение оправдано; порядок — **avalanche** (по убыванию ставки).
- **Прочие** (`rate < r_bench + 0.02`): досрочно не гасим — деньги в безриске
  работают не хуже, ликвидность дороже. Единый порог для всех риск-профилей.

## 4. Каскад распределения месячного FCF (FCF > 0)

Обозначения: L = запас ликвидности (мес), E = есть дорогой долг.

| Фаза | Условие | Распределение FCF |
|---|---|---|
| A | L < 1 | E: резерв 70% / долг 30%. Не E: резерв 100% |
| B | 1 ≤ L < 3 | E: долг 60% / резерв 40%. Не E: резерв 100% |
| C | L ≥ 3, но bliq < target_reserve | E: долг 70% / резерв 30%. Не E: резерв 40%, остаток 60% → цели/инвестиции (п. 5) |
| D | bliq ≥ target_reserve | E: долг 80%, остаток 20% → цели/инвестиции. Не E: всё → цели/инвестиции |

Месячный взнос в досрочное гашение ограничен суммой остатков дорогих долгов;
переполнение уходит в резерв (фазы A–C) или в цели/инвестиции (фаза D).

## 5. Цели и инвестиции

- Потребность цели = `max(0, target − current)`; перефинансированные — 0.
- Цели с дедлайном: требуемый взнос = `потребность / max(1, месяцев до дедлайна)`
  (просроченный дедлайн → 1 мес, финансировать немедленно). Финансируются
  первыми, суммарно не выше доступного остатка.
- Остаток после дедлайновых целей: при наличии бессрочных целей с потребностью —
  50% в цели / 50% в инвестиции; иначе 100% в инвестиции.
- Бакет `inv` включает и консервативные инструменты (депозиты/ОФЗ) для
  риск-профилей 1–2 — инструментный состав на суммы бакетов не влияет.

## 6. Разовые ходы из накоплений (lump)

`deployable = max(0, bliq − target_reserve)` — излишек сверх целевой подушки.

- **status=ok:** развернуть весь deployable: (1) полное/частичное закрытие
  дорогих долгов по убыванию ставки → (2) разовое закрытие недофинансированных
  целей с дедлайном ≤ 12 мес → (3) размещение остатка в инструменты по
  риск-профилю. `lump = deployable`.
- **status=deficit:** `lump = min(deployable, Σ остатков долгов)` — гашение
  долгов по убыванию ставки ради снижения обязательных платежей. Без долгов —
  lump = 0: излишек остаётся взлётной полосой, крупные разовые размещения в
  дефиците не рекомендуются.

## 7. Выходные величины (CSV)

- Все суммы — целые ₽ (пол); контроль: `res + debt + goal + inv ≤ max(0, FCF)`.
- `dom` = крупнейший из {debt, reserve, goals+ = goal + inv}; тай-брейк
  debt > reserve > goals+; `none` при FCF ≤ 0 или пустых бакетах.
- Если FCF > 0, но все бакеты округлились в 0 — остаток кладётся в резерв.

## 8. Контроли

1. Ровно 12 000 строк данных, все id из входа, шапка по спецификации.
2. Число нарушений баланса (`res+debt+goal+inv > FCF`) — обязано быть 0.
3. `lump ≤ bliq` для каждой записи.
4. Сверка JSONL ↔ md-карточки минимум на 3 случайных портретах.
