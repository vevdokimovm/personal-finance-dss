# Метаданные прогона — экспертная оценка портретов v3

**Модель и инструменты.** Claude Fable 5 (Anthropic), чат-интерфейс claude.ai с
исполнением кода (bash + Python 3.12 в песочнице). Решения по каждой записи
вычислены детерминированным Python-скриптом (`expert_run.py`), реализующим
экспертные правила из `expert_methodology_v3.md`; правила зафиксированы автором
до обработки массива (до фиксации просмотрены только схема брифа и первые 2–3
записи каждого файла для проверки формата). Ручной разбор записей не применялся —
при 12 000 строк это единственный воспроизводимый способ; сами правила являются
профессиональным суждением, скрипт — лишь их исполнитель.

**Дата и длительность.** Обработка 2026-07-17. Машинное время основного прогона —
менее 2 секунд; полный цикл (фиксация методологии, прогон, верификация,
статистический аудит, оформление документов) — порядка 15 минут одной сессией.

**Полнота.** Обработаны все 12 000 входных строк данных (4 части × 3000; 4 meta-строки
пропущены и строк ответа не порождали). В `expert_answers_v3.csv` — ровно 12 000
строк данных + шапка, по одной строке на входную строку в порядке входа, включая
оба ответа на каждый из 50 дублей `id`.

**Итоги классификации.** `ok` — 7161, `deficit` — 4239, `invalid` — 600 (5.0 %).
`dom`: debt — 3045, reserve — 2249, goals+ — 1793, none — 4913 (дефицит, нулевой
поток и invalid). Разовые ходы (`lump` > 0) предложены в 6458 строках.

**Верификация.** Автоматические проверки после прогона: количество строк;
`res+debt+goal+inv ≤ ⌊F⌋` для каждой ok-записи; нулевые распределения при
deficit/invalid; неотрицательность и целочисленность всех сумм; допустимые значения
`status`/`dom`; пересчёт `dom` из бакетов; покрытие идентификаторов
(50 дублей = 50 пар «валидная + дефектная», 50 id диапазона отсутствуют во входе).
Все проверки пройдены.

**Чистота прогона.** Диалог инициирован только брифом и файлами данных; проектная
документация, память и описания каких-либо алгоритмов при принятии решений не
использовались и не читались. Прогон выполнен в пользовательском чат-окружении;
единственный источник правил — настоящая методология, зафиксированная заранее.

## Дополнение от 2026-07-17 (после сдачи основного пакета)

После сдачи получена методичка координатора (`testset_methodology_and_prompt.md`).
По её обязательному чек-листу (§5 п. 6) ревью датасета доведено до редакции 2:
моменты и σ всех полей, полные матрицы Пирсона и Спирмена, KS-тест лог-нормальности
дохода, бакеты ПДН/ликвидности/горизонтов/готовности, реконструкция пяти слоёв
генерации, пронумерованные проблемы P1–P9 с доказательствами. Ответы
(`expert_answers_v3.csv`) и методология эксперта не менялись: правила были
зафиксированы до обработки, методичка на решения не влияла и во время прогона
и не была доступна.

Дополнительные контроли по §5: сверка JSONL с карточками на 3 случайных портретах
(SP3-05578, SP3-02592, SP3-06809) — полное совпадение по риск-профилю, r_bench,
доходу, расходам, накоплениям, числу кредитов и целей. Контроль сохранения сумм —
0 нарушений: для каждой ok-записи сумма месячных бакетов равна ⌊F⌋ (при F < 1 ₽ —
нули, 74 записи), lump-действия не превышают развёртываемый излишек, при
deficit/invalid все бакеты нулевые.

Скрипты приложены as-run: `expert_run.py` (движок решений), `dataset_stats_v3.py`
(статистика ревью). Движок сдан в исходном процедурном виде — без пост-фактум
рефакторинга под ООП-требование методички: приложенный код обязан побайтно
соответствовать тому, что породило CSV; классовая структура будет заложена в
движок следующей итерации. Выходной контракт файлов следует брифу v3 (строгий CSV
`id,status,dom,res,debt,goal,inv,lump`), который для раунда 3 замещает шаблонный
контракт §5 (recommendations.jsonl / summary.csv / aggregate_report.md).
