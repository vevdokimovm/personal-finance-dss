# Методология независимой экспертной оценки — портреты v3

**Дата фиксации: 2026-07-17, до обработки массива.** До фиксации я видел только схему
из брифа и первые 2–3 записи каждого файла (проверка формата); агрегаты по датасету

**Роль:** независимый консультант по личным финансам, практика в РФ, июль 2026.
Решения — как для живого клиента «по телефону»: консервативно при неопределённости,
без до-придумывания данных. Дата среза для всех дедлайнов: **2026-07-16**.

## 1. Базовые величины

- Обязательные месячные расходы: `needs = expense_total + Σ monthly_payment`.
- Свободный поток: `F = income_total − expense_total − Σ monthly_payment`.
- Статус: `ok` при `F ≥ 0`, `deficit` при `F < 0` — строго по исходным данным записи.

## 2. Константы (зафиксированы заранее)

| Параметр | Значение | Обоснование |
|---|---|---|
| Целевая подушка, мес. `needs` | риск 1→6, 2→5, 3→4, 4→3, 5→3 | классическая вилка 3–6 мес., консервативнее — больше ликвидности |
| Неприкосновенный минимум ликвидности | 1 × `needs` | ниже месячного запаса не опускаемся даже ради долгов |
| «Дешёвый» долг | ставка ≤ `r_bench` + 2 п.п. | арбитраж: безрисковое размещение выгоднее досрочного гашения; не гасим досрочно вообще (в т.ч. беспроцентные рассрочки и льготную ипотеку) |
| «Дорогой» долг | `r_bench` + 2 п.п. < ставка < `r_bench` + 10 п.п. | гасим после минимального буфера; разовые ходы — только сверх **целевой** подушки |
| «Токсичный» долг | ставка ≥ `r_bench` + 10 п.п. | кредитки/микрозаймы; гасим агрессивно, разово — всё сверх **1 мес.** ликвидности |
| Порядок гашения | по убыванию ставки (avalanche) | математически минимизирует переплату |
| «Горящая» цель | дедлайн ≤ 3 мес. или уже просрочен | кандидат на разовое закрытие из излишка |
| Разовое размещение излишка | излишек сверх целевой подушки, если ≥ 50 000 ₽ | «деньги должны работать»; мелочь спецходом не считаем |
| Буфер при разовых закрытиях долгов в дефиците | 2 × `needs` (токсичные — 1 × `needs`) | в дефиците ликвидность ценнее |
| Доля потока на цели до заполнения подушки | ≤ 40 % | подушка в приоритете, но горящие дедлайны не бросаем |
| Сплит «резерв/долг» при токсичном долге и подушке < 1 мес. | 30 / 70 | минимальный буфер строим параллельно с атакой на долг |
| Сплит «резерв/долг» при дорогом долге и подушке ниже цели | 50 / 50 | баланс ликвидности и гарантированной «доходности» гашения |

## 3. Распределение месячного потока (status = ok, F > 0) — каскад

План строится по состоянию **после разовых ходов** (см. §4): остатки долгов уменьшены,
платежи полностью закрытых кредитов освобождены, «горящие» цели пополнены, подушка
уменьшена на сумму разовых ходов. Суммарно `res+debt+goal+inv` не превышает
исходный `F`.

1. **Токсичные долги.** Если ликвидность < 1 мес. — 30 % потока в резерв (до 1 мес.),
   остальное в досрочное гашение токсичных (по убыванию ставки), с ограничением
   суммой остатков. Если ликвидность ≥ 1 мес. — весь поток в гашение.
2. **Дорогие долги** (токсичных не осталось). Пока подушка ниже целевой — 50/50
   резерв/гашение; подушка на цели — 100 % в гашение. Ограничение — сумма остатков.
3. **Подушка до целевой** (плохих долгов нет). До заполнения подушки цели с
   дедлайнами получают не более 40 % потока (в размере расчётной месячной
   потребности), остальное — в резерв до целевого уровня.
4. **Цели с дедлайнами.** Месячная потребность цели =
   `(target − current) / max(1, месяцев до дедлайна)`; месяц = 30.44 дня, округление
   вверх; просроченный или сегодняшний дедлайн → «нужно сейчас» (вся нехватка).
5. **Инвестиции** — весь остаток потока. Бессрочные цели финансируются через этот
   бакет (инструменты — по риск-профилю клиента; для консервативных это
   депозиты/ОФЗ, это тоже «инвестиции»).

При `F = 0`: распределений нет, `dom = none`.

## 4. Разовые ходы из накоплений (`lump`)

**Для ok:** последовательно, без двойного счёта источника:
1. Токсичные долги — из средств сверх 1 × `needs`, по убыванию ставки, частичное
   гашение допустимо.
2. Дорогие долги — из средств сверх **целевой** подушки, по убыванию ставки.
3. «Горящие» цели (дедлайн ≤ 3 мес. или просрочен) — из средств сверх целевой
   подушки, по возрастанию дедлайна, до закрытия нехватки.
4. Размещение излишка: всё, что осталось сверх целевой подушки, если это ≥ 50 000 ₽
   (перевод из ликвидной «подушки» в целевой/инвестиционный капитал).

**Для deficit:** цель разовых ходов — снять процентное давление и вернуть поток к нулю:
1. Токсичные долги — из средств сверх 1 × `needs` (частично или полностью).
2. Пока поток остаётся отрицательным — **полные** закрытия оставшихся кредитов из
   средств сверх 2 × `needs`, в порядке максимального освобождаемого платежа на
   рубль остатка (`monthly_payment / amount`, по убыванию). Частичные гашения
   платёж не освобождают и дефицит не лечат.
3. Разовых ходов по целям и размещения излишка в дефиците не предлагаю —
   приоритет ликвидности.

Дешёвые долги (≤ `r_bench`+2 п.п.) досрочно не гасятся ни потоком, ни разово,
кроме полного закрытия в дефиците по правилу выше.

## 5. Критерий `invalid` (дефектная запись)

Запись помечается `invalid` (все суммы = 0, `dom = none`), если её нельзя однозначно
прочитать как валидные финансовые данные:

- строка не парсится как JSON-объект;
- отсутствует любое поле схемы: `id`, `income_total`, `expense_total`, `obligations`,
  `goals`, `bliq`, `r_bench`, `risk_tolerance`; внутри кредита — `name`, `amount`,
  `interest_rate`, `monthly_payment`; внутри цели — `name`, `target_amount`,
  `current_amount`, `deadline`;
- нарушен тип: строка/`null`/bool вместо числа, не-строка вместо `name`,
  не-список вместо `obligations`/`goals`, пустой или нестроковый `id`;
- нарушен знак: отрицательные доход/расход/подушка/остаток/ставка/платёж/суммы целей;
- `NaN`/`Infinity` в числовом поле;
- `deadline` — не `null` и не парсится как ISO-дата (включая несуществующие даты);
- `risk_tolerance` вне целых 1–5 (дробное значение — дефект; целозначный float
  вида `3.0` принимается);
- `interest_rate` > 3.0 (300 % годовых): выше законодательного потолка МФО (~292 %),
  однозначно не читается (вероятна путаница «проценты vs доля»).

**НЕ дефект:** пограничные, но читаемые значения — очень большие суммы, ставка 59 %,
дедлайн в прошлом, нулевой доход, `target_amount = 0`, платёж 0 при остатке > 0.
**Дубли `id` — не дефект:** каждая строка оценивается самостоятельно, ответ — на каждую.
Лишние поля (например, служебные `id` внутри кредитов/целей) игнорируются.

## 6. Формат и технические договорённости

- Ровно одна строка ответа на каждую входную строку данных, в порядке входа;
  meta-строки (`"__meta__": true`) пропускаются и строк ответа не порождают.
- Все суммы — целые рубли (усечение вниз; копеечный остаток от округления
  докладывается в крупнейший бакет, чтобы не нарушить `Σ ≤ F`).
- При дефиците `res = debt = goal = inv = 0` (распределять нечего), `lump` — по §4.
- `dom` = крупнейший из `debt` / `reserve` / `goals+` (= `goal` + `inv`);
  при равенстве приоритет `debt > reserve > goals+`; `none` — при нулевых бакетах,
  дефиците и `invalid`.
- Для `invalid`-строк в колонке `id` возвращается исходный идентификатор «как есть»,
  если он читается; иначе — пустое значение.
