# Ревью датасета — expert_portraits_v3 · редакция 2 (по чек-листу методички, §5 п. 6)

Редакция 2 заменяет первичное ревью: после сдачи основного пакета получена методичка
координатора, ревью доведено до её обязательного чек-листа. Ответы
(`expert_answers_v3.csv`) и методология эксперта не менялись. Все числа посчитаны
программно (`dataset_stats_v3.py`, приложен). База: 12 000 строк данных, из них
11 400 валидных и 600 дефектных (5.0 %); статистики — по валидным, если не сказано иное.

**Резюме.** Пятислойная архитектура методички в v3 реально реализована: слой D — ровно
5.00 %, слой E реконструирован полностью (все 300 метаморфических пар найдены и
верифицированы), каталог C на месте круглыми тиражами. Но слои никак не помечены —
`kind`/`index`/`l_min` в данных отсутствуют, и это порождает большинство проблем ниже.
Главная дыра реалистичности — тип кредита не несёт информации; главный статистический
дефект — доход не лог-нормален, а Пирсон вырожден каталожными экстремумами.

## (в) Формы распределений

Асимметрия и эксцесс — в таблице (а). Проверка лог-нормальности дохода (KS,
параметры оценены по выборке — вариант Лиллиефорса, анти-консервативен, но величина D
снимает сомнения): полный сет D = 0.0999, p ≈ 10⁻⁹⁸; после отсечения хвоста до p99
D = 0.0552, p ≈ 5·10⁻³⁰. **Лог-нормальность отвергается даже без хвоста.** σ_log = 1.04
(трим) против типичных для росстатовских региональных распределений 0.6–0.8 —
дисперсия завышена смесью слоёв. Следствие: приёмочный гейт §3 п. 1 методички
(KS p > 0.05) на выпущенном сете не проходит; проверить его «только для слоя A»
потребитель не может — метки слоёв отсутствуют (P1).

## (е) Валидация меток типов → реконструкция слоёв

Полей `kind`, `index`, `l_min` и обёртки `engine` в v3 нет (0 вхождений на 12 000
строк) — прямой дрейф от входной схемы §5. Meta-строка содержит только
`dataset_version`, `part`, `rows`, `frozen_today`; seed виден лишь в имени файла
карточек, конфиг слоёв и целевая корреляционная матрица отсутствуют — §4 выполнен
частично. Валидация меток невозможна, поэтому слои реконструированы эмпирически:

- **Слой D:** 600 invalid = ровно 5.00 %. ✓
- **Слой E:** реконструирован полностью, по 60 пар каждого типа (300 пар = 600 записей
  = 5.0 % ✓): M1 — доход ×1.0100 при побайтно идентичных остальных полях
  (верифицировано 60/60); M2 — ставка одного кредита +1.00 п.п. (медиана дельты
  0.0100; пример SP3-00054 ↔ SP3-00090); M3 — сдвиг дедлайна одной цели (пример
  SP3-00103 ↔ SP3-00142); M4 — накопления ×1.01; M5 — все денежные поля ×k
  (выборочно 5/5 — точное масштабирование). Пары никак не помечены и восстановимы
  только полным перебором коллизий.
- **Слой C:** каталожные тиражи круглыми числами — нулевой доход 120; нулевые расходы
  100; просроченные дедлайны 160 целей; target == current 80; перефинансированные 80;
  ставка == бенчмарку с точностью до бита 105; interest-only (платёж ≤ месячному
  проценту) 109; записи с суммами ≥10⁸ — ровно 100.
- **Слои A и B** статистически неотделимы друг от друга и от хвостов C.

## (ж) Проблемы P1–P9 (числовое доказательство → последствие для тестирования)

**P1. Слои не атрибутируемы.** `kind`/`index`/`l_min` — 0 вхождений; meta без seed и
конфига. → Приёмочные гейты §3 непроверяемы потребителем; популяционные статистики
загрязнены слоями B/C/E; метаморфические пары (готовый инструмент поиска багов без
разметки) нельзя использовать без реконструкции перебором.

**P2. Тип кредита не несёт информации.** Медианы ставок по всем шести типам —
24.1–24.7 %, диапазоны 1.5–59.9 % у каждого; медианные остатки ~239–270 т.р.,
расчётные сроки ~50 мес. — «Ипотека под 59.5 % на 50 мес. с остатком 261 т.р.»
статистически неотличима от кредитки. → Семантика льготной ипотеки, рассрочек и МФО
не тестируется; модель, читающая `name`, получает шум; avalanche-против-ипотеки —
ключевой продуктовый кейс — в сете не представлен.

**P3. Доход не лог-нормален.** D = 0.0999 (полный) / 0.0552 (≤p99), p ≈ 0;
σ_log = 1.04 после трима. → Гейт §3 п. 1 не пройден; «реалистичная популяция» слоя A
(40 %) не подтверждается: дефицит у 37.2 % сета против типичных 10–15 % в клиентской
популяции.

**P4. Пирсон вырожден.** inc↔gsum = 1.000; источник — 100 записей слоя C с полями
≥10⁸. → Гейт §3 п. 2 (допуск ±0.05) бессмыслен на смеси; контроль корреляций возможен
только послойно (снова упирается в P1).

**P5. Нижняя граница k-масштаба целей нарушена.** target/(12·доход): max = 4.995 и
доля >5 равна 0 % — верхняя граница k ≤ 5 выдержана идеально; но 51.3 % целей ниже
k = 0.2 (медиана 0.19) против заявленного k ∈ [0.2…5]. → Генератор расходится со
спекой §1.A.3; эмпирика при этом реалистичнее спеки (мелкие цели «Техника» за 25 т.р. —
норма жизни) — править стоит спеку, до [0.02…5].

**P6. Сроки аннуитета вне [6, 360].** 0.16 % кредитов < 6 мес. (min 5.4) и 0.15 % >
360 мес. (max 1493); interest-only — 109 шт. → Нарушение инварианта §1.A.2 вне
каталога C; из-за P1 намеренность неотличима от бага генератора.

**P7. Дубли id только «валидная + дефектная».** 50 пар: 31 ok+invalid,
19 deficit+invalid; при этом 50 id диапазона вытеснены и не встречаются вовсе. →
Конфликт двух валидных версий одного id (реальный сценарий склейки данных) не
тестируется; в покрытии id — дыры.

**P8. Дефекты круглыми тиражами.** 2×100 + 8×50 ровно. → Предсказуемость: квоты
дефектов реконструируются за один прогон, тестируемую модель можно подгонять под
известную структуру мусора.

**P9. Мощность тонких страт ниже собственного порога методички.** §2 требует ~385
наблюдений на страту для ±5 %; каталожные тиражи C — 80–160, целей с дедлайном
≤3 мес. — 347. → Доли ошибок модели по этим стратам будут оценены грубее ±5 %;
полоса 4–12 мес. (пик конфликта «долг против цели») — лишь 9.4 % датированных целей.

## (з) Рекомендации следующей итерации генератора

1. Вернуть в схему `kind`/`index`/`l_min` (или хотя бы `kind`), в meta — seed, конфиг
   слоёв и целевую корреляционную матрицу (§4). Это разблокирует P1, P3, P4, P6 разом.
2. Публиковать рядом с датасетом результаты приёмочных гейтов §3, посчитанных
   послойно, — KS маргиналов, корреляции, pairwise-покрытие.
3. Тип-зависимые параметры кредитов в слое A: ипотека 6–19 %, остаток 1–15 млн,
   срок 120–360 мес.; карта 25–45 %; рассрочка 0–5 %; микрозайм 50–292 % с малыми
   суммами и короткими сроками.
4. Калибровать σ лог-дохода слоя A по целевому распределению (0.6–0.8 против
   текущего 1.04 после трима).
5. Привести спеку k-масштаба целей к факту: [0.02…5] — либо ввести enforcement
   нижней границы 0.2.
6. Дубли valid+valid с конфликтующими полями; рандомизировать объёмы дефектов и
   расширить их на `bliq`, `r_bench`, `risk_tolerance`, `target_amount`, вложенные null.
7. Дотянуть тонкие страты (каталог C, дедлайны ≤12 мес.) до ≥385 наблюдений — по
   собственному power-порогу §2.
8. Помечать метаморфические пары (`pair_of: <id>`, тип M1–M5) — сейчас готовый
   E-слой практически недоступен потребителю без переборной реконструкции.

**Сильные стороны итерации.** Формат и meta стабильны; карточки побайтно согласованы
с JSONL (случайная сверка 3/3 — полное совпадение по всем полям); слой E исполнен
образцово (дельты ровно ×1.01 и +1.00 п.п.); каталог C богат и разнообразен;
аннуитетная согласованность 99.4 %; r_bench непрерывный на сетке 1 б.п.; хвост
ПДН>80 % удержан в «единицах процентов»; риск-профиль равномерен и независим от
денежных полей — чистое покрытие сетки сценариев.
