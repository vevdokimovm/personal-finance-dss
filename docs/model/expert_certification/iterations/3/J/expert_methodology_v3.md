# Методология независимой экспертной оценки — раунд 3 (12 000 портретов)

> Роль: независимый эксперт по личным финансам, практика РФ, июль 2026.
> Все правила и константы этого документа зафиксированы ДО обработки данных.
> Дата среза для всех расчётов дедлайнов: **2026-07-16**.

## 1. Базовые определения

- **Обязательный месячный отток (MO)** = `expense_total + Σ monthly_payment`.
- **Свободный месячный поток (F)** = `income_total − expense_total − Σ monthly_payment`.
- **Статус**: `ok` при F ≥ 0; `deficit` при F < 0; `invalid` — дефектная запись.
- Все распределения — целые рубли; `res + debt + goal + inv ≤ F` (для `ok`).

## 2. Критерий `invalid` (дефектная запись)

Запись дефектна, если её нельзя однозначно прочитать как валидные финансовые
данные. Конкретно — при любом из условий:

1. Строка не парсится как JSON-объект.
2. Отсутствует обязательное поле: `id`, `income_total`, `expense_total`,
   `obligations`, `goals`, `bliq`, `r_bench`, `risk_tolerance`.
3. Числовое поле имеет неверный тип: `null`, строка (в т.ч. «числа словами»),
   булево, NaN/Infinity. Касается: `income_total`, `expense_total`, `bliq`,
   `r_bench`, `risk_tolerance`, а внутри массивов — `amount`, `interest_rate`,
   `monthly_payment`, `target_amount`, `current_amount`.
4. Отрицательное значение любого денежного поля или ставки.
5. `risk_tolerance` вне множества {1,2,3,4,5} (принимаю целые и целозначные
   float: 3.0 ≡ 3).
6. Непарсящийся `deadline` (не null и не корректная ISO-дата; «2026-02-30»,
   «2026-13-45» — дефект). `null` = бессрочная цель, валидно.
7. Ставка (`interest_rate` или `r_bench`) > 3.0 (т.е. >300% годовых): выше
   законодательного потолка МФО с запасом; почти наверняка «проценты вместо
   доли» (напр. 12.0 вместо 0.12) — прочтение неоднозначно ⇒ дефект.
   Ставки в диапазоне 0…3.0 (включая 0% рассрочки и 59% годовых) — НЕ дефект.
8. `obligations` / `goals` не являются списками, либо элемент списка — не объект.

Что дефектом НЕ является (оценивается по существу): очень большие/малые суммы,
нулевой доход/расход, дедлайн в прошлом, `current_amount > target_amount`,
дубли `id` (обе строки оцениваются независимо, каждая по своему содержимому),
отсутствие/нечисловой `name` у кредита или цели (косметика, финансово не влияет).

Дефектную запись не чиню и не додумываю: `status=invalid`, `dom=none`, все суммы 0.

## 3. Константы советника

| Параметр | Значение | Обоснование |
|---|---|---|
| Целевая подушка (мес. × MO) | риск 1→6; 2→5; 3→4; 4→3; 5→3 | консервативным — больший запас ликвидности |
| Аварийный минимум подушки | 1 × MO | месяц обязательных платежей — неприкосновенный порог |
| «Дорогой» долг (гасить досрочно) | ставка ≥ r_bench + 1.5 п.п. | досрочное погашение = гарантированная доходность выше безрисковой |
| «Токсичный» долг | ставка ≥ 30% годовых | кредитки/МФО-уровень; приоритет над всем, кроме аварийного минимума |
| «Дешёвый» долг (НЕ гасить досрочно) | ставка < r_bench + 1.5 п.п. | арбитраж: деньги на депозите под r_bench работают лучше; льготную ипотеку не гасим |
| Доля инвестиций в «свободном» ярусе | риск 1→10%; 2→25%; 3→40%; 4→60%; 5→75% | аппетит к риску управляет долей рынка vs целей |
| Порог разового размещения излишка | излишек ≥ max(50 000 ₽, 0.2×MO) | мелкие остатки не гоняем — операционный шум |

## 4. Ежемесячное распределение F (для `ok`, F > 0)

Состояние подушки (после разовых ходов, см. §5): S0 — `bliq < 1×MO`;
S1 — `1×MO ≤ bliq < цель`; S2 — `bliq ≥ цель`. Доли от F:

| Состояние | Есть токсичный долг | Есть дорогой (не токс.) | Долгов дорогих нет |
|---|---|---|---|
| S0 (нет минимума) | резерв 50% / долг 50% | резерв 70% / долг 30% | резерв 100% |
| S1 (копим до цели) | долг 60% / резерв 30% / цели-ярус 10% | долг 40% / резерв 40% / цели-ярус 20% | резерв 50% / цели-ярус 50% |
| S2 (подушка полна) | долг 80% / цели-ярус 20% | долг 60% / цели-ярус 40% | цели-ярус 100% |

Досрочные платежи по долгам направляются только на «дорогие» долги
(ставка ≥ r_bench + 1.5 п.п.); дешёвые долги досрочно не гасятся никогда.

**Цели-ярус** делится между `goal` и `inv`:
1. Считаю требуемый темп по срочным целям
   `P = Σ (target − current) / max(1, месяцев до дедлайна)` по всем активным
   целям с дедлайном (просроченный дедлайн ⇒ 1 месяц, «догоняем срочно»).
   Месяцы = ceil(дней / 30.4375).
2. `goal` получает min(ярус, P) — закрываем требуемый темп.
3. Остаток яруса: если есть активные бессрочные цели — делится
   `goal : inv = (1 − inv_share) : inv_share` по риск-профилю; иначе весь в `inv`.
4. Активная цель: `current < target` и не закрыта разовым ходом (§5).

Округление: доли вниз до рубля, остаток («пыль») — в крупнейший бакет,
так что Σ = F точно. При F = 0: все бакеты 0, `dom = none`.

## 5. Разовые ходы из накоплений (`lump`)

Для `ok`:
1. **Токсичные долги** — из средств выше аварийного минимума (bliq − 1×MO):
   гашу по убыванию ставки, допускается частичное погашение (любой рубль под
   30%+ — гарантированная доходность).
2. **Дорогие (не токсичные) долги** — только из излишка выше целевой подушки,
   только полное закрытие (снятие платёжной нагрузки), по убыванию ставки.
3. **Срочные цели** — из оставшегося излишка, полное разовое закрытие
   (ближайший дедлайн первым; просроченные — первыми). Бессрочные цели разово
   не закрываю (нет срочности — финансируются потоком).
4. **Размещение излишка** — остаток выше целевой подушки при
   излишке ≥ max(50 000 ₽, 0.2×MO) размещается разово (депозит/инвестиции
   по риск-профилю).

`lump` = сумма всех разовых ходов. Ежемесячное распределение (§4) считается
по состоянию ПОСЛЕ разовых ходов: закрытые долги/цели исключаются, `bliq`
уменьшается на потраченное, MO пересчитывается по выжившим платежам, — но
ограничение `res+debt+goal+inv ≤ F` держится по исходному F из данных.

Для `deficit`:
- Ежемесячные бакеты = 0, `dom = none` (по условию задания).
- Разовый ход: полное закрытие долгов из `bliq` по убыванию эффективности
  «платёж/остаток» (максимум снятия месячной нагрузки на рубль), если после
  закрытия остаётся ≥ 1 × `expense_total` ликвидности. Частичные погашения в
  дефиците не делаю: аннуитетный платёж они не снижают, а ликвидность — критична.
- Долгов нет или подушки не хватает — `lump = 0` (рекомендация «резать расходы /
  поднимать доход» в CSV невыразима).

## 6. `dom`

`dom` = крупнейший из {`debt`, `reserve` (=res), `goals+` (=goal+inv)}.
При равенстве — приоритет: debt → reserve → goals+. `none` — при нулевом F,
дефиците и invalid.

## 7. Прочее

- На каждую входную строку — ровно одна строка ответа, в порядке входа
  (метастроки частей пропускаются). Дубли `id` получают по своему ответу.
- Если `id` не извлекается из битой строки — подставляется `UNKNOWN`
  (записей терять нельзя).
- Просроченная цель — не дефект: трактуется как «нужно вчера» (горизонт 1 мес.).
- `current ≥ target` — цель достигнута, не финансируется.
- Кредит с `amount = 0` — закрыт: досрочно не гасится, но его `monthly_payment`
  (если указан) входит в MO по формуле задания.
