  детерминированный скрипт на Python 3 (только stdlib: `json`, `gzip`, `math`,
  `datetime`, `statistics`), изолированная среда, без доступа в сеть.
- **Дата обработки**: 2026-07-17. Длительность вычислительной части: **0.73 с**
  на все 12 000 записей; сессия целиком (методология, прогон, самопроверки,
  аудит датасета) — порядка нескольких минут.
- **Порядок работ**: методология и константы зафиксированы в
  `expert_methodology_v3.md` **до** запуска обработки; после прогона не менялись.
- **Полнота**: обработаны все 4 части, **12 000 / 12 000** строк данных
  (по 3000 в части), 4 служебные мета-строки пропущены по брифу. Подвыборок нет.
- **Способ обработки**: скрипт (парсинг → валидация → решение по каждой записи →
  CSV + статистика), а не вручную. Ручные выборочные проверки: полный пересчёт
  водопада для SP3-00001 (сошёлся до рубля), разбор дефектных записей
  (SP3-00071, SP3-00147), дублей (SP3-07266 — две строки, два ответа),

  (нарушений 0); на каждый дубль id выдано по ответу на каждую входную строку,
  порядок строк ответа = порядку входа.
- **Итоговые статусы**: `ok` — 7198, `deficit` — 4252, `invalid` — 550.
  Разовые ходы (`lump` > 0) предложены в 5616 строках.
