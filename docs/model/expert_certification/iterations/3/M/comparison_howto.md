# Как сравнить своё решение с эталоном эксперта (portraits v3)

## Зачем
Эталон (`expert_answers_v3.csv`) — независимые экспертные решения по всем 12 000
портретам. Чтобы оценить сравниваемое решение, оно прогоняется на **тех же**
входных файлах, экспортирует ответы в том же CSV-формате, и компаратор считает,
где решения совпадают, где расходятся и есть ли у кандидата внутренние
противоречия.

## Шаг 1. Экспорт CSV кандидата
Формат — идентичен эталону:

```
id,status,dom,res,debt,goal,inv,lump
```

Правила:
- одна строка ответа на каждую входную строку данных, **в порядке входа**
  (мета-строки `__meta__` не считаются); дубликаты id — обе строки;
- `status` ∈ {ok, deficit, invalid}; `dom` ∈ {debt, reserve, goals+, none};
- суммы — рубли/месяц (lump — разовая), целые числа, без разделителей;
- дефектная входная строка → `id,invalid,none,0,0,0,0,0`
  (id — как удалось извлечь, иначе пусто).

## Шаг 2. Запуск

```bash
python3 compare_answers.py \
  --portraits expert_portraits_v3_part1_jsonl.gz \
              expert_portraits_v3_part2_jsonl.gz \
              expert_portraits_v3_part3_jsonl.gz \
              expert_portraits_v3_part4_jsonl.gz \
  --reference expert_answers_v3.csv \
  --candidate candidate_answers.csv \
  --out cmp_out
```

Только Python 3 stdlib, ~2–3 секунды. Выравнивание строк — позиционное со
сверкой id; если порядок кандидата не совпал, включается запасной режим
join по id (с учётом дубликатов, по порядку вхождения) — режим печатается
в отчёте.

## Шаг 3. Чтение результатов (`cmp_out/`)
- `comparison_report.md` — главный отчёт:
  - **Вердикт** — четыре числа: совпадение `status`, совпадение `dom`,
    доля полностью точных строк (status+dom+все 5 сумм до ₽),
    число жёстких нарушений аудита;
  - матрицы ошибок `status` и `dom` — видно, *куда именно* уезжают решения
    (например, кандидат систематически ставит reserve там, где эксперт debt);
  - таблица сумм по колонкам res/debt/goal/inv/lump — MAE, медиана/p95/max |Δ|,
    суммарный сдвиг в ₽ (знак показывает систематическое смещение);
  - разрезы: риск-профиль, квинтили дохода, ПДН, токсичный долг, lump —
    локализуют, на каком классе портретов решения расходятся;
  - **аудит кандидата** (не зависит от эталона): отрицательные суммы,
    invalid-классификация, `res+debt+goal+inv ≤ FCF`, `lump ≤ bliq`,
    согласованность статуса со знаком FCF.
- `worst_mismatches.csv` — топ-200 худших строк для ручного разбора
  (сначала расхождения статуса, потом dom, потом по Σ|Δ|; с FCF/риском/ПДН).
- `comparison_metrics.json` — все числа машинно (для CI-гейта или графиков).

## Самопроверка инструмента

```bash
python3 compare_answers.py --portraits <4 файла> \
  --reference expert_answers_v3.csv --selftest --out demo_out
```

Делает два прогона: identity (эталон против себя — обязан дать 100%/0
расхождений) и возмущённый кандидат с точно посаженными правками
(37 флипов status, 61 dom, 200×res+123 ₽, 150×inv+777 ₽, 80×lump→0) —
компаратор обязан найти ровно их. Оба прогона заканчиваются assert'ами;
`PASS` в конце = инструменту можно верить. Демо-отчёт из второго прогона —
пример того, как выглядит выход (`comparison_report_DEMO.md`).

## Как трактовать расхождения
Расхождение ≠ ошибка кандидата. Три категории:
1. **Нарушения аудита** — дефект кандидата всегда (арифметика/инварианты).
2. **Систематические сдвиги** в матрицах и суммах — разница параметров или
   философии (например, другой порог токсичности долга или размер подушки);
   решается сознательно: принять или откалибровать.
3. **Точечные расхождения** в `worst_mismatches.csv` — кандидаты в баги,
   разбирать руками.
