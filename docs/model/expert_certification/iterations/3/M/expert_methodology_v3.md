# Методология независимого финансового эксперта — раунд 3

Зафиксирована **до** обработки файлов `expert_portraits_v3_part1..4.jsonl.gz`.
Дата фиксации: 2026-07-17. Дата среза для всех дедлайнов: **2026-07-16**.
Роль: независимый консультант по личным финансам, практикующий в России в 2026 г.
Принцип: сначала устойчивость (ликвидность), затем гарантированная «доходность»
(досрочное погашение дорогих долгов), затем цели и инвестиции. Недостающее
трактуется консервативно. Правила детерминированные: одинаковый вход → одинаковый ответ.

## 1. Критерий валидности записи (`invalid`)

Запись невалидна, если её нельзя однозначно прочитать как валидные финансовые данные:

- строка не парсится как JSON-объект;
- отсутствует любое поле схемы: `id`, `income_total`, `expense_total`, `obligations`,
  `goals`, `bliq`, `r_bench`, `risk_tolerance`; у кредита — `name`, `amount`,
  `interest_rate`, `monthly_payment`; у цели — `name`, `target_amount`,
  `current_amount`, `deadline`;
- нарушен тип: денежные поля и ставки не числа (строка, `null`, bool, NaN/Inf);
  `name` не строка; `obligations`/`goals` не списки; `risk_tolerance` не целое
  число 1–5 (целочисленный float, напр. `3.0`, принимается как 3);
- нарушен знак: отрицательные `income_total`, `expense_total`, `bliq`, `r_bench`,
  `amount`, `interest_rate`, `monthly_payment`, `target_amount`, `current_amount`;
- `deadline` не `null` и не корректная календарная ISO-дата (`YYYY-MM-DD`;
  «2026-02-31» и т.п. — дефект).

**Не дефект** (оценивается по существу): очень большие суммы, ставка 59 % годовых,
нулевой доход, дедлайн в прошлом, `current_amount > target_amount`, дубли `id`
(отвечаю на каждую строку отдельно), лишние поля вне схемы (игнорируются).

Ответ по невалидной записи: `status=invalid, dom=none`, все суммы `0`.
Служебные мета-строки (`"__meta__": true`, первая строка части) пропускаются и
строк ответа не порождают.

## 2. Базовые величины

- Свободный поток: `FCF = income_total − expense_total − Σ monthly_payment`
  (по исходным полям записи; знак FCF определяет статус `ok` / `deficit`).
- Базовая месячная потребность: `B = expense_total + Σ monthly_payment` —
  то, что должна покрывать подушка.
- Целевая подушка: `T = k(risk) × B`, где `k` = **6 / 5 / 4 / 3 / 3** месяцев
  для риск-профилей 1 / 2 / 3 / 4 / 5.
- Несгораемый минимум ликвидности: `F = 1 × B`.

## 3. Классификация долгов (относительно `r_bench` клиента)

| Класс | Условие | Действие |
|---|---|---|
| Дешёвый | ставка ≤ `r_bench` + 2 пп | досрочно **не** гасить никогда (депозит работает не хуже) |
| Токсичный | ставка ≥ max(25 %, `r_bench` + 10 пп) | гасить в первую очередь, в т.ч. из подушки выше минимума `F` |
| Дорогой | между ними | гасить после подушки: из потока и из излишка сверх `T` |

Порядок погашения внутри класса — по убыванию ставки (avalanche).

## 4. Разовые ходы (`lump`) — определяются до месячного плана

**При FCF ≥ 0**, последовательно:
1. Токсичные долги — из `bliq` **выше F**: полное закрытие — без порога,
   частичное — от 10 000 ₽.
2. Дорогие долги — из `bliq` **выше T**: то же правило.
3. Цели с дедлайном (по возрастанию дедлайна) — из `bliq` **выше T**:
   полное закрытие — без порога, довзнос — от 10 000 ₽.
4. Остаточный излишек сверх `T` (если ≥ 10 000 ₽) — разово разместить
   (инвестиции / бессрочные цели).

**При FCF < 0** (дефицит): только **полные** погашения кредитов со ставкой
> `r_bench` + 2 пп, по убыванию ставки, при условии, что после погашения
остаётся ликвидность ≥ 1 × B′ (B′ — уже без платежа погашенного кредита).
Разовые размещения излишка и взносы в цели в дефиците не предлагаются:
задача подушки в дефиците — запас хода.

`lump` = суммарные разовые ходы, целые ₽. Месячные распределения в строках
`deficit` равны нулю (по формату ответа).

## 5. Месячное распределение (только `status=ok`; бюджет = FCF, целые ₽)

Водопад по остатку бюджета (балансы — после разовых ходов, цели резерва — по исходному B):
1. Резерв до минимума `F` (если после разовых ходов ликвидность ниже `F`).
2. Досрочное погашение токсичных долгов (в пределах остатка тела).
3. Резерв до цели `T`.
4. Досрочное погашение дорогих долгов.
5. Цели с дедлайном, по возрастанию дедлайна: взнос месяца =
   ⌈остаток цели / месяцев до дедлайна⌉; дедлайн сегодня или в прошлом = 1 месяц
   (просроченную цель финансируем немедленно).
6. Остаток: если есть недофинансированные бессрочные цели — доля в `goal`
   по риску **60 / 50 / 40 / 30 / 20 %** (риск 1→5), остальное в `inv`
   (в пределах фактической потребности целей); иначе весь остаток в `inv`.

При FCF = 0 — статус `ok`, все бакеты 0, `dom = none`.

## 6. `dom`, округление, формат

- `dom` — крупнейший из бакетов `debt` / `reserve` / `goals+` (= `goal` + `inv`);
  при равенстве приоритет `debt` > `reserve` > `goals+`; все бакеты нулевые
  (FCF = 0, `deficit`, `invalid`) → `none`.
- Все суммы — целые рубли (усечение вниз); гарантия `res + debt + goal + inv ≤ FCF`.
- На каждую входную строку данных — ровно одна строка CSV в порядке входа;
  `id` возвращается как есть (при дубле — два ответа с одним `id`;
  при нечитаемом `id` — пустое значение в колонке `id`).
