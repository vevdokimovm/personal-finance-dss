# Методология независимого эксперта — раунд 3 (датасет v3)

**Зафиксировано до обработки данных: 2026-07-17, 05:00 UTC.**
Дата среза для всех дедлайнов: **2026-07-16** (из мета-строки датасета).
Все правила детерминированы и применяются одинаково ко всем 12 000 записям.

## 1. Базовые величины

- **Свободный месячный поток**: `F = income_total − expense_total − Σ monthly_payment`.
- **Essentials** (месячная стоимость жизни с обслуживанием долга):
  `E = expense_total + Σ monthly_payment`. Все полы и цели подушки считаются в месяцах E.
- **Статус**: `ok` при F ≥ 0, `deficit` при F < 0, `invalid` — дефектная запись (§6).
  При F = 0 — `ok`, все месячные бакеты 0, `dom = none`.

## 2. Целевая подушка по риск-профилю

| risk_tolerance | Цель подушки, мес. E |
|---|---|
| 1 (консервативный) | 6 |
| 2 (умеренно-консервативный) | 6 |
| 3 (сбалансированный) | 5 |
| 4 (умеренно-агрессивный) | 4 |
| 5 (агрессивный) | 3 |

Обоснование: чем ниже толерантность к риску, тем больше запас прочности; 3–6 месяцев —
стандарт частной практики РФ.

## 3. Классификация долгов (спред к безрисковой ставке)

`s = interest_rate − r_bench` (годовые доли):

- **Токсичный**: `s ≥ +0.06`, **либо** кредит interest-only / отрицательная амортизация
  (`monthly_payment ≤ amount × interest_rate / 12` при amount > 0 и rate > 0) —
  такой долг не гасится сам и токсичен независимо от спреда.
- **Дорогой**: `+0.02 ≤ s < +0.06`.
- **Дешёвый**: `s < +0.02` — досрочно не гасим: деньги на безрисковой ставке работают
  не хуже, ликвидность дороже.

## 4. Разовые ходы из накоплений (lump)

Порядок применения; каждый шаг ограничен своим полом ликвидности. Минимальный размер
одного разового блока — **10 000 ₽** (мельче советник не гоняет), для размещения
излишка в рынок — **50 000 ₽**.

1. **Гашение токсичных долгов**: доступно `max(0, bliq − 2×E)`;
   направляется до суммарного тела токсичных долгов. Пол 2×E — минимальный запас
   выживания, ниже которого подушку не трогаем даже ради ставки 60%.
2. **Гашение дорогих долгов**: доступно `max(0, bliq_остаток − цель подушки)` —
   дорогие долги гасим только из излишка сверх целевой подушки.
3. **Размещение излишка** (только при статусе `ok` и F > 0, риск-профиль 2–5):
   `max(0, bliq_остаток − цель подушки)` при излишке ≥ 50 000 ₽ — разово в
   недофинансированные датированные цели, остаток в инвестиции по профилю.
   Для риск-профиля 1 излишек остаётся в депозитах/ОФЗ-лестнице (это не «ход»,
   lump не начисляется). При F = 0 и дефиците излишек не размещаем — ликвидность важнее.
4. **Дефицит**: разовые ходы = только шаги 1–2 (пол шага 2 — 3×E вместо целевой
   подушки: дефицитному клиенту запас нужнее, но снятие платежа с бюджета лечит сам
   дефицит). Инвестиций из подушки при дефиците не бывает.

`lump` в CSV = сумма всех разовых блоков. При E = 0 полы равны 0.

## 5. Распределение месячного потока (status = ok, F > 0)

Состояние после lump-ходов: остались ли токсичные / дорогие долги; подушка ниже цели
(`low`) или нет (`ok`). Базовые доли F:

| Состояние | res | debt | остаток (цели+инвестиции) |
|---|---|---|---|
| токсичный долг, подушка low | 25% | 65% | 10% |
| токсичный долг, подушка ok | 0% | 85% | 15% |
| дорогой долг, подушка low | 40% | 45% | 15% |
| дорогой долг, подушка ok | 0% | 70% | 30% |
| долгов нет/дешёвые, подушка low | 60% | 0% | 40% |
| долгов нет/дешёвые, подушка ok | 0% | 0% | 100% |

Капы и переливы (каскад):
- `debt` ≤ остаток тела токсичных+дорогих долгов после lump; излишек доли уходит вниз.
- `res` ≤ разрыв до целевой подушки; излишек уходит вниз.
- Остаток делится: `goal` = месячная потребность датированных недофинансированных целей
  `Σ (target − current) / max(1, месяцев до дедлайна)`, но не более остатка;
  просроченный недобранный дедлайн — знаменатель 1 (гасить как можно скорее).
  `inv` = всё, что осталось (бессрочные цели финансируются через инвестиционный
  контур — по смыслу это накопление богатства).
- Целые рубли; сумма бакетов = ⌊F⌋ (остаток округления — в крупнейший бакет);
  инвариант `res + debt + goal + inv ≤ F` проверяется программно, нарушений быть не должно.

**dom** = argmax(debt, res, goal+inv); при равенстве приоритет debt > reserve > goals+.
При F ≤ 0 или invalid — `none`.

Инструменты (для протокола, на CSV не влияют): резерв — накопительный счёт/короткий
депозит; инвестиции по риск-профилю 1→ОФЗ/депозиты, 2→80/20 облигации/акции,
3→60/40, 4→40/60, 5→20/80; цели с горизонтом < 3 лет — только депозиты/ОФЗ.

## 6. Критерий invalid

Запись дефектна, если её нельзя однозначно прочитать как валидные финансовые данные:

- строка не парсится как JSON;
- отсутствует любое поле схемы записи (id, income_total, expense_total, obligations,
  goals, bliq, r_bench, risk_tolerance) или обязательное поле элемента
  obligations/goals (включая name);
- числовое поле не число (строка, null, bool), NaN/Infinity, отрицательное
  (суммы, ставки, платежи, накопления);
- `risk_tolerance` не целое из {1..5};
- `deadline` не null и не парсится как ISO-дата;
- `obligations`/`goals` не являются списками.

**Не дефект** (пограничное, но читаемое — оценивается по существу): очень большие
суммы, ставка 59% годовых, дедлайн в прошлом, target = current, перефинансированная
цель, пустые списки, лишние поля, дубль id (обе строки получают полноценный ответ).

Для invalid: `status=invalid, dom=none, res=debt=goal=inv=lump=0`. Если JSON не
парсится, id извлекается регуляркой `SP3-\d{5}` из сырой строки; при неудаче — `UNKNOWN`.
