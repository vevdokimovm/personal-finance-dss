# План сравнения экспертов — раунд 3 (датасет v3)

**Назначение:** протокол координатора. Выполняется один раз, когда собраны CSV со
всех эксперт-аккаунтов (V / S / J / M). Вход — по 4 файла с каждого аккаунта:
`expert_allocations_v3.csv`, `expert_methodology_v3.md`, `dataset_review.md`,
`run_metadata.md`. Результат — отчёт согласия, консенсус-разметка и кандидаты в
слой C для датасета v4.

---

## 0. Предусловия (гейты до любого сравнения)

1. **Версия датасета.** Из `run_metadata.md` каждого эксперта: `dataset_version=3`,
   срез `2026-07-16`, полнота = все 12 000. Несовпадение версии → CSV в сравнение
   не допускается (итерации несравнимы).
2. **Структура CSV.** Шапка ровно `id,status,dom,res,debt,goal,inv,lump`;
   12 000 строк данных; `status ∈ {ok,deficit,invalid}`,
   `dom ∈ {debt,reserve,goals+,none}`; бакеты — целые ≥ 0.
3. **Инварианты против исходного JSONL** (пересчитать самим, не верить отчётам):
   - `res+debt+goal+inv ≤ max(0, поток)` для каждой строки;
   - `deficit`/`invalid` → все бакеты 0 и `dom=none`;
   - `dom` = argmax фактических бакетов (tie-break допускается любой — фиксировать).
   Нарушения — в лог; единичные (<0.1%) строки исключить из сравнения с пометкой,
   массовые → вернуть эксперту на перепрогон.

## 1. Выравнивание строк — ТОЛЬКО по позиции

В датасете 50 дублей `id`, поэтому **join по id запрещён** — merge размножит
строки. Каноническое выравнивание: номер входной строки (0…11999) в порядке
part1→part4, мета-строки пропущены. Ключ сравнения = позиция; `id` — только для
человекочитаемости и связи с исходником. Если чей-то CSV не совпал по позициям
(проверка: последовательность id файла == последовательность id входа) — файл
чинится по уникальным id, строки-дубли у такого файла помечаются unalignable и
исключаются (их всего 100 позиций).

Партиальный CSV (эксперт обработал не всё) — деградация: сравнение на пересечении
позиций; если пересечение < 12 000, для оценок долей действует запасной режим §6
методички — стратифицированный общий сабсет ~400 портретов даёт точность ±5%.
При полных файлах сабсет не нужен: считаем на всех 12 000.

## 2. Слой A — статусы (сначала отделить баги от разногласий)

`status` почти объективен, поэтому расхождения делятся на два принципиально
разных класса:

- **Класс «баг»: ok ↔ deficit.** Знак потока вычислим из данных однозначно.
  Любое такое расхождение — ошибка чьего-то движка, а не «мнение». Ожидание: 0.
  Если не 0 — найти, починить, перепрогнать *до* дальнейшего анализа.
- **Класс «критерий»: invalid ↔ (ok|deficit).** Это разница трактовок дефектности
  (например, отсутствующий `name` — дефект или нет). Метрики: Jaccard множеств
  invalid-позиций по каждой паре; таблица «тип дефекта × эксперт» (какие из
  классов 150/100/100/100/50/50 кто пометил). Расхождения здесь — не кейсы в
  слой C, а **уточнения формулировок брифа v4** (правка спеки, не датасета).

Отчитать: распределение статусов по экспертам; Fleiss' κ по статусам на всех
12 000; попарные Cohen's κ.

## 3. Слой B — направления (dom)

Основной срез «независимость»: константы у всех разные, направления должны
сходиться.

1. **База сравнения:** строки, где статус `ok` у всех экспертов и суммарная
   аллокация > 0 у всех (обозначить `ALL-OK`, зафиксировать размер). Попарные
   метрики дополнительно считать на попарных пересечениях (больше n на пару).
2. **Метрики:** доля полного совпадения dom; Fleiss' κ (4 класса, номинальные,
   без весов) на ALL-OK; попарные Cohen's κ; попарные confusion-матрицы 4×4 —
   это и есть **матрица согласия доминант**. Смотреть, куда именно утекает
   несогласие (типично: reserve↔debt при подушке около цели, debt↔goals+ при
   спреде около порога).
3. **Классификация строк:** unanimous (все совпали) / majority (≥⌈N/2⌉) /
   split (нет большинства). Доли трёх классов — заглавная цифра отчёта.
4. Bootstrap CI (1000 ресэмплов строк) для κ и долей — при 12 000 строк даже
   1–2 п.п. разницы значимы, CI это формализует.

Шкала интерпретации κ (Landis–Koch): <0.2 слабое, 0.2–0.4 удовлетворительное,
0.4–0.6 умеренное, 0.6–0.8 существенное, >0.8 почти полное.

## 4. Слой C — количественная близость аллокаций

dom груб (65/35 и 51/49 дают одинаковый dom). Дополнительно на ALL-OK:

- Доли бюджета `s_b = bucket / (res+debt+goal+inv)` по 4 бакетам →
  **L1-дистанция на симплексе** `d = Σ_b |s_b^A − s_b^B| ∈ [0, 2]`
  (d/2 = доля бюджета, размещённая по-разному). Отчёт: медиана и p90 по каждой
  паре. При сравнении goal и inv допустимо схлопывать в goals+ (эксперты по-разному
  проводят границу «датированная цель vs инвестиция» — это не разногласие по сути).
- **lump:** (а) бинарное согласие lump>0 (Cohen's κ); (б) на строках, где lump>0
  у обоих — относительное расхождение `|lA−lB| / max(lA,lB)`, медиана/p90.
  lump чувствительнее всего к полам ликвидности — ожидаемо самый шумный показатель.

## 5. Стратификация расхождений (где именно расходимся)

Все метрики §§2–4 пересчитать по стратам, вычисляемым из **исходных данных**
(не из экспертных констант): бакет ПДН (0/0–20/20–40/40–60/60–80/80+);
месяцы ликвидности (<1/1–3/3–6/6–12/12–24/24+); максимальный спред ставки к
r_bench (<0/0–2/2–4/4–6/6–10/10+ п.п.); риск-профиль 1–5; наличие датированных
целей; знак и величина потока. Отсортировать страты по возрастанию согласия —
верх списка = зоны методологических развилок. Если появится сайдкар со слоями
A–E от генератора (рекомендация R4 ревью) — добавить страту «слой».

Отдельно пометить **пороговые** расхождения: строка лежит в ε-окрестности
(±1 п.п. спреда, ±0.5 мес. подушки) заявленного порога хотя бы одного эксперта →
тег `borderline` (расхождение объясняется константами — это и есть штатная
независимость). Остальные → `structural` (разная логика каскада) — вот они
по-настоящему интересны.

## 6. Диф констант методологий

Свести таблицу из `expert_methodology_v3.md` всех аккаунтов: целевая подушка по
риску; пороги «токсичного»/«дорогого» (спред); правило interest-only; полы
ликвидности для lump; минимальные размеры lump; доли месячного распределения по
состояниям; критерий invalid (строгость к `name`, датам, risk вне 1–5);
tie-break dom. Вывод в двух строках: (1) константы различаются — да/нет и где
(если совпали дословно — независимость под вопросом, эксперты «слиплись»);
(2) направления при этом сходятся — метрики §3.

## 7. Консенсус и кандидаты в слой C v4

1. **`consensus_labels.csv`:** позиция, id, консенсус-статус, консенсус-dom
   (большинством), n_agree, теги borderline/structural. Это внешняя референс-разметка
   для будущего сравнения с чем угодно.
2. **`disagreements.csv`:** все split-строки + majority-строки с L1 > 1.0,
   с приложенным профилем признаков (ПДН, ликвидность, спреды, цели, поток).
3. **Отбор кандидатов в слой C:** split/structural-строки кластеризовать по
   профилю признаков (грубо: комбинация страт §5), из каждого кластера — 1–2
   представителя, итого ~15–30 кейсов. В генератор v4 они входят **не копиями
   строк, а параметризованными детерминированными кейсами** (описание угла +
   допуски), иначе слой C зарастёт дублями одного и того же угла.
4. Расхождения по invalid (§2) → правки формулировок брифа v4, в слой C не идут.

## 8. Критерии приёмки раунда (настраиваемые пороги)

| Метрика | Цель | Смысл |
|---|---|---|
| ok↔deficit расхождения | 0 | движки без багов |
| Jaccard invalid-множеств (мин. по парам) | ≥ 0.90 | критерий дефектности читается одинаково |
| Fleiss' κ по dom на ALL-OK | ≥ 0.60 | направления сходятся существенно |
| Мин. попарная Cohen's κ по dom | ≥ 0.55 | нет одного «выпавшего» эксперта |
| Медиана L1 | ≤ 0.50 | ≤ 25% бюджета размещено по-разному |
| p90 L1 | ≤ 1.00 | хвост разногласий ограничен |
| Константы методологий | различаются ≥ чем в 2 параметрах | независимость реальная, не постановочная |

Ниже целей — не «провал», а маршрутизация: κ низкая + расхождения borderline →
разброс констант велик, но здоров; κ низкая + structural → у экспертов разные
каскады приоритетов, разбирать вручную по кластерам §7.3.

## 9. Артефакты на выходе

`expert_agreement_report.md` (гейты → статусы → dom-матрицы → L1/lump → страты →
диф констант → вердикт по приёмке), `consensus_labels.csv`, `disagreements.csv`,
`layer_c_candidates.md`, и скрипт `compare_experts.py`.

Скелет скрипта (ООП, по стандартам):

```python
class SourceIndex:        # порядок строк JSONL + признаки для страт (ПДН, ликвидность, спреды)
class ExpertCsv:          # load, structural gates, инварианты против SourceIndex
class Alignment:          # позиционное выравнивание, unalignable-лог
class StatusComparator:   # баг-класс vs критерий-класс, каппы, Jaccard invalid
class DomComparator:      # Fleiss/Cohen, confusion 4×4, unanimous/majority/split
class AllocComparator:    # L1 на симплексе, lump-метрики
class Stratifier:         # метрики по стратам, borderline vs structural
class MethodologyDiff:    # таблица констант из .md (полуручной ввод — ок)
class ReportBuilder:      # md-отчёт + consensus/disagreements/candidates
```

Зависимости: pandas + scipy (Fleiss' κ — statsmodels или своя реализация,
формула короткая). Bootstrap — numpy.
