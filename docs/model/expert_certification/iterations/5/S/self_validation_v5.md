## 5. Сверка JSONL против карточек

Карточки — вторая, человекочитаемая копия тех же данных. Если она расходится с JSONL,
слепой пакет внутренне противоречив и все ответы на нём под вопросом. Поэтому сверка идёт
**до** сдачи, а не после.

**Результат: `CONSISTENT`, 0 расхождений.**

| Что сверялось | Записей |
|---|---|
| количество карточек против количества строк JSONL | 12 000 = 12 000 |
| позиционная последовательность `id` | 12 000 сверено |
| доход, расходы, накопления | до копейки |
| безрисковая ставка | до 0.06 п.п. (карточка округляет до 0.1%) |
| риск-профиль | точно |
| число кредитов и число целей | точно |
| остаток / ставка / платёж по каждому кредиту | 19 561 обязательство |
| сумма / накоплено / дедлайн по каждой цели | 36 280 целей |

Значения, помеченные в карточках как битые (`!None!`, `!'сто тысяч'!`, `!'2026-02-30'!`,
`!'0,2'!`, `!6!`, `!'средний'!`), сверялись как «обе стороны считают поле битым», а не по
значению — иначе сверка ловила бы сам факт дефекта вместо рассогласования копий. Ни одного
случая, где карточка показывает битое поле, а JSONL — нормальное, или наоборот.

движком на выборке из 40 портретов, покрывающей все классы моей типологии.

**Итог: 40 из 40 совпали, максимальное расхождение по любому бакету ≤ 0.05 ₽.**

одно, а код делает другое, и обе стороны выглядят правдоподобно.
