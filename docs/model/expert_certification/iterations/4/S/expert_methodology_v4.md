# Методология независимого эксперта — раунд 4 (v4)

**Статус:** зафиксирована ДО обработки датасета (до запуска движка по 12 000 записям).
До фиксации я просмотрел только: бриф, методичку, метастроки четырёх частей и
2–3 первые записи (структурная сверка схемы §1 брифа). Никакие агрегаты датасета
на константы не влияли. Константы по ходу обработки не менялись.

**Дата среза:** 2026-07-18. Все дедлайны и горизонты — относительно неё.

**Роль:** независимый финансовый советник, практика РФ, 2026 г. Философия:
«резерв безопасности → математика долга (avalanche) → обязательства клиента
(дедлайны целей) → размещение излишка». Недостающее трактую консервативно,
как советник по телефону; дефектные записи — по правилам §2 брифа, без починки.

---

## 1. Базовые величины (по каждой валидной записи)

| Величина | Формула | Граничные ветки |
|---|---|---|
| Платежи `P` | Σ `monthly_payment` по **всем** валидным кредитам записи | кредит с остатком 0 платёж всё равно вносит в `P` (график не отменён банком) — консервативно |
| Свободный поток `fcf` | `income_total − expense_total − P` | считается от **входной** записи (до разовых ходов) |
| Месячное сжигание `burn` | `expense_total + P` | `burn = 0` → вырожденный кейс, флаг `zero_burn` |
| ПДН | `P / income_total` | `income = 0, P > 0` → ПДН = ∞ (в отчёте 999.0); `income = 0, P = 0` → 0 |
| Запас ликвидности, мес | `bliq / burn` | `burn = 0` → 999.0 при `bliq > 0`, иначе 0 |
| Целевая подушка | `K(risk) × burn` | `burn = 0` → 0 |

**K(risk):** 1 → **6** мес · 2 → **5** · 3 → **4** · 4 → **3** · 5 → **3** мес.
**Минимальный резерв** `min_reserve = 1 × burn` (неприкосновенный месяц).

ПДН-пороги (диагностика и вердикт, на арифметику бакетов не влияют — аллокация
приоритетная, а не пороговая): комфорт < 0.30 ≤ повышенный ≤ 0.50 < высокий;
\> 0.80 — критический (`flag pdn_critical`).

## 2. Классификация долга (годовая ставка `r` против `r_bench`)

| Класс | Условие | Действие |
|---|---|---|
| Дешёвый | `r ≤ r_bench + 0.02` | не гасить досрочно, платить по графику |
| Дорогой | `r_bench + 0.02 < r < 0.45` | досрочное погашение после закрытия резерва (см. §3–4) |
| Токсичный | `0.45 ≤ r ≤ 3.00` | гасить в первую очередь, в т.ч. из подушки сверх 1 мес |
| Мусор | `r > 3.00` | дефект выгрузки → вся запись `invalid` (§2.2 брифа) |

Обоснование спреда 2 п.п.: транзакционные издержки, НДФЛ на процентный доход,
опционная ценность ликвидности. Порог 45%: верхняя граница банковской
беззалоговой розницы 2026; выше — МФО-зона, экономически разрушительная при
любом `r_bench`. Внутри класса порядок погашения — **avalanche** (по убыванию
ставки; при равенстве ставок — больший остаток первым).

## 3. Разовые ходы из накоплений (`lump`)

**Доступная ликвидность = `bliq` и только она.** Средства, накопленные внутри
целей (`current_amount`), считаю целевыми и в разовых ходах не задействую;
излишек перефинансированных целей (`current > target`) рекомендую высвободить
текстом в плане цели, но в `lump` не считаю (см. журнал допущений, A-высвобождение).
Гарантия: `lump ≤ bliq` всегда.

Полы ликвидности: `floor_toxic = 1 × burn` (столько остаётся даже при гашении
токсичного); `floor_normal = целевая подушка`. Минимальный частичный ход —
**10 000 ₽**; ход, полностью закрывающий кредит или цель, от минимума освобождён.

Порядок (каждый шаг работает с остатком излишка предыдущего):

1. **L1 токсичные:** излишек сверх `floor_toxic` → токсичные долги, avalanche,
   до полного тела каждого.
2. **L2 дорогие:** излишек сверх `floor_normal` → дорогие долги, avalanche.
3. **L3 срочные цели:** излишек сверх `floor_normal` → недобор целей с дедлайном
   ≤ 12 мес от среза (включая просроченные), по возрастанию дедлайна, до гэпа.
4. **L4 размещение:** остаток излишка сверх `floor_normal` (≥ 10 000 ₽) —
   разовое размещение (инструмент по риску/горизонту, §7). Учитывается в `lump`.

При `fcf < 0` (deficit): выполняются только **L1–L2** (снижение долговой
нагрузки — единственный разовый ход, улучшающий поток); L3–L4 не выполняются —
ликвидность нужна как runway. Частичное досрочное погашение — в **сокращение
срока** (платёж не меняется); полное закрытие убирает платёж — эффект на поток
отражаю в вердикте, но статус и месячный бюджет считаю от входного `fcf`
(консервативно и совместимо с позиционной проверкой бюджета координатора).

## 4. Месячный план (водопад, только при `fcf > 0`)

`rem` — нераспределённый остаток `fcf`; состояние долгов и целей — **после**
разовых ходов; `bliq_after = bliq − lump`.

1. **W1 аварийный резерв:** если `bliq_after < min_reserve` →
   `res += min(rem, (min_reserve − bliq_after) / 3)` (добор минимума за ~3 мес).
2. **W2 токсичные остались** → `debt += rem` целиком; goal = inv = 0; стоп.
3. **W3 датированные цели:** по каждой валидной цели с дедлайном и гэпом > 0:
   `m_left = max(1, ceil(days_to_deadline / 30.4375))`; просроченный дедлайн →
   `m_left = 12` (ребейзлайн, флаг `goal_overdue`); дедлайн в день среза →
   `m_left = 1`. Требуемый взнос `req = gap / m_left`. Суммарно в `goal` идёт
   `min(Σ req, cap)`, где `cap = 0.5 × rem` при живых дорогих долгах, иначе
   `1.0 × rem`. Раздача внутри — по возрастанию дедлайна, каждой до её `req`.
   Если выделено < Σ req — флаг `goal_at_risk` (недостижимость к дедлайну).
4. **W4 дорогие долги остались:** если подушка ниже цели →
   `debt += 0.7 × rem`, `res += 0.3 × rem`; иначе `debt += rem`. Стоп.
5. **W5 резерв до цели:** если `bliq_after < целевой подушки` →
   `res += min(rem, gap_to_target / 6)` (добор за ~6 мес).
6. **W6 остаток:** есть недофинансированные бессрочные цели →
   `goal += 0.5 × rem`, `inv += 0.5 × rem`; иначе `inv += rem`.

Округление: каждый бакет — вниз до целого ₽; гарантия
`res + debt + goal + inv ≤ max(0, fcf)`. При `fcf ≤ 0` все месячные бакеты = 0.

## 5. Статус, доминанта, флаги

- `status`: `invalid` (§6) · `deficit` (`fcf < 0`) · `ok` (`fcf ≥ 0`).
- `dom`: максимум из {`debt`, `res`, `goal + inv`}; метки `debt` / `reserve` /
  `goals+`; при равенстве приоритет `debt > reserve > goals+`; все нули → `none`.
  Доминанта — по месячным бакетам; `lump` на неё не влияет.
- Ключевые флаги: `zero_income`, `zero_burn`, `zero_flow`, `pdn_gt_05`,
  `pdn_critical`, `toxic_debt`, `no_reserve` (bliq = 0), `reserve_below_min`,
  `goal_overdue`, `deadline_today`, `goal_at_risk`, `goal_completed`
  (`target == current` или `target = 0`), `goal_overfunded`, `zero_balance_debt`,
  `interest_only_debt` (платёж ≤ месячному проценту), `dup_id`.

## 6. Критерий `invalid` (операционализация §2 брифа)

Запись `invalid`, если выполняется хотя бы одно:

1. Строка не парсится как JSON-объект, либо содержит `NaN`/`Infinity`.
2. Отсутствует любой обязательный ключ записи: `id`, `income_total`,
   `expense_total`, `obligations`, `goals`, `bliq`, `r_bench`, `risk_tolerance`.
3. Тип нарушен: деньги/ставки не числа (строка, bool, null); `obligations`/`goals`
   не списки; элемент списка не объект; `name` не строка; `id` записи не строка.
4. Знак нарушен: отрицательные `income_total`, `expense_total`, `bliq`,
   `amount`, `monthly_payment`, `interest_rate`, `target_amount`, `current_amount`.
5. У кредита отсутствует любой из ключей `name`, `amount`, `interest_rate`,
   `monthly_payment`; у цели — любой из `name`, `target_amount`,
   `current_amount`, **`deadline`** (отсутствие ключа ≠ `null`; явный `null` —
   валидная бессрочная цель).
6. `interest_rate > 3.00` (ставка выше 300% годовых — мусор).
7. `deadline` не `null` и не строгая календарная дата `YYYY-MM-DD`
   («2026-02-30» — дефект).
8. Домены: `risk_tolerance` не целое из {1…5} (bool — не целое);
   `r_bench` вне [0, 1] (ставка задана долей).

**Не дефект** (оценивается по существу): ставка 59% или ровно 292%, доход
8 млн ₽/мес, нулевой доход/расходы/подушка, дедлайн в прошлом или сегодня,
`target == current`, `current > target`, кредит с нулевым остатком или нулевым
платёжом, пустые списки целей/кредитов, лишние ключи (напр. внутренние `id`
кредитов/целей). Для `invalid`: `status=invalid`, `dom=none`, все суммы 0,
`lump=0`. Дубли `id` не мержатся: каждая входная строка → ровно одна строка
ответа, позиционно.

## 7. Инструменты (текстовый уровень, в развёрнутой разметке)

Резерв — накопительный счёт/короткий вклад под ~`r_bench`. Цели по горизонту:
≤ 12 мес — накопительный счёт/вклад; 1–3 года — вклады/ОФЗ до дедлайна;
\> 3 лет — ОФЗ + индексные фонды, доля акций по риску: 1 → 0%, 2 → 20%,
3 → 40%, 4 → 60%, 5 → 80%. Бакет `inv` — та же риск-сетка, горизонт «длинный».

## 8. Правило `confidence` (детерминированное)

`confidence = max(1, 5 − Σ штрафов)`:

| Штраф | Условие («кейс на кромке») |
|---|---|
| −1 | ставка любого кредита в пределах ±0.02 от границы класса (`r_bench + 0.02` или `0.45`) |
| −1 | `0.8 ≤ bliq / целевая подушка ≤ 1.2` (подушка на границе цели) |
| −1 | `|fcf| < 0.05 × max(income, 1)` (поток около нуля) |
| −1 | есть датированная цель с гэпом: просрочена, сегодня или ≤ 3 мес до дедлайна |
| −1 | `income = 0` или `burn = 0` (вырожденная запись) |

`invalid` → `confidence = 5` (критерий однозначен).

## 9. Вердикт

Одна строка по-русски, детерминированные шаблоны от статуса и флагов:
deficit → «Поток отрицательный: резать расходы / реструктуризация…»;
токсичный долг → «Пожар: закрыть МФО/токсичный долг…»; и т.д. Полный текст —
в `recommendations_v4.jsonl.gz`.

## 10. Контроль качества (обязательства перед сдачей)

1. Σ месячных бакетов ≤ `max(0, fcf)` для каждой строки; `lump ≤ bliq`;
   нарушений — 0 (отчёт `self_validation_v4.md`).
2. Ровно 12 000 строк ответа, порядок = порядку входа, `id` как есть.
3. Enum-поля строго из словарей §5–6 брифа.
4. Программная сверка JSONL ↔ карточки ≥ 3 случайных портретов.
5. Чувствительность к константам — отдельный прогон ±20% по одной (§11 брифа).
