всем 12 000 строкам входа и финальному комплекту ответов.

| Проверка | Результат |

  (распределение: 5 → 7 444, 4 → 3 836, 3 → 682, 2 → 38, 1 → 0).

## 3. Позиционный контракт — ПРОШЛО

`id` каждой строки ответа сверен с `id` соответствующей входной строки
(включая 260 строк в дублях и 600 дефектных): расхождений **0**. Записей

## 4. Контроль сохранения сумм — ПРОШЛО, нарушений 0 (§4.4)

- `res + debt + goal + inv ≤ max(0, свободный поток)` — пересчитано от
  входной строки независимо от движка: нарушений **0** из 12 000.
- `lump ≤ bliq` (доступная ликвидность): нарушений **0**.
- Статус ↔ знак потока (`deficit` ⇔ fcf < 0; `invalid` ⇔ мой критерий §6
  методологии; у invalid все суммы = 0): расхождений **0**.
- `dom` пересчитан заново из бакетов с правилом приоритета при равенстве:
  расхождений **0**.

## 6. Сверка JSONL ↔ карточки — ПРОШЛО (5 портретов ≥ требуемых 3)

Детерминированная выборка (seed 20260718) валидных позиций: 1070, 4394,
5664, 6284, 6545. Сравнивались: доход, расходы, подушка, риск, бенчмарк,
каждый кредит (имя, остаток, ставка, платёж), каждая цель (имя, сумма,
накоплено, дедлайн). Допуски: деньги ±0.01 ₽ (карточка печатает 2 знака),
ставки ±0.06 п.п. (карточка печатает 0.1%). Итог: **5/5 OK**.

Примечание честности: первый запуск кросс-чека дал 5/5 «расхождений» —
причиной оказался баг в самом проверочном скрипте (индекс группы регулярки
для хвоста цели: `group(3)` вместо `group(4)`). Ответы движка не менялись;
после исправления скрипта — полное совпадение. Данные карточек и JSONL
согласованы.
