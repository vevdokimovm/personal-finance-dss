## 1. Диагностика (M-блок)

| Метрика | Формула | Примечания |
|---|---|---|
| M1. Обязательные платежи | `pay = Σ monthly_payment` | по всем кредитам записи |
| M2. Полное месячное сжигание | `burn = expense_total + pay` | база и для ликвидности, и для подушки |
| M3. Свободный поток | `fcf = income_total − burn` | |
| M4. ПДН | `pdn = pay / income_total` | `income = 0, pay > 0` → ПДН = ∞ (флаг `pdn_infinite`); `income = 0, pay = 0` → 0 |
| M5. Запас ликвидности | `liq_months = bliq / burn` | **знаменатель — полный burn** (M2): при потере дохода платежи по кредитам никуда не деваются (A11). `burn = 0` → ∞ (в CSV печатается кап 999) |
| M6. Целевая подушка | `reserve_target = месяцы(риск) × burn` | таблица C4 |
| M7. Минимальный пол подушки | `floor = 1.0 × burn` | несгораемый минимум при разовых ходах |

## 3. Критерий `invalid` — операционализация правил брифа §2

Запись **дефектна**, если её нельзя однозначно прочитать как валидные финансовые
данные. Дефектную запись не чиним: `status=invalid`, `dom=none`, все суммы 0,
`lump=0`. Проверки (все программные, порядок не влияет на вердикт):

1. Строка — не валидный JSON-объект → invalid (`parse_error`), id в ответе — пустой (A14).
2. Отсутствует любой обязательный ключ верхнего уровня: `id, income_total,
   expense_total, obligations, goals, bliq, r_bench, risk_tolerance`.
3. `id` — не строка (содержимое строки не валидируется, echo как есть, A20).
4. Денежные поля `income_total, expense_total, bliq` — число (не bool, не
   строка, не null, конечное), **≥ 0**. Отрицательное значение = сломанный знак
   (A16). NaN/Infinity → invalid.
5. `r_bench` — число в [0; 1.0]. Безрисковой доходности > 100% годовых в
   легальном контуре РФ-2026 не существует (A5).
6. `risk_tolerance` — целое 1..5 (float с целым значением, например `3.0`,
   принимается — A15).
7. `obligations` — список словарей; в каждом: `name` — строка; `amount ≥ 0`;
   `monthly_payment ≥ 0`; `interest_rate` — число в [0; 3.0].
   **`interest_rate > 3.0` (300% годовых) — мусор выгрузки, запись invalid**
   (бриф §2.2). Пустая строка `name` — валидна с флагом (A4).
8. `goals` — список словарей; в каждом: `name` — строка; `target_amount ≥ 0`;
   `current_amount ≥ 0`; ключ `deadline` **обязан присутствовать**:
   отсутствие ключа → invalid (бриф §2.3); значение — либо `null` (бессрочная
   цель), либо строка строго `YYYY-MM-DD`, существующая в календаре
   («2026-02-30» → invalid). Иные форматы дат, включая datetime, → invalid (A7).
9. Лишние поля (например, служебные `id` внутри кредитов/целей) **не** делают
   запись дефектной — типичный шум CRM-выгрузки (A3).
10. **Пограничное — не дефект** (бриф §2.4): нулевой доход/расходы/подушка,
    дедлайн в прошлом/сегодня, ставка 292%, доход 8 млн ₽/мес,
    `target == current`, перефинансированная цель, `amount = 0` при
    `monthly_payment > 0` (флаг `zero_balance_paying`, платёж учитывается в
    burn — трактуем данные буквально, A8).

Классы дефектов для уверенности: «грубый» (нечитаемо, conf = 5) и
**near-miss** (синтаксис почти верен: ставка в (3.0; 3.5], календарно
невозможная, но формально корректная дата, псевдочисловая строка `'0,2'`,
bool вместо числа, пустая строка вместо суммы) → conf = 3 (§7).

Дубли `id` **не** мержатся: каждая строка входа оценивается независимо, на
каждую — ровно одна строка ответа, порядок позиционный (бриф §2.5–2.6, A13).

## 4. Разовые ходы из накоплений (L-блок)

Идут **до** месячного плана; всё месячное считается на пост-lump состоянии
(остатки долгов, `bliq`, `burn`, `reserve_target` пересчитываются после каждого
хода). Суммарный lump ≤ исходной `bliq` — жёсткий инвариант.

Статус `ok`:

1. **L1 — гашение токсичных долгов** (по убыванию ставки). Разрешён частичный
   платёж (≥ C9). Защищаемый минимум — `floor` = 1 × burn: подушку ниже одного
   месяца сжигания не опускаем даже ради МФО.
2. **L2 — полное закрытие дорогих долгов** (по убыванию ставки; только целиком,
   ход ≥ C8). Условие: после хода `bliq ≥ reserve_target`, посчитанной по
   **новому** burn (закрытие долга уменьшает burn и высвобождает подушку).
3. **L3 — закрытие целей целиком** из излишка над `reserve_target`: сначала
   датированные по возрастанию дедлайна (просроченные — первыми), затем
   бессрочные по возрастанию остатка. Ход ≥ C8.
4. **L3b — частичное пополнение** ближайшей датированной недофинансированной
   цели остатком излишка (≥ C8).
5. **L4 — размещение остатка излишка** над `reserve_target` в инвестиции
   согласно C14 (≥ C8). Считается разовым ходом и входит в `lump`.

Статус `deficit` (поток < 0): месячные бакеты нулевые, но разовые ходы
уместны, если чинят бюджет:

- **L1 действует всегда** (токсичный долг растёт быстрее любой подушки).
- **L2 действует только если** серия закрытий (в порядке лавины) выводит поток
  в `fcf ≥ 0` **и** после неё остаётся `bliq ≥ 3 × новый burn` (подушка — это
  runway, её нельзя сжечь в ноль ради частичного облегчения платежей, A12).
- L3/L3b/L4 в дефиците запрещены: излишков в дефиците не бывает, кэш = runway.

## 5. Месячный план — водопад (W-блок)

Бюджет `F = floor(max(0, fcf_после_lump))`. Каждый шаг забирает из остатка:

- **W1.** Остались токсичные долги → **весь** `F` в `debt` (пожар тушат первым).
- **W2.** `bliq < floor` → в `res` до заполнения пола (min(F, floor − bliq)).
- **W3.** Остались дорогие долги → в `debt` **50%** остатка потока (C10),
  лавина: досрочный платёж самому дорогому.
- **W4.** `bliq < reserve_target` → в `res` до `ceil(дефицит подушки / 12)` (C11).
- **W5.** Датированные незакрытые цели по возрастанию дедлайна: каждой — до её
  требуемого взноса `need = остаток / месяцы_до_дедлайна` (месяцы =
  дни/30.4375; дедлайн ≤ сегодня или < 1 мес → весь остаток цели сразу).
- **W6.** Остаток: риск 1–2 и есть любой долг → `debt`; иначе есть бессрочные
  цели → 50/50 `goal`/`inv`; иначе → `inv` (C12).

`dom` = крупнейший из {`debt`, `res`, `goal + inv`}; тай-брейк в порядке
`debt` → `reserve` → `goals+`; все нули → `none` (в т.ч. дефицит и ровно
нулевой поток). Дешёвые долги досрочно не гасятся (кроме W6 для риска 1–2) —
обслуживаются по графику.

## 6. Цели — план и достижимость

По каждой цели: остаток `rem = max(0, target − current)`; `rem = 0` → цель
закрыта (`goal_done`, взнос 0); `current > target` → `overfunded_goal`,
действий нет (A18). Датированная цель: требуемый взнос по C13 (0% доходности);
просроченная/сегодняшняя — потребность «немедленно» (A17). Достижимость:
закрыта lump'ом → да; иначе — план W5 покрывает требуемый взнос → да/нет.
Бессрочная цель — достижимость не оценивается, в плане — ожидаемый срок при
текущем темпе (если темп > 0). Инструменты — по горизонту и риску (C14).

## 7. Уверенность `confidence` — детерминированное правило

Валидная запись: старт 5, минус 1 за каждый сработавший детектор кромки,
кламп в [1; 5]:

| # | Детектор «кейс на границе» |
|---|---|
| D1 | `abs(fcf) ≤ max(2000, 0.03 × income)` — поток на ноже нуля |
| D2 | `income > 0` и `abs(pdn − 0.50) ≤ 0.05` — ПДН у порога перегруза |
| D3 | есть кредит со ставкой в пределах ±1.5 п.п. от порога C5 (`r_bench + 0.02`) |
| D4 | есть кредит со ставкой в пределах ±3 п.п. от порога токсичности 45% |
| D5 | `reserve_target > 0` и `bliq` в пределах ±15% от `reserve_target` |
| D6 | какой-либо разовый ход (или отвергнутый кандидат) размером в [0.8; 1.2] × min_lump |
| D7 | есть просроченная датированная цель (зона «школ мысли») |
| D8 | противоречивые данные: `zero_balance_paying`, `suspicious_rate`, `overfunded_goal` |

`invalid`: 5 («однозначно мусор»); near-miss-дефект (§3) → 3.

## 8. Порядок обработки и контракты

1. Методология (этот файл) → приёмка датасета (§8 брифа) → статаудит →
   полная программная обработка всех 12 000 строк → самопроверка → отчёты.
2. Позиционный контракт: части 1→4, служебная meta-строка каждой части
   пропускается, на каждую входную строку — ровно одна строка ответа в порядке
   входа; `id` echo как есть.
3. Инварианты выхода: `res + debt + goal + inv ≤ max(0, fcf)`;
   `lump ≤ bliq`; invalid → все нули; deficit → месячные нули. Число
   нарушений обязано быть 0 (отчёт — `self_validation_v4.md`).
4. Диагностические колонки `summary_v4.csv` (`bliq`, `liquidity_months`,
   `reserve_target`, `pdn`, `fcf`, `monthly_burn`) считаются от **входного**
   состояния (диагноз пациента); планы (`res/debt/goal/inv`) — от пост-lump
   состояния. `dom` — только по месячным бакетам (подтверждено примером брифа:
   deficit с lump > 0 имеет `dom=none`).
5. Sensitivity (§11 брифа) гоняется по одной константе за раз: C5 ±20%
   (0.016/0.024), C6 (0.36/0.54), C4 (×0.8/×1.2), C8 (8/12 тыс.), C2-перегруз
   (0.40/0.60), C10 (0.40/0.60), M7-floor (0.8/1.2 мес). База неизменна.
