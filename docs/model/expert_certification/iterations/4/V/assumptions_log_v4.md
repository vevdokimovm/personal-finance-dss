# Журнал допущений — раунд 4

Каждое допущение: формулировка → мотив → масштаб влияния (программный счётчик по датасету, не оценка на глаз).

**A1. Строка-число в числовом поле = дефект типа.** `"85000"` вместо `85000` — нарушение контракта схемы, запись invalid. Мотив: строгая типизация объявлена в методологии до обработки; финансовый продукт не должен «догадываться», что имел в виду источник данных. Масштаб: interest_rate-строк 47, amount-строк 20, income-строк 34 — суммарно ~101 запись из 600 invalid держится в том числе на этом допущении. Это главная предсказуемая зона расхождений с экспертами-«либералами» (см. прогноз разногласий).

**A2. Целочисленный float в `risk_tolerance` (например 3.0) — валиден.** Мотив: математически это целое, запрет был бы формализмом. Масштаб: 0 случаев в датасете — допущение не понадобилось.

**A3. `r_bench` обязан лежать в [0, 1).** Значение 0.15 = 15% годовых; 15.0 считалось бы дефектом. Масштаб: нарушений 0, диапазон фактический [0.0801; 0.2396].

**A4. Ставка в (2.92; 3.00] — валидна и токсична.** ПСК-кэп 292% — регуляторная граница генератора, а не контракт данных; дефект только > 300%. Масштаб: 0 случаев (генератор не кладёт ставки в эту щель), 64 ставки > 3.00 ушли в invalid.

**A5. Просроченный дедлайн → перепланирование на 12 месяцев.** Дата в прошлом при недоборе цели — не отмена потребности, а сорванный план; req = remaining / 12. Масштаб: 200 целей (все past- и today-цели датасета недобраны).

**A6. Разовое закрытие цели из подушки: только дедлайн ≤ 12 мес и remaining ≥ MIN_LUMP, из излишка сверх целевой подушки.** Мотив: подушка — не источник финансирования дальних целей; близкая цель с покрываемым остатком — да. Масштаб: ходов `close_goal` в lump-планах — учтено в 4 825 записях с lump > 0.

**A7. Бюджетный контракт месячных бакетов — по входному FCF.** Высвобожденные платежи закрытых разовыми ходами кредитов не раздувают res/debt/goal/inv текущего месяца (эффект отражён в вердикте, не в цифрах). Мотив: §6 требует res+debt+goal+inv ≤ max(0, FCF) от входных данных; двойной учёт сломал бы сверку. Масштаб: все 7 334 ok-записи; нарушений бюджета 0.

**A8. Ликвидность и подушка считаются от burn = expense + Σ payments.** Обязательные платежи — часть месячного сжигания; подушка «6 месяцев расходов без кредитов» была бы дырявой. Масштаб: все валидные записи; целевая подушка в среднем на 21% выше, чем при burn = expense.

**A9. MIN_LUMP = 10 000 ₽ отсекает мелкие разовые ходы.** Транзакционные издержки и внимание пользователя дороже эффекта. Масштаб: 223 цели с remaining < 10 000 ₽ при дедлайне ≤ 12 мес не закрываются разово — финансируются месячным потоком.

**A10. Любой дефект любого элемента → вся запись invalid.** Не «выкинуть битую цель и посчитать остальное»: частичный совет по битому портрету опаснее отказа. Масштаб: 25 записей с составными дефектами, 600 invalid всего.

**A11. id из unparseable-строки извлекается регуляркой для позиционного ответа.** Масштаб: 0 случаев (нечитаемых строк нет), защитный код не сработал ни разу.

**A12. burn = 0 → ликвидность ∞, полы lump-ходов = 0.** Портрет без расходов и платежей не имеет месячного сжигания; деление на ноль исключено конструктивно. Масштаб: 35 записей.

**A13. target == current → цель funded, из планов исключена.** Масштаб: 60 целей ровно-профинансированных, ещё 60 перефинансированных (current > target) — трактуются так же.

**A14. ПДН при нулевом доходе с платежами = ∞ (флаг pdn_critical).** Мотив: 0 в знаменателе — предельный случай закредитованности, а не «ПДН неопределён, пропустим». Масштаб: 76 записей.
