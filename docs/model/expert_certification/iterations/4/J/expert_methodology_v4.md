# Экспертная методология и константы (раунд 4)

> **Независимый эксперт по личным финансам, РФ, 2026.** Слепое исследование:
> методология построена **с нуля**, только по приложенным файлам, без опоры на
> чужие алгоритмы, память или прошлые раунды. Все константы **зафиксированы ДО
> обработки данных** и не меняются по ходу (§4.1 брифа). Числовые сдвиги — только
> в отдельном прогоне чувствительности (`sensitivity_v4.md`), исходные значения
> при этом не трогаются.
>
> Дата среза `FROZEN = 2026-07-18`. Все дедлайны — относительно неё.

---

## 0. Философия одной строкой

Свободный поток и избыточную ликвидность распределяю по **водопаду приоритетов**,
максимизируя гарантированный риск-скорректированный результат относительно
безрисковой ставки `r_bench`:

**сначала минимальная безопасность → потом гарантированная доходность (гашение
дорогого/токсичного долга) → потом обязательства с дедлайном → потом полная
подушка → потом остальные цели → потом инвестиции по риск-профилю.**

Это **долговая (avalanche-leaning) школа с защитным полом**: токсичный долг под
50–292% губит капитал быстрее, чем любая цель приносит пользу, поэтому после
минимального буфера он идёт первым. Осознаю, что существует конкурирующая
«резервная/целевая» школа — фиксирую это в `disagreement_forecast_v4.md` и
проверяю в `sensitivity_v4.md`.

## 1. Диагностика (метрики по каждой валидной записи)

| Метрика | Определение | Примечание |
|---|---|---|
| `fcf` (свободный поток) | `income − expense − Σ monthly_payment` | знак определяет `status` |
| `monthly_burn` (обязательный отток) | `expense_total + Σ monthly_payment` | база для подушки и запаса |
| `pdn` (ПДН) | `Σ monthly_payment / income` | если `income = 0` → ∞, флаг `no_income` |
| `liquidity_months` (запас) | `bliq / monthly_burn` | если `burn = 0` → ∞ (кап 999 в отчётах) |
| `reserve_target` | `months(risk) × monthly_burn` | целевая подушка, см. §2 |
| `starter_reserve` | `1 × monthly_burn` | минимальный защитный пол |

**Почему запас и подушку считаю от `monthly_burn`, а не от одних расходов.**
При потере дохода прекращаются не только траты на жизнь, но и обязанность
платить по кредитам никуда не девается — до реструктуризации это тоже отток.
Подушка обязана держать **весь** обязательный поток, иначе при первом же шоке
человек уходит в просрочку. Это осознанно консервативная позиция; эксперт,
считающий подушку от одних расходов, получит меньшие цели и более «здоровые»
запасы — это зафиксированная зона расхождения (см. `assumptions_log_v4.md` A2).

## 2. Целевая подушка по риск-профилю (константа)

Чем консервативнее профиль, тем больше буфер. Пол в 3 месяца держу даже у
агрессивных — ликвидная подушка не заменяется портфелем, она и есть страховка от
необходимости распродавать портфель на дне.

| risk | Название | Полная подушка, мес. `monthly_burn` |
|---|---|---|
| 1 | консервативный | 6 |
| 2 | умеренно-консервативный | 5 |
| 3 | сбалансированный | 4 |
| 4 | умеренно-агрессивный | 3 |
| 5 | агрессивный | 3 |

`starter_reserve = 1 месяц` для всех профилей — неснижаемый защитный пол перед
любой атакой на долг.

## 3. Классификация долга относительно `r_bench` (константы)

Для каждого кредита `spread = interest_rate − r_bench`.

| Класс | Условие | Логика |
|---|---|---|
| **cheap** (дешёвый) | `rate ≤ r_bench + DEAR_SPREAD` | доходность гашения ≤ безрисковой — выгоднее инвестировать; платим только минимум |
| **expensive** (дорогой) | `r_bench + DEAR_SPREAD < rate` и не toxic | гарантированный выигрыш от досрочного гашения > спреда; гасим после защитного пола |
| **toxic** (токсичный) | `rate ≥ TOXIC_ABS` **или** `rate ≥ r_bench + TOXIC_SPREAD` | уничтожает капитал; атакуем первым, разрешён разовый ход из подушки до `starter` |

**Константы:**

| Константа | Значение | Обоснование |
|---|---|---|
| `DEAR_SPREAD` | **0.03** (3 п.п.) | долг дороже безриска менее чем на 3 п.п. даёт слишком тонкий и неустойчивый (налоги, ликвидность) выигрыш от гашения — считаю дешёвым |
| `TOXIC_ABS` | **0.35** (35%) | абсолютный потолок «здоровой» ставки; карты 36–40% и все МФО — токсичны |
| `TOXIC_SPREAD` | **0.20** (20 п.п.) | долг на 20+ п.п. дороже безриска токсичен даже при низком `r_bench` |
| `INVALID_RATE` | **3.00** (300%) | выше — мусор выгрузки (§2.2 брифа); данные подтверждают: легальный максимум 2.92, дефекты на 3.01/12.0 |

Проверка на данных при `r_bench ≈ 0.16`: ипотека 9.8% → cheap; рассрочка 0.9% →
cheap; потребкредит 18% → cheap (спред 2 п.п.); потребкредит 25% → expensive;
карта 36% → toxic; МФО 50–292% → toxic. Согласуется с интуицией советника.

**Дополнительные метки долга (не меняют класс, но флагуются):**
`interest_only` — `monthly_payment ≤ amount × rate / 12` (платёж не покрывает
даже проценты сверх тела) → долг не убывает; `growing_debt` — платёж строго
меньше месячного процента → тело растёт. Оба усиливают приоритет гашения.

## 4. Разовые ходы из накоплений (`lump`)

**Источник разовых ходов — только `bliq` (ликвидная подушка).** Накопленное по
целям (`current_amount`) — отдельный, целевой и, возможно, неликвидный пул; не
считаю его доступной ликвидностью (консервативное чтение «советника по
телефону», §13 брифа). Это зафиксировано как допущение A1.

Водопад разовых ходов (каждый шаг ограничен своим полом по подушке, из `bliq`
последовательно, никогда не уходя ниже пола и не превышая остаток):

1. **Гашение токсичного долга** — из `bliq` сверх `starter_reserve` (1 мес.).
   Гарантированные 35–292% годовых бьют любую ценность кэша. Avalanche: сначала
   самый дорогой.
2. **Гашение дорогого долга** — из `bliq` сверх **полной** подушки. В
   штатную страховку ради «просто дорогого» долга не залезаем.
3. **Закрытие почти готовой срочной цели** — из `bliq` сверх полной подушки,
   если цель профинансирована `≥ GOAL_CLOSE_FRAC` и дедлайн в пределах
   `URGENT_MONTHS`. Добиваем остаток разово.
4. **Размещение явного излишка** — если `bliq` сильно выше полной подушки и нет
   токсичного/дорогого долга и срочных недофинансированных целей, излишек сверх
   `SURPLUS_BUFFER × reserve_target` уводим в инвестиции (риск ≥ 3) или в
   безрисковый инструмент (риск ≤ 2). Это тоже `lump`.

| Константа | Значение | Смысл |
|---|---|---|
| `LUMP_MIN` | **5 000 ₽** | разовые ходы меньше — шум, не предлагаем |
| `GOAL_CLOSE_FRAC` | **0.85** | цель, готовая на 85%+, при срочном дедлайне добивается разом |
| `URGENT_MONTHS` | **12** | дедлайн в пределах года — срочная цель |
| `SURPLUS_BUFFER` | **1.25** | излишком считаем `bliq` сверх 1.25× полной подушки |

Контроль: сумма разовых ходов ≤ `bliq`. Разовое гашение долга не превышает
остаток тела; разовое закрытие цели не превышает её недобор.

## 5. Месячный план (сплит свободного потока `fcf`)

Если `fcf ≤ 0` → `status = deficit`, все месячные бакеты `0` (разовые ходы и
вердикт всё равно даются). Если `fcf > 0`, распределяем `pool = floor(fcf)` по
водопаду; каждый бакет забирает из остатка, пока поток не иссякнет:

1. **`res` — стартовая подушка**: добить `starter_reserve` (с учётом уже
   потраченного/оставшегося `bliq`). Не капируется — маленькая и критичная.
2. **`debt` — токсичный долг**: avalanche-гашение (после разового хода — по
   остаткам). Не капируется.
3. **`debt` — дорогой долг**: avalanche-гашение.
4. **`res` — полная подушка**: добор до `reserve_target`, **капируется**
   `гэп / RESERVE_FILL_MONTHS` в месяц (строим полную подушку ~за год, не
   замораживая всё остальное).
5. **`goal` — цели с дедлайном**: требуемый месячный взнос
   `required = остаток / months_left` по каждой (просрочка → остаток как
   catch-up с флагом). Сортировка по близости дедлайна.
6. **`goal` — бессрочные цели**: делят остаток поровну (перед инвестициями,
   долевой параметр — см. ниже).
7. **`inv` — инвестиции/безриск**: весь остаток. Инструмент — по горизонту (§6).

**Аллокация излишка по риск-профилю (константа).** Шаги 6–7 делят остаток после
целей с дедлайном между «инвестировать» и «доп-буфер безриска» по профилю:

| risk | доля в `inv` | доля в `res` (доп-буфер) |
|---|---|---|
| 1 | 20% | 80% |
| 2 | 40% | 60% |
| 3 | 60% | 40% |
| 4 | 80% | 20% |
| 5 | 100% | 0% |

| Константа | Значение | Смысл |
|---|---|---|
| `RESERVE_FILL_MONTHS` | **12** | горизонт добора полной подушки |
| `URGENT_MONTHS` | 12 | (см. §4) граница срочной цели |

`dom` (доминанта) = argmax из `{debt, res, goal+inv}`; в терминах §6 категории:
`debt` · `reserve` · `goals+` (цели+инвестиции) · `none` (всё ноль).

**Целочисленность и сохранение сумм.** Все бакеты округляются вниз до рубля;
Σ бакетов ≤ `floor(max(0, fcf))` гарантированно. Разовые ходы округляются до
рубля, Σ `lump` ≤ `bliq`. Число нарушений обязано быть 0 (`self_validation_v4.md`).

## 6. Инструменты по горизонту цели (справочно, для прозы и вердикта)

| Горизонт до дедлайна | Инструмент |
|---|---|
| < 1 года / просрочено | только безриск (вклад, накопительный счёт, `r_bench`) |
| 1–3 года | преимущественно безриск + консервативные облигации |
| 3–7 лет | смешанный портфель по риск-профилю |
| > 7 лет / бессрочно | портфель по риск-профилю (для risk 4–5 — акцент на акции) |

Горизонт влияет на инструмент, а не на факт финансирования: недофинансированную
цель с дедлайном финансируем в любом случае (требуемый взнос из §5.5).

## 7. Критерий `invalid` (дефектная запись)

Запись **дефектна** (не чинить, не додумывать: `status=invalid`, `dom=none`, все
суммы `0`, `lump=0`, `confidence=5`), если выполнено хотя бы одно:

1. **Отсутствует обязательный ключ** верхнего уровня: `id`, `income_total`,
   `expense_total`, `obligations`, `goals`, `bliq`, `r_bench`, `risk_tolerance`.
2. **Тип/знак денежного поля** (`income_total`, `expense_total`, `bliq`,
   `r_bench`): не число, `null`, `bool`, строка, или **отрицательное**.
   (Ноль — валиден, §2.4 брифа.)
3. `risk_tolerance` не целое в диапазоне 1–5.
4. `obligations`/`goals` не список; элемент не объект.
5. **Кредит**: отсутствует `name`/`amount`/`interest_rate`/`monthly_payment`;
   `amount` или `monthly_payment` не число или отрицательны; `interest_rate` не
   число, отрицательна или **> 3.00**; `name` не строка.
6. **Цель**: отсутствует `name`/`target_amount`/`current_amount`;
   **отсутствует ключ `deadline`** (≠ явный `null`, §2.3 брифа); `deadline` не
   `null` и не валидная ISO-дата (битый формат/тип); суммы не числа или
   отрицательны; `name` не строка.

Любой дефект в любом вложенном элементе делает **всю запись** invalid: частично
чинить и «спасать» валидные куски нельзя (§2.1). Дубли `id` обрабатываются
**позиционно** — по строке на входную строку, не мержим (§2.5–2.6).

**Валидация критерия на данных.** Критерий даёт ровно **600/12000 = 5.00%**
дефектных (= слой D методички). Позиционная сверка с карточками: **0** записей,
которые я счёл валидными при наличии маркера `!` в карточке (я не пропускаю ни
одного помеченного дефекта). 211 дополнительных дефектов — отрицательные суммы,
ставки > 300% и отсутствующие ключи, которые карточка не оборачивает в `!`, но
которые дефектны по §2. Подробности — `self_validation_v4.md`.

## 8. Правило `confidence` (1–5, детерминированное)

Уверенность отражает, насколько кейс близок к моим порогам: на кромке малое
изменение данных переворачивает решение — там и ждём расхождений экспертов.

- `invalid` → **5** (однозначный отказ).
- Иначе старт **5**, вычитаем за близость к порогам (пол — 1):
  - `|fcf| < max(5000, 0.05 × income)` (поток на ноже нуля): **−2**;
  - `|pdn − 0.40| < 0.03`: **−1**;
  - любой долг со ставкой в пределах `±0.02` от границы класса
    (`r_bench+DEAR_SPREAD`, `TOXIC_ABS`, `r_bench+TOXIC_SPREAD`): **−1**;
  - `|liquidity_months − months(risk)| < 0.5` (подушка ровно у цели): **−1**;
  - есть цель с дедлайном в пределах 1 месяца или просроченная: **−1**;
  - `interest_only`/`growing_debt` присутствует: **−1**.
- Явно глубокий дефицит (`fcf < −0.10 × income`) или явный профицит без долгов и
  срочных целей → близость к нулю не срабатывает, уверенность остаётся высокой.

## 9. Ветки граничных случаев (§4.3 брифа)

| Случай | Обработка |
|---|---|
| Нулевой доход | `pdn=∞`, флаг `no_income`; если есть отток → почти всегда `deficit` |
| Нулевые расходы | `burn = Σ payments`; если и долгов нет → `burn=0`, подушка не нужна |
| `burn = 0` | `reserve_target=0`, `starter=0`, `liquidity=∞`; весь `fcf` → цели/инвест |
| Дефицит | бакеты `0`; разовые ходы (гашение токсичного из подушки) и вердикт — да |
| Перегрузка долгом (ПДН>0.40 / >0.80) | флаги `high_pdn`/`severe_pdn`; обработка штатная |
| Перефинансированная цель (`current ≥ target`) | цель закрыта, взнос `0`, флаг `overfunded_goal`, в вердикте — перенаправить |
| `target == current` в копейку | цель достигнута, взнос `0` |
| Бессрочная цель (`deadline=null`) | без требуемого минимума, финансируется из излишка |
| Просроченный дедлайн | флаг `overdue_goal`, catch-up, при нереалистичности — совет пересмотреть |
| Нет целей / нет кредитов | соответствующие бакеты пусты |
| Нулевая подушка | `starter`-добор — высший приоритет месячного плана |
| Стресс-магнитуда (поле ≥ 1e8) | флаг `stress_magnitude`; правила масштабно-инвариантны, считаем как есть |
