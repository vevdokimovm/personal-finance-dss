# Самопроверка ответов (§4.4–4.5)

> Два независимых скрипта перечитывают **записанные** файлы ответов с диска и
> сверяют их с сырым входом и с карточками. Оба завершаются с кодом 0.
> Воспроизведение: `python validate_answers_v4.py` и `python card_crosscheck_v4.py`.

## 1. Формат / бюджет / enum / полнота — `validate_answers_v4.py`

Проверяется `expert_allocations_v4.csv` + сверка с `summary_v4.csv` и
`recommendations_v4.jsonl.gz`. **Итог: 0 нарушений** по всем 20 проверкам:

| Группа | Что проверено | Результат |
|---|---|---|
| Полнота | 12 000 строк данных в каждом из трёх файлов; шапка CSV точна | OK |
| Позиционный контракт | `id` строки ответа = `id` входной строки по позиции (дубли не мержатся) | OK |
| Кросс-файловая сверка | `id`/`status`/бакеты совпадают между allocations, summary, recommendations | OK |
| Enum | `status∈{ok,deficit,invalid}`, `dom∈{debt,reserve,goals+,none}`, `confidence∈1..5`, суммы ≥ 0 | OK |
| **Бюджет (месячный)** | `res+debt+goal+inv ≤ max(0, ⌊fcf⌋)` для всех валидных | **OK (0 нарушений)** |
| **Бюджет (разовый)** | `lump ≤ bliq` для всех валидных | **OK (0 нарушений)** |
| Знак статуса | `deficit ⇔ fcf<0`; при дефиците месячные бакеты = 0 | OK |
| Дефект | `invalid` ⇒ все суммы 0, `dom=none` | OK |
| Доминанта | `dom` = argmax из {debt, reserve, goals+} (или none) — согласованность с бакетами | OK |

Контроль сохранения сумм из §4.4 брифа выполнен: **0 нарушений** и по месячным
бакетам, и по разовым ходам.

## 2. Сверка JSONL ↔ карточки — `card_crosscheck_v4.py`

- **Полный позиционный скан 12 000 строк**: расхождений `id` между JSONL и
  карточками — **0**; валидных записей, несущих в карточке маркер дефекта `!`, —
  **0** (я не принимаю за валидные ни одной помеченной генератором записи).
- **Детальная числовая сверка** на стратифицированной детерминированной выборке
  (каждый 300-й id + три фиксированных: 1234, 6789, 11111) — **41 валидный
  портрет**, числовых расхождений (доход/расходы/подушка/число кредитов/число
  целей) — **0**. Примеры: SP4-00000, SP4-00300, SP4-00600, SP4-00900,
  SP4-01200, SP4-01234 — все OK.

Дефектные карточки рендерят сырые значения в `!..!` и намеренно исключены из
проверки числового равенства (их нельзя прочитать как числа) — это и есть
критерий `invalid`, а не расхождение.

## Вывод

Записанный комплект ответов формально корректен, полон, укладывается в бюджет
без единого нарушения и побайтово согласован с исходными данными и карточками.
