## 2. Проблемы датасета (по убыванию важности)

**P1. Кредиты не связаны с доходом.** corr(income, платежи) = **0.02**. Итог: у 3 641 из 8 000 «типовых» портретов платежи ≥ 150% дохода, ещё у 1 382 — 80–150%. Де-факто ~63% plain — неплатёжеспособны, т.е. «типовой» слой хуже помеченного `overleveraged` (445 шт.). Последствия: (а) метки типов не отражают фактическое состояние; (б) любая агрегатная метрика качества модели измеряет ветку «реструктуризация», а не качество аллокации (SAW-веса, портфельные сплиты почти не тестируются); (в) сравнение модель↔эксперт вырождается — все эксперты сойдутся на «выживании», различия методик не проявятся.

**P2. Цели не связаны с доходом.** corr(income, Σ target) = **−0.01**. Массовая недостижимость целей — артефакт генератора, а не тестируемое свойство модели.

**P3. 1 482 кредита (6%) — вечные.** Платёж ≤ месячному проценту → долг не амортизируется никогда. Если это задуманный токсичный кейс — нужна метка типа `interest_only_trap`; если нет — баг сэмплера платежей.

**P4. r_bench — всего 5 дискретных значений** {0.10 … 0.20}. Пограничная логика «ставка кредита vs бенчмарк» тестируется в 5 точках вместо непрерывного покрытия; кейсы ставка ≈ r_bench (зона неоднозначности) почти не встречаются.

**P5. `l_min` мёртвое поле** — всегда 0. Либо генерить ненулевые (это отдельная ветка логики), либо убрать из схемы.

**P6. `zero_expenses` экономически бессмыслен** (расходы = 0 у живого человека). Как технический тест деления на ноль — ок, но его надо маркировать «validity-тест», не включать в статистическую популяцию при подсчёте метрик качества.

**P7. Нет поля срока кредита в JSONL** (в карточках есть). Срок восстанавливается из аннуитета, но лучше отдавать явно — меньше места для расхождений между экспертами.

**P8. Нет отрицательных/нулевых сумм, дублей ID, битых дат** — т.е. validity-слой почти пуст. Для тестирования устойчивости парсинга это отдельный нужный слой (см. методичку, слой D).

---

**Следствие для объёма следующей итерации:** при 5-слойной структуре (см. методичку) достаточно ~6 000 портретов вместо 12 000 i.i.d. — информации больше при вдвое меньшем объёме; текущие 444 на edge-тип уже дают ±4.7% точности на страту.
