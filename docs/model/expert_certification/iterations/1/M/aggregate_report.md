# Итоговый отчёт независимой экспертной оценки FINPILOT

**Задача:** слепое (независимое от методики генератора) экспертное оценивание 12 000 синтетических финансовых портретов для тестирования матмодели FINPILOT. Роль: независимый финансовый советник. Методология зафиксирована **до** обработки данных и не менялась по ходу.

**Выходные артефакты:**
- `recommendations.jsonl` — 12 000 структурированных рекомендаций (диагностика, план по долгам, разовое развёртывание излишка, месячный план, план по целям, вердикт);
- `summary.csv` — плоская сводка по всем портретам (одна строка = один портрет);
- `dataset_review.md` — критический разбор самого набора (чек-лист а–з, проблемы P1–P10 с числами);
- `expert_engine.py`, `dataset_stats.py`, `card_crosscheck.py` — исполняемый код (детерминированный движок, статистика, сверка).

# Часть I. Методология (зафиксирована до расчётов)

# Методология независимой экспертной оценки (зафиксирована до обработки данных)

**Эксперт:** независимый финансовый советник (банкинг, экономика, инвестиционное консультирование).
**Дата среза:** 2026-07-08. **Датасет:** `portraits_12000.jsonl`, 12 000 портретов (версия в файле не указана — см. dataset_review, P1). **Валюта:** ₽, потоки месячные, ставки годовые.

**Зафиксированные допущения по семантике входа** (проверены по карточкам до расчётов):
- `expense_total` НЕ включает платежи по кредитам (карточки: «Расходы — … (без платежей по кредитам)»).
- `bliq` — ликвидная подушка в ₽; `l_min` — минимальный порог ликвидности в месяцах (в сете константа 0).
- `r_bench` — годовая доходность-бенчмарк безрисковой альтернативы (депозит/ОФЗ короткой дюрации).

## 1. Базовые метрики

| Метрика | Формула |
|---|---|
| Обязательный отток | `outflow = expense_total + Σ monthly_payment` |
| Свободный поток (FCF) | `income_total − outflow` |
| ПДН (DSTI) | `Σ monthly_payment / income_total`; при доходе 0 и платежах > 0 — не определён (флаг `dsti_undefined`, трактуется как критический) |
| Ликвидность, мес. (Lt) | `bliq / outflow`; при `outflow = 0` — не определена (флаг `liq_undefined`) |

## 2. Константы

**Пороги ПДН:** < 0.30 — комфортный; 0.30–0.50 — повышенный; 0.50–0.80 — высокий; ≥ 0.80 — критический. (Ориентиры макропруденциальных надбавок ЦБ РФ — 50 % и 80 %; 30 % — консервативный комфорт-порог розничного андеррайтинга.)

**Целевая подушка** (месяцев обязательного оттока, по риск-профилю 1–5): 6 / 5 / 4 / 3 / 3. Итог: `target_months = max(l_min, по профилю)`; `target_cushion = target_months × outflow`. Минимальная стартовая подушка — 1 месяц оттока. При `outflow = 0` целевая подушка = 0 (флаг `no_outflow`), весь `bliq` — потенциальный излишек.

**Классификация долга по ставке относительно `r_bench`:**
- **дорогой**: `rate > r_bench + 0.015` (спред 1.5 п.п. — премия за риск/налоги/потерю ликвидности: гарантированная «доходность» досрочного погашения должна бить бенчмарк с запасом) → приоритетное досрочное погашение, avalanche (по убыванию ставки);
- **нейтральный**: `r_bench < rate ≤ r_bench + 0.015` → платить по графику, досрочно не гасить;
- **дешёвый**: `rate ≤ r_bench` → платить строго по графику, досрочное погашение экономически невыгодно.
- **Interest-only** (`monthly_payment ≤ amount × rate/12`): долг математически не амортизируется — флаг `interest_only_debt`, рекомендация реструктуризации; если дорогой — первый кандидат на досрочное/рефинансирование.

**Аллокация акции/облигации по риск-профилю (1–5):** 0/100, 20/80, 40/60, 60/40, 80/20.

**Инструменты по горизонту цели (месяцев до дедлайна):**
- < 12: депозит / фонд денежного рынка (доля акций 0 %);
- 12–36: ОФЗ и корпоративные облигации короткой дюрации + депозит (акций 0 %);
- 36–84: смешанный портфель, доля акций = min(профильная, 50 %);
- > 84 или без дедлайна: полный профильный портфель.

**Ожидаемая доходность** для проверки достижимости: `r_exp = r_bench + eq_share_eff × ERP`, премия за риск акций ERP = 4 п.п. годовых; месячная ставка `i = (1 + r_exp)^(1/12) − 1`. Для горизонта < 12 мес. `r_exp = r_bench`.

## 3. Месячный водопад распределения FCF (при FCF > 0)

1. `Lt < 1` мес. → **100 %** FCF в подушку.
2. Есть дорогие долги: подушка ниже цели → **70 %** avalanche / **30 %** подушка; подушка на цели → **80 %** avalanche / **20 %** цели. Если транш превышает остаток тел дорогих долгов (после lump) — избыток переливается в цели.
3. Нет дорогих долгов: подушка ниже цели → **60 %** подушка / **40 %** цели; подушка на цели → **100 %** цели.
4. Бакет целей: цели с дедлайном в порядке возрастания дедлайна получают требуемый месячный взнос (см. §5); остаток — целям без дедлайна пропорционально остаточной потребности; если целей нет либо все закрыты — бакет «инвестиции сверх целей» по профильной аллокации.

**Контроль:** Σ месячных бакетов = `max(0, FCF)` с точностью до копейки. При FCF ≤ 0 все бакеты равны 0 (кризисная ветка).

## 4. Развёртывание излишка ликвидности (lump)

`deployable = max(0, bliq − target_cushion)`. Развёртывание разрешено только при `FCF > 0` и `ПДН < 0.50`; иначе излишек заморожен как резерв выживания (флаг `lump_frozen`, план пуст). Порядок: (1) дорогие долги avalanche до полного тела; (2) цели по возрастанию дедлайна до закрытия остатка потребности (инструмент — по горизонту); (3) остаток — инвестиции по профильной аллокации. **Контроль:** Σ lump-действий ≤ `deployable`.

## 5. Цели

Месяцев до дедлайна: `n = floor((deadline − 2026-07-08).days / 30.4375)`, минимум 1 для будущих дедлайнов. Требуемый взнос: `need_fv = target − current × (1+i)^n`; при `need_fv ≤ 0` взнос 0 (цель закрывается органическим ростом). `PMT = need_fv × i / ((1+i)^n − 1)` (при `i = 0` — `need_fv / n`).

Статусы: `achieved` (current = target), `overfunded` (current > target, рекомендация высвободить излишек — вне контроля сумм lump), `on_track` (назначенный транш ≥ требуемого, допуск 1 %), `underfunded`, `unreachable` (требуемый взнос > всего FCF), `no_deadline` (расчёт срока достижения при фактическом транше), `overdue` (дедлайн в прошлом: разовая потребность + пересчёт реалистичного срока).

## 6. Статус профиля (детерминированная лестница, первый сработавший)

1. `INVALID` — брак данных (отрицательные суммы, NaN, битые даты, дубли ID, отсутствующие обязательные поля, риск вне 1–5): запись отклоняется с флагами, советы не выдаются.
2. `CRISIS` (кризис) — FCF < 0, или ПДН ≥ 0.80, или ПДН не определён при платежах > 0. Доп. диагностика: `runway = bliq / |FCF|` — месяцев жизни на подушке.
3. `STRAINED` (напряжённый) — ПДН ≥ 0.50 или Lt < 1.
4. `STABILIZING` (стабилизация) — есть дорогие долги или подушка ниже цели.
5. `SURPLUS` (профицит) — излишек > 0 и (целей нет или все on_track/achieved/overfunded).
6. `STEADY` (устойчивый) — остальное.

## 7. Граничные ветки (явные)

Нулевой доход → CRISIS (при платежах/расходах) либо «спящий» профиль (отток 0). Нулевые расходы → ПДН и водопад считаются штатно, отток = платежи. Дефицит потока → кризисная ветка, runway, без развёртывания lump. Перегруженность долгами → пороги ПДН. Перефинансированные цели → взнос 0 + высвобождение излишка. Цели без дедлайна → остаточное финансирование + срок достижения. Просроченные дедлайны → overdue-ветка. Отсутствие целей → бакет «инвестиции сверх целей». Отсутствие кредитов → долговые ветки пропускаются. Аномальная подушка → deployable-механика без капов.

Правила детерминированные, одинаковые для всех 12 000 записей; обработка программная и полная. Один прогон, без ручных правок выходов.

# Часть IV. Главный вывод

Движок и контроли исправны (0 нарушений инвариантов, чистая сверка). **Однако сам тест-сет в текущем виде для полноценного тестирования матмодели непригоден** из-за корневых дефектов генератора:

1. **Долг не привязан к доходу** (income↔payments = 0.024) → 81 % портретов в кризисной ветке → **основная логика распределения профицита тестируется лишь на 19 % набора** (P2).
2. **Метка `overleveraged` инвертирована** — «перегруженный» срез легче типового (медианный ПДН 0.68 против 1.29) (P3).
3. **Аннуитет не соблюдён** — формуле соответствуют 12.7 % кредитов при допуске 0.1 % (P4).

Полный перечень (P1–P10) с числами и конкретными исправлениями генератора — в `dataset_review.md`. После починки связки долг↔доход↔аннуитет (блокер) и добавления слоёв DOE/validity/метаморфики набор станет пригоден; приёмочные тесты §3 методики следует вынести в CI генератора как gate.
