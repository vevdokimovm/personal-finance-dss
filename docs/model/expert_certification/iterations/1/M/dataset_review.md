## Проблемы (P1–P10) с числами и последствиями

**P1 — Нет паспорта набора.** Первая строка JSONL не содержит `dataset_version` / `seed` / конфигурации генератора; seed 20260702 указан только в шапке карточек. *Последствие:* прогон невоспроизводим из самого набора, невозможно связать результат теста с версией генератора. *Фикс:* добавить первую строку-объект с версией, seed, датой генерации, счётчиками слоёв и хэшем конфига.

**P2 — Платежи по кредитам не привязаны к доходу (корневой дефект).** income↔payments Пирсон 0.024 (plain), медианный ПДН plain 1.29, ПДН ≥ 0.8 у 62.8 % plain; FCF < 0 у 80.8 % всего набора. *Последствие:* набор вырожден в «поголовный кризис», основная логика модели не нагружается; распределение ПДН не похоже ни на один реальный кредитный портфель. *Фикс:* генерировать долг от целевого ПДН: сначала розыгрыш `dsti* ~` смеси (напр. большинство 0.1–0.4, тонкий хвост 0.5–0.8, единицы процентов > 0.8), затем `Σ payment = dsti* × income`, и уже из платежа и срока восстанавливать `amount` через аннуитет. Требование методики (хвост ПДН > 80 % — единицы процентов) сейчас нарушено более чем на порядок.

**P3 — Инверсия метки `overleveraged`.** Медианный ПДН 0.678 против 1.287 у plain; доля ПДН ≥ 0.8 — 24 % против 62.8 % у plain. *Последствие:* специальный «тяжёлый» срез легче базовой популяции — тест на устойчивость к перегрузу фактически проверяет обратное; метка вводит в заблуждение. *Фикс:* после починки P2 задать `overleveraged` явным диапазоном ПДН (напр. 0.6–1.2) — тогда он станет действительно верхним хвостом, а не подмножеством с заниженной нагрузкой.

**P4 — Платежи не согласованы с аннуитетом.** Из 24 368 кредитов при допуске 0.1 % аннуитетной формуле (целый срок 6–360 мес) соответствуют лишь **3083 (12.7 %)**; при допуске 1 % — 17 665 (72.5 %); чистых interest-only (платёж ≤ проценты) — 1482 (6.1 %). *Последствие:* «срок» кредита в карточках декоративен, платёж не выводит корректный график погашения — расчёт процентов/срока досрочного закрытия на этих данных нельзя верифицировать. Приёмочный тест «аннуитет 100 %» проваливается. *Фикс:* генерировать платёж строго `PMT = A·i / (1 − (1+i)^−n)` с целым `n ∈ [6, 360]`, затем округлять до копейки один раз и хранить и `n`, и платёж.

**P5 — Вырожденные `r_bench` и `l_min`.** `r_bench` принимает 5 фиксированных значений вместо непрерывного диапазона; `l_min` = 0 у всех 12 000. *Последствие:* граница «дорогой/дешёвый долг» тестируется лишь в 5 точках; ветка минимального порога ликвидности не тестируется вовсе. *Фикс:* `r_bench` — непрерывно (напр. 0.09–0.21), `l_min` — розыгрыш из {0, 1, 2, 3, 6} мес, чтобы задействовать соответствующую ветку модели.

**P6 — Цели не масштабированы доходом.** income↔goal_target_sum Пирсон −0.009; коэффициент k = Σtarget / годовой доход: p50 2.63, p90 6.87, p99 13.47, max 26.77. *Последствие:* заявленный диапазон k ∈ [0.2, 5] нарушен — у существенной доли портретов цели физически недостижимы при любом плане, статус `unreachable` выставляется массово и неинформативно. *Фикс:* привязать `target` к доходу — `target = k × 12 × income`, `k` из [0.2, 5], и лишь отдельным малым слоём — заведомо недостижимые цели как стресс.

**P7 — Отсутствуют слои B / D / E.** Фактически только популяция (plain, 66.7 %) и границы (edge, 33.3 %); DOE/LHS-сетка, validity-срез и метаморфические пары как размеченные группы отсутствуют. *Последствие:* нет систематического покрытия пространства параметров (DOE), нет негативных кейсов для проверки валидации входа (модель не проверяется на мусоре), нет метаморфических инвариантов (монотонность ответа при масштабировании дохода и т. п.). *Фикс:* добавить LHS-сетку по (income, dsti, risk, r_bench, l_min, k, горизонт), явный validity-слой с битыми/пограничными записями и метаморфические пары (базовый портрет + его контролируемая трансформация с известным ожидаемым сдвигом ответа).

**P8 — Неполный каталог граничных случаев.** Просроченных дедлайнов — 0; дедлайнов «сегодня» — 0; целей ровно `current = target` (копейка-в-копейку) — 0; горизонтов ≥ 84 мес — 0 (макс. 58.9 мес при заявленных 10 годах); сумм порядка 10⁹ — нет; «8 целей на один дедлайн» — 1 портрет. *Последствие:* ветки `overdue`, `deadline_today`, `achieved`-ровно, длинного горизонта (полный профильный портфель по горизонту > 84 мес) и экстремальных сумм не покрыты. *Фикс:* добавить целевые edge-кейсы под каждую граничную ветку модели, включая просрочку, ровное равенство, дедлайны у сегодняшней даты, горизонты до 120 мес и суммы у верхней границы валидного диапазона.

**P9 — Счётность как равномерный шум.** `n_loans` (0–4) и `n_goals` (0–4, плюс пик 8) распределены почти равномерно. *Последствие:* реалистичная популяция имеет убывающее распределение числа кредитов/целей; равномерность завышает долю сложных портретов и не отражает типичного пользователя. *Фикс:* задать убывающее распределение (напр. усечённое Пуассона/геометрическое) для числа обязательств и целей.

**P10 — Смысловая нагрузка вынесена в необязательный слой.** «Срок кредита», разбивки дохода/расходов, названия целей и банков живут только в карточках (`.md`); в JSONL, который потребляет модель, `name` целей — плейсхолдеры `goal_1..goal_8`, у кредитов нет срока. *Последствие:* поле `deadline` — единственный носитель горизонта, срок кредита для расчёта графика недоступен движку; тест не может проверить логику, зависящую от срока обязательства. *Фикс:* перенести `term_months` кредита в движковый объект (и хранить его согласованно с платежом — см. P4).

## Приоритет исправлений для следующей итерации генератора

1. **P2 + P3 + P4** (связка долг↔доход↔аннуитет) — без этого набор непригоден для теста основной логики; это блокер.
2. **P6** (масштаб целей от дохода) — убирает массовый ложный `unreachable`.
3. **P8 + P5** (полный каталог границ + непрерывные r_bench/l_min) — покрывает незадействованные ветки.
4. **P7** (слои B/D/E) — переводит набор из «популяция + границы» в полноценный DOE + validity + метаморфика.
5. **P1 + P10 + P9** (паспорт, срок кредита в движок, реалистичная счётность) — гигиена и воспроизводимость.

**Обязательный шаг:** вынести приёмочные тесты (§3 методики: доля FCF<0 в норме, хвост ПДН, 100 % аннуитет, диапазон k, покрытие горизонтов) в CI генератора как gate — тогда дефекты P2/P4/P6 не дойдут до релиза набора.
