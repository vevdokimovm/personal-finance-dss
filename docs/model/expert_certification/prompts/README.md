# Эволюция экспертного промпта: что менялось от итерации к итерации и почему

> Промпт — это инструмент измерения. Меняя его, мы меняем то, что видим, поэтому
> каждое изменение фиксируется здесь с причиной. Живые файлы промптов не
> дублируются — ссылки ниже ведут на них.

| Итерация | Файл | Формат ответа | Что добавилось и почему |
|---|---|---|---|
| **1** (датасет v1) | `docs/model/expert_certification/expert_prompt_unified.md` | `recommendations.jsonl` — богатая запись (diagnostics, debt_plan, lump_sum_plan, monthly_plan, goal_plan, verdict) + `summary.csv` + `aggregate_report.md` + `dataset_review.md` + движок | Базовый промпт (написан вместе с методичкой тест-сетов). Слепоты **не было**: записи содержали `kind` — эксперт видел типы портретов. Ревью датасета по чек-листу а–з. |
| **2** (датасет v2) | `docs/model/expert_brief_v2.md` | **CSV** `id,status,dom,res,debt,goal,inv,lump` | Слепая раздача (метки убраны). Переход на CSV: 4 × 12 000 jsonl не сводились автоматически, а для метрики согласия нужен один плоский формат. Потери: пропала проза-обоснование и богатая разметка — их сохранил только один аккаунт. |
| **3** (датасет v3) | `docs/model/expert_brief_v3.md` | CSV + `run_metadata.md` | Появился слой D → правило **`status=invalid`** («не чинить и не додумывать»). Дубли id → правило «одна строка ответа на входную строку, в порядке входа». `run_metadata` стал обязательным (в р.2 его не собрали — часть расхождений осталась необъяснимой). |
| **4** (датасет v4) | `docs/model/expert_brief_v4.md` | CSV + **обязательный комплект из 13 артефактов** | (1) Критерий `invalid` уточнён по расхождениям р.3: ставка > 300% = мусор; отсутствие ключа ≠ `null`; пограничное читаемое — не дефект. (2) Введены **валидные дубли id** → правило «мержить по id нельзя». (3) Возвращены и сделаны обязательными для всех находки прошлых раундов (`artifact_catalog.md`): богатый jsonl, summary с диагностикой, самовалидация, приёмка датасета, проза + ручная сверка на 40 портретах. (4) Ревью датасета — в два прохода, с обязательным разделом «что хорошо». |

## Инварианты (не менялись ни разу)

- **Слепота к алгоритму:** эксперт не знает, с чем сравнивают, и не должен гадать.
- **Константы фиксируются ДО обработки** и не меняются по ходу.
- **Полная программная обработка** всех записей, без выборок.
- **Контроль сохранения сумм** с отчётом о числе нарушений (ожидается 0).
- **Свежая сессия**, без памяти и контекста проекта.

## Правило изменения промпта

Промпт правится **только** между итерациями и только по двум основаниям:
(1) эксперты разошлись в трактовке — значит формулировка неоднозначна;
(2) находка одного эксперта оказалась ценной — значит её делают все
(см. `artifact_catalog.md`). Изменение без основания запрещено: оно ломает
сравнимость раундов.
