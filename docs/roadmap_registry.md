# Реестр редакций роадмапа

> Приказ владельца (2026-07-03): старые карты вех не теряем. `docs/ROADMAP.md` всегда
> содержит ТОЛЬКО актуальную редакцию; каждая смена карты (состав/порядок/темы вех)
> фиксируется здесь новой строкой-редакцией с обоснованием. Детальные тексты старых
> редакций не копируем — они восстановимы из git-истории файла и из архивов релизов
> (указана версия-граница). Правило: изменил карту вех → добавь редакцию сюда +
> строку `_(Редакция RN...)_` под таблицей вех в ROADMAP.

## R1 — «старый роадмап» P0–P3 (до вехи 4)

- **Файл:** `03_Будущий_роадмап.md` (вне репо; жил в базе знаний проекта Claude).
- **Структура:** приоритеты P0 (прод-минимум) → P1 (качество) → P2 (ценность) →
  P3 (перспектива), без нумерации вех.
- **Действовал:** до старта карты вех (v4.0.0).
- **Судьба:** поглощён — почти все пункты закрыты в вехе 4, остатки разложены по
  вехам (см. `ROADMAP.md` «Что уже сделано» и вливания P1.5/P2.1–P2.3/P3.1–P3.2 в
  веху фронта). История закрытий — `CHANGELOG.md`, `docs/RELEASES.md`.

## R2 — карта вех 4–9, порядок «фронт до тестирования»

- **Порядок:** бэк(4) → организация(5) → **фронт(6) → тестирование(7)** → юр(8) → деплой(9).
- **Действовал:** v4.0.0 – v5.17.0.
- **Логика:** сначала показать возможности бэка пользователю, потом фундаментальная
  проверка ядра перед юр/деплоем.
- **Где смотреть текст:** `docs/ROADMAP.md` в архивах релизов ≤ v5.17.0 (assets
  GitHub приватного репо) и git-история файла.

## R3 — карта вех 4–9, порядок «тестирование до фронта» (АКТУАЛЬНАЯ)

- **Порядок:** бэк(4) → организация(5) → **тестирование(6) → фронт(7)** → юр(8) → деплой(9).
- **Действует:** с v5.18.0 (приказ владельца 2026-07-03).
- **Обоснование:** ядро (мат-модель, импорт) проверяем ДО строительства React-фронта
  поверх него — если тестирование потребует правок модели/контракта, UI не придётся
  переделывать; пред-работа уже есть (портретный свип 12k, v5.17.0). Юриспруденция
  остаётся вехой 8 (после фронта): полные юр-документы зависят от финальной
  пользовательской поверхности, а юр-требования к UI зафиксированы заранее в
  корневом `LEGAL.md` — фронт (веха 7) закладывает их сразу, без ожидания юриста.
- **Затронутые перенумерации:** `§6.x` = тестирование (бывш. 7.x), `§7.x` = фронт
  (бывш. 6.x); свип ссылок по репо — см. merge-манифест
  `docs/reports/merges/merge_manifest_v5_18_0.md`.
