# API-контракт — принципы и снапшот

> Короткий контракт поверх автогенерируемой спеки. **Снапшот:** `docs/api/openapi.json` —
> фиксированная точка для вехи 8 (фронт пишется против него, дрейф виден дифом).
> Перегенерация: `python tools/api_snapshot/dump_openapi.py` (venv, ~секунда).

## Принципы

1. **REST поверх FastAPI**, JSON-only. SSR-страницы — отдельные роуты, не API.
2. **Auth:** `Authorization: Bearer <JWT c jti>`. Гостевой режим — без заголовка (данные
   `user_id IS NULL`). Ревокация server-side: logout (jti) / logout-all (`tokens_valid_since`).
3. **Версионирование:** внутренний фронт — `/api/*` без версии (мы единственный потребитель до
   вехи 6 включительно); внешний B2B — `/v1/*` (контракт стабильный, ломающие изменения = `/v2`).
4. **Ошибки:** FastAPI-формат `{"detail": ...}`; валидация — 422 с полями Pydantic; доменные
   отказы — 400/409 с человекочитаемым detail; auth — 401/403; rate-limit — 429.
5. **204-паттерн:** удаления возвращают `Response(status_code=204)` без тела (WebKit-грабля —
   `docs/engineering_practices.md`).
6. **CSRF:** cookie/форменные маршруты под CSRFMiddleware; чистый Bearer-API — нет.
7. **Идемпотентность:** GET/PUT/DELETE идемпотентны; POST-расчёт (`/api/planning/calculate`)
   детерминирован на фиксированных входах (кроме Monte-Carlo сида — фикс в тестах).
8. **Пагинация:** limit/offset на списках; дефолт и потолок — в схемах Pydantic.

## Снапшот-дисциплина

- Снапшот перегенерируется **в каждом батче, меняющем роуты/схемы**; диф попадает в ревью батча.
- CI-проверка «спека не дрейфует молча» — кандидат в fast-tier (веха 8, вместе со стартом фронта).
- Источник истины — код; снапшот — зафиксированное обещание фронту.
