# SLO и перф-бюджеты

> Целевые уровни сервиса до нагрузочного тестирования (веха 7, Locust) и деплоя (веха 9).
> Принцип: бюджеты фиксируем ДО оптимизаций — иначе «быстро» останется мнением.

## Доступность (MVP → рост)

- **99.5%** месячная доступность на старте (даунтайм ≤ ~3.6 ч/мес; один VPS, без HA);
  после выхода на платящих — пересмотр к 99.9% (веха 9+, требует резервирования).
- Error budget: 0.5%/мес; сгорел — фичи стоп, стабилизация.

## Латентность (p95, сервер, без сети клиента)

| Класс | Цель p95 | Комментарий |
|---|---|---|
| SSR-страницы | ≤ 300 мс | Jinja2 + лёгкие запросы |
| CRUD `/api/*` | ≤ 150 мс | одиночные сущности, пагинация |
| `/api/planning/calculate` | ≤ 1200 мс | 66 альтернатив + SES + Monte-Carlo (доминанта CPU) |
| Импорт выписки (файл ≤ 1 МБ) | ≤ 5 с | парсинг + категоризация + вставка |
| `/v1/analyze` (B2B) | ≤ 1500 мс | внешний контракт, буфер к внутреннему |

Полный расчёт тяжелее 1200 мс — кандидат на прогрев/кэш `cbr_key_rate_cache` (уже есть) и
предрасчёт прогноза; фиксируем факт на Locust до оптимизаций.

## Пропускная способность (цели Locust, веха 7)

- Базовый профиль: 50 RPS смешанного трафика (80% чтение / 20% запись) без деградации p95.
- Пиковый: 10 одновременных `calculate` — p95 ≤ 2× бюджета, без 5xx.
- Импорт: 5 параллельных файлов — без блокировок БД (матрица PG обязательна).

## Деградации (уже в коде — фиксируем как контракт)

- cbr.ru недоступен → БД-кэш ставки → фолбэк 0.14; расчёт НЕ падает.
- SMTP/Telegram/Sentry недоступны → функциональность ядра не блокируется (фоновые отправки).
- Rate-limit: 429 с заголовками окна; лимиты — `app/config.py`.

## Измерение

`RequestLoggingMiddleware` (X-Request-ID, финальный статус) + Sentry perf; Locust-скрипты и
пороги — `docs/reports/testing/` (веха 7). SLO нарушен две недели подряд → инцидент по диспетчеру.
