# Операционная таблица Claude для FINPILOT

Сводка семи заходов исследования (30.07–05.08.2026) в один рабочий справочник: что выбрать,
сколько это стоит по времени и токенам, и насколько числу можно верить. Исходники —
`docs/research/raw/`, выжимки — `docs/research/*.md`.

**Метки уверенности.** [ОД] официальная документация Anthropic · [НП] независимо измерено
(указан кто) · [ОЦ] оценка · [ДН] публично не существует.

## 1. Модель × усилие × время × токены

Замеры латентности — Artificial Analysis, медиана P50 за 72 часа при нагрузке 10 000 входных
токенов. TTFT у ризонинг-моделей включает время «мышления», то есть это **не** сетевая задержка.
E2E — производная (TTFT + 500 / скорость), помечена как оценка.

| Модель / усилие | TTFT, с | Скорость, t/s | E2E на 500 ток., с | Уверенность |
|---|---|---|---|---|
| Opus 5 low | 2,98 | 51,6 | ~12,7 | [НП] AA / E2E [ОЦ] |
| Opus 5 medium | 6,46 | ~52 | ~16 | [НП] AA / E2E [ОЦ] |
| Opus 5 high | 12,83 | ~53 | ~22 | [НП] AA / E2E [ОЦ] |
| Opus 5 xhigh | 24,63 | ~53 | ~34 | [НП] AA / E2E [ОЦ] |
| **Opus 5 max** | **92,02** (eesel: 68) | 53,8 | ~101,3 | [НП] AA + eesel / E2E [ОЦ] |
| Sonnet 5 max | 179 | — | — | [НП] AA |
| Fable 5 (разбивка по усилиям) | — | — | — | **[ДН]** |

**Три факта, которые меняют поведение:**

1. Скорость генерации Opus 5 почти не зависит от усилия (≈50–55 t/s на всех уровнях).
   Растёт только объём размышлений, а значит TTFT и полное время. Поднимая effort, вы
   покупаете обдумывание, а не скорость.
2. Разница low → max по времени до первого токена — **тридцатикратная** (2,98 → 92,02 с).
   Это самая дорогая ручка в контуре.
3. Между снапшотами AA есть разброс (Opus 5 medium 6,46 против 6,13; Sonnet 5 max 179,03
   против 192,06) — разные 72-часовые окна. Порядок величины устойчив, третья значащая цифра — нет.

**Наш дефолт:** Opus 5 / high. `max` — только эскалация на сложную многофайловую отладку
и архитектурные развилки. Для React-компонентов и рефакторинга TS max почти всегда избыточен.

## 2. Что сколько стоит в контексте

| Статья | Токены | Уверенность |
|---|---|---|
| Системный промпт свежей сессии Claude Code | ~4 200 | [ОЦ] вторичный источник со ссылкой на доки |
| `CLAUDE.md` до первого промпта | ~1 800 | [ОЦ] там же |
| Чтение одного файла | 1 100 – 2 400 | [ОЦ] там же |
| Определение одного MCP-инструмента | 200 – 800 **на каждый запрос** | [ОД] |
| 3 MCP-сервера по 50 инструментов | ≈60 000 на ход | [ОД] |
| MCP после Tool Search | ~600 вместо ~12 000 (−95%) | [ОД] |
| Оверхед Claude Code на первый запрос | ≈33 000 | [НП] Systima |
| Коннектор GitHub в claude.ai | ≈26 000 на каждом ходу | [НП] |
| Точные токены на правку файла, на скриншот Playwright, остаток окна | — | **[ДН]** |

## 3. Множители делегирования

| Что | Множитель | Уверенность |
|---|---|---|
| Fan-out на 2 субагента, Opus | до 2,6× | [НП] Systima |
| Fan-out на 2 субагента, Fable | до 5,9× | [НП] Systima |
| Зафиксированный худший кейс | 4,2× (513k против 121k) | [НП] Systima |
| Agent teams против обычной сессии | ≈7× | [ОД] |
| Пиннинг субагентов на Haiku | −37% | [НП] Systima |
| Параллелизм на мелких задачах | **медленнее**: 8 мин против 4,25 | [НП] Systima |

Причина официальна: каждый субагент держит собственное полное окно контекста.
**Порог отказа:** множитель >3× без выигрыша по времени — fan-out на этой задаче не нужен.

## 4. Кэш

| Параметр | Значение | Уверенность |
|---|---|---|
| Чтение из кэша | 10% базовой цены входа | [ОД] |
| Запись в кэш, TTL 5 мин | +25% | [ОД] |
| Запись в кэш, TTL 1 час | +100% | [ОД] |
| Точка окупаемости | второй хит | [ОЦ] |
| Минимальный кэшируемый блок | 1024 ток. (Sonnet/Opus), 2048 (Haiku) | [ОД] |
| Экономия на входе | до −90% | [ОД], независимо 60–90% |
| Экономия латентности на длинном префиксе | до −85% | [ОД] |
| Здоровое отношение `cache_read / total_input` | **>0,7** | [ОЦ] порог для действия |

**Что ломает кэш:** любой изменившийся токен **до** breakpoint. Динамическая дата или
`session_id` в начале системного промпта = промах на каждом вызове. Структура должна быть
«статичное знание → маркер → динамика». На Opus 5 смена набора инструментов в середине
диалога кэш больше не инвалидирует [ОД].

## 5. Выбор механизма управления

| Механизм | Задача | Когда брать |
|---|---|---|
| Hook | Enforcement | Пропуск должен быть НЕВОЗМОЖЕН: безопасность, гейты, формат |
| CLAUDE.md | Guidance всегда | Конвенция, нужная каждую сессию (стек, стиль) |
| Rules (`paths:`) | Guidance точечно | Конвенция для конкретных путей и типов файлов |
| Skill | Capability | Процедура со своими инструкциями и скриптами, on-demand |
| Subagent | Delegated work | Изоляция контекста, свой tool-set, независимая ветка |
| Output style | Роль, тон, формат | Как Claude общается глобально |
| MCP | Внешние данные | Доступ к БД, API, сервисам |

**Тест выбора:** какова цена, если модель проигнорирует это один раз? Раздражение → CLAUDE.md.
Инцидент → hook.

## 6. Пороги, при которых меняем решение

| Наблюдение | Действие |
|---|---|
| Контекст baseline >30% на старте сессии | Чистить CLAUDE.md, отключать лишние MCP и коннекторы |
| Заполнение контекста >60–70% | Качество деградирует: `/compact focus on X` или новый чат |
| `cache_read / total_input` <0,7 | Искать дрейфующий токен в префиксе |
| Множитель субагента >3× без выигрыша | Отказаться от fan-out |
| MCP-строка в `/context` заметна | Проверить, включился ли Tool Search |
| Recall код-ревью упал после апгрейда | «Report every issue, filter separately» вместо «only high-severity» |
| Работа идёт >1 суток без собранного архива | Собрать чекпоинт немедленно (PIT-015) |

## 7. Диагностика: чем смотреть

| Команда | Что показывает |
|---|---|
| `/context` | Разбивка токенов по категориям, свободное место |
| `/usage` (`/cost`, `/stats`) | Стоимость сессии и остаток лимитов плана |
| `/memory` | Все загруженные CLAUDE.md и rules |
| `/hooks` | Read-only просмотр событий и какой settings-файл дал хук |
| `/mcp` | Стоимость по серверам |
| `/doctor` | Авто-аудит CLAUDE.md и скиллов под Claude 5 |
| Ctrl+O | Verbose transcript |
| `claude --debug` | Debug-лог |

Внешние: OpenTelemetry (`CLAUDE_CODE_ENABLE_TELEMETRY=1` + OTLP endpoint) → Prometheus/Grafana/SigNoz;
`npx ccusage@latest daily`; транскрипты в `~/.claude/projects/<hash>/`.

## 8. Ориентир стоимости

«Around $13 per developer per active day and $150-250 per developer per month, with costs
remaining below $30 per active day for 90% of users» [ОД]. Это про API-биллинг; на подписочном
плане ограничение другое — пятичасовое окно, и его расходуют те же множители из разделов 2–4.

## 9. Чего публично не существует

Отрицательный результат ценен: он избавляет от повторного поиска.

- Разбивка TTFT/скорости Fable 5 по уровням усилия.
- Формула зависимости TTFT от длины входного контекста для 5-поколения.
- Разбивка латентности по поверхностям (API / Claude Code / claude.ai / Cowork).
- Деградация латентности в пиковые часы.
- Распределение длительности сессий Claude Code.
- Точные токены на правку файла и на скриншот Playwright.
- Соотношение reasoning/answer токенов по уровням усилия.
- Остаток окна в токенах.

Всё перечисленное — только собственными замерами. Методика и шаблоны — `docs/claude_token_lab/`.
