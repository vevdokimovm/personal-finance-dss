# Карта персональных данных (ПДн) — для юриста и 152-ФЗ

> Инвентаризация: какие ПДн обрабатываем, где лежат, зачем, на каком основании, как защищены,
> как удаляются. Опора для вехи 8 (юр) и приложение к `docs/legal_questions_for_lawyer.md`.
> Схема-источник: `app/database/models.py` (28 таблиц), срез защиты — `SECURITY.md`.

## Категории и размещение

| Категория ПДн | Таблицы / колонки | Цель обработки | Основание | Защита в покое |
|---|---|---|---|---|
| Идентификатор личности | `users.email` (UK) | аккаунт, вход, письма verify/reset | согласие при регистрации (чекбокс consent) | БД-доступ; TLS в транзите |
| Аутентификационные | `users.password_hash`, `mfa_recovery_codes.code_hash`, `revoked_tokens.jti`, `mfa_pending_attempts.jti` | вход, MFA, ревокация сессий | согласие / законный интерес (безопасность) | bcrypt / хеши; необратимо |
| Финансовые сведения | `transactions.*`, `obligations.*`, `goals.*`, `liquid_assets.*`, `budgets.*`, `plan_snapshots.*`, `recommendations.*` | суть сервиса: учёт и рекомендации СППР | согласие (оферта/ПС) | БД-доступ; агрегаты без прямой идентичности вне `user_id` |
| Интеграционные секреты | `plaid_tokens.token_encrypted` | подключение банка (задел) | согласие при подключении | **Fernet** (`EncryptedString`) |
| Домохозяйство | `households.*`, `household_memberships.*`, `household_invites.token` | семейный доступ | согласие участников | токен-приглашение UK, срок жизни |
| Поведенческая телеметрия | `events.event_type`, `experiments/-assignments`, `notification_log.dedup_key` | продукт-аналитика, A/B, антидубли уведомлений | согласие/законный интерес | без прямых идентификаторов личности, кроме `user_id` |
| Пользовательский контент | `manual_snapshots.payload`, `user_category_rules.*`, `scenarios.*` | пользовательские настройки/сценарии | согласие | БД-доступ |

Гостевые данные (`user_id IS NULL`) не привязаны к личности — вне ПДн до момента регистрации.

## Потоки за пределы контура

| Куда | Что уходит | Зачем | Примечание |
|---|---|---|---|
| SMTP-провайдер | email, содержимое письма | verify / reset | провайдер РФ-юрисдикции — вопрос юристу №3 |
| Telegram Bot API | chat_id, текст уведомления | уведомления | по явной привязке пользователем; **на 08.09.2026 привязка доступна только через API — экрана нет**, поэтому фактической передачи не происходит |
| Sentry | стектрейсы, request-id | мониторинг ошибок | PII-скраббинг включить до прода (веха 9) |
| cbr.ru | ничего пользовательского | ставка/курсы | входящий поток |

## Права субъекта и удаление

- **Доступ/выгрузка:** экспорт данных пользователя — Excel-экспорт (P2) + `/api`-выгрузки.
- **Право на забвение:** удаление аккаунта → каскад по `user_id`; доменные записи soft-delete
  (`is_deleted`) с последующей физической зачисткой регламентом; `created_by` в household-строках —
  разграничение «чьи данные удалять» при общем доступе.
- **Бэкапы:** попадание ПДн в дампы и истечение по retention — `docs/backup_restore.md` §152-ФЗ.

## Открытые вопросы юристу (дубли в `legal_questions_for_lawyer.md`)

1. Формулировка согласия (регистрация + подключение банка) — достаточно ли двух чекбоксов.
2. Локализация: подтверждение, что VPS и офсайт-бэкапы в РФ закрывают требование.
3. SMTP/Sentry как обработчики: нужны ли ДС на поручение обработки.
4. Срок «доудаления» soft-delete записей после запроса на забвение.
