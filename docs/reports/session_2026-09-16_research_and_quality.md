## 2. Находки, меняющие продукт

1. 🔴 **Avalanche доказательно не оптимален.** Rios-Solis et al., PLoS ONE 12(4):e0175782
   (2017), CC BY: MILP ровно нашей задачи, доказана NP-трудность, разрыв с оптимумом
   в среднем >4 %, в пределе 40 %, хуже всего на длинных долгах. «Оптимальный порядок
   погашения» — некорректная формулировка; верно «эвристика». Взамен получено обоснование
   выбора эвристики, которого раньше не было.
2. 🔴 **Новизна снова просела:** три предшественника по объекту, включая публикацию 2012 года
   с линейной свёрткой взвешенных критериев в личных финансах.
3. 🔴 **Красная линия за рубежом сдвинулась против нас** (ЕС, UK, два-пять штатов США, CFPB).
   Для РФ — без изменений.
4. **Пятое расхождение канона с данными:** порог ПДН 0,40 против 75-го перцентиля 52 %.

## 3. Механизмы, заведённые в этот день (v9.11.0)

- `exa-gate.py` — агент не стартует, если Exa не загружена в процесс, отвалилась или сервис
  лежит. Exa подключена напрямую, мимо коннектора claude.ai (тот ломается при смене аккаунта).
- `research-channels-gate.py` — обязательные каналы добычи: `r.jina.ai`, OpenAlex, Crossref,
  EuropePMC, **Wayback**, локальные `curl`/`pdftotext`/`tesseract`, плюс наличие нужных
  инструментов у агента-исследователя. Semantic Scholar — только при наличии ключа.
- `watch-identity.sh` починен и подключён: вахта определяется на старте **и на каждом
  сообщении** (`/login` меняет аккаунт посреди сессии). Попутно исправлен дефект, из-за
  которого при неизвестной почте хук молчал вместо крика.
- Правило очереди: каждый батч записывает состояние каналов на начало работы.

## 4. 🔴 Качество кода: числа завышены, и это измерено

Пилот мутационного тестирования ядра (`docs/reports/mutation_pilot_2026-09-16.md`):
**501 мутант, 292 убито, 133 выжило, балл 68,7 %** при гейте покрытия ≥90 %.
Треть намеренных порч ядра тесты не замечают. Показательный случай: снятие ключа сортировки
в `select_avalanche_targets` — порядок погашения долгов по ставке исчезает, тесты молчат.

**Причина названа:** покрытие меряет исполнение строк, а не проверку поведения. У нас почти
везде один вид тестов — с заранее известным эталонным значением. Целевая раскладка
(ядро → инварианты и метаморфические отношения; парсер → эталонные файлы и фаззинг;
слой данных → дифференциальный прогон SQLite/PostgreSQL; HTTP → контрактные; интерфейс →
браузерные) записана в `docs/ROADMAP.md` и во входные требования синтеза.
