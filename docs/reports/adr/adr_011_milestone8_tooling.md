# ADR-011: Инструментальный контур вехи 8 — поверхности, модели, плагины, субагенты

Дата: 2026-07-31 · Статус: Accepted · Вахта: M

> Заведён потому, что веха 8 — первая, которую делаем не «в чате с архивом», а в агентском
> контуре: Claude Code на машине владельца, Claude Design для визуального поиска, плагины,
> субагенты и хуки. Контур выбирается один раз и должен быть одинаковым на всех четырёх
> аккаунтах: если V соберёт один набор плагинов, а J другой, это всплывёт не сразу, а на
> первом же мёрже — расхождением стиля кода и разной строгостью гейтов. Оформлено по
> `docs/reports/adr/adr_template.md`.

---

## 1. Контекст

Бэкенд закрыт на v7.7.1: 1473 теста SQLite, 141 PostgreSQL, ревизионный гейт CLEAN, готовность
к вехе 86/100. Впереди — перенос фронтенда с Jinja2 + vanilla JS на React + TypeScript
(решение зафиксировано в ADR-001) и полный редизайн под планку российских финтехов.

Три обстоятельства, которых не было на прошлых вехах:

1. **Работа переезжает в агентский контур.** До сих пор всё делалось в чате: архив на вход,
   архив на выход. Веха 8 — сотни файлов и итеративный визуальный цикл; чат для этого не
   приспособлен.
2. **Каталог моделей и инструментов изменился после последней сверки.** Методичка
   `knowledge/guides/claude_infrastructure_methodology.md` сверялась 5 июля 2026 и называет
   вершиной Opus 4.8. Opus 5 вышел 24 июля. Одновременно у Claude Design появился двусторонний
   `/design-sync`, а в claude.ai — отдельный каталог Skills / Connectors / Plugins.
3. **Провал качества фронтенда — не провал кода, а провал визуального суждения.** Модели пишут
   корректный фронтенд-код и заметно хуже судят, как он выглядит. Значит, критерий приёмки из
   `docs/ui_visual_design_brief.md` нужно сделать исполняемым, а не оставлять пожеланием.

Основание для решения — три методички в `docs/research/` и реестр источников там же.

---

## 2. Решение

### 2.1. Разделение поверхностей

- **Claude Code — около 85% работы.** Единственное место, где живут TDD, гейты, матрица
  SQLite + PostgreSQL, хуки, субагенты и батч-церемония.
- **Claude Design — около 10%.** Только этап визуального поиска: импорт существующей системы
  через `/design-sync`, три направления главного экрана, фиксация выбора. Не генератор
  продакшен-кода.
- **Проект claude.ai — около 5%.** Канон: ADR, WATCHLOG, разбор инцидентов, планирование.
- **Cowork — не используется.** Отдельная поверхность ради одной задачи (контент онбординга)
  не окупается при дисциплине четырёх аккаунтов.

Побочный эффект, который стоит зафиксировать: Claude Code работает на машине владельца, поэтому
ограничение из ADR-001 «E2E в песочнице только chromium, Firefox и WebKit блокирует CDN» на веху
8 не действует. Кросс-браузерный прогон становится доступен локально.

### 2.2. Модели

Отказ от практики «всегда сильнейшая модель на максимальном усилии». Раскладка — в
`docs/frontend_milestone8_plan.md` §1. Коротко: Opus 5 / high по умолчанию, xhigh на трудных
падениях, Sonnet 5 / medium на рутине, Haiku 4.5 на церемонии. Уровень `max` — политика
эскалации, а не режим: он почти вдвое дороже high ради двух пунктов индекса.

### 2.3. Плагины Claude Code

Ставятся скриптом `scripts/setup_claude_code_plugins.sh`. Только проверенные Anthropic
и официальные MCP:

- обязательные: `frontend-design`, `typescript-lsp`, `playwright`, `chrome-devtools`,
  `claude-code-setup`, `claude-md-management`, `security-guidance`;
- по ходу: `context7`, `code-review`, `pr-review-toolkit`, `playground`, `skill-creator`,
  `hookify`, `pyright-lsp`, `semgrep`, `session-report`.

Не ставим: Figma (её нет), Vercel и подобные (деплой — свой VPS в РФ), а также плагины
сообщества без верификации Anthropic. Последнее — не снобизм: продукт обрабатывает персональные
данные, и непроверенный сторонний код в агентском цикле не та экономия, ради которой стоит
рисковать.

### 2.4. Слой claude.ai

В самом claude.ai включаются: плагин **Design** (критика, аудит доступности, работа с дизайн-
системой, handoff) и скиллы `web-artifacts-builder`, `theme-factory`. Остальные держатся
выключенными — они конкурируют за контекст с базой знаний Проекта.

### 2.5. Собственные субагенты

Три, в `.claude/agents/`:

- **`design-critic`** (только чтение, Opus 5) — судит экран против §7 брифа: кратность четырём,
  отсутствие магических значений вне токенов, табличные цифры на деньгах, дозированный акцент,
  длительность переходов, размер целей нажатия. Это и есть превращение критерия приёмки в
  исполняемую проверку.
- **`a11y-auditor`** (только чтение, Sonnet 5) — WCAG AA, контраст, вложенная интерактивность,
  порядок фокуса.
- **`api-contract-guard`** (только чтение, Sonnet 5) — сверяет использование API с типами,
  выведенными из `docs/api/openapi.json`.

Права урезаны намеренно: субагент-ревьюер не должен уметь править код, который проверяет.

### 2.6. Хуки

Детерминированные скрипты вместо текстовых запретов. Текстовый запрет модель может обойти
рассуждением, хук — нет. Минимум: линтер стилей на каждую правку файла и блокировка
завершения при падающих гейтах.

## 3. Альтернативы, которые отклонены

**Делать веху в чате, как прошлые.** Отклонено: сотни файлов и итеративный визуальный цикл;
стоимость переупаковки архива на каждой итерации превышает выигрыш от привычности.

**Собрать фронт целиком в Claude Design.** Отклонено: инструмент прототипов и презентаций,
а не продакшен-кода; в нём нет гейтов, тестов и матрицы баз.

**Взять Fable 5 как сильнейшую модель.** Отклонено: Opus 5 отстаёт от неё в пределах процента
на нашем классе задач при вдвое меньшей цене, знает экосистему свежее и не тянет обязательного
тридцатидневного хранения данных.

**Поставить Superpowers и другие популярные плагины сообщества.** Отклонено по разделу 2.3.

**Писать своих субагентов вместо плагина Design.** Отклонено частично: плагин закрывает критику,
аудит доступности и handoff; свои субагенты нужны только там, где проверяется наш собственный
бриф и наш контракт API. Дублировать то, что уже поддерживается Anthropic, смысла нет.

---

## 4. Последствия

**Хорошие.** Контур одинаков на четырёх аккаунтах и зафиксирован письменно. Критерий приёмки
внешнего вида стал исполняемым. Кросс-браузерный E2E разблокирован. Расход на моделях падает
без потери качества там, где качество не требуется.

**Плохие.** Вырос порог входа: вахта обязана поставить плагины и прочитать `CLAUDE.md` до
начала работы. Появилась зависимость от версии Claude Code (не ниже v2.1.181 для `/design-sync`).
Контур придётся пересматривать: инструменты меняются быстрее, чем идёт веха.

**Что делать при устаревании.** Если ADR разошёлся с реальностью — не переписывать молча.
Завести ADR-012 со ссылкой на этот и указать, что именно изменилось. История решений ценна
именно тем, что показывает, почему в тот момент выбрали так.
