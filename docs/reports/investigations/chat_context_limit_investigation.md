# Расследование: переполнение контекста чата остановило батч (INV-CHAT-CTX-LIMIT)

**Дата:** 2026-07-23. **Тип:** расследование (внешнее ограничение платформы,
дефекта в продуктовом коде нет). **Реестр:** `investigations_summary.md`.

## Симптом

Проектный чат «Оценка рекомендаций мат модели в сравнении с экспертами 2»
(claude.ai, проект FINPILOT Product) перестал принимать ответы ассистента:
баннеры «This conversation is too long to continue. Start a new chat, or
remove some tools to free up space» и «Your message was sent, but Claude
couldn\'t respond — try again». Сообщение владельца доставлялось, ответ не
генерировался. Незакрытый хвост батча: обновление брифа, решение по
регенерации сборки, раздаточный пакет.

## Подозрение

Сбой продукта или потеря работы батча.

## Снято с подозрения (корень)

Дефекта нет ни в коде FINPILOT, ни в работе ассистента. Корень — жёсткое
ограничение платформы claude.ai на суммарный размер контекста одного чата:
переписка + системный контекст проекта (инструкции, память, project
knowledge) + приложенные файлы превысили лимит, и платформа блокирует
генерацию ответа целиком. Это ожидаемое поведение платформы, а не сбой.
Форс-факторы конкретного чата: длинная серия батчей в одном чате, объёмные
вставки (брифы, ревизии, отчёты) прямо в сообщения, тяжёлый постоянный
контекст проекта.

## Доказательства

1. Скриншот владельца: оба баннера платформы; поле ввода активно, отправка
   работает, ответ не приходит (симптом «лимит», не «ошибка сети»).
2. Работа возобновилась в новом чате того же проекта без каких-либо правок
   кода — с того же архива `finpilot_v6_20_3_intl.zip` (протокол «один zip =
   полный контекст» отработал штатно).
3. Класс ограничения известен и документирован протоколом непрерывности
   (`docs/session_continuity.md`, баннер WATCHLOG): «токены/контекст
   кончаются внезапно».

## Последствия

Потерь нет: рабочее состояние жило в архиве v6.20.3, WATCHLOG вёлся по ходу,
последний ответ ассистента был доставлен (излечён из чата владельцем как
выдержка). Стоимость инцидента — простой на переключение чата и ручной
перенос контекста владельцем.

## Что опробовано / почему не вышло

- Повторная отправка в тот же чат — платформа блокирует ответ независимо от
  содержимого нового сообщения (лимит суммарный, не на сообщение).
- «Remove some tools to free up space» — не применялось: инструменты проекта
  (project knowledge, память) нужны рабочему процессу; выигрыш разовый,
  чат продолжит упираться в лимит.

## Правила, чтобы не наступать снова

1. **Новый чат на каждый крупный батч** внутри проекта; история живёт в
   CHANGELOG/WATCHLOG, не в переписке. Чат — рабочая сессия, не архив.
2. **Не вставлять большие документы в сообщения**, когда они уже есть в
   архиве/репо: ссылка на путь внутри zip вместо полного текста.
3. **Чекпоинт-архив рано и часто** (протокол непрерывности): при первых
   признаках тяжёлого чата — немедленная выдача архива через present_files.
4. **Выдержки вместо перечитывания:** при переносе вахты в новый чат
   передавать последний ответ + архив, а не просить пересказ.
5. Порог настороженности: если в чате уже 3+ батча или один ответ занял
   заметную долю окна — закрывать чат по собственной инициативе, не дожидаясь
   баннера.

## Что можно попробовать ещё

Ничего не требуется: ограничение внешнее, протокол непрерывности его уже
покрывает; правила выше — калибровка порогов, не новый механизм.
