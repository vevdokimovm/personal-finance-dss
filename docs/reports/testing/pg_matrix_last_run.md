## 🔴 Почему прогон вообще стал возможен только сейчас

Полгода в журнале стояло «матрицу локально не прогнать — нет Docker», и это читалось
как «нет базы». `postgresql@14` при этом стоял через brew всё это время: `which postgres`
даёт `/usr/local/bin/postgres`. Отсутствие одного способа было принято за отсутствие
возможности — тот же класс, что `SYN-020`: вывод «этого нет» без называния области поиска.

## Миграции в прогоне

**06.09.2026, v9.2.0:** добавлена **0037** (`mfa_pending_attempts`) — счётчик неудачных
кодов на один `mfa_pending`-токен. Прогнана на обеих БД: `test_mfa_token_burns_after_failures.py`,
`test_migration_reversibility.py`, `test_budget_upsert_scope.py` — 11/11 на PostgreSQL,
цикл `head → base → head` пройден.


Головная ревизия на момент прогона — **0036** (`0036_budget_category_per_owner.py`):
сужает глобальный unique по `Budget.category` до пары `(user_id, category)`. До неё
категория бюджета была уникальна **на всю таблицу**: второй пользователь, заводящий
«Продукты», получал 500.

Цепочка `head → base → head` пройдена на PostgreSQL целиком
(`tests/test_migration_reversibility.py`), на SQLite тест скипается осознанно —
динамическая типизация не ловит дефекты каста, ради которых он заведён.

## Два падения и что за ними стояло

### 1. `test_sqlite_is_refused_in_production` — тест был негерметичен

`Settings` читает `DATABASE_URL` из окружения. Под матрицей эта переменная указывает
на PostgreSQL, значит тест, проверяющий отказ от SQLite, получал корректный прод-конфиг
и не находил проблемы.

🔴 **Тест проверял машину, на которой запущен, а не код.** Локально зелёный (в окружении
пусто → дефолт SQLite), в матрице красный — и оба раза по причине, не связанной
с предметом проверки.

**Исправлено:** `_settings` задаёт `DATABASE_URL=DEV_DB` явным аргументом. Явный аргумент
Pydantic бьёт переменную окружения — проверено запуском с выставленной переменной.

### 2. `test_status_block_names_the_current_version` — гейт поймал реальное расхождение

Блок `<!-- STATUS -->` в README показывал `v9.0.0` при `VERSION=9.1.0`. Церемония батча
обновляет **бейдж** и не трогает текст рядом с ним — ровно тот дефект, против которого
гейт и заводился в v9.0.0.

Это не артефакт матрицы: тест падал и на SQLite. В сводку матрицы он попал случайно,
потому что полный прогон идёт только там.

**Исправлено:** блок приведён к v9.1.0.

## Что из этого следует

🔴 **Тест, читающий окружение, проверяет окружение.** Любая настройка, которую
`Settings` берёт из `.env` или переменных, должна задаваться в тесте **явно** — иначе
вердикт зависит от того, где запущено, и расходится между локалью, матрицей и CI.
Ближайший родственник — `PIT-032`: локальная машина в состоянии, которого нет у CI.
