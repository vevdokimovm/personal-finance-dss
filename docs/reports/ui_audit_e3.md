# UI-аудит дашборда (Э3, пилотный экран) — findings

Дата: 2026-08-08. Инструмент: `chrome-devtools-mcp`, локальный бэк (`:8000`) + Vite dev (`:5173`).
Сценарии: загрузка, пусто, ошибка, дефицит (кейс `pavel`) — светлая/тёмная тема, 1440px/375px.
Не путать с последующими фиксами (v8.5.2) — этот файл фиксирует находки ДО правок, как есть на
Э3 (v8.5.0).

## P0 — блокирует продукт

### P0-1. Прогноз резерва — сплошной чёрный прямоугольник в тёмной теме

`frontend/src/pages/dashboard/ui/ForecastPanel.tsx:71-84` (на момент аудита). Полоса p10-p90
рисовалась двумя `<Area>` без `stackId`: вторая (`fill="var(--c-bg)"`, задумана как маска,
вырезающая всё ниже p10) без стека рисуется НЕ узкой полосой поверх первой, а самостоятельной
областью от нуля до p10 — то есть закрашивает почти всю высоту графика цветом фона.

В светлой теме баг визуально незаметен только потому, что `--c-bg` там почти белый и сливается
с белой панелью — совпадение цветов, не корректность. Воспроизведено на 1440 и 375px.
Дефицитный сценарий (`pavel`, отрицательные значения) баг НЕ проявлял — по случайности области
на отрицательном домене перекрывали другой участок графика. Тест только на `pavel` дал бы
ложно-зелёный результат.

Затронуто: dashboard сейчас; риск переноса того же паттерна на другие экраны в Э4.

### P0-2. Тумблера светлой/тёмной темы нет вообще

В `frontend/src` — ни компонента переключателя, ни кода, выставляющего `data-theme` на `<html>`.
Токены светлой темы в `tokens.css` корректны, но недостижимы обычным пользователем (только через
ручной `document.documentElement.setAttribute('data-theme','light')` в консоли). Тёмная —
единственная реальность, поэтому P0-1 гарантированно видна каждому.

## P1 — заметно, не блокирует

### P1-3. Критичные метрики не подсвечены цветом при превышении порога

Дефицитный кейс (`pavel`): ПДН = 82,2% при пороге 40% («Запас −42.2 п.п. до порога») —
нейтральный текст, тот же, что и в норме (`anna`, 34,7%). Токены `--c-red`/`--c-amber` в системе
есть, `MetricCard`/`MetricsGrid` их не используют по состоянию. Продукт заявляет fail-loud
философию текстом панели «Плана распределения нет», но не подкрепляет её визуально на самой
тревожной цифре.

### P1-4. Skeleton короче реального контента

`DashboardSkeleton.tsx` мокает только Hero и 3 метрик-карточки, не резервирует место под
`AllocationPanel` и `ForecastPanel`. При loading → loaded страница «прыгает» вниз на высоту двух
панелей — заметный layout shift. Сам skeleton сделан аккуратно (a11y, `prefers-reduced-motion`,
`role="status"`) — не хватает только двух блоков-заглушек.

## P2 — по мелочи

### P2-5. TanStack Router Devtools перекрывает кнопку на 375px

Виджет в правом нижнем углу перекрывает «Построить план распределения →» в Hero-карточке на
мобильной ширине. Dev-only (`import.meta.env.DEV`), в проде не появится, но мешает тестировать
с телефона сейчас.

### P2-6. `favicon.ico` — 404

Единственная реальная ошибка в консоли браузера за всю сессию. Косметика.

## Что без замечаний

Пустое состояние, состояние ошибки (включая клик «Повторить» — корректный возврат в error, без
зависания), адаптивность карточек на 375px — чисто в обеих темах. Денежный формат (табличные
