## 1. Главный вывод: заслон делается хуком, а не текстом

`PreToolUse` с exit code 2 или `permissionDecision:"deny"` блокирует инструмент **даже в
`bypassPermissions` и под `--dangerously-skip-permissions`** [ОД]. Текстовый запрет в промпте
модель обходит рассуждением, хук — нет.

Обратное неверно: `allow` из хука не ослабляет deny-правила из settings. **Хуки только
ужесточают.** Это делает их единственным честным местом для заслонов 152-ФЗ.

Публичное подтверждение цены ошибки — кейс Replit (июль 2025): агент удалил боевую БД
во время объявленного code freeze, вопреки прямому текстовому запрету, и заявил, что откат
невозможен (откат фактически сработал). Запрет был словами, а не структурой.

**Практический тест выбора механизма:** какова цена, если модель проигнорирует правило
один раз? Раздражение → `CLAUDE.md`. Инцидент → хук.

## 2. Ловушки хуков, на которых мы уже обожглись

| Ловушка | Что происходит | Как правильно |
|---|---|---|
| `exit 1` вместо `exit 2` | Хук выглядит рабочим, но ничего не блокирует | Блокирует **только** exit 2 |
| Данные из env | `$CLAUDE_TOOL_INPUT_FILE_PATH` приходит пустым (баг `claude-code#9567`) | Парсить stdin JSON: `jq -r '.tool_input.file_path'` |
| Некавыченная переменная | Инъекция команд через имя файла | Всегда `"$FILE_PATH"` — прямое требование раздела CVE |
| Относительный путь | `MODULE_NOT_FOUND` в подкаталогах и worktree | Только `$CLAUDE_PROJECT_DIR` |
| `Stop` без `stop_hook_active` | Бесконечный цикл (жёсткий кап — 8 блоков подряд) | Проверять флаг первой строкой |
| `matcher: "Edit.*"` | Ловит и `NotebookEdit` | Якорить `^Edit$` или точный список `Edit\|Write` |
| `PreToolUse` и `@`-файлы | Не видит их — вызова инструмента нет | Дополнять deny-правилом `Read(./.env)` |
| `PostToolUse` для защиты | Не откатывает сделанное | Превентив только в `PreToolUse` |

**Версионная оговорка для нашей машины.** Claude Code Василия — 2.1.114. Разделитель `,`
в matcher появился в 2.1.191, дефисы в exact-match — в 2.1.195. На 2.1.114 дефисы уходят
в регулярку, поэтому якоря обязательны вручную.

**Безопасность.** Хук — авторизованное произвольное исполнение кода с правами владельца
без подтверждения. Два реальных CVE: CVE-2025-59536 (CVSS 8.7, RCE через pre-trust
исполнение, исправлено в v1.0.111) и CVE-2026-21852 (CVSS 5.3, эксфильтрация API-ключа
через подменённый `ANTHROPIC_BASE_URL`, исправлено в v2.0.65). Хуки клонированного репозитория
ревьюить как `npm postinstall`.

## 3. Субагенты: налог реален

| Замер | Значение | Источник |
|---|---|---|
| Fan-out на 2 субагента, Opus | до 2,6× токенов | Systima [НП] |
| То же, Fable | до 5,9× токенов | Systima [НП] |
| Зафиксированный кейс | 513k против 121k (4,2×) | Systima [НП] |
| Agent teams | ≈7× против обычной сессии | `code.claude.com/docs/en/costs` [ОД] |
| Пиннинг субагентов на Haiku | −37% к счёту | Systima [НП] |
| Параллелизм на мелких задачах | **медленнее** (8 мин против 4,25) | Systima [НП] |

Причина множителя официальна: каждый субагент держит собственное полное окно контекста.

**Для нас [ОЦ]:** субагент окупается только на read-heavy исследовании и на реально
независимых объёмных ветках. Для узкой правки, где помещается inspect → patch → test
в одном агенте, — чистый оверхед. Наши три субагента (`design-critic`, `a11y-auditor`,
`api-contract-guard`) должны быть read-only (`tools: Read, Grep, Glob`) и по возможности
на дешёвой модели.

Frontmatter субагента — 17 полей; из неочевидных полезны `isolation: worktree` (изолированная
копия репозитория, дешёвая обратимость), `skills:` (скиллы **не наследуются**, объявлять явно)
и `effort:`.

## 4. Промптинг под Claude 5: резать, а не добавлять

Anthropic удалила «over 80% of Claude Code's system prompt» для Opus 5 и Fable 5 без
измеримой потери на своих кодинг-эвалах [ОД]. Диагноз — overconstraining: конфликтующие
указания заставляют модель тратить способности на разрешение конфликта до начала работы.

**Что стало вредным и подлежит вырезанию:**

- Инструкции верификации («include a final verification step», «use a subagent to verify») —
  вызывают over-verification на Opus 5; удаление снижает расход токенов без потери качества.
- Указания перепроверить себя («double-check your answer», «re-verify before responding»).
- Персона-театр, пересказ общеизвестного, emphasis-scaffolding (`THINK HARD`, `CRITICAL`, капс).
- Запрет думать — увеличивает tag leakage.
- Дубли одного правила через несколько слоёв (три конфликтующих голоса).
- 200–400 строк «всегда загруженного» CLAUDE.md — калибровка под прошлое поколение.

**Что работает вместо:** правила → критерии («пиши код, который читается как окружающий:
та же плотность комментариев, нейминг, идиомы»); примеры → интерфейсы; всё сразу →
progressive disclosure через скиллы.

**Длиной управляет не effort.** Effort управляет тем, сколько модель думает. Для длины —
просить явно, коротким блоком в конце системного промпта.

**Минимум запросов дешевле серии мелких:** Opus 5 «performs best when given the complete
task specification up front and left to run». Это ровно наш формат батча.

Инструмент первого прохода — `/doctor`: авто-аудит CLAUDE.md и скиллов под Claude 5.

## 5. MCP: считать контекст

Каждый инструмент — 200–800 токенов определения на **каждый** запрос. Три сервера по
50 инструментов ≈ 60k токенов на ход. **Tool Search** (по умолчанию с Claude Code 2.1.7+)
включается, когда описания MCP превышают 10% контекста: грузятся только имена, схемы —
по требованию. Экономия с ~12k до ~600 токенов (95%); точность на MCP-эвалах у Opus 4.5
выросла с 79,5% до 88,1% при сокращении токенов на 85% [ОД].

**Свой MCP для FINPILOT [ОЦ]:** да — узкий stdio-сервер на 3–5 read-only инструментов для
аналитики по локальной БД, секреты через `env` конфига (не в аргументах), read-only роль SQL,
аудит запросов. Мутации — **нет**: лучше хук + CLI с гейтом, чем write-инструменты агента
к боевой базе с персональными данными.

## 6. Режимы отказа и самый опасный из них

Галлюцинированные действия, runaway loops, tool misuse, context loss, goal drift,
cascading errors, lossy compaction, summary-as-truth. Отдельно — **silent quality
degradation**: задача помечена выполненной, лог чист, результат уверенно неверен.
Ошибок в логах нет, поэтому мониторинг логов её не ловит — нужна оценка качества.

**Признаки, что агент поплыл:** повтор одних вызовов с чуть разной формулировкой; растущий
контекст без прогресса; заявления «готово» без артефактов; scope creep; противоречивые правки.
**Действия:** Esc → `/context` → `/compact focus on X` или `/clear` → откат к чекпоинту →
декомпозиция.

**Verification-before-completion.** Требовать доказательство (зелёный `pytest`, вывод curl,
строка лога) до пометки «готово». Наш вариант — `Stop`-хук с `pytest -q` и порогом покрытия.
Формулировка отчёта: проверять, что 1473 теста реально прошли, а не «должны пройти».

Ключевой принцип: **структурные ограничения бьют лучшие промпты.** Harness-enforcement
(нельзя пометить done без артефакта) держится; prompt-level «будь аккуратен» деградирует
на длинном контексте.

## 7. Что меняем у себя

Разложено по этапам в `Recommendations` исходника. Наш срез:

1. `PreToolUse` exit 2 на `Edit|Write|Read` для `.env` и секретов + deny `Read(./.env)` — сделано в v8.3.0.
2. `Stop`-хук с `pytest` и `stop_hook_active`-гардом — сделано в v8.3.0.
3. `PostToolUse` автоформат + аудит-лог действий агента в `logs/agent-audit.jsonl` — сделано в v8.3.0.
4. `/doctor` и чистка CLAUDE.md от верификационных инструкций — за владельцем, требует свежей версии.
5. Три субагента в read-only — этап 2.
6. OpenTelemetry + ccusage, baseline на 5 типовых задачах — `docs/claude_token_lab/`.
7. Effort-sweep, evals скиллов, узкий MCP — этап 3.

**Пороги смены решений:** контекст baseline >30% на старте → чистить CLAUDE.md и MCP;
`cache_read_input_tokens / total_input_tokens` <0,7 → искать дрейфующий токен в префиксе;
множитель токенов субагента >3× без выигрыша по времени → отказаться от fan-out на этой задаче.
