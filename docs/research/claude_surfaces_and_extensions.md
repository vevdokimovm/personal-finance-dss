## 0. Находка вне заказа, которую нельзя пропустить

Исследование выявило то, о чём не спрашивали: **Россия отсутствует в списке поддерживаемых
стран Anthropic** (проверено 01.08.2026 на `anthropic.com/supported-countries` — соседи по
региону в списке есть, России нет). Consumer Terms §3 допускают доступ только по Supported
Regions Policy; §12 разрешает прекратить доступ без уведомления и без возврата средств. [Ф]

Отдельно: **режим нескольких параллельных аккаунтов ради обхода лимитов** противоречит
условиям. Легитимная альтернатива по деньгам сопоставима — один Max 5x против четырёх Pro. [О]

Это не юридическая консультация и не предмет для паники — но и не то, что стоит узнать
из письма о блокировке. Практическое следствие, которое действует независимо от юридического
статуса: **реальные ПДн пользователей FINPILOT не уходят в Claude ни на одной поверхности**.
Работа — на синтетике и обезличенном зеркале. Это правило у нас уже действует, теперь у него
появилось второе основание помимо 152-ФЗ.

## 1. Разделение поверхностей

| Поверхность | Роль в FINPILOT | Почему |
|---|---|---|
| **Claude Code** | ядро вехи 8 | локальные файлы, гейты, git, worktrees, скиллы, окно до 1M |
| **Claude Design** | только идеи UI | прототип, не боевой код; дальше `/design-sync` |
| **Проект claude.ai** | канон и решения | ADR, WATCHLOG, разбор инцидентов |
| **Cowork** | **не используется** | ПДн + нет в audit logs + серверы вне РФ |

## 2. Claude Code — что важно знать сразу

**Обновление.** У владельца `claude` стоит нативно (`~/.local/bin/claude`), поэтому
`npm update -g` его **не обновляет** — отсюда и ошибка EACCES на чужом пакете corepack.
Правильно: `claude update`. Диагностика — `claude doctor`. [Ф]

Есть известная мина: `claude update` иногда ошибочно принимает нативную установку за
npm-глобальную и подменяет её. Если появились две копии — выигрывает первая в PATH;
лечится удалением npm-копии и `rehash`. [Ф]

**Режимы разрешений** — шесть. Практическая раскладка для одиночки на боевой машине: [О]
- `plan` — по умолчанию для всего нетривиального (read-only, сначала план);
- `acceptEdits` — заранее заскоупленная работа по фронтенду;
- `default` — всё, что касается БД и миграций;
- `bypassPermissions` — **только** в изолированном контейнере, никогда на машине с ключами.

**Чекпоинты.** `/rewind` откатывает код и диалог, но **не отменяет действия bash** —
`rm -rf`, `mv` не откатываются. Git остаётся первичной защитой, `/rewind` — вторичной. [Ф]

**Наблюдаемость.** `/context` (заполнение окна), `/usage` (лимиты), `/status`, `claude doctor`.
Статус-строка умеет показывать процент контекста и остаток окна — стоит настроить, потому что
это единственный способ увидеть приближение стены заранее. [Ф]

**Worktrees.** Позволяют вести 2–3 задачи параллельно без конфликтов файлов. Но защищают
только от файловых конфликтов, **не от логических**: два агента с несовместимыми допущениями
всё равно дадут сломанный мёрж. Для одиночки — максимум 2–3 явно раздельные задачи. [Ф + О]

## 3. Cowork — почему не берём

Исполняется в изолированной среде **на серверах Anthropic**. Расходует лимиты заметно сильнее
чата. Главный риск — непрямая инъекция промпта через файлы и веб: успешная атака может увести
локальные файлы, выполнить команду, создать постоянную задачу по расписанию. Активность Cowork
**не попадает в audit logs**. [Ф]

Для продукта с персональными данными это стоп. Максимум — непроектная обвязка на обезличенных
данных, и то с осторожностью.

## 4. Claude Design — узкая роль

Research preview, движок Canva, на Opus 4.7. Умеет читать дизайн-систему из кодовой базы —
это наш случай: 68 CSS-переменных импортируются, а не пересказываются. `/design-sync`
двусторонний, требует Claude Code **не ниже 2.1.181**. [Ф]

Независимые обзоры прямо говорят: инструмент помогает понять, как продукт **мог бы** выглядеть,
и заметно слабее, когда дизайн должен жить внутри реального меняющегося приложения. [Ф]
Отсюда роль: идеи и направления — да, боевые компоненты — руками.

## 5. Плагины — что отключить

Установленный набор содержит дубли: [О]
- `code-review` и `pr-review-toolkit` — оба мультиагентное ревью PR. Оставить один
  (скорее `pr-review-toolkit` — агенты специализированнее).
- `playwright` и `chrome-devtools-mcp` — пересекаются по браузеру; для E2E хватит Playwright,
  DevTools включать точечно под отладку производительности.
- `semgrep` и `security-guidance` — **не дубли**: первый реальный статический анализ,
  второй лёгкий хук-напоминание. Держать оба.

Свой приватный маркетплейс — это просто git-репозиторий с `marketplace.json`. Так контур
переносится между машинами и репозиториями. [Ф]

## 6. Скиллы — когда что применять

Дерево решений: [О]

| Нужно | Инструмент |
|---|---|
| Всегда и коротко | `CLAUDE.md` |
| Повторяемая процедура | **скилл** |
| Изолированный контекст под тяжёлое исследование | субагент |
| Дотянуться до внешней системы | MCP |
| Детерминированный побочный эффект | хук |

Механика скилла: при старте грузится только имя и описание (медиана ~80 токенов на скилл),
тело — по срабатыванию, справочники — по требованию. Проект с восемью скиллами стоит ~500
токенов на старте вместо ~70 000. [Ф]

**Ключевое правило:** описание должно говорить **когда** применять, а не только что делает.
Иначе скилл не сработает. Проверяется eval-тестами через `skill-creator` — он гоняет набор
запросов и смотрит, потянулся ли Claude к скиллу, включая проверку «не должен срабатывать». [Ф]

**Скиллы под FINPILOT** (предложение): `finpilot-fastapi-endpoint`, `finpilot-152fz-guard`,
`finpilot-react-component`, `finpilot-katex-formula`, `finpilot-test-coverage`,
`finpilot-migration`. Смысл: это повторяемые процедуры, которые иначе раздуют `CLAUDE.md`
и будут грузиться всегда вместо «по надобности».

**Образец для изучения:** официальный скилл `xlsx` из `anthropics/skills` — там финансовые
конвенции (цветовой код модели: синий ввод, чёрный формула, зелёный внутренняя ссылка,
красный внешняя). Прямо релевантно финтеху.
