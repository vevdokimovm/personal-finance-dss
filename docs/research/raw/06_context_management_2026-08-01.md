# FINPILOT: Управление контекстом в Claude на трёх уровнях (запрос → чат → Проект)

## TL;DR
- **Две разные стены, которые Василий путает.** «This conversation is too long to continue» — это исчерпание **контекстного окна одного чата** (техническое, привязано к чату); «You're out of usage credits… wait until 3:00 AM» — исчерпание **лимитов плана Pro** (биллинговое, привязано к 5-часовому и недельному окнам). Первое лечится только новым чатом (покупка кредитов не помогает), второе — ожиданием сброса или покупкой кредитов (новый чат не помогает). [независимо проверено]
- **Ключ к предсказуемости — включить Code Execution.** Дословно из справки Anthropic: «For users on paid plans with code execution enabled, Claude automatically manages your conversation context». Тогда Claude при приближении к лимиту сам суммирует ранние сообщения, чат живёт почти бесконечно, и это не расходует лимит плана. Без Code Execution — жёсткая стена без восстановления. Автосжатие безвозвратно теряет точные детали (числа, код, ранние инструкции), поэтому важное надо чекпоинтить вручную на ~70% заполнения. [официальная документация + независимо проверено]
- **Загрузка zip по 70 МБ — главная ошибка Василия.** Архив кода раздувает контекст и провоцирует раннюю стену; правильный путь для FINPILOT — GitHub-коннектор с выбором только нужных файлов + база знаний Проекта + Claude Code, а не zip в веб-чат. [официальная документация + оценка]

## Раздел 1. Контекстное окно чата claude.ai — механика и числа

### 1.1. Точный размер окна по моделям (claude.ai, веб и мобайл)
Официально (Claude Help Center, «How large is the context window on paid Claude plans», обновлено 2026), дословно:
- **Opus 5 и Sonnet 5** — **1M токенов** на всех платных планах при чате с Claude. [официальная документация]
- **Opus 4.8, Opus 4.7, Opus 4.6 и Sonnet 4.6** — «support a 500K token context window on all paid plans when chatting with Claude». [официальная документация]
- **Прочие модели (в т.ч. Haiku 4.5)** — **200K токенов** («about 500 pages of text or more»). [официальная документация]
- **Free-план** — ограничен 200K даже на Sonnet. [независимо проверено]

Важно: окно в **чате claude.ai меньше**, чем то же окно у модели через API/Claude Code. Дословно из справки: «When using Claude Code… Claude Sonnet 5, Fable 5, Opus 5, Opus 4.8, Opus 4.7, and Opus 4.6 support a 1M token context window. **Pro users need to enable usage credits to access the 1M token context window for Opus models.**» То есть тот же Sonnet 4.6 = 500K в вебе, но 1M в Claude Code/API; а Василию (Pro) для 1M на Opus в Claude Code нужно включить usage credits. [официальная документация]

Enterprise — 500K на некоторых моделях (Василия не касается, он на Pro). [официальная документация]

### 1.2. Из чего складывается заполнение контекста чата
Каждое ваше сообщение отправляет Claude **весь** накопленный контекст заново. Порядок величин (оценки на основе публичных данных Anthropic и независимых замеров):

| Компонент | Примерный расход | Тип |
|---|---|---|
| Системный промпт Claude | несколько тысяч токенов (не под вашим контролем) | оценка |
| Профильные инструкции аккаунта (Settings → profile) | по длине текста; лимит порядка 1 500 символов | независимо проверено |
| Инструкции Проекта | до ~8 000 символов (≈2 000 слов ≈ 2 500–3 000 токенов) | независимо проверено |
| База знаний Проекта | грузится целиком, пока не включится RAG; затем — только релевантные фрагменты | официальная документация |
| Описания инструментов/коннекторов (MCP) | тяжёлые: GitHub ~26K, Slack ~21K, Jira ~17K, Sentry ~3K токенов | независимо проверено |
| Скиллы/плагины | ~6 000 токенов за сессию на набор | оценка |
| Вся история сообщений (ваши + ответы Claude) | растёт линейно, самый крупный потребитель в длинном чате | независимо проверено |
| Вложенные файлы | остаются в контексте и пересылаются при каждом сообщении | независимо проверено |
| Артефакты | считаются в окно | независимо проверено |
| Результаты веб-поиска / чтения | добавляются в контекст по мере вызова | оценка |

### 1.3. Почему ошибка предлагает «remove some tools»
Описания подключённых инструментов и коннекторов (их JSON-схемы) **инжектируются в контекст на каждом ходу**, ещё до вашего текста. По данным инженерного блога Anthropic («Introducing advanced tool use on the Claude Developer Platform»), это очень дорого и сильно зависит от коннектора: «GitHub: 35 tools (~26K tokens); Slack: 11 tools (~21K tokens); Sentry: 5 tools (~3K tokens)… That's 58 tools consuming approximately 55K tokens before the conversation even starts», а «Jira (which alone uses ~17K tokens)». Anthropic признаёт крайний случай: «At Anthropic, we've seen tool definitions consume 134K tokens before optimization». По баг-репортам claude.ai, ~11 включённых коннекторов могут ронять новый чат сразу, превышая лимит на ~33 609 токенов («This request exceeds Claude's context limit by about 33,609 tokens. Try turning off some tools or shortening your message»). [независимо проверено]

**Как отключить (веб claude.ai):**
1. **Быстро, для конкретного чата** — меню **«Search and tools»** (иконка у поля ввода, слева снизу): переключатели тумблерами, выключите нерелевантные коннекторы/веб-поиск/Research. Официальная рекомендация Anthropic именно такая: «Temporarily disable non-critical tools and connectors». [официальная документация]
2. **На уровне аккаунта** — **Settings → Connectors**: отключить/удалить интеграцию целиком. [независимо проверено]

Эффект: освобождает тысячи–десятки тысяч токенов до начала работы.

### 1.4. Может ли пользователь видеть заполнение контекста чата
**В веб-интерфейсе claude.ai индикатора заполнения контекста конкретного чата НЕТ.** Есть только **Settings → Usage** — прогресс-бары 5-часового и недельного лимитов ПЛАНА, но это не про контекст чата. [официальная документация; для контекста чата — данных нет]

Обходные способы оценки:
- Считать токены вручную внешними счётчиками (claudetokenizer.com, tokencounter.org, claude-tokenizer.vercel.app). [независимо проверено]
- Эвристика: **~4 символа/токен** для английского (≈1,3 токена/слово); для **русского примерно вдвое дороже** — кириллица токенизируется хуже (ориентир ~2 символа/токен, т.е. русский текст съедает контекст быстрее английского). Отдельно: модели с 4.7 и новее используют новый токенизатор, дающий примерно на 30% больше токенов на тот же текст. [оценка / официальная документация по токенизатору]
- Признак приближения к стене — учащение сообщений о сжатии («organizing its thoughts» / «Compacting…»).

### 1.5. Что происходит с вложенными файлами
- Загруженный в чат файл **остаётся в контексте и пересылается при каждом последующем сообщении** — токены компаундируются. Официальный совет: «Don't re-upload files within the same conversation». [официальная документация]
- Размер в МБ ≠ размер в токенах: плотный текстовый PDF на 5 МБ может дать больше токенов, чем 20 МБ с картинками. [независимо проверено]
- Лимиты: **чат — 30 МБ/файл, 20 файлов/чат** (широко цитируемая норма; новая редакция официальной справки указывает уже **500 МБ/файл** для чата — расхождение, см. Раздел 6). PDF: полный анализ (текст+визуал) до 100 страниц, только текст — до 1000 страниц, свыше — ошибка «Uploaded file is too large». [официальная документация, с оговоркой]

## Раздел 2. Сжатие и обрезка разговора — что именно теряется

### 2.1. Механика автосжатия в claude.ai
На платных планах **с включённым Code Execution** Claude при приближении к лимиту окна **суммирует ранние сообщения**, освобождая место, и продолжает чат. Дословно: «When your conversation approaches the context window limit, Claude summarizes earlier messages to make room for new content. This does not count towards your usage limit, and allows conversations to continue indefinitely in most cases». Полная история сохраняется для ссылки, но в активном контексте остаётся сжатая версия. Признак — «Claude organizing its thoughts» / «Compacting our conversation». Механизм подтверждён и анонсом Sonnet 4.6 («context compaction in beta, which automatically summarizes older context as conversations approach limits»). [официальная документация]

Если Code Execution **выключен** — автосжатия нет, вы упираетесь в жёсткую стену «too long to continue». [независимо проверено]

Порог: по независимым замерам сжатие срабатывает около **83,5% окна (~167K из 200K)**; далее сжимается повторно, включая «сжатие сжатия», что усиливает потерю деталей. [оценка / независимо проверено]

### 2.2. Что теряется
Сжатие сохраняет «суть», но теряет **точные технические детали**: конкретные числа, дословный код, ранние инструкции, кросс-файловые связи. После 2–3 проходов понимание проекта у Claude заметно деградирует. [независимо проверено]

Признаки, что сжатие уже произошло/навредило: Claude «забывает» ранние инструкции, противоречит прежним решениям (например, вы договорились о PostgreSQL — он выдаёт MySQL), выдумывает детали кодовой базы, снова задаёт отвеченные вопросы, ответы становятся общими. [независимо проверено]

### 2.3. Деградация качества
Anthropic прямо признаёт: «as a conversation grows, response quality degrades» — компакция нужна именно чтобы держать активный контекст маленьким. Явление известно как «context rot»: качество падает даже до жёсткого лимита из-за «attention drift» (ранние инструкции получают меньше внимания). [официальная документация + независимо проверено]

### 2.4. Отличие от /compact в Claude Code
В claude.ai сжатие автоматическое и почти неуправляемое (нельзя отключить, нельзя таргетировать). В **Claude Code** есть ручной **/compact**, а также **/rewind** (Esc-Esc) с опциями: «Restore code and conversation», «Restore conversation», «Restore code», **«Summarize from here»** и **«Summarize up to here»** — двунаправленная точечная компакция; чекпоинты создаются автоматически на каждый промпт и хранятся 30 дней. Это в вебе недоступно. [официальная документация]

### 2.5. «This conversation is too long to continue»
- **Что это:** чат исчерпал контекстное окно и (при выключенном автосжатии) писать в него больше нельзя. [независимо проверено]
- **Восстановление:** чат **не «оживает»** — продолжить в нём нельзя. Но история **не удаляется**, её можно прочитать и скопировать. [независимо проверено]
- **Что делать после появления:**
  1. Если Claude ещё отвечает на короткие сообщения — попросить сводку: цель, все ключевые решения, созданные артефакты, важный контекст, что осталось. [независимо проверено]
  2. Скопировать нужное вручную; для всего аккаунта — **Settings → Privacy → Export data** (zip с JSON, доставка до 24 ч). [независимо проверено]
  3. Начать новый чат (лучше внутри Проекта) и вставить сводку + переприкрепить файлы. [независимо проверено]
- **Профилактика:** включить Code Execution; чекпоинтить на 70%.

### 2.6. Функции управления разговором: веб vs Claude Code

| Функция | claude.ai (веб) | Claude Code |
|---|---|---|
| Автосжатие | Да (при Code Execution) | Да (auto-compact) |
| Ручной /compact | Нет | Да |
| /rewind, чекпоинты | Нет | Да (Esc-Esc, восстановление кода/чата) |
| Fork/ветвление | Нет (в вебе нет) | Да (--fork-session) |
| Редактирование прошлого сообщения | Да (edit → перегенерация ветки) | н/д |
| Summarize from/up to here | Нет | Да |
| Поиск по прошлым чатам | Да (Search and reference chats, платно) | н/д |
| Память между чатами | Да (Memory, с марта 2026 даже на Free) | Файловая /memory |

## Раздел 3. Проект claude.ai — база знаний и её пределы

### 3.1. Ёмкость базы знаний
- Исторически Проект имел ёмкость, привязанную к контекстному окну (200K), и по достижении порога добавлять было нельзя. [официальная документация]
- Сейчас работает **RAG для Проектов**. Дословно: «When your project knowledge approaches the context window limit, Claude will automatically enable RAG mode to expand your project's capacity by up to 10x while maintaining quality responses». Файлы: **30 МБ/файл, число файлов не ограничено, пока общий объём укладывается** (при RAG — сверх лимита). [официальная документация]
- В UI ёмкость показывается в **процентах** («% of project capacity used»). [независимо проверено]

### 3.2. Порог включения RAG и его влияние на качество
- Официально: RAG включается «при приближении/превышении лимита окна», появляется индикатор и надпись «To save space in chats, Claude will look up specific information as needed». [официальная документация]
- Независимый тест (баг-репорт Anthropic #25759): **RAG включился при 13 файлах на ~2% ёмкости** при неизменном общем объёме ~73K токенов — то есть **порог зависел от ЧИСЛА файлов, а не от объёма**. При 10–12 файлах — прямая загрузка в контекст; при 13 — RAG. Удаление самого крупного файла не выключало RAG. [независимо проверено]
- Влияние на качество: **конфликт источников.** Anthropic утверждает «Maintained quality: Response accuracy remains consistent with in-context processing». Тот же независимый тест #25759 сообщает обратное: RAG-поиск давал худшие результаты, чем прямая загрузка — частичные фрагменты, потеря кросс-файловых связей, галлюцинации и падение следования инструкциям. Василию стоит учитывать этот конфликт и по возможности держать Проект в режиме прямой загрузки. [конфликт источников]

### 3.3. Как структурировать базу знаний
- **Меньше файлов, крупнее** — чтобы дольше оставаться в режиме прямой загрузки (RAG триггерится числом файлов, порог наблюдался около 13). [независимо проверено]
- **Описательные имена файлов** («FINPILOT_API_auth_module.py», «2026_Q3_milestone8_frontend.md») — имена используются ретривером как сигнал. [независимо проверено]
- Держать базу **фокусированной**: лишний слабо связанный материал разбавляет релевантность. [независимо проверено]
- **Проверять ретрив**: явно просить Claude сослаться на конкретный документ («Based on the … in project knowledge…») и убеждаться, что он его находит. [независимо проверено]

### 3.4. Как база знаний расходует контекст в каждом чате
- **До RAG** — знания грузятся **целиком** в каждый чат Проекта (ускоряет наступление стены). [независимо проверено]
- **После RAG** — грузятся **только релевантные фрагменты** по запросу через инструмент project_knowledge_search (экономит контекст, но снижает полноту). [официальная документация]

### 3.5. Инструкции Проекта
- Практический лимит **~8 000 символов** (живой счётчик в UI). Применяются **к каждому чату** Проекта → расходуют контекст каждого чата. [независимо проверено]
- Официальный совет: «Keep project instructions concise: Claude performs best when you use project instructions for general context around your project, key guidelines, and Claude's role». Не дублировать очевидное; плотные однозначные формулировки — слишком длинные размывают внимание. [официальная документация + независимо проверено]

### 3.6. Что делать при переполнении Проекта
- Разбить на **несколько Проектов по темам** (напр. «FINPILOT-backend», «FINPILOT-frontend-M8», «FINPILOT-152ФЗ»). [оценка]
- Архивировать устаревшие файлы, датировать и помечать решения active/superseded, а не удалять молча. [независимо проверено]
- Ротировать: убирать неактуальные версии кода, оставляя один «источник истины». [оценка]

### 3.7. Взаимодействие с памятью и поиском по чатам
- **Память между чатами** (Memory) синтезирует сводки, редактируется в Settings → Features → «View and edit memory»; обновляется в течение 24 ч; удаление чата удаляет и его вклад в память. [официальная документация]
- **Search and reference chats** — опциональный поиск по прошлым чатам (платные планы), срабатывает по вашему явному запросу, эвристичен (может пропускать старые чаты). [независимо проверено]
- Внутри Проекта контекст между чатами **не разделяется автоматически** — общими являются только инструкции и база знаний Проекта. [официальная документация]

## Раздел 4. Разграничение двух стен: контекст vs лимиты плана

### 4.1. Таксономия ограничений Pro

| Ограничение | Сообщение / где видно | Что значит | Восстановление |
|---|---|---|---|
| Контекстное окно чата | «This conversation is too long to continue…» | исчерпано окно данного чата | Не восстанавливается; новый чат |
| 5-часовой лимит сессии | «You're out of usage credits… wait until 3:00 AM» / Settings → Usage | исчерпан лимит плана в текущем 5-часовом окне | Автоматически через ~5 ч от первого сообщения сессии |
| Недельный лимит | Settings → Usage (Weekly) | исчерпан 7-дневный лимит | Фиксированный день/время недели аккаунта |
| Лимит по модели (Opus) | отдельный счётчик в Usage | Opus расходуется быстрее | Отдельный сброс |
| Usage credits (докупаемые) | «out of extra usage» | закончился докупленный баланс | Пополнить вручную |
| Размер файла | «Uploaded file is too large» | превышен лимит МБ/страниц | Уменьшить/разбить файл |
| Число файлов на чат | ошибка при 21-м файле | лимит 20 файлов/чат | Новый чат/удалить файлы |
| Лимит Проектов | — | Free: 5 проектов; платные: без жёсткого лимита | — |

### 4.2. Два сообщения дословно
- **«This conversation is too long to continue. Start a new chat, or remove some tools to free up space.»** → **контекстное окно чата**. Помогает: отключить коннекторы/инструменты в «Search and tools»; начать новый чат; включить Code Execution заранее. **Покупка кредитов НЕ помогает.** [независимо проверено]
- **«You're out of usage credits. Buy more to keep going now, or wait until 3:00 AM when your plan usage resets.»** → **лимит плана** (5-часовой/недельный). Помогает: подождать до указанного времени сброса ИЛИ докупить кредиты. **Новый чат НЕ помогает.** [независимо проверено]

### 4.3. Что такое usage credits
- Механизм «оплата по мере использования» **после** исчерпания включённого лимита плана: работа продолжается по стандартным API-ценам. Дословно: «Instead of being blocked when you hit your session limits, you can switch to consumption-based pricing at standard API rates». Включается в **Settings → Usage**, требует привязки карты. [официальная документация]
- Можно докупать бандлы: дословно «you can pre-purchase usage credits in bundles and save up to 30%... **Individual Pro and Max plan subscribers can purchase up to $2000 worth of discounted bundles per month**» (Team — до $3000). Баланс общий для Claude, Claude Code, Cowork, сторонних продуктов. [официальная документация]
- Отдельно с 15 июня 2026 введён **программный кредитный пул** ($20 Pro / $100 Max5x / $200 Max20x), из которого тратят только Agent SDK, claude -p, GitHub Actions, сторонние API-приложения; обычный чат и Claude Code в терминале — из обычного лимита плана. [независимо проверено]
- Отличие от подписки: подписка — включённый лимит, сбрасывается по окнам; кредиты — деньги сверх, списываются по факту; дашборд различает эти два ведра. [официальная документация]

### 4.4. Время сброса и «3:00»
- **5-часовое окно — скользящее**: стартует с первого сообщения сессии и сбрасывается через ~5 ч, **нет фиксированного времени по часам**. «3:00 AM» в сообщении — это просто конкретное время конца текущего окна для данного аккаунта, а не универсальная константа. [независимо проверено]
- **Недельный лимит** сбрасывается в фиксированный день/время, закреплённые за аккаунтом; «your reset day and time stay the same regardless of when you start using Claude». [официальная документация]
- **Часовой пояс:** сообщения показывают время в **локальном часовом поясе системы** аккаунта; надёжнее смотреть Settings → Usage, где время уже с учётом пояса. Для Москвы Василию стоит ориентироваться на своё отображаемое время, а не на «3:00» буквально. [независимо проверено]
- **Важно про несколько аккаунтов:** на Pro/Max лимиты общие для claude.ai, Claude Code и Claude Desktop одного аккаунта — интенсивный кодинг днём может «съесть» вечерний чат-лимит того же аккаунта. [официальная документация]

## Раздел 5. Практическая оптимизация трёх сущностей

### 5.1. Оптимизация запроса
- Задавать **несколько вопросов в одном сообщении** при работе с длинными документами — эффективнее, чем по одному (официальный совет Anthropic: «Ask multiple questions at once»). [официальная документация]
- **Не переприкреплять** уже загруженный файл. [официальная документация]
- Небольшой фрагмент — **вставлять текстом**, а не файлом (текст ограничен только окном, файл добавляет накладные расходы и живёт в контексте). Большой документ/бинарь — файлом. [оценка]
- Просить **краткий ответ** явно; для рутины — использовать более лёгкую модель (Sonnet/Haiku), Opus беречь для сложного (Opus расходует лимит намного быстрее). [независимо проверено]

### 5.2. Оптимизация чата — «эстафета»
Начинать новый чат **на ~70% окна**, не дожидаясь стены (лучше своя контролируемая сводка, чем автосжатие на 95%). Шаблон передачи состояния (сохранять обязательно):
1. Цель и текущая веха: «FINPILOT 8.1.0, веха 8, перенос фронтенда на React+TS+Vite».
2. Все ключевые архитектурные решения и договорённости.
3. Стек и ограничения: Python 3.12, FastAPI, PostgreSQL, 152-ФЗ, запуск осень 2026, 1473 теста.
4. Что уже сделано (артефакты/файлы) и что осталось.
5. Открытые вопросы.

Хранить этот «handoff» как файл в базе знаний Проекта, обновлять в конце каждой сессии.

### 5.3. Оптимизация Проекта
- Держать **немного крупных файлов** вместо множества мелких (чтобы не триггерить RAG около 13 файлов). [независимо проверено]
- Разделять по темам на несколько Проектов; заводить второй Проект, когда ёмкость/число файлов растёт или темы расходятся. [оценка]
- Регулярно ротировать устаревший код.

### 5.4. Метрики и мониторинг
- **Settings → Usage** — единственный официальный дашборд (лимиты плана, не контекст чата). [официальная документация]
- Внешние счётчики токенов для оценки своих текстов; для русского закладывать множитель (~2× против английского) и +30% для нового токенизатора. [независимо проверено]
- Официальный token-counting API — для точности, но он для разработчиков. [официальная документация]

### 5.5. Готовые процедуры

**Чек-лист ПЕРЕД длинной работой:**
1. Создать/открыть нужный Проект, проверить, что база знаний ≤12 файлов (или осознанно принять RAG).
2. Убедиться, что **Code Execution включён** (Settings → tools).
3. Отключить лишние коннекторы в «Search and tools» (каждый тяжёлый коннектор — десятки K токенов).
4. Выбрать модель под задачу (Sonnet для рутины, Opus для сложного).
5. Вставить/обновить handoff-сводку.

**Чек-лист при признаках переполнения** (учащение «Compacting», забывание инструкций):
1. Немедленно попросить Claude сделать полную сводку состояния.
2. Скопировать сводку и важные артефакты наружу.
3. Отключить неиспользуемые инструменты.
4. Начать новый чат в том же Проекте со сводкой.

**Аварийное спасение умирающего чата:**
1. Если ещё отвечает — «Собери всё важное из этого чата: цель, решения, код, числа, что осталось».
2. Скопировать вручную; при риске потери — Settings → Privacy → Export data.
3. Новый чат + вставка сводки + переприкрепление файлов.

## Раздел 6. Важное, о чём не спросили

### 6.1. Сводная таблица управления контекстом

| Свойство | Чат claude.ai | Проект claude.ai | Claude Code | Cowork |
|---|---|---|---|---|
| Окно | 200K–1M по модели | как чат + RAG 10× для знаний | до 1M (API; Pro Opus — через credits) | как база Code |
| Автосжатие | Да (при Code Exec) | Да | Да (auto-compact) | Да |
| Ручной контроль (/compact, /rewind) | Нет | Нет | Да | Частично |
| Персистентные знания | Нет | Да (база знаний) | CLAUDE.md/файлы | Файлы |
| Индикатор контекста | Нет | % ёмкости Проекта | /context, /status | Ограниченно |

### 6.2. Свежие изменения 2026
- Память для всех, включая Free (март 2026). [независимо проверено]
- 6 мая 2026 — удвоены 5-часовые лимиты, убраны peak-hour снижения. [независимо проверено]
- Отмена long-context наценки (март 2026); 1M-окно стало GA по стандартной цене. [независимо проверено]
- Программный кредитный пул с 15 июня 2026. [независимо проверено]
- Новый токенизатор (модели 4.7+): тот же текст = ~+30% токенов. [официальная документация]
- **Расхождение в справке:** новая редакция официальной статьи об аплоадах указывает **500 МБ/файл** для чата (вместо прежних 30 МБ), при этом база знаний Проекта — по-прежнему **30 МБ/файл**. Василию стоит перепроверить лимит в своём аккаунте перед загрузкой крупного файла. [конфликт источников]

### 6.3. Типичные ошибки, из-за которых чаты умирают рано
1. Загрузка zip/архивов и больших документов в веб-чат вместо Проекта/GitHub.
2. Множество включённых коннекторов (десятки K токенов впустую — GitHub ~26K, Slack ~21K, Jira ~17K).
3. Ведение одного бесконечного чата по всем темам.
4. Переприкрепление одних и тех же файлов.
5. Игнорирование признаков сжатия до жёсткой стены.
6. Выключенный Code Execution (нет автосжатия → жёсткая стена).

### 6.4. Большие zip-архивы кода (боль Василия — 70 МБ)
- **.zip официально НЕ входит** в список поддерживаемых типов чата (PDF, DOCX, CSV, TXT, HTML, ODT, RTF, EPUB, JSON, XLSX + изображения). На практике сторонние источники сообщают, что Claude может читать структуру и текстовые файлы внутри zip, но это **не подтверждено Anthropic**. [официальная документация + оценка]
- **Размер:** по прежнему лимиту 30 МБ 70-МБ zip **отклоняется сразу**; по новой редакции (500 МБ) — пройдёт по размеру, но **упрётся в контекстное окно** при распаковке в текст (70 МБ кода — сотни тысяч/миллионы токенов, что превышает даже 1M). [независимо проверено]
- **Куда девается контекст:** извлечённый текст всего архива летит в окно с каждым сообщением — это и есть причина ранней стены.
- **Правильные альтернативы для FINPILOT:**
  1. **GitHub-коннектор** (доступен всем планам, включая Free): «Add from GitHub» → выбрать **только нужные файлы/папки** через «Configure files», «Sync now» для обновления. Синхронизируются только имена и содержимое файлов ветки (без истории/PR). Anthropic предупреждает: не выбирать лишние файлы, чтобы уложиться в токены. [официальная документация]
  2. **База знаний Проекта** — положить ключевые модули (немного крупных файлов, описательные имена).
  3. **Вставка текстом** нужных фрагментов.
  4. **Code Execution sandbox** — может программно распаковать zip (Python/bash), но без интернета и с эфемерным хранилищем; для 70 МБ кода всё равно нерелевантно из-за окна.
  5. **Claude Code** — оптимальный инструмент для крупной кодовой базы: работает с файлами локально, окно до 1M, есть /compact, /rewind, /context.

### 6.5. Что ещё сказал бы независимый эксперт
- **Держите внешний «источник истины».** Claude — не система хранения; ведите handoff-документ и решения в репозитории/базе знаний, а не только в чате. История «умершего» чата не удаляется, но полагаться на неё нельзя.
- **Работа с нескольких аккаунтов Pro** не расширяет контекст одного чата — окно привязано к чату/модели, а не к числу аккаунтов; несколько аккаунтов помогают только обходить лимиты ПЛАНА, но фрагментируют память, Проекты и историю (усложняя «эстафету»).
- **Для production-проекта с 152-ФЗ** проверьте политику хранения данных перед загрузкой чувствительного кода/данных в базы знаний; потребительские Pro-условия отличаются от Enterprise (у консьюмерских планов удаление из бэкенда в течение 30 дней после удаления чата).
- **Опус только при явной необходимости** — он резко быстрее исчерпывает лимит плана, приближая вторую стену.
- **Синхронизируйте включение Code Execution** во всех рабочих контекстах — это единственный переключатель, превращающий «жёсткую стену» в «мягкое автосжатие».
