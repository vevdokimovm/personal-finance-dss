## Money vs Dimensionless Migration Audit — app/core/*.py

**Call graph**: `services/planning.py` is the sole orchestrator; it calls `alternatives`, `amortization`, `crisis`, `filtering`, `goals_priority.preallocate_from_bliq`, `investment.annotate_investment_tranche`, `surplus`, `metrics`, `ranking`, `recommendation` directly — these receive float from planning.py today and must accept Decimal money post-migration. `avalanche.py`, `preprocessing.py` are pure computation consumed transitively (via alternatives/surplus, and services elsewhere). `categorization.py`/`category_rules.py`/`experiments.py`/`legal.py` carry no money at all — skip.

**amortization.py** — Money: `x_obl_monthly`, `r_bench`(rate, dimensionless actually), obligation `amount`/`monthly_payment`, all `balances`/`total_interest`/`interest_saved` fields, `DebtScheduleSummary.*_total_interest`. Dimensionless: `interest_rate` (annual), `rates_m` (monthly rate), month counters, `horizon_months`. **Mixed-expression risk (highest)**: `_simulate` line 125 `interest = balances[i] * rates_m[i]` (money × rate), line 111 `rates_m = ... interest_rate / 12` (rate/12, fine as float), line 79 `payment * pay / amount` pattern is elsewhere (avalanche) but same shape appears via cascade `pool -= apply` mixing money only. Line 128 `pay <= interest + 1e-9` mixes money with a float epsilon tolerance — needs Decimal-safe epsilon. This file is the compounding/rounding-order hotspot: interest accrues every month on a running Decimal balance, and rounding order (round each month vs accumulate unrounded) changes `baseline_total_interest`/`accelerated_total_interest` results — needs explicit design decision (round interest to cents each month, matching real bank amortization, vs keep unrounded and only round at output).

**avalanche.py** — Money: `x_obl`, obligation `amount`, `monthly_payment`, `x_obl_effective`, `x_obl_unused`. Dimensionless: `interest_rate`, `r_bench`. **Mixed-expression risk**: line 79 `old_payment * (new_amount / old_amount)` — money × (money/money ratio), safe if all Decimal. `select_avalanche_targets` only compares rates (pure float, fine to leave). No incompatible math functions.

**alternatives.py** — Money: `rt`, `obligation_payments`, `goals_total`, `x_obl`, `x_res`, `x_goa`, `bliq`, all `Rt_new`/`x_*` outputs, `paid_in`, `payment_saved`. Dimensionless: `step`, `steps` (grid indices), `r_bench`, `Dt_new` (ratio), `Si` (score), percentages `pd/pr/pg`. **Mixed-expression risk**: line 96-98 `x_obl = round(rt * d * step, 2)` — money × dimensionless int × dimensionless float step; line 217 `new_dt = new_obligation_payments / income_total` (money/money → dimensionless ratio, a boundary crossing back to float); line 216 `new_lt = (bliq + x_res_effective) / expense_total` same pattern. These money/money→ratio divisions are exactly where Decimal must convert back to float before feeding ranking.py. Uses `money()` from money.py already at several spots (173,178-183,190-193) — good precedent to extend.

**crisis.py** — Money: `deficit`, `bliq`, `expense_total`, obligation `amount`/`monthly_payment`, `recovered`, `spent`, `bliq_remaining`, `new_rt`, `max_affordable`, `cut`. Dimensionless: `interest_rate`, `ratio = payment/amount` (line 77, money/money→dimensionless rate-like ratio used for sorting), `runway` (months), `severity` labels. **Mixed-expression risk**: line 86 `pay = min(left, need / ratio + 0.01)` — money divided by a dimensionless ratio plus a hardcoded float epsilon (0.01 ₽) — needs Decimal epsilon; line 90 `saved = money(payment * pay / amount)` — money×money/money; line 113 `bliq_remaining / expense_total` money/money→dimensionless Lt. line 132 `bliq / deficit` → runway in months (money/money→dimensionless). Already uses `money()` wrapper extensively — good migration anchor.

**envelopes.py** — Money: `current_amount`/`amount` (asset), effective `current_amount`. Dimensionless: `savings_rate`/`interest_rate`, ids. No arithmetic mixing (just passthrough via `to_float`). Low risk, but every `to_float(...)` call for a money field needs to become `to_money`/Decimal.

**filtering.py** — All comparisons only, no money arithmetic (`Rt_new`, `Lt_new`, `Dt_new` compared to thresholds `b_min`, `l_min`, `dt_max`). `Rt_new` is money; `Lt_new`/`Dt_new`/thresholds are dimensionless. Only risk: comparing Decimal `Rt_new` against float `b_min=0.0` — needs type coercion at boundary, no math functions.

**forecast.py** — Entirely float/dimensionless-adjacent but forecasts MONEY balances/flows (`history`, `point_forecast`, `p10/p50/p90`). Contains **incompatible math**: `math.sqrt` (line 112) on `sigma_h` (dimensionless factor, ok), `random.gauss` producing money noise (line 114) — Monte Carlo on money values is fundamentally a float/statistical operation; recommend converting money to float at the boundary for this whole module rather than porting to Decimal (no decimal-native Gaussian sampling). `phi ** h` (line 77, dimensionless, fine). `monthly_rate`: `(1+annual_rate) ** (1/12)` — dimensionless rate compounding, `**` with fractional exponent is exactly the case Decimal can't do directly (`Decimal ** Decimal` with non-integer exponent raises); if ever fed a Decimal rate, must convert to float or use `decimal.Decimal.ln/exp`. This whole module should likely stay float end-to-end (money in, money out, but internal computation is statistical/dimensionless) — flag for explicit scope decision with the user.

**goals_priority.py** — Money: `x_goals`, `target_amount`, `current_amount`, `remaining`, allocation dict values, `bliq`. Dimensionless: `urgency`, `weight`, `priority`, `Si` (returned ratio in [0,1]), months. **Mixed-expression risk**: `calculate_goals_si` line 156-159 `x_goa_s = min(x_goals * share, g["_remaining"])` (money × dimensionless share, capped by money) then `weighted_x += x_goa_s * g["_priority"]` (money × dimensionless), `si = weighted_x / weighted_total` (money/money → dimensionless, boundary point). `inflated_target_amount` line 106 `target_amount * (1.0 + rate) ** years` — money × (dimensionless base)^years; `**` with non-integer `years` (money-adjacent computation) is an incompatible-math flag — same as forecast.monthly_rate pattern, needs float conversion or `Decimal ** Decimal(years)` support check (Decimal only supports integer exponents natively without `decimal.Context`—actually `Decimal.__pow__` supports Decimal exponents via correctly-rounded power since Python's decimal module implements general power for a base/exp per the General Decimal Arithmetic spec, but it's finicky with precision context — flag for verification). `preallocate_from_bliq` line 200 `max_use = bliq * BLIQ_USAGE_THRESHOLD` (money × dimensionless).

**investment.py** — Money: `amount`, `invest`, `eligible_amount`, `deduction`, `equity`/`deposits`/`bonds`, `x_res`, `bliq`, `cushion_gap`. Dimensionless: `iis_type`, `risk_tolerance`, `equity_share`, `rate`/`years` lists, `months_left`. **Mixed-expression risk**: line 79 `eligible * IIS_DEDUCTION_RATE` (money × rate); line 112 `amount * (1 + rate) ** y` — same non-integer-safe `**` compound-interest pattern as goals_priority, **incompatible math flag**; line 141-144 `build_shelf_split`: `amount * equity_share`, `non_equity / 2`, `amount - equity - deposits` — pure money arithmetic already wrapped in `money()`, straightforward Decimal port; line 168 `lt_target * expense_total - bliq` money×dimensionless-months minus money.

**metrics.py** — Money: `balance`, `liquid_assets`, `expense_total`, `income_total`, `obligation_payments`, `Bt`. Dimensionless: `Dt`, `Lt`, `BLR` (all outputs are ratios/months despite being computed from money inputs). **Mixed-expression risk (pervasive, boundary-defining file)**: every function here is money/money → dimensionless: `calculate_lt` (line 94, `liquid_reserve/expense_total`), `calculate_dt` (line 107, `obligation_payments/income_total`), `calculate_blr` (line 118). This file is effectively THE boundary layer between money-Decimal and dimensionless-float in the whole engine — every function should take Decimal money in, return float ratio out. No incompatible math.

**ranking.py** — Almost entirely dimensionless (`Rt_new`, `Lt_new`, `Dt_new`, `Si` are read but only normalized/weighted — SAW core, explicitly meant to stay float per money.py docstring). `normalize_value` operates on already-dimensionless-ish `alt["Rt_new"]` etc., but note `Rt_new` itself is a **money value** being min-max normalized alongside dimensionless Lt/Dt/Si — this is the sanctioned float boundary (per user's framing) but the caller must convert `Rt_new` from Decimal→float before passing alternatives into `rank_alternatives`. No math incompatible with Decimal (only `**` absent here; `income_cv` in same file uses `variance ** 0.5` for sqrt — line 105 — but that's on `income_history` (money values!) for CV computation — **flag**: `income_cv` computes standard deviation of monthly income (money) via `** 0.5`; if income_history is ever Decimal, this breaks — needs float conversion at entry, or use `decimal.Decimal.sqrt()`.

**recommendation.py** — Pure NLG/formatting, reads already-computed `Rt_new`, `Dt_new`, weighted_scores, money amounts for string interpolation (`:,.0f`). No arithmetic risk beyond `delta_rt = alt.get("Rt_new", rt) - rt` (money − money, fine) and percentage math (`dt*100`, dimensionless). Entry point receiving float from ranking output; formatting `{:,.0f}` works fine with Decimal too (or convert to float first for f-string formatting simplicity).

**spending_advice.py** — Money: `amount` (ExpenseRecord), `baseline`, `current`, `potential_saving`, `mad`, `avg_check`, `target_amount`, `current_amount`, `monthly_contribution`, `redirected_saving`, `remaining`. Dimensionless: `z_score`, `share`, `compressibility`, `freq_month`, `slope_pct`, `pain_score`. **Mixed-expression risk**: `robust_zscore` line 177 `MAD_SCALE * (value - center) / mad` — money-diff/money(mad) × dimensionless const → dimensionless z (boundary); `pain = freq_month * avg_check * comp` (dimensionless × money × dimensionless → money-ish "pain score", ambiguous units, likely should stay float as a derived score); `theil_sen` computes slopes of money-over-month (money/dimensionless-month). Uses `statistics.median` — **incompatible-math flag**: `median()` works fine on Decimal actually (statistics module supports Decimal since it's just sorting/averaging), but `mad`/`robust_zscore` mix medians of money values — low risk but worth testing. This whole module is describes-past-data analytics (not the decision core) — reasonable candidate to keep money inputs as Decimal only at the ExpenseRecord boundary, compute internally in float (like forecast.py), given heavy statistical/robust-stats machinery.

**surplus.py** — Money: `bliq`, `expense_total`, `reserve_target`, `deployable`, `left`, obligation `amount`/`monthly_payment`, `pay`, `payment_freed`, `opportunity_gain_yearly`, goal `target_amount`/`current_amount`. Dimensionless: `r_bench`, `risk_tolerance`, `rate`, `lt_target`, `months`. **Mixed-expression risk**: line 91 `pay * (rate - r_bench)` — money × (rate−rate, dimensionless spread) → money "yearly gain" (actually unit-inconsistent already — monthly pay × annual rate spread, pre-existing float quirk, not migration-specific but worth flagging); line 89 `payment * pay / amount` money×money/money. Already uses `money()` wrapper throughout — straightforward port.

**categorization.py, category_rules.py, experiments.py, legal.py** — No money arithmetic at all (string/rules/hash-based). Skip entirely for Decimal migration.

**preprocessing.py** — `_normalize_*` functions cast money fields (`amount`, `monthly_payment`, `target_amount`, `current_amount`) via `_to_float`. This is the actual **input boundary** where floats first enter the engine from services — migration requires a parallel `_to_money`/Decimal cast here, and this is likely the single highest-leverage file to change first since every money-bearing dict downstream depends on its normalization.

### Summary of general findings
1. **Boundary files** for money↔dimensionless conversion: `metrics.py` (Dt/Lt/BLR = money/money), `alternatives.py` (Rt_new/Dt_new/Lt_new computation), `preprocessing.py` (input cast), `ranking.py` (Rt_new gets normalized alongside float scores — sanctioned float zone entry).
2. **Highest compounding/rounding risk**: `amortization.py._simulate` (monthly interest accrual loop) and `avalanche.py.allocate_obligations_avalanche` (proportional payment reduction) — both do repeated money arithmetic with implicit float epsilon tolerances (`1e-9`, `0.005`, `0.01`) that need Decimal-safe equivalents.
3. **Incompatible-math (`**` with non-integer exponent) on money-adjacent values**: `forecast.monthly_rate`, `goals_priority.inflated_target_amount`, `investment.project_compound_growth` — all compute compound growth `amount * (1+rate)**years/h`; recommend converting to float at these specific call sites rather than forcing Decimal through `**`.
4. **`math.sqrt`/`** 0.5` on money**: `ranking.income_cv` (stdev of income history), `forecast.monte_carlo_intervals` (Monte Carlo on money via `random.gauss`) — both statistical, best kept float with Decimal→float conversion at entry.
5. **statistics.median on money**: `spending_advice.py` — module recommended to stay float internally per the same rationale as forecast.py, converting only at the ExpenseRecord boundary.
