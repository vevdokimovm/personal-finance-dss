## 🔴 Формат `constructPath` в pdf.js v6 — расшифрован замером, в документации не описан

Первая попытка по описанию из отчёта Б-01 (`[paintOp, [Float32Array], bbox]`, коды `OPS.moveTo`/
`OPS.lineTo`) дала **0 сегментов**. Дамп реальных аргументов:

```
=== constructPath #213
[ 20,
  [ Float32Array(6) [ 0, 0, 46.79999923706055, 1, 400.2578125, 46.79999923706055 ] ],
  Float32Array(4) [ 0, 46.79999923706055, 400.2578125, 46.79999923706055 ] ]
```

Разбор: `args[0]` — код операции закраски (число, НЕ массив); `args[1]` — **массив
`Float32Array`**; `args[2]` — bbox. Внутри `Float32Array` лежат **тройки `(код, x, y)`**,
где **0 = `moveTo`, 1 = `lineTo`**, 2 = `curveTo` (+6 координат), 3 = `closePath`.
🔴 Это **не** константы `OPS.moveTo` (13) и `OPS.lineTo` (14) — у пути своя нумерация,
и именно на этом ломается перенос «по документации». `DrawOPS` из пакета не экспортирован.

Полный состав операторов страницы ВТБ: `constructPath` ×24, `transform` ×7, `save`/`restore`
×12, `showText` ×23, `setLineWidth` ×1.

CTM ведётся вручную (`save`/`restore`/`transform`), перевод в систему `pdfplumber` —
`top = height − y`, начало координат сверху.

### Откуда берутся 0,003 pt и почему это не дефект

`pdf.js` отдаёт координаты в `Float32Array` (≈7 значащих цифр), `pdfplumber` — в float64.
Пример дословно: одна вертикаль ВТБ — `pdf.js` **467,45**, `pdfplumber` **467,4527**.

🔴 **Ловушка сравнения, в которую я сам попал:** при округлении до одного знака 467,45 → 467,4,
а 467,4527 → 467,5, и ребро выглядит как расхождение. Первый прогон так и показал «11 из 12».
Расхождения не было — был порог округления. **Сравнивать такие замеры надо допуском по сырым
значениям, а не равенством округлённых.** Ошибка моя, зафиксирована, чтобы не повторилась.

## Второй результат, не менее важный: два шаблона из четырёх линий не имеют вовсе

`sber` и `tinkoff` — **0 линий** и у `pdfplumber`, и у `pdf.js`. Это подтверждает вывод Г20
(раздел 1.2: «таблицы находятся только там, где нарисованы линии») и означает, что
**для половины шаблонов линейная стратегия не работает в принципе** — ни на сервере, ни в
браузере. Там нужна текстовая стратегия по координатам слов. То есть перенос на клиент
не ухудшает положение: у обоих движков оно одинаковое.

## Вердикт по остатку Б-01

🟢 **Закрыт замером: приём переносится по факту, а не только по документации.** Графические
примитивы в браузере доступны с точностью 0,005 pt на наших шаблонах; ширина колонки таблицы
— десятки пунктов, то есть запас четыре порядка.

**Цена переноса, уточнённая замером** (была «CTM вести самому»):
1. CTM вести самому — подтверждено.
2. 🔴 **Кодировка пути недокументирована и своя** — тройки `(код, x, y)` с собственной
   нумерацией, `DrawOPS` не экспортирован. Отчёт Б-01 описал формат неверно, и по его описанию
   получается ноль рёбер. Значит при обновлении `pdfjs-dist` это место обязано быть закрыто
   тестом на эталонных рёбрах, иначе смена формата пройдёт молча.
3. Координаты `Float32` — сравнение с эталоном только с допуском.
