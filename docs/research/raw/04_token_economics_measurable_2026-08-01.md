# Измеримая экономика запросов к Claude: операционная методичка для Василия (FINPILOT, август 2026)

## TL;DR
- **Латентность измерена независимо и растёт нелинейно с уровнем усилия**: у Opus 5 время до первого токена (включая «мышление») по замерам Artificial Analysis — 2,98 с (low) → 6,46 с (medium) → 12,83 с (high) → 24,63 с (xhigh) → **92,02 с (max)**; у Sonnet 5 max — **179 с**. Независимое подтверждение порядка величины: eesel AI намерил у Opus 5 «68 seconds at max effort, versus a class median of 2.81 seconds». «Max на Opus 5» — самая дорогая и самая медленная комбинация; для вехи 8 (React-фронтенд) она почти всегда избыточна.
- **Расход токенов на задачу имеет огромную дисперсию, а не одно число**: единственный публичный воспроизводимый замер код-ревью (CodeRabbit) — ≈60,5 тыс. входных / 9,5 тыс. выходных токенов на вызов Opus 5 (разброс 55–64 тыс. / 8,1–10,8 тыс.); базовый оверхед харнесса Claude Code — ≈33 тыс. токенов на первый запрос (Systima), субагенты множат расход до 4–5,9×. Официальных чисел «токенов на генерацию компонента / рефакторинг / фикс бага» **не существует** — их надо мерить самому.
- **Нагрузку на серверы Anthropic со стороны пользователя измерить нельзя** (принципиально ненаблюдаемо, кроме статус-страницы и кодов 429/529); а вот собственный расход и время **полностью измеримы** через `ccusage`, OpenTelemetry-экспорт Claude Code и API `count_tokens`. Ниже — готовый план эксперимента с формулой размера выборки.

## Key Findings (с пометкой типа каждого числа)

1. **TTFT у ризонинг-моделей — это в основном время «мышления», а не префилл.** Заявленные 92 с и 179 с для max доминируются reasoning-токенами; eesel AI отдельно замерил, что Opus 5 делает «103, 91, and 76 turns per task across its top three effort levels, compared to 55 for Opus 4.8 (max)». [измерено независимо, Artificial Analysis, медиана P50 за 72 ч, нагрузка 10k входных токенов; corroboration — eesel AI]
2. **Скорость генерации Opus 5 почти не зависит от усилия** (≈50–55 t/s на всех уровнях) — растёт только объём размышлений и, соответственно, TTFT и полное время. [измерено независимо, AA]
3. **Fast mode** ускоряет вывод Opus 5 ровно в 2,5× за 2× цену ($10/$50 против $5/$25): по документации Anthropic «Fast mode is exactly 2x standard pricing for 2.5x output speed», это research preview, только first-party API (не Bedrock/Vertex/Foundry), не сочетается с Batch API. [официальное значение, Anthropic]
4. **Промпт-кэш** даёт до −90% стоимости входа и до −85% латентности на кэшированном префиксе. [официальное значение Anthropic; независимые продакшн-замеры: устойчиво 60–90%]
5. **«Context Rot»** (Chroma, 18 моделей): даже с замаскированными дистракторами точность падает в среднем на 7,9% только от длины («accuracy still fell 7.9% on average from length alone»); «мёртвая зона» — позиции 5–15 из 20 (−30+ п.п.). [измерено независимо, Chroma]
6. **Официальных данных о деградации латентности в пиковые часы нет**; известно лишь, что 6 мая 2026 Anthropic убрал peak-hour reductions и удвоил 5-часовые лимиты Claude Code для «Pro, Max, Team, and seat-based Enterprise plans» плюс «substantially higher API rate limits for Claude Opus», под компьютные мощности SpaceX Colossus 1 («more than 300 megawatts and over 220,000 NVIDIA GPUs»). [официальное значение о лимитах; данных о латентности в пик — нет]
7. **chrome-devtools ставится НЕ из claude-plugins-official.** Правильно: `/plugin marketplace add ChromeDevTools/chrome-devtools-mcp`, затем `/plugin install chrome-devtools-mcp@chrome-devtools-plugins`. Ошибка пользователя закономерна. [официальное значение, Chrome for Developers + claude-plugins-official]
8. **`/design-sync` требует Claude Code v2.1.181+.** У пользователя 2.1.114 — команда недоступна; при этом даже часть пользователей на v2.1.195 сообщала, что команда всё ещё отсутствует (GitHub issue #71738). [независимо, Vibe Coder Blog + GitHub]

### НАПРАВЛЕНИЕ 2. Токены на запрос по типам нагрузки

**Единственный воспроизводимый публичный замер по задаче — код-ревью (CodeRabbit):** дословно — «It averaged ≈60.5k input tokens per call (55k to 64k depending on configuration) and ≈9.5k output tokens (8.1k to 10.8k), against ≈40.5k in and ≈5.8k out for the GPT-5.6 lanes doing the same job». Выборка — «roughly 100 verified error patterns» из реальных PR, три прохода на конфигурацию. [измерено независимо, CodeRabbit]

**Оверхед харнесса Claude Code (Systima, логирующий прокси на API-границе, Claude Code 2.1.207, sonnet-4-5):**
- Пустой ответ «OK»: ≈33 тыс. токенов (система + схемы 27 инструментов + reminder-блоки) против ≈7 тыс. у OpenCode. [измерено независимо]
- Из них ≈24 тыс. — определения инструментов.
- Файл инструкций 72KB (CLAUDE.md/AGENTS.md) добавляет ≈20 тыс. токенов на каждый запрос.
- 5 MCP-серверов: +5–7 тыс. токенов.
- Итог реального сетапа: 75–85 тыс. токенов до первого слова пользователя.
- Задача «прочитать файл и суммировать» (T2): 6 HTTP-запросов, ≈199 тыс. кумулятивных входных токенов (большинство — cache reads по 1/10 цены).
- Задача write-run-test-fix (T3, FizzBuzz): 3 запроса, ≈121 тыс. токенов; на новой модели — ≈298 тыс.
[всё — измерено независимо, Systima, малая выборка 3 прогона/задачу]

**Телеметрия Claude Code (OpenTelemetry).** Claude Code нативно эмитит OTLP-метрики и события. Доступные поля: `claude_code.token.usage` (с разбивкой на input/output/cacheRead/cacheCreation по моделям), `claude_code.cost.usage`, сессии, строки добавлено/удалено, коммиты, PR, активное время, доля принятых правок, события `claude_code.api_request`, `claude_code.tool_result`, `claude_code.tool_decision`. [официальное значение, Claude Code docs; SigNoz, AWS, Faros, Bindplane, KubeRocketCI]. Faros: Claude Code стримит per-developer телеметрию (сессии, токены, стоимость, tool acceptance rates). AWS CloudWatch Coding Agent Insights даёт готовый дашборд.

**Статистика распределения нагрузки (Anthropic research через Tribe AI):** 79% диалогов Claude Code — задачи автоматизации; 35,8% — feedback-loop; 43,8% — директивные; JS/TS доминирует (31% запросов), HTML/CSS 28%, Python 14%. [официальное значение, приведено вторично через Tribe AI]

**Токены на один вызов инструмента (независимая оценка AICosts):** выполнение команды 200–1000 токенов; отчёт о прогрессе 300–1500; обработка ошибки/восстановление 2000–10000 на инцидент. [оценка, вторичный источник — относиться осторожно]. Точных официальных цифр по чтению файла/правке/поиску/скриншоту Playwright/снапшоту доступности **нет** [данных нет].

**Соотношение «токены размышления / токены ответа» по уровням усилия.** Точных измерений с числами **нет** [данных нет]. Качественно: конфигурация усилия сильнее влияет на reasoning-токены Opus 5, чем на Opus 4.8; Opus 5 «notably slow and very verbose» (AA); eesel косвенно даёт метрику ходов: 103/91/76 turns на топ-3 уровнях против 55 у Opus 4.8 (max). [измерено независимо, качественно + eesel]

**Субагенты.** Один субагент = свой полный baseline (система + инструменты) на каждый ход; кэш не пересекается между моделями. Замеры: задача 121 тыс. токенов напрямую → 513 тыс. при фан-ауте на 2 субагента (4,2×); в другом кейсе — до 5,9×. Правило: 3 субагента ≈ 4× расхода одного потока. Реддит-кейс: «85% расхода пришло из subagent-heavy сессий». Стоимость линейна: 6 субагентов ≈ 6× токенов. [измерено независимо, Systima; вторично — youcanbuildthings, aibuilderclub]

### НАПРАВЛЕНИЕ 3. Длина промпта — измеренная зависимость

**Context Rot (Chroma, Kelly Hong, Anton Troynikov, Jeff Huber, июль 2025; 18 фронтир-моделей, включая Claude 4, контексты 1K–1M):**
- Деградация у всех 18 моделей с ростом длины, нелинейно, иногда на 30–50% задолго до предела окна. [измерено независимо]
- Модели с окном 1M «не ведут себя как 1M» после ~200K; модели 200K начинают «заваливаться» на 80–100K. [измерено независимо]
- «Мёртвая зона» — позиции 5–15 из 20 документов: точность падает на 30+ п.п. («lost in the middle»). [измерено независимо]
- Даже с замаскированными дистракторами: «accuracy still fell 7.9% on average from length alone». [измерено независимо]
- Полная история чата (~113K токенов) роняет точность на ~30% против фокусной версии (~300 токенов). [измерено независимо, LongMemEval]

**Коэффициенты токенизации (Claude использует BPE-токенизатор, с Opus 4.7 / Sonnet 5 / Fable 5 — новый токенизатор):**
- Английская проза: ~1,3–1,5 токена/слово, ~3,5–4 символа/токен. [измерено, Anthropic glossary + токен-счётчики]
- Новый токенизатор 5-поколения: тот же текст маппится в ~1,0–1,35× больше токенов (зависит от типа контента); по другим оценкам — до +30%. [официальное значение диапазона, Anthropic; независимая оценка +30%]
- Код плотнее: ~3 символа/токен; каждый отступ, скобка, оператор — часто отдельный токен. Python-функция 1000 символов ≈ 400–500 токенов против 250–300 для прозы. [измерено, токен-счётчики]
- Русский и не-латиница: 2–6× дороже за слово, чем английский. [измерено, токен-счётчики]
- tiktoken (OpenAI) недосчитывает Claude на ~15–20% на обычном тексте и больше на коде — не использовать для планирования; только `count_tokens`. [измерено независимо]
- Claude-токенизатор относительно маленький (~22–65K словаря по независимому анализу); 8311 из 10000 самых частых английских слов — один токен. [измерено независимо, tokencontributions]
- JSON/Markdown/CSV: измерены отдельно в датасете TextKit через официальный count_tokens API (envelope 6 токенов на Opus 4.8, 7 на Sonnet/Haiku). [измерено независимо]

**Влияние длины промпта на время и выходные токены:** прямая измеренная связь на Claude 5 — только качественная (длинный вход → длиннее TTFT; см. таблицу префилла). Точной формулы для 5-поколения **нет** [данных нет].

**Что экономят техники (проценты):**
- Промпт-кэш: −60–90% стоимости входа, −85% латентности. [официальное значение Anthropic; независимо 60–90% устойчиво]
- Batch API: −50% на всех токенах (но задержка до 24 ч). [официальное значение]
- Очистка контекста между задачами (`/clear`, `/compact`): один из самых устойчивых способов снизить расход. [независимо, Faros]
- ContextRecoveryHook (ClaudeFast): восстанавливает ~15 000 токенов за сессию. [оценка вендора — осторожно]

### НАПРАВЛЕНИЕ 4. Нагрузка и лимиты как наблюдаемая величина

**Заголовки ответа API (можно читать на каждом ответе):**
- `anthropic-ratelimit-requests-remaining` / `-reset`
- `anthropic-ratelimit-tokens-remaining` / `-reset` (а также раздельно input/output tokens)
- `retry-after` (секунды до повтора при 429)
- `x-should-retry: false` (если стоит — повтор бесполезен, надо менять квоту)
- `anthropic-fast-*` (статус fast-mode лимитов)
- объект `usage` в теле с `input_tokens`, `output_tokens`, cache-полями.
[официальное значение, Anthropic docs]

**429 против 529:**
- **429** `rate_limit_error` — превышен ваш лимит (RPM/ITPM/OTPM). Читать `retry-after`, ждать ровно столько, снижать конкурентность. [официальное значение]
- **529** `overloaded_error` — перегружены серверы Anthropic, не ваша вина, `retry-after` доверять нельзя; экспоненциальный backoff + jitter, при повторах — фолбэк на Bedrock/Vertex. Отклонённые 529 не тарифицируются. [официальное значение + независимо]

**Таблица 2. Лимиты API (после реформы 26 июня 2026 — тиры Start/Build/Scale/Custom)** [официальное значение структуры; числа — через сторонние трекеры, «verify in console»]:

| Тир | Порог | Потолок расхода/мес | Ориентир RPM / ITPM / OTPM |
|---|---|---|---|
| Start | от $5 | $500 | низкий (проверять в консоли) |
| Build | — | $1 000 | ~5 000 RPM / 5M ITPM (Sonnet) |
| Scale | — | $200 000 | ~4 000 RPM / ~2M ITPM / 400–800K OTPM |
| Custom | sales | без потолка | договорной |

Ключевое: с 26.06.2026 Sonnet 4.x/5 и Haiku 4.5 имеют **те же** RPM/ITPM/OTPM, что и Opus 4.x на каждом тире; лимиты пулятся по семействам моделей; cache reads **не считаются** в ITPM. [официальное значение]

**Команды в Claude Code:**
- `/usage` — текущая сессия и статус окон (подписчики). Не показывает тренды и не показывает остаток окна в токенах. [официальное значение]
- `/status` — статус сессии/окон.
- `/cost` — для API-пользователей: кумулятивный расход, время, строки, токены по моделям (input/output/cache read/cache write). Для подписчиков Pro/Max скрыт и **не релевантен для биллинга** (прямая цитата Anthropic: session cost «isn't relevant for billing purposes» для подписчиков). [официальное значение]
- Известное расхождение: `/cost` считает по API-ценам, что бессмысленно на подписке; ccusage оценивает стоимость из токенов и прайса — тоже оценка, не счёт.

**Можно ли измерить «нагрузку на серверы» со стороны пользователя? Прямой ответ: НЕТ.** Принципиально ненаблюдаемо, кроме: (1) status.claude.com; (2) частота/тип 529; (3) исторически — peak-hour деградация (убрана 6.05.2026). Метрика «остаток моего окна в токенах» публично **не существует** — Anthropic её не публикует. [данных нет — прямое подтверждение]

**Пятичасовые окна (технически):**
- Стартует с **первого сообщения**, не по фиксированным часам; сбрасывается через 5 ч после первого сообщения. [официальное значение]
- Недельные лимиты: у Max — два (все модели + отдельно Sonnet); сброс в фиксированное время, привязанное к аккаунту. [официальное значение]
- Общий пул с claude.ai чатом (Claude Code и чат тратят одно окно). [официальное значение]
- Переключение модели через `/model` **не восстанавливает** доступ (лимиты общие). [официальное значение]
- Быстрее всего бюджет жгут: Opus, длинный контекст, extended thinking, большие вложения, субагенты. [официальное значение + независимо]
- Независимое наблюдение: `seven_day` лимит по факту сбрасывался каждые ~72 ч (±0,6 ч), не 7 дней, в июне 2026 — недокументированное поведение (могло измениться). [измерено независимо, единичное наблюдение 11 дней]

### НАПРАВЛЕНИЕ 5. Методология эмпирического измерения

**План эксперимента:**
1. Зафиксировать переменные: модель, уровень усилия, версия Claude Code, набор MCP, CLAUDE.md, время суток.
2. Собрать эталонный набор из N воспроизводимых задач FINPILOT (см. ниже).
3. Гонять каждую задачу k раз в свежем контексте (`/clear` между прогонами).
4. Логировать через OTLP + ccusage; экспортировать в таблицу.
5. Считать медиану, среднее, стандартное отклонение, CV, доверительный интервал.

**Формула размера выборки** [подтверждено, статистический источник — ISME, «Sample size (n) = Z² · CV² / (%)²»]:

n = (1,96 · CV / relative_margin)²

где CV = σ/μ (коэффициент вариации), relative_margin — желаемая относительная погрешность (0,10 для ±10%), 1,96 — z при 95%.

**Пример:** если CV расхода/времени агентских задач = 0,30, то для ±10%:
n = (1,96 × 0,30 / 0,10)² = 5,88² ≈ **35 прогонов**.
- ±5% при том же CV: ≈ 139 прогонов.
- CV = 0,50, ±10%: ≈ 97 прогонов.

Практический вывод: агентские задачи имеют высокий CV (часто 0,3–0,6 из-за недетерминизма), поэтому для честного ±10% нужно **не менее 35–100 прогонов на ячейку** таблицы. Для быстрой ориентировки достаточно 5–10 прогонов и отчёта медианы + межквартильного размаха вместо среднего.

**Борьба с недетерминизмом:** фиксировать `temperature` где возможно; репортить медиану и перцентили, не среднее; отделять «стоимость на успешно принятую задачу» от сырой стоимости.

**Инструменты сбора:**
- **ccusage** (`npx ccusage@latest`) — парсит локальные JSONL, без сети/ключа; отчёты daily/monthly/per-session/5h-block с разбивкой по моделям и cache-токенам; statusline-режим. [официальное описание проекта]
- **Claude-Code-Usage-Monitor** (`pip install claude-monitor`) — live burn rate, прогноз до лимита, прогресс-бары.
- **ccflare, ccstatusline** — статус-строка/прокси.
- **OpenTelemetry-экспорт** (`CLAUDE_CODE_ENABLE_TELEMETRY=1`) → SigNoz/Grafana/CloudWatch/Faros. Метрики + события раздельно (`OTEL_METRICS_EXPORTER` / `OTEL_LOGS_EXPORTER`).
- **API `count_tokens`** — единственный точный счётчик входа до отправки; envelope 6–7 токенов.
[всё — официальное/описания проектов]

**Метрика «стоимость на успешно принятую задачу»:** cost_per_accepted = (сумма токенов всех попыток, включая отказы и переделки) × прайс ÷ (число принятых задач). Обязательно включать неудачные прогоны и итерации, иначе метрика занижена. [методология]

**Готовые харнессы:** открытый rig Systima (логирующий прокси + tamper-evident датасет), Meridian (локальный прокси Claude Max ↔ SDK). [открытые проекты]

### НАПРАВЛЕНИЕ 6. Оптимизация промптов — доказанное измерениями

**Новые правила для 5-поколения (официально, Anthropic «The new rules of context engineering», автор Thariq Shihipar, 24 июля 2026):**
- Дословно: «We removed over 80% of Claude Code's system prompt for models like Claude Opus 5 and Claude Fable 5 with no measurable loss on our coding evaluations». По независимому разбору (DEV Community) промпт «shrank from roughly 2,686 words down to around 514 with memory disabled». [официальное значение]
- Причина: модели переограничивали — конфликтующие инструкции («leave documentation as appropriate» vs «DO NOT add comments») в системном промпте, CLAUDE.md и скиллах заставляли модель тратить размышления на разрешение противоречий. [официальное значение]
- Инструмент `claude doctor` / `/doctor` — авто-«правка размера» скиллов и CLAUDE.md. [официальное значение]
- Модели 5-поколения понимают намерение — избыточные ограничения вредны. [официальное значение]

**Что перестало работать / стало вредным:**
- Тяжёлый role-prompting и обилие XML-тегов — «менее необходимы» с современными моделями. [независимо, DreamHost/официальные доки]
- С Sonnet 4.5 (сен 2025) и далее модели «буквальны»: делают ровно то, что просят, не додумывают. Старые промпты, полагавшиеся на «додумывание», ломаются. [официальное значение announcement]
- Конфликтующие инструкции в CLAUDE.md — прямой вред. [официальное значение]

**Что работает (5 техник прошли отбор из 25):** структурированные XML/JSON, extended thinking, явные требования, few-shot примеры, контекст перед вопросом. [независимо, DreamHost, со ссылкой на доки]

**Промпт-кэш — как структурировать:**
- Стабильный контент первым (система, определения инструментов, RAG-контекст), динамический — в конец. [официальное значение]
- Минимум кэша: 1024 токена (Sonnet/Opus), 2048 (Haiku) — ниже директива молча игнорируется. [независимо/доки]
- До 4 breakpoints; cache write = 1,25× (5 мин TTL) или 2× (1 ч); cache read ≈ 10% цены входа. [официальное значение]
- Инвалидирует кэш: изменение любого токена в префиксе; пауза > TTL (5 мин/1 ч). У Opus 5 смена инструментов mid-conversation больше **не** инвалидирует кэш (beta). [официальное значение]
- Claude Code кэш-неэффективен: переписывает десятки тысяч cache-токенов mid-session, до 54× больше cache-writes, чем OpenCode на той же задаче. [измерено независимо, Systima]

**Anti-patterns (раздувают расход/ухудшают):** длинные сложные промпты не лучше коротких; смешение всех техник сразу; неясная база; конфликтующие инструкции; повторная отправка идентичного контекста без кэша. [независимо, официальные доки]

**Как формулировать задачи агенту (минимум запросов):**
- Декомпозиция + режим плана; один большой батч-запрос дешевле, когда Claude Code батчит tool-calls в один round-trip (T3: 3 запроса vs 9 у OpenCode). [измерено независимо]
- Субагенты — только при 4+ параллельных ветках, изоляции контекста, повторяемости; иначе чистый оверхед. [независимо]
- Роутить механическую работу субагентов на Haiku. [независимо]

## Recommendations

**Этап 1 — немедленно (веха 8, React+TS+Vite):**
1. **Смените дефолт с «Opus 5 / max» на «Sonnet 5 / medium или high».** Обоснование: на max Opus 5 TTFT ≈92 с (eesel: 68 с) и почти нет прироста скорости генерации; для фронтенд-компонентов и рефакторинга TS это чистая потеря времени и бюджета 5-часового окна. Держите Opus 5 (high, не max) только для сложной отладки многофайловых багов и архитектурных решений.
2. **Обновите Claude Code** с 2.1.114 до максимально свежей (≥2.1.181, а лучше последней) — иначе `/design-sync`/`/design` не работают; на веху 8 (перенос фронтенда) эта связка вам нужна.
3. **Поставьте chrome-devtools правильно:** `/plugin marketplace add ChromeDevTools/chrome-devtools-mcp` → `/plugin install chrome-devtools-mcp@chrome-devtools-plugins`. Если хотите официальный — сначала `/plugin marketplace update claude-plugins-official`.
4. **Включите промпт-кэш и OTLP-телеметрию** сразу: `CLAUDE_CODE_ENABLE_TELEMETRY=1`, экспорт в локальный SigNoz/Grafana; параллельно `npx ccusage` для быстрых сводок.

**Этап 2 — построить свою таблицу (2–3 дня):**
5. Соберите 8–12 эталонных задач FINPILOT (генерация React-компонента, рефакторинг эндпоинта FastAPI, фикс типичного бага, написание pytest, код-ревью PR, чтение модуля). Гоняйте каждую **5–10 раз** на матрице {Sonnet 5, Opus 5} × {medium, high} с `/clear` между прогонами.
6. Репортьте **медиану и межквартильный размах** (не среднее), плюс cost_per_accepted_task. Для «настоящего ±10%» позже добьёте до 35+ прогонов на важных ячейках (формула выше).
7. Считайте бюджет 5-часового окна в «принятых задачах на окно», а не в токенах — на подписке вы покупаете rate, не токены.

**Этап 3 — оптимизация:**
8. Прогоните `/doctor`, вычистите конфликтующие инструкции из CLAUDE.md (после сокращения системного промпта Claude Code на 80% лишние ограничения активно вредят).
9. Вынесите переиспользуемое между 4 аккаунтами/репозиториями в приватный marketplace + пользовательский `~/.claude/CLAUDE.md`; секреты и локальные пути — в `.claude/settings.local.json` (не коммитить).
10. Субагенты — только при 4+ параллельных ветках; механику роутьте на Haiku.

**Пороги смены решений:**
- Если медиана времени задачи на Sonnet 5/high приемлема (< ~30 с TTFT) и качество проходит ваши приёмочные тесты → не трогайте Opus.
- Если cost_per_accepted на Opus 5 не ниже Sonnet 5 хотя бы в 1,5× при вашей приёмке → Opus не окупается на этой задаче.
- Если упираетесь в 5-часовое окно чаще 2 раз/неделю → переходите на Opus-Sonnet-Opus роутинг или рассмотрите Max.

## Caveats

- **Все AA-числа латентности — независимые замеры, не официальные Anthropic**; медиана P50 за 72 ч при 10k входных токенов; между снапшотами есть разброс (примеры расхождений отмечены). Ваши реальные числа будут иными из-за длины контекста, MCP-оверхеда и времени суток.
- **TTFT ризонинг-моделей ≠ префилл**: 92 с и 179 с — это преимущественно «мышление», а не сетевая задержка.
- **Многие операционные числа публично не существуют**: распределение длительности сессий Claude Code, точные токены на чтение/правку файла и на скриншот Playwright, соотношение reasoning/answer токенов по уровням, разбивка латентности по поверхностям, деградация латентности в пик, остаток окна в токенах. Здесь помечено «данных нет» — не подменяйте оценками без собственных замеров.
- **Ряд источников — вторичные блоги и вендоры** (AICosts, ClaudeFast, tech-insider и др.); их числа помечены как «оценка» и требуют перепроверки собственными замерами. Первичны: Anthropic docs, Artificial Analysis, CodeRabbit, Systima (открытый rig), Chroma.
- **Наблюдение о 72-часовом сбросе недельного лимита** — единичное, 11 дней, июнь 2026; поведение могло измениться.
- **Список официальных плагинов меняется**; для скрипта установки всегда берите актуальный через `/plugin`.
- Данные актуальны на 1 августа 2026; модели, цены и лимиты Anthropic меняются часто.
