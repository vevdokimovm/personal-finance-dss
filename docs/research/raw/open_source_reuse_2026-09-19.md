  (проверить числом, не утверждение):
  - (H1) в `_simulate` закрытый долг (`balances[i] <= 0`) в следующих месяцах пропускается `continue`,
    значит его минимальный платёж попадает во `freed` ТОЛЬКО в месяц закрытия, а не каждый месяц после.
    Классический snowball/avalanche «rollover» добавляет освободившийся минимум к пулу ПОСТОЯННО.
  - (H2) в месяц закрытия `freed += pay` — весь платёж, хотя долг съел из него `balance+interest`;
    корректно `pay - (balance + interest)`.
  - (H3) долг, закрытый пулом (досрочкой), не освобождает свой минимум вовсе.
  Код не правим (постановка); кандидат в находки для синтеза.

### Какие решения меняет

**Матядро.**
1. §10.5, `app/core/amortization.py::_simulate` — **код расходится с каноном**: освободившийся минимум закрытого долга учитывается один раз (целиком, в месяц закрытия) вместо ежемесячного переката; долг, закрытый досрочкой из пула, свой минимум не освобождает вовсе. По факту поведение = вариант «без переката» (SenseiFi). Решение вахты: эталон — постоянный перекат (ray, debtfree, текст канона); в месяц закрытия освобождается `pay − (balance + interest)`. Уточнение модели «перекат × доля x_d выбранной альтернативы» — вопрос синтеза.
2. Там же — **последний платёж = остаток + проценты**; счётчик месяцев не должен делать отдельный месяц из хвоста < 1 платежа. Масштаб: 110 из 252 типичных кредитов (44 %), хвост до 41,05 ₽.
3. §10.4 «досрочка уменьшает платёж пропорционально остатку при сохранении срока» — **подтверждено внешним вектором точно** (14 600,60). Отсутствует второй режим досрочки «сокращение срока», который по эталону дешевле на 7,9 % переплаты (2 328,73 ₽ на векторе) и который в РФ выбирает заёмщик. Кандидат в канон.
4. Проценты r/12 против дневного счёта банков РФ: на 500 000 / 12 / 11,5 % расхождение 6,10 ₽ (0,02 %) — для диагностики допустимо, модель НЕ менять; но первый нестандартный период (выдача → первая дата платежа) даёт до ~5 тыс. ₽ на векторе — учитывать, если когда-нибудь показывать «график как в банке».
5. Классы долга без модели: кредитная карта с беспроцентным периодом и минимальным платежом в % от долга, BNPL-рассрочки — идеи в SenseiFi; в очередь синтеза.

### Что осталось неизвестным
- Как конкретно банки РФ округляют последний платёж и проценты первого периода по каждому продукту — из кода одного автора (loan-schedule.js) не обобщить; нужны договоры/графики реальных банков (не эта тема).
- Бюджетирование «конвертами» YNAB/Actual и наш «конверт» (цель ↔ актив) — разные понятия; сравнение по качеству прогноза не делалось (нет общего набора данных).
- `bucketwise` и `better-debt` не читались: у better-debt нет лицензии; bucketwise не найден поиском этого прогона — отрицательный результат, не добирался (строго не нужен для ответа).
