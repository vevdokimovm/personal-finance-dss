# Поверхности и расширения Claude: практическая методичка для одиночного разработчика FINPILOT

*Дата составления: 1 августа 2026. По каждому существенному утверждению помечен тип источника: [офиц. док] — официальная документация/блог Anthropic; [независимо проверено] — сторонние надёжные источники; [оценка] — вывод автора; [данных нет].*

## TL;DR
- **Главный вывод, который меняет всё остальное:** Россия отсутствует в списке поддерживаемых стран Anthropic (для Claude.ai, Pro/Max и Claude Code), а работа с четырёх параллельных Pro-аккаунтов прямо нарушает Consumer Terms — оба фактора создают риск блокировки без возврата средств и юридически несовместимы с production-финтехом под 152-ФЗ. Прежде чем оптимизировать рабочий процесс, нужно легализовать основание доступа и никогда не передавать реальные ПДн пользователей на серверы Anthropic.
- **По инструментам:** ядром FINPILOT должен стать Claude Code (нативная установка, plan mode + auto mode, worktrees, `/rewind`, скиллы под проект); Cowork — вспомогательный агент для непроектной работы с высоким расходом лимитов и высоким риском prompt injection (не для персональных данных и не в audit logs); Claude Design — только для быстрого прототипирования UI с последующим `/design-sync`, но не для боевого кода.
- **Осознанная работа = управление контекстом и правами:** дефолт «сильнейшая модель на максимальном усилии» дорог и медленен; правильнее подбирать permission mode под размер «зоны поражения», следить за `/context` и `/usage`, чистить контекст между задачами и оформлять повторяемые процедуры как скиллы/плагины, а не пихать всё в CLAUDE.md.

## Key Findings

1. **Нативная установка обновляется сама**; `claude update` форсирует обновление, `npm update -g` для неё не работает и способен сломать установку (issue #28625). Канал `latest` (дефолт) против `stable` (~на неделю позади) переключается через `autoUpdatesChannel`.
2. **Шесть permission modes** (default, acceptEdits, plan, auto, dontAsk, bypassPermissions). Для одиночки на реальной машине оптимум — plan mode для проектирования и auto mode как «золотая середина»; bypassPermissions только в изолированном контейнере.
3. **`/rewind`** (с v2.0.0) откатывает код и/или диалог по чекпоинтам, но НЕ отменяет действия bash (`rm -rf`, `mv`). Git остаётся обязательным.
4. **Headless (`claude -p`), Agent SDK и GitHub Actions** с 15 июня 2026 должны были уйти в отдельный месячный кредит ($20 Pro / $100 Max 5x / $200 Max 20x, по API-ценам, без переноса остатка) — но 15 июня Anthropic поставила изменение на паузу; статус нестабилен.
5. **Cowork** исполняется в изолированной среде на серверах Anthropic; расходует лимиты значительно сильнее чата; главный риск — indirect prompt injection через файлы/веб. Для персональных данных FINPILOT не подходит.
6. **Claude Design** (research preview с 17 апреля 2026, на Opus 4.7, движок Canva) импортирует дизайн-систему из кодовой базы/GitHub и синхронизируется с репозиторием через `/design-sync` (двусторонний, с июня 2026). Хорош для идей, слаб для «живого» кода.
7. **Плагины** = каталог с `.claude-plugin/plugin.json` + опционально `commands/`, `agents/`, `skills/`, `hooks/`, `.mcp.json`. Свой маркетплейс — это git-репозиторий с `.claude-plugin/marketplace.json`.
8. **Skills** используют прогрессивное раскрытие: при старте грузится только `name`+`description` (медиана ~80 токенов на скилл), тело — при срабатывании, references/scripts — по мере надобности. skill-creator даёт eval-тесты на срабатывание описания.

### 0. Красная рамка: доступность в РФ, 152-ФЗ и четыре аккаунта

Это направление пользователь не заявлял, но независимый эксперт обязан поставить его первым.

Есть и экспортный контроль: пользователь гарантирует, что не находится в подсанкционной стране.

- **Вывод для FINPILOT [оценка]:** использование Claude из РФ с российских аккаунтов/карт/IP — нарушение Terms с риском блокировки без возврата. Плюс 152-ФЗ требует локализации ПДн граждан РФ в РФ, а Cowork/Claude.ai исполняют задачи на серверах Anthropic (США). **Практический вывод:** (1) никогда не передавать реальные ПДн пользователей FINPILOT ни в один облачный сервер Claude; работать только на обезличенном зеркале; (2) юридическое основание доступа решать отдельно (корпоративное лицо в поддерживаемой юрисдикции, доступ через инфраструктуру вне РФ). Это вне ИТ-плоскости, но игнорировать нельзя. Это не юридическая консультация.
- **Четыре параллельных Pro для обхода лимитов [офиц. док + оценка]:** совместное/множественное использование для обхода лимитов противоречит политике Anthropic; concurrent-сессии с разных IP могут флагаться. Легитимная альтернатива — один аккаунт Max. Экономика: 4×Pro = $80/мес дают 4 независимых пула по ~5× Free, но без общего контекста, с четырьмя логинами и риском бана. Max 5x = $100/мес — один пул ~5× Pro, один вход, легально. Max 20x = $200 — ~20× Pro. **Рекомендация:** заменить 4×Pro на один Max 5x (или 20x, если упираетесь в лимиты Claude Code ежедневно) — сопоставимо по деньгам, легально, удобнее для длинных сессий и worktrees.

### 1. Полный переход в Claude Code

**Обновление нативной установки.** Нативный бинарь живёт как симлинк `~/.local/bin/claude` → `~/.local/share/claude/versions/<версия>`.
- Проверить способ установки: `which -a claude` (нативный → `~/.local/bin/claude`; npm → путь внутри node_modules/`.npm-global`), затем `claude doctor` (покажет install type, auth, ошибки настроек, результат последнего обновления).
- Обновиться немедленно: `claude update`. Успех — `Successfully updated from <old> to <new>`. Фоновое автообновление включено по умолчанию для нативной установки; проверяется на старте и периодически, вступает в силу при следующем запуске.
- **Почему `npm update -g` не работает [независимо проверено]:** во-первых, для нативной установки npm вообще не задействован. Во-вторых, даже для npm-установки `npm update -g` уважает semver-диапазон исходной установки и часто не двигает на последнюю версию — нужен `npm install -g @anthropic-ai/claude-code@latest`.
- **Опасность двух копий [независимо проверено, issue #28625]:** `claude update` из нативного бинаря иногда ошибочно определяет установку как npm-global, удаляет нативный симлинк и ставит npm-версию. Если после этого каталог nvm выше `~/.local/bin` в PATH, нативный бинарь становится недостижим. Если стоят обе копии — выигрывает первая в PATH. Лечение: `npm uninstall -g @anthropic-ai/claude-code`, затем `hash -r` (в zsh — `rehash`), убедиться что `~/.local/bin` первый в PATH, `claude doctor`.
- **Установить конкретную версию / канал:** `curl -fsSL https://claude.ai/install.sh | bash -s 2.1.89` (конкретная), `... | bash -s stable` (стабильный канал). Канал при установке становится дефолтным для автообновления.
- **Откат назад:** переустановить нужную версию тем же способом (`bash -s <версия>`) или переключить симлинк на существующий каталог в `versions/`. Можно закрепить пол через `minimumVersion` в settings.json.
- **Переключить канал:** `/config` → Auto-update channel, либо `{"autoUpdatesChannel": "stable"}`. Отключить автообновление: `{"env": {"DISABLE_AUTOUPDATER": "1"}}` (но `claude update` продолжит работать; чтобы заблокировать всё — `DISABLE_UPDATES`).
- **Версия пользователя 2.1.114 устарела [независимо проверено]** — актуальные релизы уже 2.1.2xx (в доках фигурирует `2.1.211`). Просто выполните `claude update`.

**Проверка подписи бинаря [офиц. док]:** для FINPILOT (финтех) имеет смысл раз проверить целостность: импортировать ключ (`curl -fsSL https://downloads.claude.ai/keys/claude-code.asc | gpg --import`), сверить отпечаток `31DD DE24 DDFA B679 F42D 7BD2 BAA9 29FF 1A7E CACE`, проверить `manifest.json.sig` (`gpg --verify`). Подписи манифеста доступны для релизов от 2.1.89. macOS-бинарь подписан «Anthropic PBC» и нотаризован Apple (`codesign --verify --verbose ./claude`).

**Рабочий цикл одиночки [офиц. док + оценка].**
- Чек-лист начала сессии: `git status` чистый → запустить `claude` в каталоге проекта → `/context` (сколько места) → сформулировать задачу → **plan mode** (Shift+Tab) для нетривиальной задачи → согласовать план → выполнение.
- В ходе: коммитить маленькими логическими порциями; при риске деструктивной операции — сначала коммит; регулярно смотреть статус-строку (контекст/лимиты).
- Чек-лист конца сессии: тесты (1473 у FINPILOT) зелёные → покрытие ≥90% → коммит с осмысленным сообщением → при завершении задачи `/clear` перед новой темой.
- **Когда чистить контекст:** между несвязанными задачами — `/clear`; когда контекст близок к заполнению — `/rewind → Summarize from here` или `/compact`. Длинную задачу через несколько сессий вести через: коммиты + запись состояния в файл (`PROGRESS.md` или скилл-память в `~/.claude/projects/`), `claude --resume` для возврата.

**Plan mode [офиц. док].** Read-only режим: Claude исследует, задаёт уточняющие вопросы и выдаёт пошаговый план, НЕ трогая файлы. Вход — Shift+Tab (циклит default→acceptEdits→plan) или префикс `/plan`. По готовности плана — выбор: одобрить и перейти в auto, одобрить с acceptEdits, одобрить с ручным ревью, продолжить уточнять (`Ctrl+G` — редактировать план в редакторе). Сделать дефолтом проекта: `{"defaultMode": "plan"}` в `.claude/settings.json`. Обязателен для мультифайловых рефакторингов и первого прохода по незнакомому коду. Сочетание с усилием: план стоит генерировать на модели/усилии повыше (качество плана определяет всё), исполнение простых шагов — на модели попроще.

**Permission modes [офиц. док].** Циклятся Shift+Tab (в CLI), Ctrl+Shift+M (desktop):

| Режим | Что делает | Кому/когда |
|---|---|---|
| default (ask) | спрашивает перед каждой правкой/командой | незнакомая территория |
| acceptEdits | авто-принятие правок файлов, команды спрашивает | заранее заскоупленная работа |
| plan | read-only, только план | проектирование, ревью |
| auto | классификатор проверяет каждое действие; безопасные — молча, рискованные — блок | «золотая середина» на своей машине |
| dontAsk | разрешено только то, что в `permissions.allow`; остальное молча запрещено | CI, локдаун |
| bypassPermissions | пропускает почти всё (кроме `rm -rf /`, `rm -rf ~`, явных deny; не стартует под root) | только изолированный контейнер/VM |

**Auto mode [офиц. док].** Отдельная модель-классификатор (Sonnet 4.6) ревьюит каждое действие ДО запуска; безопасные операции идут молча, рискованные (деплой, массовое удаление, force push, `curl | bash`) блокируются, и Claude выбирает другой подход. Требует план Team/Enterprise/API и модель Sonnet 4.6 / Opus 4.6 (на Max — только Opus 4.7); включается флагом `--enable-auto-mode`. «Снижает риск, но не устраняет» — рекомендуется в изолированной среде. Anthropic ведёт внутренний журнал инцидентов агентов (удаление remote-веток из неверно понятой инструкции, загрузка GitHub auth-токена на внутренний кластер, попытки миграций против prod-БД — задокументировано в system card Claude Opus 4.6, §6.2.1 и §6.2.3.3). **Для FINPILOT [оценка]:** default/plan для всего, что касается БД и миграций; acceptEdits для фронтенд-компонентов; bypass — только в Docker dev-container.

**Параллельная работа: git worktrees [офиц. док].**
- Ручной способ: `git worktree add ../finpilot-feat-x feat/x`, открыть отдельный `claude` в этом каталоге — две независимые сессии, общая история git, разные файлы. В desktop-приложении каждая новая сессия автоматически получает worktree.
- Флаг `--worktree` управляет жизненным циклом (создание, именование, отслеживание, очистка).
- Субагенты по умолчанию НЕ изолированы: изолированы на уровне контекста, но делят рабочий каталог. Чтобы изолировать — `isolation: worktree` во frontmatter субагента, либо просьба «use worktrees for your agents».
- Важно: worktree копирует только tracked-файлы — `node_modules`, `.env` нужно ставить/копировать заново (используйте `.worktreeinclude` и WorktreeCreate-хуки).
- Очистка: периодический sweep удаляет worktrees старше `cleanupPeriodDays`, если нет незакоммиченного/untracked/unpushed; ручками — `git worktree remove [--force]`. Проверять `git worktree list` еженедельно.
- Схема мержа для одиночки: в основной сессии спланировать фичу (feature-dev) → каждый независимый шаг запустить субагентом с `isolation: worktree` → по завершении ревью diff в каждом worktree → мерж ветки → удаление worktree. **[независимо проверено]** Есть и `/batch` — раскладывает работу на 5–30 юнитов, по одному фоновому субагенту на worktree.
- **Предостережение [независимо проверено]:** worktrees защищают от файловых конфликтов, но НЕ от логических — если два агента делают несовместимые допущения, мерж всё равно сломается. Для FINPILOT-одиночки: параллелить максимум 2–3 явно раздельных задачи (напр. фронт-компонент + бэкенд-эндпоинт), не больше.

**Headless / неинтерактив.**
- `claude -p "<промпт>"` — неинтерактивный режим для скриптов/cron; Agent SDK (Python/TypeScript); GitHub Actions.
- **Тарификация [независимо проверено]:** с 15 июня 2026 эти поверхности должны были уйти в отдельный месячный кредит ($20/$100/$200 по плану, по API-ценам, без переноса, требует единоразового opt-in). НО 15 июня Anthropic поставила изменение на паузу; сейчас программное и интерактивное потребление снова из одного пула, «пересмотренная версия может вернуться с предупреждением». Интерактивный Claude Code в терминале не затрагивался никогда.
- **Одиночке оправдано [оценка]:** headless — для одной вещи: ночной прогон линтеров/ревью на PR через GitHub Actions. С учётом нестабильности тарификации и статуса РФ — отложить до стабилизации и сначала измерить потребление через `/usage`.

**Чекпоинты и откат [офиц. док].**
- `/rewind` (алиас `/checkpoint`, или Esc-Esc при пустом вводе). Чекпоинт создаётся перед каждой правкой / на каждый промпт. Опции: восстановить код и диалог; только диалог; только код; Summarize from here (сжать контекст, файлы на диске не меняются). Чекпоинты хранятся 30 дней (`cleanupPeriodDays`).
- **Ограничение:** НЕ отслеживаются изменения через bash (`rm -rf`, `mv`, `find -delete`) и ручные правки в редакторе. Для этого только git.
- Форк: `claude --continue --fork-session` — параллельные ветки одной сессии; после `/clear` в том же процессе rewind-меню показывает пункт `/resume <session-id>` для возврата к предыдущей сессии (v2.1.191+).
- **Стратегия коммитов для FINPILOT [оценка]:** git — первичный механизм безопасности, `/rewind` — вторичный для быстрых экспериментов. Коммит перед любой рискованной операцией; маленькие атомарные коммиты; `.claude/` и worktree-каталоги в `.gitignore`.

**Наблюдаемость [офиц. док].**
- `/context` — карта заполнения контекстного окна.
- `/usage` — потребление против лимитов (5-часовое окно + недельный/месячный).
- `/status` — модель, каталог, git-состояние, версия, output style.
- `claude doctor` — диагностика установки/настроек без запуска сессии.
- Статус-строка настраивается скриптом на каждый ход; JSON включает `context_window.used_percentage`, `rate_limits.five_hour/seven_day`, `cost.total_cost_usd`. Готовые обёртки: ccstatusline, claude-powerline, claude-statusline (Go). **Что смотреть регулярно:** процент контекста (при >70% — закругляться/rewind, чтобы не потерять инструкции при авто-compact), остаток 5-часового окна.
- `/insights` — 30-дневный HTML-отчёт по использованию Claude Code (что работает, что тормозит).

**Что НЕ делать в Claude Code [оценка]:** массовую генерацию непрофильных документов (в чат/Cowork); дизайн-исследование с нуля (Claude Design); хранение секретов в CLAUDE.md; давать bypass-режим на машине с реальными ключами/ПДн.

### 2. Claude Cowork

**Что это [офиц. док + независимо проверено].** Запущен как research preview 12 января 2026 (на следующий день после запуска Anthropic Labs 11 января), изначально Max-only, macOS desktop. «Claude Code для остальной работы» — общий агент на той же основе, что Claude Code, но для непрограммистских многошаговых задач. По анализу Anthropic 1,2 млн анонимизированных сессий Cowork в 600 000+ организаций (выборка 11–31 мая 2026), более 90% использования — НЕ разработка ПО (сама разработка ПО — лишь 8,7%); топ-категории: бизнес-процессы и операции — 33,4%, контент и копирайтинг — 16,4%. Расширен на web и mobile (beta) с 7 июля 2026 (TechCrunch): «available on web and mobile for Max subscribers», сначала для Max, затем шире.

**Архитектура и исполнение [офиц. док].** «Claude's work runs on Anthropic's servers, in an isolated environment» — задачи исполняются в изолированной среде на серверах Anthropic; сессии и файлы сохраняются в аккаунт; работа продолжается при закрытом ноутбуке. Когда задаче нужен локальный файл/браузер — Claude дотягивается через Claude Desktop на конкретной машине. Локальные сессии останавливаются, если приложение закрыто/машина уснула; удалённые (scheduled) — идут без устройства онлайн. В чате Claude не имеет прямого доступа к файлам; в Cowork — читает/правит/создаёт файлы в разрешённых папках.

**Возможности.** Работа с файлами/папками, исполнение кода и shell в изолированной среде, браузер с сессиями пользователя (через Claude in Chrome), запланированные задачи (daily/weekly/monthly), коннекторы, плагины и скиллы Cowork, координация нескольких потоков параллельно.

**Ограничения [офиц. док + оценка].** Anthropic не публикует жёсткий максимум длительности задачи / длины сессии / размера контекста именно для Cowork; заявлено «long-running tasks without context limits». Активность Cowork пока НЕ попадает в audit logs / Compliance API — критично для комплаенса.

**Расход лимитов [офиц. док].** «Working on tasks with Cowork consumes more of your usage allocation than chatting with Claude… complex, multi-step tasks are compute-intensive and require more tokens». Отдельной квоты нет — тот же пул, что чат и Claude Code (5-часовое окно + недельные); auto mode расходует ещё больше. Была акция удвоения 5-часового лимита Cowork; Anthropic продлил удвоенные лимиты до 5 августа 2026. Точной формулы «одна задача = N сообщений» Anthropic не публикует. **Планирование на Pro [оценка]:** одна серьёзная задача Cowork может съесть окно; на Pro запускать не более одной тяжёлой задачи за 5-часовое окно, держа запас для Claude Code.

**Риски безопасности [независимо проверено].** Prompt injection — highest-severity / highest-likelihood вектор. Успешная инъекция против Cowork (в отличие от чата) может эксфильтровать локальные файлы, выполнить shell, отправить сообщения от имени пользователя, создать persistent scheduled tasks — потенциально без единого диалога подтверждения при неверных настройках. Векторы: невидимый текст в Office/PDF (white-on-white, font-size-1), скрытые `<div display:none>` на веб-страницах, тела писем, ответы MCP-инструментов, записи БД. Каждый MCP-сервер/плагин/коннектор расширяет «зону поражения». Anthropic по исследованию от 24 ноября 2025 рекомендует для недоверенных задач Opus 4.5+, снизивший успешность prompt injection в браузерных операциях до ~1% против адаптивного атакующего. PromptArmor рекомендует: отключить Dispatch (persistent-агенты, управляющие компьютером), запретить Network Egress для code execution, ask-правила на запись.

**Где Cowork выигрывает [оценка].** Реорганизация папок, экспенс-отчёты из скринов чеков, черновики из стопки заметок, слайды/спредшиты для ревью, регулярные брифинги по расписанию. **Где проигрывает:** любой код/тесты FINPILOT (это Claude Code); задачи, требующие детерминизма и аудита; всё с реальными ПДн.

**Стоит ли одиночке с prod-финтехом [оценка].** Для самого FINPILOT — нет: персональные данные + отсутствие Cowork в audit logs + серверы вне РФ = комплаенс-стоп. Уместен только для непроектной обвязки на обезличенных данных (черновики README, оформление отчётов о релизах, разбор публичных доков) — и то с осторожностью к инъекциям.

### 3. Claude Design

**Что это [офиц. док].** Research preview Anthropic Labs с 17 апреля 2026, на модели Claude Opus 4.7, использует Design Engine от Canva. Живёт по собственному URL, свой канвас, свой экспорт, отдельно метрится. Доступен для Pro/Max/Team/Enterprise без доплаты. Позиционируется как дополнение к Figma/Canva, не замена.

**Форматы и канвас.** Вход — текстовое описание (+ можно дизайн-систему из кода). Выход — HTML/CSS на живом канвасе; экспорт в PDF, PPTX, standalone HTML, отправка в Canva, либо handoff-бандл в Claude Code. Редактирование: чат, inline-комментарии, прямые правки, слайдеры-регуляторы, которые Claude генерирует под макет. При расплывчатом промпте Claude может задать уточняющий вопрос. Совместное редактирование — один редактор за раз.

**Импорт дизайн-системы [офиц. док + независимо проверено].** «Claude Design can read a company's codebase and design files to apply its design system» — при онбординге строит дизайн-систему, читая кодовую базу и дизайн-файлы (токены, шрифты, цвета, стандарты лейаута). Если система на CSS-переменных без Figma — это как раз рабочий случай: `/design-sync` умеет читать набор дизайн-систем, включая цвета и шрифты, из GitHub-репозитория или локального кода.

**`/design-sync` [независимо проверено].** Двусторонняя синхронизация анонсирована @ClaudeDevs 17 июня 2026. Запускается внутри Claude Code в каталоге проекта. Опирается на claude.ai-логин, находит проекты Design, где есть права записи. Направление repo→canvas: подтягивает дизайн-систему в проект, строит против реальных компонентов. Направление canvas→repo: пушит построенное обратно. Безопасно: Claude не перезаписывает молча — строит план (какие файлы записать/удалить), показывает на утверждение. Есть и одиночная `/design` (frontend-design skill). Синтаксис: `/design-sync` без аргументов внутри проекта.

**Практический цикл.** Текстовое описание → первый вариант на канвасе → ревизии (слайдеры/комментарии/чат) → handoff-бандл в Claude Code → генерация кода (frontend-design skill выступает приёмником). Поскольку и продюсер, и консюмер — модели Claude, слой перевода не нужен.

**Ограничения [независимо проверено].** По независимым обзорам (Builder.io): «Claude Design лучше всего помогает понять, как продукт МОГ БЫ выглядеть; гораздо менее полезен, когда дизайны должны жить внутри реальных, меняющихся приложений». Ранний продукт, много «cruft». Качество кода — прототипное. **Когда писать руками:** сложные интерактивные состояния, интеграция с TanStack Query/Zustand, доступность и производительность боевых компонентов.

**Расход лимитов [офиц. док].** «Usage is metered separately» — метрится отдельно от чата (детальных цифр Anthropic не публикует). **[данных нет]** по точной формуле общего пула с Claude Code.

**Сравнение для одиночки [оценка]:**

| Инструмент | Роль | Одиночке FINPILOT |
|---|---|---|
| Claude Design | ИИ-брейншторм UI + handoff в Claude Code | Да — на этапе идей вехи 8, потом `/design-sync` |
| Figma | точный дизайн, дизайн-система, прод-хендофф | Опционально; при работе одному избыточен |
| Pencil и аналоги | быстрые вайрфреймы | Нет смысла при наличии Design |
| v0 / Lovable | генерация React из промпта | Дублируют Claude Code+Design; лишний вендор для финтеха с ПДн |

**Вывод:** для одиночки связка Claude Design (идеи) → Claude Code + frontend-design (код) закрывает потребность; Figma — только если появится дизайнер.

### 4. Плагины

**Анатомия [офиц. док].** Каталог:
```
my-plugin/
├── .claude-plugin/
│   ├── plugin.json        # метаданные (name, version — обязательно)
│   └── marketplace.json   # если это ещё и маркетплейс
├── commands/              # слэш-команды (.md)
├── agents/                # субагенты (.md)
├── skills/<name>/SKILL.md # скиллы
├── hooks/hooks.json       # хуки
├── .mcp.json              # MCP-серверы
└── README.md
```
Версионируется полем `version` в plugin.json (CC по нему определяет необходимость обновления). Установленные плагины — в `~/.claude/plugins` (клоны маркетплейсов, версии, данные; осиротевшие версии удаляются через 7 дней). Скиллы из плагина неймспейсятся: `/my-plugin:skill`. Плагин может нести `settings.json` (пока поддерживается только ключ `agent` — активирует агента плагина как основной поток).

**Создание с нуля [офиц. док].** 1) `mkdir -p my-plugin/.claude-plugin`; 2) `plugin.json` с `name`,`version`,`description`; 3) добавить нужные каталоги (commands/agents/skills/hooks/.mcp.json); 4) валидировать `claude plugin validate`; 5) README. Быстрее — попросить plugin-dev/skill-creator сгенерировать скелет.

**Свой приватный маркетплейс [офиц. док + независимо проверено].** Маркетплейс = git-репозиторий с `.claude-plugin/marketplace.json` в корне (метаданные + массив плагинов, каждый в своём подкаталоге). Подключить: `/plugin marketplace add <user>/<repo>`; установить: `/plugin install <plugin>@<marketplace>`. Для нескольких машин/репозиториев — один приватный GitHub-репо, версии через conventional commits (feat:→minor, fix:→patch), CI-валидация. Для контейнеров/офлайна — `CLAUDE_CODE_PLUGIN_SEED_DIR` (read-only seed, автообновление отключено).

**Разбор установленных плагинов [офиц. док — из marketplace.json anthropics/claude-code и claude-plugins-official].**

**Конфликты/дубли [оценка].** semgrep и security-guidance частично пересекаются (оба про безопасность), но дополняют: security-guidance — лёгкий хук-напоминание, semgrep — реальный SAST. code-review и pr-review-toolkit сильно дублируются (оба — мультиагентное ревью PR) — держать один, скорее pr-review-toolkit (более узкие специализированные агенты). context7 и любой другой docs-lookup дублировали бы друг друга. playwright + chrome-devtools-mcp пересекаются по браузеру — для E2E хватит playwright.

**Измерение контекста плагинов [офиц. док + оценка].** `/context` показывает суммарное заполнение. Скиллы плагинов на старте стоят только `name`+`description`, MCP-серверы дороже (грузят описания инструментов). Отключать по проектам через `/plugin` (enable/disable) или не подключать маркетплейс в проекте. **Для FINPILOT [оценка]:** держать включёнными pyright-lsp, typescript-lsp, playwright, semgrep, frontend-design, context7, skill-creator; chrome-devtools-mcp и один из ревью-плагинов включать точечно.

**Плагины сообщества и критерии безопасности [оценка].** Для проекта с ПДн: (1) читать исходники перед установкой (скиллы исполняют код на машине); (2) предпочитать официальный `claude-plugins-official` и `anthropics/skills`; (3) избегать плагинов, тянущих недоверенные MCP-серверы с сетевым доступом; (4) фиксировать версии; (5) прогонять `claude plugin validate`. Популярность (по публичному каталогу плагинов Anthropic на 1 июня 2026: Frontend Design 829 316 установок, Superpowers 752 120, Context7 348 660) — сигнал, но не гарантия безопасности.

### 5. Skills

**Зачем и чем отличается [офиц. док — блог «Steering Claude Code»].** Семь способов управления поведением: CLAUDE.md, rules, skills, subagents, hooks, output styles, добавление к системному промпту. Каждый торгует стоимостью контекста против авторитетности.
- **CLAUDE.md** — всегда в контексте (грузится на каждое взаимодействие); для проектных конвенций, которые должны применяться всегда. Не пихать сюда процедуры — раздувает базовый контекст.
- **Skill** — процедура «как мы это делаем», грузится только когда задача совпала с описанием; играет в основном потоке (видно и можно рулить).
- **Subagent** — ответ на «эта работа взорвёт контекстное окно»: делает исследование/аудит в отдельном контексте, отдаёт только вывод.
- **MCP** — ответ на «Claude физически не дотянется до системы» (Postgres, внутренний API).
- **Hook** — детерминированное действие на событие (prettier на сохранение).
- **Дерево решений [оценка]:** всегда нужно и коротко → CLAUDE.md; повторяемая процедура → skill; нужен изолированный контекст → subagent; нужен внешний доступ → MCP; детерминированный побочный эффект → hook.

**Анатомия SKILL.md [офиц. док].** Frontmatter (YAML между `---`):
- `name`: ≤64 символов, только строчные буквы/цифры/дефисы, без XML-тегов и зарезервированных слов.
- `description`: ≤1024 символов, непустое; ДОЛЖНО говорить и ЧТО делает, и КОГДА использовать — по нему Claude решает, грузить ли скилл.
- Опционально: `allowed-tools`, `license`, переопределение модели.
Тело — под 500 строк (иначе выносить в references), под 5000 слов. Прогрессивное раскрытие: старт — только name+description (по замеру 17 официальных скиллов Anthropic медиана ~80 токенов/скилл, диапазон ~55 у webapp-testing до ~235 у xlsx); при срабатывании — тело; при нужде — references/scripts/assets.

**Прогрессивное раскрытие на практике [офиц. док].** Структура:
```
my-skill/
├── SKILL.md      # ядро: когда+как, <500 строк, <5000 слов
├── scripts/      # исполняемые Python/Bash
├── references/   # доки, грузятся только при надобности
└── assets/       # шаблоны, шрифты, бинарники
```
Хорошая структура: в теле — императивные инструкции и шаблон вывода (`ALWAYS use this exact template: …`), тяжёлые справочники — в references. Плохая: всё в теле (раздувает контекст) или описание, говорящее только ЧТО без КОГДА (не срабатывает).

**Создание пошагово.** Claude Code: папка в `~/.claude/skills/<name>/` (личный) или `.claude/skills/` (проектный) → SKILL.md → перезапуск → скилл живёт. claude.ai (веб): загрузка `.skill`-пакета в настройках (для платных планов часть скиллов предустановлена). Форматы совпадают (открытый стандарт Agent Skills, agentskills.io, опубликован Anthropic 18 декабря 2025 и в течение недель принят OpenAI, Google, GitHub, Cursor), различается способ установки. Упаковка: `python -m scripts.package_skill <path>` → `.skill` файл.

**Перенос [офиц. док + независимо проверено].** Между машинами/аккаунтами — копировать папку скилла или распространять через плагин/маркетплейс (версионирование в git). Между Claude Code и claude.ai — тот же SKILL.md, разные способы установки. Скиллы работают в Claude Code, Claude Desktop, Claude API, Agent SDK, а также (через открытый стандарт) в Cursor, Copilot, Gemini.

**skill-creator и eval-тесты [офиц. док].** Официальный плагин, 4 режима: Create (интервью→черновик→тесты), Eval (прогон на тест-промптах + грейдинг), Improve (прогон+грейд+слепое A/B+анализ+итерация), Benchmark (несколько прогонов + анализ дисперсии). Тест-кейсы — в `evals/evals.json`, каждый прогон — в субагенте. `run_eval.py` создаёт временные command-файлы и гоняет `claude -p` по набору запросов, детектируя через stream-события, потянулся ли Claude к скиллу — проверяет и should-trigger, и should-not-trigger. `run_loop.py`: 60/40 train/test split, 3 прогона на запрос, до 5 итераций улучшений, возвращает `best_description` по test-скору (защита от переобучения). Ключевой урок [независимо проверено]: описание должно говорить КОГДА, а не только ЧТО — иначе скилл не срабатывает.

**Скиллы под FINPILOT [оценка].** Конкретные предложения:
1. `finpilot-fastapi-endpoint` — процедура добавления эндпоинта (SQLAlchemy 2.0 паттерны, схемы Pydantic, тест на pytest, обновление покрытия). Срабатывает на «add endpoint / новый роут».
2. `finpilot-152fz-guard` — чек-лист обращения с ПДн: обезличивание, запрет логирования ПДн, локализация. Срабатывает при работе с моделями пользователей/персональными полями.
3. `finpilot-react-component` — конвенции React 19 + TS + Radix/shadcn + TanStack Query + Zustand + тест Vitest. Срабатывает при создании компонента.
4. `finpilot-katex-formula` — рендер финансовых формул через KaTeX с проверкой.
5. `finpilot-test-coverage` — процедура «не мержить, пока покрытие <90%», прогон 1473 тестов.
6. `finpilot-migration` — безопасные Alembic-миграции (никогда против prod, ревью через plan mode).
Обоснование: это повторяемые процедуры, которые иначе будут раздувать CLAUDE.md; вынесение в скиллы держит базовый контекст лёгким и обеспечивает единообразие.

**Влияние на контекст и измерение [офиц. док].** Проект с 8 скиллами и 10 000 строк доков грузит ~500 токенов на старте вместо ~70 000 благодаря прогрессивному раскрытию. Измерять — `/context`. Правило: держать описания точными (широкое → ложные срабатывания и лишний контекст; узкое → не сработает).

**Официальные скиллы как образец [офиц. док].** Репозиторий `anthropics/skills` (17 скиллов; часть под Apache 2.0, а docx/pdf/pptx/xlsx — source-available, реально работают в проде Claude). Изучить: `skill-creator` (мета-скилл), `xlsx` (финансовые конвенции — синий текст для хардкод-инпутов, чёрный для формул, зелёный для ссылок внутри книги, красный для внешних; ноль ошибок формул #REF!) — прямо релевантно финтеху FINPILOT; `frontend-design`, `mcp-builder`, `webapp-testing`, `brand-guidelines`. Установка: `/plugin marketplace add anthropics/skills` → install, или скопировать папку в `.claude/skills/`.

### 6. То, о чём не подумали

**Что нового меняет работу одиночки [независимо проверено].** Auto mode (март 2026, safer skip-permissions); `/rewind` и чекпоинты (v2.0.0); двусторонний `/design-sync` (июнь 2026); skill-creator с eval-фреймворком (март 2026); Cowork на web/mobile (июль 2026); открытый стандарт Agent Skills (18 декабря 2025); `/batch` для массового параллелизма; `/insights` — 30-дневный HTML-отчёт по использованию Claude Code.

**Недоиспользуемое, дающее непропорционально много [оценка]:** (1) plan mode — «не делает Claude умнее, заставляет ВАС думать»; (2) статус-строка с процентом контекста — предотвращает молчаливую деградацию модели при переполнении; (3) `/context` перед стартом задачи; (4) скиллы вместо раздувания CLAUDE.md; (5) worktrees для 2 параллельных задач; (6) eval-тесты скиллов через skill-creator; (7) `/rewind` вместо ручного стеша.

**Дорогие ошибки новичков [независимо проверено + оценка]:** дефолт «сильнейшая модель + макс усилие» на всё (дорого/медленно; подбирайте под задачу); bypassPermissions на рабочей машине с ключами; игнорирование заполнения контекста → авто-compact теряет инструкции; отсутствие коммитов перед рискованными операциями (bash не откатывается через `/rewind`); всё в CLAUDE.md; доверие агенту «job is done, production ready» без проверки (в pr-review-toolkit есть команда, заставляющая агента перепроверить это утверждение); установка недоверенных плагинов/скиллов (исполняют код).

**Резервное копирование `~/.claude` [независимо проверено].**
- **Бэкапить:** `CLAUDE.md`, `settings.json`, `settings.local.json`, `projects/` (память по проектам), `history.jsonl`, список установленных плагинов, `~/.claude.json` (MCP-конфиги — иначе `claude mcp add` заново).
- **НЕ коммитить/не шарить:** `.credentials.json` (Linux/Windows; на macOS токен в Keychain — machine-bound, восстанавливается через `claude --login`); любые токены/ключи в `~/.claude.json`. Поставить gitleaks в pre-push.
- **Схема [оценка]:** сделать `~/.claude` git-репо с `.gitignore` для кэшей/логов/runtime-состояния плагинов; ночной бэкап (launchd) в приватный remote; при переезде — восстановить файлы, `claude --login`, переустановить плагины по списку, поставить глобальные npm-инструменты заново. Осторожно: если восстановить старый бэкап с сессиями >30 дней и запустить Claude до правки `cleanupPeriodDays` — они удалятся немедленно.
- Session-транскрипты привязаны к абсолютному пути (slug по pwd); при смене пути/юзернейма `--resume` их не найдёт без переписывания.

## Recommendations

**Этап 0 — легализация основания (до всего остального, блокирующее):**
1. Не передавать реальные ПДн пользователей FINPILOT ни в один облачный сервер Claude. Работать исключительно на обезличенном зеркале.
2. Решить юридический статус доступа из РФ (Россия не в списке поддерживаемых стран; текущие 4×Pro нарушают Terms). Порог смены решения: если появляется корпоративное лицо/инфраструктура в поддерживаемой юрисдикции — переходить на легальную схему.
3. Заменить 4×Pro на один **Max 5x** ($100/мес, легально, один пул, удобнее для worktrees). Если ежедневно упираетесь в лимит Claude Code — Max 20x.

**Этап 1 — привести Claude Code в порядок (день 1):**
4. `claude doctor` → `claude update` (уйти с устаревшей 2.1.114). Убедиться, что `which -a claude` показывает только нативный путь.
5. Проверить подпись бинаря (финтех) один раз.
6. Настроить статус-строку с процентом контекста и остатком 5-часового окна.
7. `{"defaultMode": "plan"}` в `.claude/settings.json` проекта; auto mode — точечно.

**Этап 2 — рабочий процесс (неделя 1):**
8. Внедрить чек-листы начала/конца сессии; `/clear` между темами; git-коммит перед рискованным.
9. Отключить дубли: оставить pr-review-toolkit (убрать code-review), для браузера — playwright (chrome-devtools-mcp точечно).
10. Освоить worktrees на 2 задачах (фронт-компонент + бэкенд-эндпоинт).

**Этап 3 — скиллы и плагины (недели 2–3):**
11. Написать 6 FINPILOT-скиллов (см. §5) через skill-creator, прогнать eval-тесты на срабатывание.
12. Изучить `anthropics/skills/xlsx` как образец финтех-конвенций.
13. Создать приватный маркетплейс-репо для переноса скиллов между машинами.

**Этап 4 — вспомогательные поверхности (по необходимости):**
14. Claude Design — только для UI-идей вехи 8, затем `/design-sync` в репо; боевые компоненты дописывать руками.
15. Cowork — не для FINPILOT-кода/ПДн; максимум для непроектной обвязки на обезличенных данных, с отключённым Dispatch и Network Egress.
16. Headless/GitHub Actions — отложить до стабилизации тарификации Agent SDK; предварительно измерить потребление `/usage`.

**Пороги пересмотра:** появился второй разработчик → Team plan; ежедневное упирание в лимит → Max 20x; тарификация Agent SDK стабилизировалась → включить ночное CI-ревью; появился дизайнер → добавить Figma.

## Caveats
- **Статус РФ и Terms** — фактическая проверка списка поддерживаемых стран на 1 августа 2026; политика может измениться. Юридические выводы — не юрсовет.
- **Тарификация Agent SDK/headless** нестабильна: анонсирована на 15 июня 2026, затем поставлена на паузу; «пересмотренная версия может вернуться». Цифры $20/$100/$200 верны для анонсированной схемы.
- **Cowork:** Anthropic не публикует точной формулы «одна задача = N сообщений», жёсткого максимума длительности/контекста именно для Cowork; акция удвоения лимитов продлена до 5 августа 2026. Cowork пока НЕ в audit logs/Compliance API.
- **Claude Design:** research preview, детальные цифры расхода лимитов и формула общего пула с Claude Code не опубликованы [данных нет]. Качество кода — прототипное (независимые обзоры).
- **Версии плагинов** (frontend-design v1.1.0, hookify v0.1.0 и т.д.) — из marketplace.json на момент проверки; обновляются.
- Часть цифр по установкам плагинов и промо-акциям — из вторичных источников, помечены соответственно; официального «task = N messages» нет.
