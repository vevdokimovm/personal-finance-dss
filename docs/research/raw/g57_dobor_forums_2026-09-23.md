## Приоритет 1 — резерв под налог НПД/УСН

### Найдено: жалоба на некорректный расчёт резерва (banki.ru)

Формат площадки: вопрос-ответ (не форум-тред), но вопрос — дословная реплика живого
человека, публикация автора, ссылка прямая. Засчитываю как голос практика.

> «Почему неправильно резервируется налог по самозанятости, тинькофф резервирует
> сумму не учитывая льготу ( 10000 ₽) Резервируется 6%, налоговая начисляет 4%
> Куда делись 2%? Поступлений возврата на карту нет, переплаты по налогу тоже.»
> — **user-82107104025**, 03.11.2025 00:36, Респ Татарстан, г Зеленодольск.
> Источник: https://www.banki.ru/services/questions-answers/question/890037/

Это прямое подтверждение бага/непонимания в существующем инструменте «Налоговая
копилка» (Т-Банк): пользователь ДОВЕРЯЕТ автоматическому резервированию, но
обнаруживает расхождение между зарезервированной ставкой (6%, без вычета налогового
вычета 10 000 ₽ для новых самозанятых) и фактически начисленной (4%, для доходов от
физлиц). То есть автоматический резерв существует и используется, но **не учитывает
персональные параметры (налоговый вычет)**, и пользователь не понимает, куда делась
разница — реплика ближе к «не разобрался, куда делась переплата», чем к «резерв не
нужен».

Ответ банка (Анна Доронина, Т-Банк) — не реплика практика, шаблонный саппорт, не
дословная жалоба, не засчитывается как голос пользователя.

### vc.ru

**Вердикт: страница добывается (HTTP 200 на `curl`, на `r.jina.ai`, в браузере),
но лента комментариев НЕ добывается ни одним из шести каналов лестницы.**

- `curl -A браузерный-UA https://vc.ru` → HTTP 200 (базовая проверка).
- `WebFetch` статьи `id5849146/2871500-samozanyatost-riski-i-podvodnye-kamni` —
  вернул только текст статьи, честно сообщил «комментариев в присланном контенте
  нет» — счётчик на странице показывает 149 комментариев.
- `curl -s "https://r.jina.ai/<url>" -H 'x-no-cache: true'` → HTTP 200, 16 341 байт,
  это Markdown статьи (подтверждён `Published Time`, полный текст), без единого
  упоминания слова «комментарий» — лента комментариев не попала и через прокси.
- Браузер (`chrome-devtools`): открыл страницу, проскроллил до конца десять раз с
  паузами по 400 мс, снял `evaluate_script` — DOM содержит только счётчик «149» в
  элементах `[class*="comment"]` и плейсхолдер поля ввода `"Комментарий…"`, ни одного
  реального текста комментария в дереве. `list_network_requests` (xhr/fetch) не
  показал ни одного запроса с «comment» или «subsite» в URL — лента комментариев на
  vc.ru — это, судя по всему, отдельный тяжёлый JS-виджет (Osnova/DTF-платформа),
  подгружаемый по внутреннему API, который не проявился в перехваченных запросах за
  время наблюдения. Вкладка закрыта, капчи не было.

**Итог:** vc.ru как площадка «пройден» с кодом 200 на всех уровнях, но КОНКРЕТНО
лента комментариев (сама цель задачи) осталась недобытой всеми шестью инструментами
лестницы. Это не пейволл и не логин — площадка технически открыта, значит по правилу
§0 CLAUDE.md это «канал не пройден нашей стороной», а не «источник недоступен».
Дальнейший шаг для добора (не сделан из-за бюджета): найти внутренний API виджета
комментариев Osnova через `list_network_requests` при активном клике на счётчик
комментариев (не только скролл), либо попробовать мобильную версию `m.vc.ru`.

### 4pda.to

**Вердикт: канал НЕ добывается ни через `curl`, ни через прокси; в браузере
доходит до Cloudflare Turnstile, который не решается (и не отдаётся владельцу).**

- `curl -A браузерный-UA --max-time 15 https://4pda.to` → **HTTP 403** (голая база).
- `curl -s "https://r.jina.ai/https://4pda.to/forum/index.php?act=search&...&keywords=..."
  -H 'x-no-cache: true'` → HTTP 200 от самого прокси, но **в теле — страница
  Cloudflare «Just a moment...»** («Kто здесь?», iframe `challenges.cloudflare.com`,
  Turnstile). Прокси не смог обойти защиту, тело — это заглушка антибота, а не
  контент 4PDA. Размер тела не считаю добычей согласно правилу «читай тело, а не код».
- Браузер (`chrome-devtools`, `new_page` → `take_snapshot`) — тот же результат:
  страница `4PDA .:. Всё в порядке, но...` с Cloudflare Turnstile-виджетом
  `checkbox "Verify you are human"`. Это **не тот класс капчи, который решает
  владелец одним кликом** — Turnstile регулярно видит признак «управляется
  автоматизированным ПО» у headless/CDP-браузеров и крутит проверку бесконечно
  (правило из системного промпта: такую капчу владельцу НЕ отдавать). Вкладка
  закрыта без клика.

**Итог:** 4PDA — честно недобытый канал в рамках доступных инструментов, но по
правилу §0 это НЕ «источник недоступен» (сайт жив, отвечает, отдаёт контент не
роботам) — это антибот-защита, которую наша лестница инструментов не пробивает.
Открытый пункт для дальнейшей работы: попробовать штатный логин-сессию в реальном
пользовательском профиле Chrome (не автоматизированном), либо мобильное приложение
4PDA (у него может не быть Cloudflare-проверки перед API).

## Приоритет 3 — RuStore

Поиск через `backapi.rustore.ru/applicationData/apps?query=...` подтвердил: приложение
«Мой налог» (`com.gnivts.selfemployed`) — это ТО ЖЕ приложение, что и «Самозанятые.РФ»
из захода 18.09.2026 (appId 260979647, рейтинг 4.18, 16 907 оценок) — прошлый заход
уже разобрал его 30 отзывов и честно зафиксировал отсутствие реплик про резерв налога.
Повторно не открывал, дублировать работу незачем.

Проверены `reviews` двух банковских приложений, у которых, по тексту задачи, есть
инструмент «копилка под налог»:

- `https://www.rustore.ru/catalog/app/com.idamob.tinkoff.android/reviews` (Т-Банк) →
  HTTP 200, 106 501 байт, ~30 отзывов. **Ноль** упоминаний «самозанят*», «копилк*»,
  «резерв*» — отзывы о карточном приложении сфокусированы на входе/крашах/переводах,
  не на функции налоговой копилки.
- `https://www.rustore.ru/catalog/app/ru.alfabank.mobile.android/reviews` (Альфа-Банк)
  → HTTP 200, 94 137 байт, ~30 отзывов. Тот же результат — **ноль** совпадений.

**Вывод:** свежие ~30 отзывов на выдаче RuStore для больших банковских приложений —
неподходящий канал для узкой фичи вроде налоговой копилки: отзывы забиты общими
жалобами (вход, сбои, переводы), фича, которой пользуется меньшинство самозанятых
клиентов банка, тонет в общем потоке. Дальнейший добор этой гипотезы требует поиска
ПО ТЕКСТУ («копилка налог» как фильтр внутри отзывов, если площадка это поддерживает)
или иного канала (Google Play, где у части приложений отзывов на порядок больше и
есть сортировка «по релевантности запросу», либо тематические Telegram-чаты
самозанятых — за рамками бюджета этого захода).

## Приоритет 1 — итог по резерву под налог НПД/УСН

**Гипотеза частично прояснена голосом практиков, но НЕ подтверждена в желаемой
форме («откладываю N% сам») — вместо этого нашлись три других паттерна:**

1. **Автоматический резерв банков УЖЕ существует и используется, но пользователи
   ему не доверяют / не понимают его логику** — реплика с banki.ru про Т-Банк
   («Налоговая копилка»): человек полагается на автоматику, но обнаруживает
   расхождение ставки (6% вместо 4%, без учёта налогового вычета 10 000 ₽) и не
   понимает, куда делись деньги. Это сильный аргумент **за** нишу продукта: людям
   нужна не просто механика резервирования, а ПРОЗРАЧНОСТЬ расчёта (почему именно
   такая сумма).
2. **Момент осознания суммы налога — постфактум, из уведомления, а не заранее**
   (habr.com, jazator, 2021): три реплики подряд показывают человека, узнающего о
   расхождении между тем, что показывало приложение «Мой налог», и тем, что
   реально начислили — только когда пришло уведомление.
3. **Психологическое сопротивление идее «часть полученных денег не моя»**
   (habr.com, leha_gorbunov, 2021): человек прямо возражает против того, чтобы
   платить/резервировать сразу при получении оплаты, предпочитая сначала получить
   деньги целиком.
4. Косвенно (forum.infostart.ru, Dmitry888, 2021): встречается и путь «не откладывать,
   а задним числом аннулировать чек», то есть обход начисления вместо резерва —
   реальная, хоть и не одобряемая, альтернативная практика.

**Итоговый статус:** гипотеза о ценности автоматического резерва **скорее
подтверждена, чем опровергнута** — но не в форме «люди сами хотят откладывать»,
а в форме «люди уже пользуются автоматикой (банковской), доверяют ей не полностью
и хотят понимать её логику». Прямых реплик вида «банк сам всё откладывает, проблем
нет» (что опровергло бы гипотезу) в этом заходе не найдено. Классического
«откладываю в уме/в конверте» тоже не нашлось — видимо, эта практика либо не
обсуждается публично, либо реально вытеснена банковскими копилками и приложением
«Мой налог», и открытым остаётся вопрос ТОЧНОСТИ и ПРОЗРАЧНОСТИ авторасчёта, а не
факта его существования.

## Что осталось непройденным (честно, для следующего захода)

1. **vc.ru — лента комментариев** (149 шт. на одной только проверенной статье) —
   не поддалась ни одному из 6 каналов; нужен отдельный разбор внутреннего API
   Osnova-платформы (клик по счётчику комментариев + перехват XHR, а не скролл).
2. **4pda.to** — Cloudflare Turnstile, не пробивается автоматизацией в принципе;
   нужен реальный (не CDP-управляемый) браузерный профиль или мобильное приложение.
3. **Резерв под НПД** — 4 релевантные реплики найдены, но ни одной в формате
   «расскажи, как именно откладываешь на свой лад» (конверт/отдельная карта/в уме) —
   похоже, этот сценарий либо редок, либо просто не обсуждается на площадках общего
   профиля (бухгалтерские форумы, IT-паблики). Кандидат для следующего добора —
   тематические Telegram-чаты самозанятых и группы ВК/Дзен, вне бюджета этого захода.
4. Т-Банк/Альфа-Банк «копилка под налог» — не нашли отзывов по теме на первых ~30
   свежих отзывах RuStore каждого приложения; нужен канал с фильтром по ключевому
   слову внутри отзывов (Google Play такое умеет через сортировку релевантности).
