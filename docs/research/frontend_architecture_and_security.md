# Методичка: архитектура SPA, безопасность, деплой в РФ, доменные паттерны

Собрано 31.07.2026. Метки: [Ф] факт · [О] оценка · [Г] гипотеза.
Источники — `sources_registry.md`, разделы 4–7.

---

## 1. Архитектура

### Структура
Feature-Sliced Design: `app` → `pages` → `widgets` → `features` → `entities` → `shared`.
Слой видит только нижележащие; соседние слайсы одного слоя друг друга не импортируют — общее
выносится вниз. Границы желательно проверять линтером, иначе правило проживёт месяц. [О]

Barrel-файлы (`index.ts` как публичный вход слайса) полезны на уровне фичи и вредны глубже:
ломают tree-shaking и замедляют сборку. [Ф]

### Состояние
Серверное — TanStack Query, клиентское — Zustand, состояние экрана — в URL через роутер.
Размеры (gzip): Zustand ~1.1 КБ, Jotai ~3.5 КБ, Redux Toolkit ~11–14 КБ. [Ф]
Jotai имеет смысл только при дереве взаимозависимых ячеек — у нас такого нет. [О]

### Роутер
TanStack Router: типобезопасные пути и параметры поиска (валидация Zod), общий кэш и
инструменты с TanStack Query. React Router v7 сильнее в SSR, который нам не нужен. [О]

### Графики [Ф]

| Библиотека | Вес (gzip) | Рендер | Веер/интервал | Санкей |
|---|---|---|---|---|
| Recharts | умеренный, узел SVG на точку | SVG | через составные области | нет |
| visx | ~49 КБ (минимально ~15) | SVG | да, полный контроль | кастом |
| ECharts | ~100–359 КБ, tree-shakeable | Canvas | да | нативно |
| Chart.js | ~92 КБ ядро | Canvas | плагины | нет |

Раскладка: Recharts — база; visx — веер Монте-Карло (полный контроль над областью между
p10 и p90); ECharts — Санкей и длинные ряды (Canvas не деградирует там, где SVG создаёт узел
на каждую точку). Лицензии MIT и Apache-2.0.

### Виртуализация
TanStack Virtual (в Table виртуализация не встроена). Порог — примерно от сотни строк в DOM.
Нужна для списка операций и графика погашения по месяцам; для 66 альтернатив избыточна. [Ф/О]

### Формулы
KaTeX: синхронный рендер, пререндер на сборке через `renderToString` — браузер получает готовый
HTML и не тянет JS ради статичных формул. MathJax шире по покрытию и лучше по доступности,
но тяжелее в разы. [Ф]

### React Compiler
Стабильная версия с октября 2025, в свежих шаблонах Vite включён по умолчанию. Мемоизирует
точнее ручного. Ручная мемоизация остаётся нужна вокруг конфигов сторонних библиотек (графики)
и тяжёлых вычислений. Компилятор не заменяет `useTransition` и `useDeferredValue`. [Ф]

### Задел на будущее [О]
Обернуть строки в `t()` **с самого начала** — иначе интернационализация означает переписывание
всего интерфейса. Для PWA: манифест предзагрузки строится по хэшам файлов; служебный работник
не должен кэшировать ответы API с персональными данными.

### Бюджеты
Целевой стартовый JS дашборда — до 250 КБ в gzip [О]; разбиение по маршрутам, анализ бандла,
лимит веса чанков блокирующим гейтом в CI.

## 2. Безопасность

### CSP
Nonce генерируется в FastAPI на каждый запрос, подставляется в HTML и заголовок:
`default-src 'self'; script-src 'self' 'nonce-...'; object-src 'none'; base-uri 'self';
frame-ancestors 'none'`.

**Известная мина.** [Ф] Radix использует инлайновые стили; строгий `style-src 'self'` ломает
Dialog и ScrollArea (открытые обсуждения в репозитории Radix). Если nonce не протаскивается —
оставить `style-src 'unsafe-inline'` и **завести явный техдолг**, а не обойти молча.
`'unsafe-eval'` в проде — никогда.

### Токены
Access — только в памяти (не в localStorage), время жизни порядка 15 минут. Refresh — httpOnly,
Secure, SameSite, с ротацией при каждом обновлении. Идеал для финтеха — BFF, когда токены
вообще не доходят до браузера. [Ф]

### CSRF
`SameSite` на refresh-куке закрывает основное. При access-токене в заголовке `Authorization`
куки к запросу не прикрепляются автоматически — синхронизирующий токен там избыточен. [О]

### XSS в React
React не спасает от `dangerouslySetInnerHTML`, ссылок `javascript:`, инъекций в SVG и в конфиги
графиков. Markdown — только через санитайзер. [Ф]

### Цепочка поставок npm [Ф]
Волна самораспространяющихся червей в npm: первая (сентябрь 2025) — 187 пакетов; вторая
(ноябрь 2025) — свыше 700 пакетов, около 27 000 вредоносных репозиториев, порядка 14 000
раскрытых секретов у 487 организаций, исполнение на этапе установки и персистентный бэкдор;
третья (май 2026) — 170+ пакетов npm и впервые одновременно PyPI.

**Защита одиночке:** lock-файл, `--ignore-scripts`, пиннинг точных версий, аудит, задержка
обновлений на несколько дней после релиза, при подозрении — откат по lock-файлу и ротация
всех токенов. Свой прокси-реестр даёт и кэш, и изоляцию.

### Секреты
В бандл попадает всё с префиксом `VITE_`. Туда нельзя класть ничего секретного. Типовая
утечка — случайно назвать секрет `VITE_...`. [Ф]

### Заголовки [О]
HSTS с `includeSubDomains` и `preload`; `X-Frame-Options: DENY` и `frame-ancestors 'none'`;
`Referrer-Policy: strict-origin-when-cross-origin`; `Permissions-Policy` с отключёнными
камерой, микрофоном, геолокацией; `X-Content-Type-Options: nosniff`.

## 3. Деплой в РФ

- Статику отдаёт Nginx: gzip и brotli, иммутабельный кэш для хэшированных ассетов,
  `no-cache` на `index.html`, откат маршрутов на `index.html`. FastAPI — только API. [О]
- **Никаких внешних CDN, шрифтов Google, зарубежной аналитики.** Это и требование локализации
  персональных данных, и устойчивость к блокировкам. [Ф]
- Российские площадки: Yandex Object Storage с CDN, Selectel, Timeweb — все с аттестацией
  под персональные данные. Ответственность оператора персональных данных остаётся на владельце,
  провайдер даёт только заключение о соответствии. [Ф]
- npm из РФ: зеркала плюс свой прокси-реестр — заодно защита от компрометации. [О]
- Мониторинг: Sentry в собственном контуре с вычисткой персональных данных. [О]

## 4. Производительность [Ф]

Пороги «хорошо» на 75-м перцентиле реальных пользователей: LCP до 2.5 с, INP до 200 мс,
CLS до 0.1. INP заменил FID в марте 2024 — гайды, где ещё упоминается FID, устарели.
INP проваливается чаще прочих метрик.

Алерты ставить на 80% порога: INP 160 мс, LCP 2.0 с, CLS 0.08. Мерить по полевым данным,
лабораторные тесты систематически недооценивают провалы в SPA.

Наибольшая отдача — структурная: разбиение по маршрутам, виртуализация, `useTransition` на
тяжёлых пересчётах (Монте-Карло, SAW), а не россыпь мемоизации.

## 5. Доменные паттерны

- **Распределение потока** — составной столбец плюс ползунки «что если». Санкей понятен не
  всем; давать как режим «подробно», не по умолчанию. [О]
- **66 альтернатив** — по умолчанию три рекомендованных, остальное за «Показать все» с
  сортировкой по критериям. Вываливать 66 карточек — потерять пользователя. [О]
- **Лавина долгов** — график по месяцам, две линии «с планом» и «без плана», экономия
  на процентах отдельной крупной цифрой: это главный ощутимый результат продукта.
- **Монте-Карло** — веерная область, формулировка через «8 сценариев из 10».
- **Автономия и ПДН** — шкала с зонами; выше 50% ПДН обязателен дисклеймер о рисках.
- **Объяснимость** — формулы KaTeX по клику, «почему эта рекомендация». В финансовом продукте
  чёрный ящик не покупают; это не украшение, а несущая конструкция доверия.

**Онбординг.** [Ф] Средний отказ на онбординге финтеха — около 68% (рост с 63% в 2020 и 40%
в 2016). Крупнейшая точка отказа — загрузка документов. Отсюда: прогрессивное раскрытие,
честный индикатор («шаг 2 из 4», «примерно 4 минуты»), микрокопия «зачем эти данные» у
чувствительных полей.

## 6. Тестирование [Ф/О]

- Vitest на доменной логике — форматтеры денег и процентов, расчёты, схемы Zod. Здесь высокое
  покрытие оправдано.
- Playwright на критических путях; фикстуры аутентификации через сохранённое состояние,
  чтобы не логиниться в каждом тесте.
- Визуальная регрессия: Playwright-скриншоты плюс сервис сравнения; для одиночки достаточно
  открытого решения, интегрированного с GitHub.
- MSW версии 2: одни обработчики в Vitest и в браузере, генерируются из схемы OpenAPI.
- Доступность: автоматика ловит примерно треть проблем. Остальное — руками: клавиатура,
  фокус, скринридер, осмысленность подписей.

**Про 90%.** Порог осмыслен на доменной логике и вреден на разметке — там он превращается
в гонку за цифрой. Контракт закрывается не покрытием, а сверкой со схемой.

## 7. Процесс одиночки [О]

- Оценка сроков с коэффициентом 1.5–2.
- Резать объём, а не качество. Порядок отказа и неприкасаемое — `docs/frontend_milestone8_plan.md` §4.
- Замена код-ревью: автоматические гейты (типы, линтер, тесты, вес бандла, доступность,
  визуальная регрессия) плюс агент-ревьюер. **Непокрытым остаётся продуктовое и вкусовое
  суждение** — его не автоматизировать, это остаётся на владельце.
- Перед первым публичным запуском обычно забывают: уведомление регулятора, план отката,
  канал обращений пользователей и того, кто на них отвечает.
