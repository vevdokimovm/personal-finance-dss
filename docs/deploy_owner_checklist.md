# Веха 9: что нужно от владельца до первой команды деплоя

> Заведено v8.49.0. `docs/DEPLOY.md` отвечает на вопрос **«какие команды выполнить»**.
> Этот документ отвечает на другой: **«что должно быть на руках, прежде чем их выполнять»**.
> Разделены намеренно: половина пунктов ниже требует денег, паспорта или ожидания
> в несколько дней, и обнаружить это посреди вечера деплоя — значит остановиться на неделю.

---

## Почему вахта не может сделать это сама

Деплой — необратимое действие вовне: боевой сервер, публичный домен, реальные платежи,
персональные данные под 152-ФЗ. Автономная вахта останавливается на этом классе по
построению (`/auto` §5). Всё, что можно подготовить без необратимых шагов, подготовлено:

- `docs/DEPLOY.md` — девять шагов от чистой VPS до работающего продукта;
- `docker-compose.prod.yml`, `nginx/templates/`, `Dockerfile` — конфигурация;
- `tests/test_deploy_config.py` — гейт: пути существуют, секретов-литералов нет,
  обязательные переменные fail-loud, БД не смотрит в интернет, том БД именованный.

🔴 **Чего гейт проверить не может:** соберётся ли образ и поднимутся ли контейнеры.
Docker на рабочей машине отсутствует (проверены `docker`, `colima`, `podman`, `nerdctl`,
`lima`, Homebrew — ни одного), поэтому первая настоящая сборка произойдёт на сервере.
Это принято сознательно: ставить Docker Desktop ради одной проверки при 18 ГБ
свободного диска — решение владельца, а не вахты.

## 1. Инфраструктура — деньги и время ожидания

| Что | Где | Почему именно так | Срок |
|---|---|---|---|
| **VPS в России** | selectel.ru | 152-ФЗ: персональные данные граждан РФ хранятся на серверах в РФ. Хостер вне РФ делает продукт нелегальным с первого пользователя | минуты |
| **Домен** | reg.ru, искать `finpilot` | нужен для TLS-сертификата: Let's Encrypt выдаёт сертификат на имя, а не на IP | часы (делегирование DNS) |
| **DNS A-запись** | панель reg.ru | домен → IP сервера. **До получения сертификата**, иначе certbot не пройдёт проверку | до 24 ч на распространение |

**Минимальная конфигурация сервера:** 2 vCPU, 4 ГБ RAM, 40 ГБ SSD. Меньше — PostgreSQL
и приложение начнут конкурировать за память при первом же импорте выписки.

## 2. Почта — БЕЗ НЕЁ ПРОД НЕ ПОДНИМЕТСЯ

🔴 **С v9.6.0 это не рекомендация, а условие старта.** `validate_production_security`
требует `SMTP_HOST`, `SMTP_USER` и `SMTP_PASSWORD`: приложение с боевым `ENVIRONMENT`
и пустой почтой падает при запуске со списком проблем, а не поднимается молча.

**Почему ужесточили.** Без SMTP отправка писем — тихий no-op, но
`POST /auth/forgot-password` при этом отвечает «на него отправлена ссылка для сброса
пароля». То есть человек, забывший пароль, теряет аккаунт навсегда и не понимает почему:
это ЕДИНСТВЕННЫЙ путь восстановления доступа. Цена ошибки несимметрична — не поднявшийся
прод чинится строкой в `.env` и виден сразу, потерянный доступ не чинится вовсе и виден
не владельцу, а пользователю.

Продукт отправляет письма: подтверждение регистрации, восстановление пароля, уведомления.
**Без работающего SMTP человек не может ни зарегистрироваться, ни восстановить пароль.**

Российские провайдеры (Яндекс 360, Mail.ru для бизнеса) требуют подтверждения владения
доменом и выдают пароль приложения отдельно от пароля аккаунта. Это не делается за пять
минут в вечер деплоя.

🔴 **Проверяется живьём и только на проде** — в песочнице письма никуда не уходят.
Рецепт проверки — `docs/DEPLOY.md` шаг 3.1.

## 3. Секреты — генерируются на сервере, не здесь

Все боевые секреты создаются командами из `docs/DEPLOY.md` шаг 3 **на самом сервере**
и живут только в `.env` там. В репозиторий они не попадают никогда — гейт
`test_deploy_config.py` следит, что в `docker-compose.prod.yml` нет ни одного литерала.

🔴 **`TOKEN_ENCRYPTION_KEY` — единственный, который нельзя сгенерировать `openssl rand`.**
Формат строгий (32 url-safe base64 байта), hex-строка уронит приложение при старте.
Только `Fernet.generate_key()`.

### Два параметра, которые не секреты, но ломают прод молча (v8.56.0)

Старт-гард `validate_production_security` теперь их требует — приложение **не поднимется**,
пока они дефолтные. Это сделано намеренно: оба дефолта не дают ошибки сами по себе,
и узнал бы о них первый живой пользователь.

| Параметр | Что будет с дефолтом |
|---|---|
| `CORS_ORIGINS` | `CSRFMiddleware` отвергает мутирующий запрос с незнакомым `Origin`. С дефолтным localhost **каждое** действие на проде вернёт 403: вход, операция, план. Сайт открывается, читается и ничего не сохраняет — по симптому это выглядит как проблема прав, а не конфига |
| `DATABASE_URL` | SQLite в контейнере — файл, исчезающий при первом пересоздании **вместе с финансовыми данными пользователей**, без следа и без ошибки |
| `TRUST_PROXY_HEADERS` | 🔴 **Обязателен на проде — старт-гард не поднимет приложение без него (v9.1.0).** Без него rate-limit считает клиентом nginx — один адрес на весь интернет: лимит тратится всеми вместе, и, исчерпав его, продукт отвечает 429 **всем сразу**, включая пришедших впервые. Защита от перебора превращается в способ положить вход всему сервису. Локально не видно: прокси нет, адрес настоящий |

Значения: `CORS_ORIGINS` — https-домены продукта через запятую (без `http://`
и без `localhost`); `DATABASE_URL` — строка PostgreSQL, тот же хост, что в
`docker-compose.prod.yml`.

## 4. Чего в песочнице проверить нельзя — список для первого дня на проде

Эти вещи впервые заработают (или не заработают) на боевом сервере:

1. **Письма реально уходят** — SMTP-провайдер, порт, TLS, пароль приложения.
2. **Курсы и ключевая ставка ЦБ** тянутся с российского IP. Из песочницы запрос
   к cbr.ru может не пройти вовсе, и это не будет видно как ошибка.
3. **TLS-сертификат и его автообновление** — certbot требует публичный домен.
4. **Поведение под нагрузкой** — сколько держит 2 vCPU при реальных пользователях.
5. **Сборка образа** — впервые выполнится здесь, см. выше про отсутствие Docker.

---

## 5. Порядок, в котором это делается

```
домен куплен → DNS указывает на IP → сервер поднят → certbot получил сертификат
→ .env заполнен → docker compose up → проверка по шагу 6 DEPLOY.md
```

🔴 **Сертификат берётся ДО первого запуска**, а не после: nginx не стартует без
файлов сертификата, и попытка «сначала поднять, потом выпустить» даёт контейнер
в перезапуске по кругу.
