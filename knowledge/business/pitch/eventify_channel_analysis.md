# Разбор Telegram-канала Eventify — референс для канала FINPILOT

> Источник: скрины канала Eventify (январь–июль 2025, 111 подписчиков, студенческий
> продукт с питч-курса Solution Factory) + их питч и разбор. Зачем нам: осенью 2026
> запускаем Telegram-канал FINPILOT одновременно с продом — это ближайший живой
> пример «канал продукта с нуля», на котором видно, что работает и где грабли.
> Наш контент-план — `knowledge/business/posts_registry.md`; сюда — выводы.

## 1. Хронология и воронка Eventify (факты со скринов)

- **Янв 2025** — канал создан; **фев** — первый пост-манифест: боль (FOMO — «сколько
  крутых событий ты уже пропустил?»), решение тремя галочками, «подробности скоро».
- **Фев–март** — серия «Как мы создаём Eventify»: система категорий (+вопрос «что
  бы ты добавил?»), карусель Телеграм-канал/Разработка/Дизайн, контент-посты
  («5 причин, почему ты пропускаешь ивенты», ивент-этикет, синдром самозванца).
- **Март** — вовлечение: «подкупить админов печеньками», «ждём вашу реакцию —
  раскроем карты», опрос «вы раньше ходили на ивенты?».
- **Апр** — «Один день из жизни команды» (реальные лица, скрин кода с мемным TODO,
  честные фейлы бэкенда); анонс альфа-теста iOS «через 2 недели».
- **1 мая** — «OH SHIT... ПЕРЕНОС. Again» — честный перенос альфы ещё на 2 недели
  («лучше отложим, чем запустим "ну вроде работает"») — 14 лайков, максимум
  поддержки на канале.
- **Май** — альфа iOS в TestFlight + форма доступа (Google Forms), альфа Android
  (apk), опросы «успел зарегистрироваться?» (39 голосов) и «как вам приложение?»
  (30 голосов); **28 мая** — публичный roadmap на лето тремя карточками
  (июнь-удобства / июль-контроль / август-комьюнити).
- **Июнь–июль** — ежемесячные апдейты («Майские обновления»: скорость, защита
  данных, фиксы), редизайн лого с объяснением «почему меняем».

## 2. Что у них работает (берём себе)

1. **Build-in-public тон** — без пафоса, с самоиронией и мемами; пост про перенос
   сроков собрал больше любви, чем анонсы. Честность = валюта доверия. Для
   финпродукта это вдвойне: мы и так строим доверие к рекомендациям.
2. **Ритм и рубрики:** манифест боли → «как мы создаём X» (фичи по одной) →
   команда изнутри → альфа-воронка → публичный roadmap → ежемесячные апдейты.
   Готовый скелет первых 3 месяцев нашего канала.
3. **Контент-посты вокруг боли, не продукта** (ивент-этикет, синдром самозванца):
   держат канал живым между релизами. Наш аналог: разборы «куда направить 10к»,
   ликбез по ПДН/подушке, интерактивы «оцени распределение».
4. **Каждый пост заканчивается вопросом/CTA** — реакции, комменты, опросы.
   Встроенные опросы = бесплатный CustDev (у них 30–39 голосов на 111 подписчиков —
   отличная конверсия вовлечения).
5. **Показ команды лицами** — очеловечивает. Нам аккуратно: правило безымянности
   публичных артефактов остаётся; для канала владелец решает отдельно, что
   показывать (можно «руки и экраны» без имён).
6. **Публичный roadmap карточками** — обязательство перед аудиторией + контент на
   3 поста. У нас уже есть ROADMAP — переупаковать вехи 7–9 в карточки для канала.
7. **Форма → доступ к альфе** — простая воронка ранних пользователей и фидбэка.
   Для FINPILOT: форма → инвайт на закрытую бету перед осенним запуском.

## 3. Их грабли (не повторяем)

- **Просмотры >> подписчики** (посты 300–3.3k просмотров при 111 подписчиках —
  разгон репостами), но конверсия в подписку слабая: канал завели ДО того, как
  продукту было что дать попробовать. Вывод: наш канал стартует не «в пустоту»,
  а с работающим продуктом/бетой в первые недели.
- **Обещания сроков в постах** («через 2 недели») → публичные переносы. Даты
  даём только на то, что уже в тестировании; иначе — «скоро» без чисел.
- **Ссылки на Google Forms** — для финпродукта чужеродно и несерьёзно; у нас
  форма/лендинг на своём домене.
- Реакции-«печеньки» и тизеры без содержания работают один раз — злоупотребление
  выжигает канал.

## 4. Скелет первых постов канала FINPILOT (совместить с posts_registry.md)

1. Манифест боли: «каждый месяц один вопрос — куда направить свободные деньги»
   (цифры из нашего опроса 322 как соц-доказательство).
2. «Как мы создаём FINPILOT»: по фиче на пост — риск-профили, Avalanche, прогноз
   p10–p90, месяцы автономии.
3. Честный инженерный пост (традиция build-in-public: тест-свип 12 000 портретов,
   0 нарушений — наша версия «дня из жизни»).
4. Публичный roadmap карточками (тестирование → фронт → запуск).
5. Форма ранних пользователей → закрытая бета.
6. Ежемесячные апдейты фиксированного формата (что стало лучше / что дальше).
