# Юридический контекст FINPILOT

## Продукт

FINPILOT — алгоритмическая система поддержки принятия решений (СППР) по личным финансам. Собирает email и финансовые данные физлиц (доходы, расходы, обязательства, цели) и рассчитывает рекомендации по распределению свободных средств между досрочным погашением долга, резервом ликвидности и финансовыми целями.

**Чем НЕ является:** не банк, не проводит платежи, не управляет чужими деньгами, не даёт инвестиционных рекомендаций по ценным бумагам. Рынок — РФ. На старте — бесплатный публичный веб-сервис. Метафора продукта: «штурман», не «водитель» (даёт информацию для решения, решение и риск — на пользователе).

## Ключевые юридические выводы (зафиксированы, актуальны)

- **Лицензия ЦБ / статус финансовой организации НЕ нужны** — не банк, не платежи (мимо 161-ФЗ), не доверительное управление, не кредитование.
- **39-ФЗ (инвестиционное консультирование) НЕ применяется** — регулирует рекомендации по ценным бумагам; ведение личного бюджета / распределение между долгом, резервом и целями вне инвестконсультирования. Красная линия: как только продукт начнёт советовать конкретные ценные бумаги — включается 39-ФЗ (реестр инвестсоветников ЦБ + СРО).
- **Основной регуляторный трек — 152-ФЗ (персональные данные).** С 2025 стал дорогим (оборотные штрафы за утечки), но суммы для физлица — малого масштаба; миллионные штрафы — про юрлица и массовые утечки.
- **Финансовые данные — «иные» ПДн, НЕ специальная категория** (спецкатегории — здоровье, раса, политика, религия, интимная жизнь). Жёсткий режим спецкатегорий не применяется.
- **Главный реальный риск — утечка данных.** Административка за утечку лежит на операторе даже как жертве взлома (уголовка 272.1 — на хакере). Закрывается защитой данных, а не бумажками.

## Выбранный подход (осознанное решение пользователя, этап MVP)

- **Оператор = сервис FINPILOT.** Работа как физлицо, без реквизитов юрлица/ИП, без ФИО в документах.
- **Без подачи уведомления в РКН** на MVP-этапе.
- Юридически неидеально (оператор по закону должен быть идентифицируем; «безымянный» оператор — дефект), но это **приемлемый прагматичный риск, принятый сознательно после полного разбора**. Для физлица потолки штрафов малы, деанонимизация требует активных действий инспектора, маловероятных по мелкому тихому сайту.
- Задача юриста: **реализовывать этот выбор профессионально, помечая его статус** — не переубеждать повторно и не подделывать данные.

## Зафиксированные параметры

- E-mail для всех обращений и отзыва согласий: **finpilot.help@proton.me** (если занят — есть запасные; адрес отзыва согласия по 152-ФЗ менять нельзя, брать на вырост).
- Аудитория: **18+** (осознанно ограничена, чтобы снять вопрос данных несовершеннолетних).
- Хранение данных: **на территории РФ**, трансграничной передачи нет.
- Дата редакции документов: 29.07.2026.

## Актуальная нормативная база (сверено, июнь 2026)

- **152-ФЗ** «О персональных данных»; Приказ РКН № 180 от 28.10.2022 (форма уведомления, подаётся на pd.rkn.gov.ru).
- **ст. 13.11 КоАП** — штрафы за нарушения обработки ПДн. С 01.01.2026 дела рассматривают мировые судьи (508-ФЗ), независимо от статуса нарушителя. Штрафы за утечку масштабируются по числу субъектов (порог 1000): <1000 → ч. 1 (для граждан 10–15 тыс, часто предупреждение); ≥1000 → спецсоставы (для физлица 100–400 тыс по масштабу; для юрлиц до 15 млн). Оборотные штрафы (1–3%, 20–500 млн) — только повторные утечки, считаются от выручки, к физлицу без выручки неприменимы.
- **ст. 272.1 УК** — незаконный оборот ПДн; субъект — тот, кто получил данные незаконным путём (хакер/сливальщик), а НЕ добросовестный оператор-жертва взлома.
- **38-ФЗ «О рекламе»** (ст. 18) — рекламная рассылка требует отдельного предварительного согласия.
- **54-ФЗ** — онлайн-касса при приёме платежей (самозанятые освобождены) — актуально при монетизации.
- Позиция ВС (определение от 21.01.2026): оператор отвечает за утечку, даже если она произошла через технического подрядчика; сам факт утечки влечёт ответственность независимо от доказанности вины.

## Требования к сбору ПДн на сайте (что реально проверяет РКН-бот, 2026)

- Чекбокс согласия пустой по умолчанию (без атрибута `checked`); пользователь ставит галочку сам.
- Отдельные согласия под разные цели (обработка ПДн / финданные / рассылка — раздельные чекбоксы).
- Текст чекбокса указывает цель обработки, а не просто «Согласен»; рядом — прямая ссылка на полный текст.
- Форму нельзя отправить без согласия.
- Фиксируются IP, время и версия текста согласия.
- Локализация: данные на РФ-хостинге (зарубежный хостинг = нарушение).
- Cookie: баннер + отдельная Cookie-политика; аналитика (Метрика и т.п.) требует согласия на cookie.
