# timing_lab — сколько стоит время

Журнал длительности прогонов и инструмент, который его ведёт. Справочник для чтения —
`docs/timing_reference.md`, он же и обновляется отсюда командой.

## Зачем

Планировать работу можно было только в токенах. Времени в картине не было, хотя полный
`pytest` идёт двадцать пять минут — это не «мелочь между делом». Заведено по требованию
владельца 2026-09-03.

## Команды

```bash
# замерить прогон и записать (сам снимет load average и число ядер)
python -m tools.timing_lab.record run --suite vitest-full --tests 271 -- npx vitest run

# записать замер, снятый вручную
python -m tools.timing_lab.record add --suite pytest-full --seconds 1471 --tests 1632

# таблица в терминал
python -m tools.timing_lab.record report

# вписать таблицу в docs/timing_reference.md между маркерами
python -m tools.timing_lab.record report --update-doc
```

## Почему устроено именно так

**Каждая запись несёт нагрузку хоста.** Длительность без неё — бессмысленное число:
один и тот же срез `test_api_demo` шёл 40.8 с на спокойной машине и 83.4 с при load
average 74 на 8 ядрах, без единой правки кода. Пять таких эпизодов задокументированы
в `docs/reports/investigations/machine_load_gate_timeout_investigation.md`.

**Медиана, а не среднее.** Один прогон под перегрузкой сдвигает среднее так, что
планировать по нему нельзя. Выбрасывать его тоже неверно — он показывает реальный
худший случай, поэтому лежит в колонке «худший».

**Порог перегрузки относительный** — load average выше числа ядер, а не абсолютное
число. Абсолютный порог был бы тем же дефектом, что 45-секундный бюджет Stop-гейта:
величина, измеренная на одной машине и применённая к другой.

**Провалившийся прогон тоже записывается** (`note=exit=N`). Упавший набор занимает
время так же, как успешный, и при планировании это время всё равно тратится.

## Чего лаборатория НЕ делает

- Не считает токены — это `tools/cost_tracker/` и скилл `/tokens`.
- Не измеряет время батча целиком, только прогоны инструментов.
- Не переносится на CI: все числа сняты на машине владельца (8 ядер, macOS),
  раннер GitHub — другое железо.
