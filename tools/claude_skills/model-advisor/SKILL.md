# FINPILOT Model Advisor — скилл выбора модели и усилия

## Захардкоженный принцип (не менять, это контракт скилла)

> **Скилл — только роутинг к докам, актуальный лайнап моделей беру из
> системного контекста (Haiku 4.5 / Sonnet 5 / Opus 4.8 / Fable-Mythos),
> цены/лимиты хардкодить не буду — они меняются, дам ссылку на docs.**

Разворачивается это так:

1. **Роутинг-only.** В скилле нет ни одной цены, ни одного числового лимита,
   ни одного «актуального» бенчмарка. Всё это гниёт за недели. Скилл хранит
   только то, что стабильно: принципы выбора, триггеры и адреса доков.
2. **Лайнап — из системного контекста, с проверкой.** Текущие модели Клод
   узнаёт из собственного системного контекста на момент разговора. Лайнап в
   скобках выше — иллюстрация на дату написания (2026-07-05), не истина
   навсегда. Системный контекст тоже может отставать от свежего релиза
   (прецедент: контекст ещё называл Sonnet 4.6, когда Sonnet 5 уже вышел) —
   при малейшем сомнении сверяйся с доками по ссылкам из §Роутинг, а не
   спорь по памяти.
3. **Цены/лимиты — только по ссылке.** На вопрос «сколько стоит X» или «какой
   лимит у Y» ответ по памяти запрещён: открой ссылку из §Роутинг (web_fetch/
   web_search) и отвечай по первоисточнику с указанием источника.

## Триггеры → автосоветы

| # | Триггер (что видишь в задаче/чате) | Действие Клода |
|---|---|---|
| 1 | Старт нетривиальной задачи | Первой строкой ответа объявить пару: `[Модель · effort — причина]`. Пример: `[Opus 4.8 · high — правка filtering.py, цена ошибки высокая]` |
| 2 | Задача трогает `app/core/*`, `app/services/planning.py`, `app/utils/time.py`, миграции Alembic, merge линий вахт, ADR/архитектуру | Советовать **Opus-класс · high**. Если в пикере слабее — предупредить о недожиме до начала работы |
| 3 | Обычная фича по ясному ТЗ (TDD red→green), багфикс с воспроизводимым repro, содержательный док/методичка | Советовать **текущий Sonnet · medium** |
| 4 | Механика: переименования, ссылки, форматирование, ротация WATCHLOG §3, «продолжай» | Советовать **Haiku · low**; отвечать коротко, без ритуальных прогонов |
| 5 | Модель в пикере заметно мощнее задачи (оверкилл) | Одной строкой: «тут хватит {модель дешевле}, сэкономишь» — и работать дальше, не нудеть |
| 6 | Модель в пикере слабее канон-/архитектурно-критичной задачи (недожим) | Одной строкой: «подними до {модель}, иначе рискуем инвариантом» — и ждать решения владельца |
| 7 | Красные плашки «Chat paused / safety…» повторяются | Диагноз: сессия на Fable-классе; совет — увести проект на Opus-класс (для FINPILOT мощь Fable избыточна, фолбэк-заслоны только мешают). Детали: `knowledge/guides/claude_infrastructure_methodology.md` §7 |
| 8 | Вопрос о ценах, лимитах, тарифах, «что почём», «какой лимит» | НЕ отвечать по памяти. Открыть соответствующую ссылку из §Роутинг и ответить по первоисточнику |
| 9 | Вопрос «какие сейчас модели / что нового у Anthropic» | Лайнап из системного контекста + сверка через ссылку Models/News из §Роутинг, если есть сомнение или спрошено «самое свежее» |
| 10 | Сессия разрослась (тема логически закрыта, контекст огромный) | Предложить перенести следующую тему в новый чат: каждый ответ в гигантской сессии дороже |
| 11 | Effort/extended thinking включён на механике или выключен на каноне | Напомнить правило: effort привязан к **цене ошибки**, не к длине текста |
| 12 | Вопрос «где работать / какой инструмент — чат, проект, Cowork, Claude Code, приложения» | Кратко развести по §12 методички: **проект** — дом канона (кэш, RAG), **Claude Code** — работа по репозиторию, **Cowork** — автономная не-кодовая работа, чат — разовое. Детали и таблица: `claude_infrastructure_methodology.md` §12 |
| 13 | Реальная работа по репозиторию: правки по многим файлам, прогон тестов, миграции, обход дерева на регрессии | Предложить **Claude Code + субагентов** (planner/code-reviewer/tester/debugger/security-audit), роутинг моделей в их YAML — как в этом скилле (ревью→Sonnet, lint→Haiku, канон→Opus). Детали: `claude_infrastructure_methodology.md` §13 |
| 14 | Вопрос про лимиты файлов, форматы, «сколько влезет в проект», почему knowledge уходит в RAG | НЕ по памяти для чисел: ссылка на загрузку файлов из §Роутинг. Принцип (200K = мягкий потолок → RAG; тезисные `.md` дольше держат «вижу всё») — `claude_infrastructure_methodology.md` §12 |

Формат совета — ровно одна строка, без лекций. Совет не блокирует работу:
объявил и продолжай; переключение модели — ручка владельца в UI, Клод её
не крутит и не делает вид, что крутит.

## Связанное

Полная методичка (каталог моделей, дерево решений, экономика токенов,
разбор заслонов Fable): `knowledge/guides/claude_infrastructure_methodology.md`.

диктует «что делать по триггеру».
