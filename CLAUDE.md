# FINPILOT

Система поддержки принятия решений в персональных финансах. Рынок РФ, запуск осенью 2026,
планка качества — Т-Банк, Сбер, Альфа. Обработка персональных данных: 152-ФЗ обязателен.

## Стек
Бэкенд — см. requirements.txt / pyproject.toml.
Фронтенд вехи 8: Vite · React 19 · TypeScript · TanStack Router/Query · Zustand ·
Radix через shadcn/ui · Recharts + visx · KaTeX · Vitest · Playwright.

```

pytest -q --junitxml=out.xml       # результаты читать через XML, не через grep
flake8 . && mypy app               # должно быть чисто
```

## Правила
1. TDD: сначала тест (red), потом реализация (green), потом гейты. Ничего не отдавать до зелёного.
2. `black .` на весь проект запрещён — ломает диф между четырьмя аккаунтами.
3. Любое изменение схемы — матрица SQLite + PostgreSQL.
4. Батч = версия по SemVer: фича MINOR, фикс и доки PATCH. Церемония: `VERSION`,
   `app/config.py`, `CHANGELOG.md`, `docs/WATCHLOG.md` (шапка, §0, окно §3 ровно из 10 версий),
   чекбоксы `docs/ROADMAP.md`, указатель «СЛЕДУЮЩАЯ ЗАДАЧА». Расхождение версий валит preflight.
5. Только семантические токены. Магические hex и px вне токенов — ошибка, не стилистика.
6. Деньги: табличные цифры, знак рубля после числа через неразрывный пробел, запятая как
   десятичный разделитель.
7. Реальные персональные данные не уходят наружу ни при каких условиях. Работа — на синтетике.
8. Не объявлять задачу невозможной, не исчерпав каналы.
9. Первичный материал извне (отчёты исследований, ответы экспертов, чужие замеры, длинные логи)
   сохраняется дословно в `docs/research/raw/` ДО написания выжимки. Реестр URL его не заменяет.
   Правило §18 WATCHLOG, история — PIT-013.

## Формат ответа
Русский для объяснений, английский для кода и путей. Без эмодзи. Сначала реализация, потом
короткое объяснение ключевых решений. Отчёты короткие: не пересказывать сделанное построчно.
Не добавлять шаг верификации по своей инициативе — он уже встроен.
